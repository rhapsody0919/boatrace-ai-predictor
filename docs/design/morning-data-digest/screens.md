### 共通化の判断根拠

- **C-2 / C-3 / C-4 は `.claude/rules/component-reuse.md` の「同じUIパターンが2箇所以上で使われる場合、必ず共通コンポーネントに切り出す」に該当する**。S-2/S-3/S-4 は指標が違うだけで枠組みは同じ
- C-3 の指標部分を props の分岐ではなく **children で差し替える**設計にする。指標の種類が増えるたびに props が増えるのを避ける
- **`App.jsx` と `RaceDetail.jsx` の両方に同じUIが必要になるケースは、本機能では発生しない**（P-1 は独立ページで、既存2ページに同じUIを置かない）。ホームへの導線は `Link` 1つで済む

### `CrossTabGrid` との関係

phase a が `src/components/analysis/CrossTabGrid.jsx`（行軸×列軸のクロス集計グリッド）を作る予定だが未着手。**本機能はクロス集計グリッドを使わない**（縦1列のカードリストであり、行軸×列軸の2次元表ではない）ため、待つ必要も先に作る必要もない。C-7 `EntryCourseTendencyBar` は1次元の確率分布バーであり別物。

### FR-7（イン崩れ指数）のデータ源

**画面側では取得しない。早朝バッチが `predictions.feature_contributions.volatilityPercentile` を直接読み、`morning_digest_rows.volatility_percentile` に 0〜100 で保存する**（[ADR-0070](../../adr/0070-morning-digest-precomputed-rows.md)）。

あわせて **spec FR-7 の受入基準も変更した**。`predictions` は日中に再生成されるため（実測: 2026-09-20 は 08:36〜22:51 の15時間帯に分散、09-21 は 01:57〜20:51 の14時間帯）、05:30 に凍結した値とホームの live 値が一致することは原理的にありえない。受入基準は「**`morning_digest_days.generated_at` 時点の値であることをUIに明示し、その時刻の値と一致する**」に改めた。`isFallback`（会場内サンプル不足のプレースホルダ値0.5）の行を除外する扱いは既存実装に合わせる。

## 5. デザイントークンと新規CSS

### トークンで表現するもの（新規CSS変数を作らない）

| 用途 | トークン |
|---|---|
| ページ背景 | `--surface-page` |
| カード背景 | `--surface-card` |
| カード境界 | `--border-hairline` |
| 見出し・本文（ページ背景に直接乗る） | **`--text-primary` / `--text-secondary`（意味トークン必須）** |
| 余白・角丸・境界幅 | 既存のスケール（`--border-width-*` 等） |

**ダークモードの必須ルール**: セクション見出し（h2）・ページヘッダ（h1）・空状態メッセージ・注記のような「要素自身が背景色を持たずページ背景が透ける」テキストは、生パレット値（`--color-gray-900` 等）ではなく**必ず意味トークンを使う**。2026-08-25 に選手ページで「ダークモードで見出しが不可視」のバグが発生した経緯がある。カード内で自前の固定背景を持つ部分のみ生パレット値を許す。

### 新規CSSが必要なもの

| 要素 | 内容 |
|---|---|
| 差分バッジ（`+24pt ▲` / `-8pt ▼`） | 正負で色を変える。**色だけに頼らず ▲▼ の記号も付ける**（色覚特性への配慮） |
| 小標本フラグ | 既存に統一された表現がない（`VenueTendencyPanel` は数値を隠す、`AttackDefenseTable` は「参考値」マーク）。本機能では **⚠ アイコン＋ツールチップ**で統一し、数値は隠さない |
| スパークライン（C-6） | インラインSVG。Recharts は重いため1コンポーネントのためには導入しない |
| 進入コース分布バー（C-7） | 横積み棒。CSS の flex で実装可能 |
| カードグリッド | デスクトップ2カラム / モバイル1カラム |

**新しいテーマカラー・独自デザインシステムは作らない**。差分バッジの正負の色も、既存トークンの範囲で選ぶ（新規に緑/赤を定義しない）。着手前に `docs/reference/brand-kit.md` のギャラリーを確認する。

## 6. 状態の設計

各セクションで以下4状態をすべて設計する。

| 状態 | 表示 |
|---|---|
| ローディング | ページ全体は `LoadingScreen`。セクション単位はスケルトン（**高さを確保してCLSを出さない**） |
| 取得失敗 | `InlineFetchError` + `onRetry` で該当セクションだけ再取得。**空配列にフォールバックしない**（`.throwOnError()` 既定適用のため例外になる） |
| 該当0件 | 「本日、条件に該当するレースはありません」と明示する。**セクションごと消さない**（「無い」と「読み込めていない」を区別させる） |
| データ不完全 | FR-5 で 2026-09-21 より前の日付が指定された場合、「この日のフライング情報は不完全です」と表示する（spec FR-5 受入基準） |

`?date=` で未来日・データの無い日を指定した場合は、エラーではなく「データがありません」を出す（spec FR-12）。

## 7. 論点と決定

### 決定済み（2026-09-24、モック提示時）

| # | 論点 | 決定 |
|---|---|---|
| 7 | **カード内の情報量** | **案A（常時表示）を採用**（ユーザー承認）。会場平均・モーター2連率・イン崩れ指数・直近90日・期別推移をカード内に常時出す。折りたたみの案Bは不採用 → **2026-09-24、実装をローカルで見たユーザーの指摘により案B寄りに改訂（下記「実物を見ての改訂」）** |
| 2 | ダークモードの配色 | モックの配色で確定。意味トークンで反転し、金色は `--ryujin-gold-500`（#c9a227）、⚠小標本フラグは `--ryujin-navy-300` 背景＋`--ryujin-silver-300` 文字 |

### 実物を見ての改訂（2026-09-24、ローカル確認後）

モックは1セクション4〜5枚の想定で描いていたが、実装では逃げが25枚並び「次のセクションに届くまでのスクロールが長い」「1枚が高い」という指摘を受けた。論点7を次のとおり改訂し、あわせて**未実装だった論点4を実装する**。

| 対象 | 改訂内容 |
|---|---|
| カード（`DigestRaceCard`） | `collapsible` を追加。既定は**要約のみ**（会場・R・締切・選手・級別・枠・率・地力・予測・小標本の注意）で、母数／信頼下限／会場平均／直近90日／モーター2連率／イン崩れ指数は ▼ で開く。**タップ領域は分離**し、カード本体は従来どおりレース詳細への `<a>`、▼ボタンだけが開閉する（`RacerCompactRow` と同じ方針。カード全体をトグルにすると詳細への導線が1タップ失われ、`<a>` でなくなる） |
| 一覧（`DigestCardGrid` 新設） | 論点4の既定を実装。初期表示は**上位6件**で、残りは「もっと見る (残りN件) ▼」（文言は既存 `HitRaces` に揃える）。5件ではなく6件なのは、2列・3列のどちらでも端数が出ないため |
| 列数 | 折りたたみで1枚が低くなったため、2列の開始を 768px から **480px** に前倒しし、1024px以上で **3列**にする |
| 小標本の⚠ | **折りたたみ中も残す**（根拠の弱い数値が無警告で並ぶのを防ぐ） |

さらに折りたたみ版を見て「若松での予測」「地力+36.6pt」が何の数値か分かりづらいという指摘を受け、指標の見せ方も改訂した（案2を採用、[ADR-0071 §改訂3](../../adr/0071-venue-adjusted-skill-delta.md)）。

| 対象 | 改訂内容 |
|---|---|
| 指標の表示（`RateWithBaseline`） | 差分の数値と**「地力」「pt」という語をUIから消す**。「会場・級別の平均」→「この選手」の2本の横バーで見せる。計算（`skill_delta`）自体は抽出・並び替えの内部処理として維持する |
| 母数 | **折りたたみ中も常に出す**（上記の改訂で畳んでしまったのを戻す）。34走の88%と9走の88%は別物で、母数の見えない率は信用度を判断できない。畳むのは信頼下限と直近90日だけ |
| ラベル | 逃げだけコース表記が無く不揃いだったため「逃げ率」→「逃げ率（1コース）」に揃える |
| 注目レースカード（`FeaturedRaceCard`） | 「地力 +33.2pt ▲」→「戸田の平均 7.5% → この選手 40.7%」。母数は見出しへ（「まくり率（4コース・26走）」） |
| 注目レースの理由文 | バッチ側（`generate-morning-digest.js`）も同じ文体に変更。書き込み済みの日の行は旧表記のまま残り、翌朝のバッチで置き換わる |
| 「このページの見方」 | 「地力」「◯◯での予測」の項目を「◯◯の平均」「この選手」に差し替え |

**採らなかった案**: 予測を主役（最大表示）にする案は、抽出条件が実績率70%以上で判定されているため見出しの数字と抽出基準が別物になる。抽出自体を予測ベースへ変えるのは spec FR-4 の変更になるため見送った。
