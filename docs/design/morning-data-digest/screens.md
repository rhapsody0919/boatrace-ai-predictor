### 共通化の判断根拠

- **C-2 / C-3 / C-4 は `.claude/rules/component-reuse.md` の「同じUIパターンが2箇所以上で使われる場合、必ず共通コンポーネントに切り出す」に該当する**。S-2/S-3/S-4 は指標が違うだけで枠組みは同じ

## 5. デザイントークンと新規CSS

### トークンで表現するもの（新規CSS変数を作らない）

| 用途 | トークン |
|---|---|
| ページ背景 | `--surface-page` |
| カード背景 | `--surface-card` |
| カード境界 | `--border-hairline` |
| 見出し・本文（ページ背景に直接乗る） | **`--text-primary` / `--text-secondary`（意味トークン必須）** |
| 余白・角丸・境界幅 | 既存のスケール（`--border-width-*` 等） |

**ダークモードの必須ルール**: セクション見出し（h2）・ページヘッダ（h1）・空状態メッセージ・注記のような「要素自身が背景色を持たずページ背景が透ける」テキストは、生パレット値（`--color-gray-900` 等）ではなく**必ず意味トークンを使う**。2026-08-25 に選手ページで「ダークモードで見出しが不可視」のバグが発生した経緯がある。カード内で自前の固定背景を持つ部分のみ生パレット値を許す。

### 新規CSSが必要なもの

| 要素 | 内容 |
|---|---|
| 差分バッジ（`+24pt ▲` / `-8pt ▼`） | 正負で色を変える。**色だけに頼らず ▲▼ の記号も付ける**（色覚特性への配慮） |
| 小標本フラグ | 既存に統一された表現がない（`VenueTendencyPanel` は数値を隠す、`AttackDefenseTable` は「参考値」マーク）。本機能では **⚠ アイコン＋ツールチップ**で統一し、数値は隠さない |
| スパークライン（C-6） | インラインSVG。Recharts は重いため1コンポーネントのためには導入しない |
| 進入コース分布バー（C-7） | 横積み棒。CSS の flex で実装可能 |
| カードグリッド | デスクトップ2カラム / モバイル1カラム |

**新しいテーマカラー・独自デザインシステムは作らない**。差分バッジの正負の色も、既存トークンの範囲で選ぶ（新規に緑/赤を定義しない）。着手前に `docs/reference/brand-kit.md` のギャラリーを確認する。

## 6. 状態の設計

各セクションで以下4状態をすべて設計する。

| 状態 | 表示 |
|---|---|
| ローディング | ページ全体は `LoadingScreen`。セクション単位はスケルトン（**高さを確保してCLSを出さない**） |
| 取得失敗 | `InlineFetchError` + `onRetry` で該当セクションだけ再取得。**空配列にフォールバックしない**（`.throwOnError()` 既定適用のため例外になる） |
| 該当0件 | 「本日、条件に該当するレースはありません」と明示する。**セクションごと消さない**（「無い」と「読み込めていない」を区別させる） |
| データ不完全 | FR-5 で 2026-09-21 より前の日付が指定された場合、「この日のフライング情報は不完全です」と表示する（spec FR-5 受入基準） |

`?date=` で未来日・データの無い日を指定した場合は、エラーではなく「データがありません」を出す（spec FR-12）。

## 7. 論点（モック提示時にユーザーと確定する）

| # | 論点 | 選択肢 |
|---|---|---|
| 1 | **URLパス** | `/today` / `/today-data` / `/morning` / `/daily-digest`。既存ルートとの衝突はいずれも無い。ja専用なので日本語検索での語との相性で決める |
| 2 | **Headerナビへの追加可否** | 追加するとホームからの回遊が上がるが、Headerの項目が増えてモバイルで窮屈になる |
| 3 | `?date=` 付きURLの robots | `noindex` にするか、canonical だけで済ませるか。既存の `useRobotsMeta` の使われ方を確認して決める |
| 4 | **S-2〜S-4 の1セクションあたりの表示上限** | 実測で逃げ70%は本日25件（両窓共通）。全件出すか上位N件に絞って「もっと見る」を置くか |
| 5 | **セクションの並び順** | 現案は 注目1件 → 逃げ → まくり → 逃がし → フライング。競合は フライングを先頭に置いている |
| 6 | S-1 の選定ロジック | spec 未確定事項#4。モックでは「逃げ率の会場平均比が最大、かつイン崩れ指数が下位25%」を仮置きする |
| 7 | カード内の情報量 | モック（§8）で実際に見て、多すぎないか判断する。30代女性ファン視点で「項目が多すぎると何を見ればいいか分からない」という指摘が出ている |
