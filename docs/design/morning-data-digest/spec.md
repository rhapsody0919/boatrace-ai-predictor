- **種別**: UI機能（→ `/step1-screens` に進む）
- **Linearチケット**: [BOA-402](https://linear.app/boat-ai/issue/BOA-402)
- **引き継ぎ**: [handoff-memo.md](./handoff-memo.md)（オーケストレーションセッションからの引き継ぎ。本specはその§3のデータreadinessを2026-09-24に再実測して更新したもの）

競合「ボートレース日和」が毎朝Xで投稿する「本日のデータ一覧」（リンク先: `https://kyoteibiyori.com/blog/YYYYMMDD0001`）に対抗する、龍神レーダー版の朝のデータ一覧ページを新設し、X・ブログ・note・YouTubeへ毎朝展開する。**模倣ではなく昇華させる**ことが目的（[handoff-memo §5](./handoff-memo.md)）。

## 2. 機能要件

優先度: **P0**=初版必須 / **P1**=初版に入れる / **P2**=入れられれば入れる

### FR-1 逃げ率が高い選手のレース抽出（P0）

本日開催の全レースのうち、**1号艇の選手の「1コース進入時の逃げ率」が閾値以上**のものを一覧表示する。

- **定義**: 分母 = その選手が1コースに進入した走数、分子 = そのうち `winning_technique='逃げ'` かつ `rank1` = 自艇の走数
- **判定窓**: 地力窓（§5.1）
- **閾値**: 70%以上（競合と揃える）
- **併記**: 調子窓（直近90日）の同指標、会場ベースライン差分（FR-4）、母数n、Wilson95%下限

**受入基準**:
- 本日のレースに対し実行したとき、抽出結果の各行について、同じ定義のSQLを `node -e` で独立に実行した値と**小数第1位まで一致**する
- 母数が閾値（§5.3）未満の選手は抽出対象に含まれない
- 1号艇の選手が欠場（`is_absent=true`）のレースは抽出しない
- 地力窓の実際の日数がUIに表示され、365等の固定値がハードコードされていない

### FR-2 まくり率が高い選手のレース抽出（P0）

本日開催の全レースのうち、**いずれかの艇の選手の「そのコース進入時のまくり率」が閾値以上**のものを一覧表示する。

- **定義**: 分母 = その選手がコースNに進入した走数、分子 = そのうち `winning_technique='まくり'` かつ `rank1` = 自艇の走数
- **判定窓**: 地力窓（§5.1）。**公式期別データによる代理は使えない**（§1.3）
- **閾値**: 25%以上（競合と揃える）
- **表示**: 選手名・会場・レース番号・枠番・進入コース・まくり率・母数n・締切時刻

**受入基準**:
- FR-1と同じくSQL独立実行との一致を確認する
- 母数が小標本閾値（§5.3）を下回る行には**小標本フラグが視覚的に出る**。**判定基準は「Wilson95%下限 < 抽出閾値(25%)」**。p̂=0.25・n=10 の Wilson 下限は 8.1% で 25% を下回るため正しくフラグが立つ（ベースレートと比較する当初案は 8.1% > 5.08% で立たず、逆に働いていた。レビュー指摘H-3）
- 1コースの選手はまくり率の対象外（1コース艇はまくりで勝てない。実測で0件）

### FR-3 逃がし率のベースライン差分（P0）

競合の「逃し50%以上」を**絶対閾値からベースライン差分に置き換える**（§1.3の無選別問題への対応）。

- **定義**: 分母 = その選手がコースN（N≥2）に進入した走数、分子 = そのうち `winning_technique='逃げ'` の走数（＝1コースに逃げられた走数）
- **比較対象**: **会場 × グレード**のベースライン（FR-4）。**「コース」は比較軸にしない** — 逃がし率は定義上コース軸を持たないため（§1.3の実測。レビュー指摘H-5）
- **抽出条件**: 地力が **+20pt以上**（2026-09-24のレビュー指摘H-4を受けて +15pt から変更。実測: +10pt→115件 / +15pt→43件 / **+20pt→12件（9会場、戸田1件）** / +25pt→3件。+15ptは目標5〜15件の約3倍だった）
- **表示**: 「この選手は**この会場・このグレードの平均より** Xpt 逃がしやすい」という文で提示する。**「このコースの平均より」とは書かない**

**受入基準**:
- 全体平均との単純比較ではなく、**会場×グレード別のベースライン**と比較している
- 本日のレースに対する該当件数が **5〜15件** に収まる
- 該当が**特定の1会場に集中しない**（素朴な差分では戸田に8/12件集中していた）
- ベースライン自体の母数が不足するセルは `race_grade='ALL'` 行へフォールバックする

### FR-4 会場ベースライン差分（P0）

FR-1・FR-2・FR-3のすべての率について、**その選手の実績率が会場構成の偏りで説明できる分を取り除いた差分**を併記する。

会場間で逃げ率が20.3pt開く（§1.3）ため、差分なしで「逃げ率70%」と出すと数値自体が誤解を招く。

#### ⚠️ 素朴な「実績率 − 今日の会場平均」は誤り（2026-09-24にモックデータ作成中に発見）

当初案の「選手の実績率 − 今日の会場のコース別平均」で本日分を試算したところ、**逃がし率の該当12件中8件が戸田に集中**した。原因は交絡である。

- 選手の実績率は**その選手が過去に走った全会場**を混ぜて算出されている
- それを**今日の会場1つ**の平均と引き算すると、会場構成の偏りが選手の地力に化ける
- 戸田のコース別逃げ率は40.2%と全国平均（約53%）より13pt低いため、**戸田に来た選手は全員、機械的に約+13ptの下駄を履く**

実測での確認（`race_results` 全期間、コース別）:

| 選手 | コース | 実績率 | 会場構成から期待される率 | 正しい差分 | 素朴な差分（戸田基準） |
|---|---|---|---|---|---|
| 山本光雄 | 2 | 76.0% | 53.6% | **+22.4pt** | +35.8pt |
| 横川聖志 | 3 | 39.4% | 53.4% | **−14.0pt** | −0.8pt |
| 柘植政浩 | 2 | 59.4% | 53.0% | **+6.4pt** | +19.2pt |
| 松尾拓 | 4 | 52.8% | 53.6% | **−0.8pt** | +12.6pt |

横川聖志の3コースは、正しくは「平均より14pt逃がしにくい」のに、素朴な差分では「ほぼ平均どおり」に見えてしまう。

#### グレードの交絡も補正する（2026-09-24のレビュー指摘H-2で追加）

会場だけでなく**グレードにも同型の交絡がある**。実測でグレード別の逃げ率は G1 62.2% / SG 61.3% / G2 54.4% / ippan 52.5% / G3 51.1%（**11.1ptの開き**）。会場だけ補正して「会場構成で説明できる分を取り除いた」と称するのは overclaim だった。

ただし**影響は会場交絡より1桁小さい**。実際に表示される行（逃げ率70%以上・n≥10、216名）での実測は **平均シフト 1.29pt・最大 8.00pt・3pt以上動く行が 29/216（13.4%）**。符号が反転するような破綻は起きていない。それでも「取り除いた」と言う以上は残せないので補正する。

#### 正しい定義

1. **期待値** = その選手の過去の走りについて、各走の「**会場 × グレード ×** コースのベースライン率」を平均したもの（＝リーグ平均の選手が同じ会場・グレード構成で走ったときの期待率）。セルの母数が100未満のときは `race_grade='ALL'` 行へフォールバックする
2. **選手の地力差** = 実績率 − 期待値
3. **今日の予測率** = 今日の会場 × 今日のグレード × コースのベースライン + 選手の地力差

UIには**2と3の両方**を出す（2が「この選手の性質」、3が「今日このレースで起きそうなこと」）。

- **情報源**: ベースラインは会場 × グレード × **進入コース**で集計する。既存の `winning_technique_stats` は会場×**枠番**のため軸が合わず使えない
- **セル数**: 実在セルは468（median n=136、n<30 は6セルのみ、n<100 が180セル＝38%）＋ フォールバック用の `ALL` 144 = 約612行
- **表示**: `逃げ率 82.6%（地力 +30pt / 三国での予測 79%）` のような形

**受入基準**:
- 上表の4件について、期待値・地力差が**小数第1位まで再現**できる
- 素朴な差分（実績率 − 今日の会場平均）を使っていないことがコードから確認できる
- グレード補正の有無で、表示行の地力が実測どおり平均1.29pt動く
- 逃がし率の該当レースが**特定の1会場に集中しない**（本日分の試算で戸田8/12件だった偏りが解消する）
- 差分の基準となった期待値・ベースライン値がツールチップ等で確認できる

### FR-5 昨日のフライング選手（P0）

前日（JST）に `finish_mark='F'` だった選手を一覧表示する。

- **情報源**: `race_start_timings.finish_mark`・`start_timing`
- **表示**: 選手名・会場・レース番号・枠番・ST値（`F.01` 形式）
- **出遅れ（L）は対象外**（§1.1で `finish_mark` に `L` が存在しないことを確認済み。`is_late_start` は全件false の既知バグ）

**受入基準**:
- 2026-09-23を対象に実行したとき、平見真彦（江戸川10R・枠1・F.01）と山本幸也（常滑9R・枠1・F.02）の2名のみが出る
- 日付の判定がJSTで行われ、UTCの `current_date` を使っていない
- `finish_mark` が100%運用される2026-09-21より前の日付を指定した場合、**データが不完全である旨を表示する**（黙って少ない件数を出さない）

### FR-6 「今日の注目1レース」の筆頭表示（P1）

ページ最上部に、その日いちばん注目すべきレースを**1つだけ**提示し、理由を文で添える。

競合ページは表が4つ並ぶだけで優先順位がない（30代女性ファン視点）。handoff-memo §5 の「文脈・説明の付加」に対応する中核要件。

**受入基準**:
- 選定ロジックが決定的（同じ入力に対し常に同じレースが選ばれる）
- 選定理由が「逃げ率78%（会場平均比+19pt）かつイン崩れ指数も低い」のように**数値の根拠付きの文**で出る
- 該当がない日は無理に出さず、その旨を表示する

### FR-7 イン崩れ指数との突き合わせ（P1）

過去実績ベースの逃げ率と、既存の**イン崩れ指数**（当日条件込みのAI予測値、`predictions.feature_contributions.volatilityPercentile`）を並べて表示する。

「実績は堅いが今日は危ない」「実績は平凡だが今日は堅い」という逆転ケースが、競合の静的閾値との最も鮮明な差別化になる（20代男性ファン視点）。

- **取得**: 早朝バッチが `predictions.feature_contributions.volatilityPercentile` を直接読み、`morning_digest_rows.volatility_percentile` に**0〜100に正規化して**保存する。情報源は **0〜1**（実測: 戸田4R=0.8373、最大0.9921）なので ×100 が必須（レビュー指摘H-1）
- `isFallback`（会場内サンプル不足のプレースホルダ値0.5）の行は除外する（既存実装と同じ扱い）

**受入基準**（2026-09-24のレビュー指摘C-2で変更）:
- 表示値が **`morning_digest_days.generated_at` 時点の値**であることがUIに明示されている
- その時刻の `predictions` の値と一致する
- `isFallback` の行が混入しない
- **値が0〜100のスケールで保存されている**（0〜1のまま `NUMERIC(5,2)` に入れると 0.84 に丸められる）

⚠️ **当初の受入基準「ホームの `TodaysVolatilityHighlights` の表示値と一致する」は撤回した。** `predictions` は日中に再生成されるため（実測: 2026-09-20 は 08:36〜22:51 の15時間帯、09-21 は 01:57〜20:51 の14時間帯に分散）、05:30 に凍結したダイジェストと live のホーム表示が一致することは原理的にありえない。この基準を残すと実装者が live 取得に倒し、ADR-0070（ページは `morning_digest_rows` だけを読む）を壊す。

**受入基準**:
- 最新期が2026年2期であり、「今期のデータは期終了後に反映される」旨が表示される
- 推移が3期未満しかない選手（新人等）でスパークラインが破綻しない

### FR-14 昨日の帰郷選手（P0。2026-09-24にPhase 2から格上げ）

前日に出走表にいたが、同一会場の開催が続いているのに翌日の出走表から消えた選手を「帰郷」として一覧表示する。

#### 格上げの経緯

当初は `race_special_notes` に依存するためPhase 2としていたが、**競合の情報源が `race/information` とはまったく別系統だった**ことが判明した。競合は**出走表の日次差分**から算出しており、これは自社の `race_entries` だけで完結する。

- 別セッションが該当5会場の `race/information?hd=20260924` を直接取得し、5会場とも「※ 現在、お知らせはありません。」であることを確認。**自社パーサーは正常**
- 出走表の日次差分で2026-09-23分を抽出したところ、**競合掲載の6名（黒崎竜也・戸田 / 黄金井力良・津 / 大久保佑香・津 / 渡邊哲也・三国 / 金子和之・徳山 / 木山誠一・福岡）を過不足なく再現**した。加えて石本裕武（若松）が1件出たが、これはまさに `race_special_notes` が「帰郷（公傷のため）」として捕捉していた1件で、競合側の取りこぼしと見られる
- **誤検知ゼロ・取りこぼしゼロ**

#### 定義

日Dについて、会場Vの出走表にいた選手のうち、**D+1にVの開催が続いている（`races` に行がある）にもかかわらず、D+1のVの出走表に存在しない**選手。

#### 節境界のガード（必須）

会場が節の切り替わりで前節の最終日と新節の初日を連続で開催した場合、前節の全選手が「帰郷」として誤検知される。直近14日の実測では検出数2〜11件/日で安定しており破綻は観測されなかった（節の切り替わりは前検日で1日空くため）が、**構造的なリスクとして必ずガードを入れる**。

- 1会場あたりの検出数が閾値（初期値20件）を超えた場合、節境界とみなしてその会場を抽出対象から除外する
- 除外した場合、その旨をログに残す（黙って0件にしない）

#### `race_special_notes` の位置づけ

帰郷の**検出**には不要。ただし「帰郷（公傷のため）」のような**理由**を持つため、行が存在する場合は補足として併記する。

**受入基準**:
- 2026-09-23を対象に実行したとき、上記7名が過不足なく抽出される
- 直近14日の各日で検出数が0〜20件の範囲に収まる
- 節境界のガードが働いたケースを人為的に作ったとき、その会場が除外されログに残る
- `race_special_notes` に対応する行がある選手では理由が併記され、無い選手でも行自体は表示される（理由の有無で出し分けない）
- 判定がJSTで行われている

### 5.3 母数の閾値

既存の慣行が3つに分かれている（統一の議論が必要）:

| 場所 | 値 |
|---|---|
| `VenueTendencyPanel.jsx:22` | `MIN_CATEGORY_SAMPLE = 20` |
| `basicInfoStats.js:43` | `SMALL_SAMPLE_THRESHOLD = 6` |
| `AttackDefenseTable.jsx` | n<2 は全国平均へフォールバック、2≤n<5 は「参考値」マーク |

本機能の方針（`/step2` で確定し、2026-09-24の独立レビューで修正済み）:
- **抽出の最低母数**: n≥10
- **小標本フラグ**: **母数が20未満（`runs < 20`）**。加えて **Wilson95%下限を数値で併記する**
  - 判定基準は2度変えている。①当初案「Wilson下限 < 全国ベースレート」→ ②レビュー指摘H-3を受けて「Wilson下限 < 抽出閾値」→ ③実装時の実測で「`runs < 20` ＋ 下限値の併記」に変更
  - ①が誤りという指摘は正しかった（p̂=0.25・n=10 の Wilson 下限 8.1% がまくりのベースレート 3.76〜5.08% を上回り、最小構成の行ですらフラグが立たない＝逆に働く）
  - **しかし②も実データで判別力を持たなかった**（2026-09-24本番実測）。逃げは216行中193行（**89.4%**）、まくりは27行中27行（**100%**）にフラグが立つ。まくりは Wilson95%下限の最大が 24.6% で**1行も閾値25%を上回れない**。母数が小さいからではなく（n<20は22%だけ）、n=16〜40 では25〜40%の率を95%の確信で「25%超」と言えないため。9割の行に立つフラグは信号にならない
  - ③では「母数が少ない」という直接の事実で判定し、確からしさは下限値そのもので見せる。下限は逃げで 46.9〜78.0%（中央値59.8）と実際にばらつくので、二値フラグより情報量が多い
  - 参考: p̂=0.70 の Wilson 下限は n=8→36.6% / n=20→48.1% / n=30→52.1% / n=35→53.5%
- **調子窓の小標本**: `runs_90d < 5` は率を出さず走数のみ表示する。`(racer, course)` セル9,471のうち `runs_90d=0` が241（2.5%）、1〜4走が878（9.3%）ある（レビュー指摘M-11）
- **並び順は地力（`skill_delta`）の降順**（生の率で並べると小標本が上位を占めるため）
