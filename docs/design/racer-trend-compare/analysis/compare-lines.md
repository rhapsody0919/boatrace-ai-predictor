# 選手ページの推移の比べる線の大きさとぶれ（2026-11-27）

選手ページの「STの推移」「展示タイムの推移」に、比べる線を足す前に測った。オーナーは 11/27 に「他の選手と比べないと良し悪しが分からない」と言い、ファン4人の議論で次の推奨が出て、オーナーが選んだ。

- ST: 同じ進入コース×同じ級の全国平均
- 展示: 同じレースの他の5艇の平均

この推奨の線に、画面に出す意味があるかを確かめた。測ったのは data-scientist。

## 結論

1. **ST の級の差は、横線にする意味がある。**
   - 同じコースで、B1 は A1 より約0.03秒遅い（コース1〜6で +0.023〜+0.030）。
   - 1走ごとのぶれ（選手1人の ST の標準偏差、中央値 0.064）の約0.45倍。点1つずつとは比べられない。
   - 平均となら比べられる。30走の平均の標準誤差（約0.012）の2倍以上ある。
   - 級を入れると、コースだけの線から ±0.013秒動く（180人の中央値）。
2. **展示は、同じレースの他の5艇の平均を引くと、ぶれが半分になる。**
   - 選手ごとの標準偏差の中央値は、生の展示で 0.106、差で 0.051（比 0.49）。
   - 生の展示を同じ会場の中だけで見ても 0.075 残る。会場の差と、日・水面の差の両方が消えている。
3. **展示の差は艇番で偏る。** 内ほど速く出る。同じ選手の中で比べた差の平均は次のとおり。
   - 1号艇 −0.020［−0.021, −0.018］
   - 2号艇 −0.004
   - 3号艇 +0.003
   - 4号艇 +0.006
   - 5号艇 +0.010［+0.009, +0.011］
   - 6号艇 +0.007
   - 期間の前半と後半（2026-05-31 で分けた）で ±0.002 以内。

## 画面での使い方

- ST の線は「点の集まりの位置」で比べさせる。1走ずつ上か下かでは読ませない。
- 展示の破線より速い側の塗りは、1号艇の走ほど入りやすい。注記に「内の艇番ほど速く出る（1号艇で約0.02秒）」を入れる。

## データと母集団

- e2e の録画（2026-11-25 録画）の `rpc/get_racer_scoped_race_rows` の応答だけを使った。本番 DB は読んでいない。
  - 選手は180人、走は38,740。期間は 2025-12-02〜2026-11-25。
- 録画の選手は、試験の対象に選ばれた選手で、全国の代表ではない。B2 は9〜17人しかいない。
- st_course_baseline（全国の表）の応答は録画に無い。級×コースの平均は、録画の走で数え直した。
- 艇番の偏りは、実進入コースでなく艇番で数えた。
- 区間は、選手で束ねた bootstrap。
- 既存の「1号艇の展示 −0.017秒」（docs/design/analogy-finder/analysis/t1/t1-result.md）とは母集団が違う。並べて足し合わせない。

## 言えないこと（未検証）

## 再実行

録画は git に入らないので、録画のある作業ツリーのフォルダを渡す。

```bash
node scripts/analysis/racer-trend-compare/measure-compare-lines.mjs e2e/recordings docs/design/racer-trend-compare/analysis/compare-lines.json
```

- 結果は compare-lines.json。母数・期間・録画の時刻・母集団の注記と、全部の表が入っている。
- generated_at は実行のたびに変わる。
- 2026-11-27 に別の作業ツリーで回し直し、generated_at と録画の場所の文字のほかは同じ値になった。
