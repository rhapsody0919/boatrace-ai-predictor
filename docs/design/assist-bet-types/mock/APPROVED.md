## 回答の要旨

オーナー「推奨通りで良い」。[spec.md](../spec.md)「オーナーに決めてほしいこと」の5項目を、全部推奨どおりで承認した。

| # | 項目 | 回答 |
|---|---|---|
| 1 | 「核連複」 | 拡連複（公式の呼び名）として作る |
| 2 | 券種の見せ方 | 券種のタブで1つずつ切り替え＋同じ候補で点数・合成オッズを並べる小表 |
| 3 | 候補の入力 | 候補の段を全券種で共有し、ボックスは近道 |
| 4 | 拡連複の計算 | 合成オッズを出さず、オッズは幅のまま、払戻とトリガミは下限で「その組だけ当たったとき」で出す |
| 5 | 取得の予算の案 A5 | この機能のためには採らない（DB のスナップショットを読むだけで、公式への取得は増やさない） |

実装の分け方も推奨どおり: ① 2連単 ② 3連複・2連複 ③ 拡連複 の3つの PR。

承認範囲の変更（承認後）:

- 2026-10-27 オーナー（PR #2027 のファン評価3周目の P2 に「推奨通りで良い」）: 1列の幅（〜1023px）では券種のタブをレンズの一番上（艇の行の上）に置く。2列（1024px〜）は今のまま右の列。図の「1着人気」は選んでいる券種の合成のまま、行の言葉を「1着人気（3連単の合成で）」「（2連単の合成で）」にする
- 2026-10-28 オーナー（ファン評価で「1着人気」が3回指摘されたのを受けて案 c）: 図の「1着人気」は券種によらずいつも3連単の合成から出し、行の名前は「3連単から見た1着人気」（公式の単勝人気と別物と分かる形）。券種のタブで順位は動かない。上の行の「選んでいる券種の合成」を置き換える。単勝のデータの直し（BOA-1174）が済めば、公式の単勝オッズ（案 d）に移す
- 2026-10-28 オーナー（BOA-1174 で単勝の締切時オッズが公式と一致すると確かめた後）: 図の「1着人気」は、締切前は「3連単から見た1着人気」（上の行の案 c のまま）、締切後は公式の単勝の締切時オッズ（`race_odds_final.win_all`）で行の名前「1着人気（公式の単勝）」。締切前に単勝を使わないのは、発売中の単勝の1番人気より3連単の合成のほうが締切時の単勝の1番人気に合うため（-10分で 835/1295 と 1054/1295、docs/knowledge/data-columns.md）
