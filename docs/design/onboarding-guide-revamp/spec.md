# オンボーディング・ガイドページ刷新 仕様書

**種別**: UI機能
**対応チケット**: なし（本セッション内の対話から起票）
**関連チケット**: [BOA-230](https://linear.app/boat-ai/issue/BOA-230/ガイドページオンボーディング刷新の多言語版展開)（多言語版展開、本仕様のスコープ外）

## 背景

新規ユーザーの週1定着率が約13%（リピーターは約48%）と低いことが判明している（詳細はメモリ`boatai_rebrand_investigation_2026_08_19`）。原因の一つとして、使い方ガイド（`/how-to-use`）が文章のみで実画面が無く、かつハンバーガーメニューの奥にしか導線が無いため、初回訪問者がほぼ気づかない・理解しにくい状態であることが確認された。本仕様は、ガイドページの刷新と、初回訪問者向けのオンサイト導線の追加によって、この課題に対処する。

## 機能要件

### A. ガイドページ（`/how-to-use`）刷新

| # | 要件 | 優先度 | 受入基準 |
|---|------|--------|----------|
| A-1 | 各ステップに実画面のスクリーンショットを追加する | 高 | 現行5ステップ（会場選択/レース選択/データ出走表/展開予測・イン崩れ指数/実績確認）それぞれに、対応する実画面のスクリーンショットが最低1枚表示される |
| A-2 | 冒頭に注釈付きツアー画像（全体像を1枚で見せる）を追加する | 中 | ページ冒頭に、実際のレース画面に①②③…の吹き出しを重ねた画像が表示され、5ステップの全体像が1枚で把握できる |
| A-3 | 「こんな人向け」の入口分岐を追加する | 中 | ページ冒頭に、代表的な利用者像ごとのショートカットリンクが表示され、クリックすると該当ステップまでスクロール/遷移する |
| A-4 | 実例ベースの解説に差し替える | 低 | 各ステップの「例」が、`/hit-races`等の実際の的中レースへのリンクに置き換わっている（少なくとも1箇所） |
| A-5 | 操作キャプチャ動画をページに埋め込む | 高 | 下記「動画」要件を満たす動画が、ガイドページ内の適切な位置（冒頭または該当ステップ）にサムネイル＋再生ボタン形式で埋め込まれている |

### B. 初回訪問者向けオンサイト導線

| # | 要件 | 優先度 | 受入基準 |
|---|------|--------|----------|
| B-1 | ホーム画面に「初めての方へ」カードを表示する | 高 | 初回訪問時（localStorageで判定）のみ、ホーム画面のレース一覧より上にカードが表示される。「動画を見る」CTAで操作キャプチャ動画が再生される。「✕」または「あとで」で閉じてもこのページ表示中は消えるだけで、判定用フラグには影響しない |
| B-2 | レース詳細ページで表示している指標セクション全般に「?」ヒントを追加する | 高 | データ出走表の列見出し・AIデータ分析エリア（展開予測・イン崩れ指数）に加え、埋め込み分析セクション全8種（この会場の枠番別傾向・モーター調子・選手調子・STのズレ・展示タイム推移・選手別決まり手傾向・回収率分析・超展開データ）の見出しにも「?」ボタンが常設表示される。タップすると初心者向けの簡潔な説明がその場に表示され、再タップまたは他の「?」タップで閉じる。初回・再訪問を問わず常に利用可能 |
| B-3 | 既存`IntroBanner`（ホーム画面既存のサービス概要バナー）とB-1の表示を出し分ける | 高 | 初回訪問時はB-1カードのみ表示し`IntroBanner`は表示しない。2回目以降の訪問時は`IntroBanner`のみ表示しB-1カードは表示しない。両方が同時に表示されることはない |
| B-4 | `IntroBanner`の文言を現行仕様に合わせて修正する | 高 | 撤去済み機能「複勝予想」への言及を除去済み（本仕様のセッション内で先行対応済み、ja/en/zh-TW/ko全ロケール修正済み） |

### 動画（A・B共通アセット）

| # | 要件 | 優先度 | 受入基準 |
|---|------|--------|----------|
| V-1 | 操作フローの注釈付きキャプチャ動画を制作する | 高 | 「会場選択→レース選択→AIの展開予想→データ出走表・会場特性・各指標分析」を連続で見せる動画（尺目安30〜60秒）が完成している。実データ・実画面のみを使用し、作り話・仮の数字は含まない |
| V-2 | 動画は横長または正方形、再生ボタン付きの通常動画として埋め込む | 高 | ページ読み込み時に自動再生・自動読み込みされず、サムネイル表示＋クリックで再生される |

## スコープ

### やること
- 上記A-1〜A-5、B-1、B-2、V-1、V-2の実装
- 用語「?」ヒントの対象語句候補をClaudeが洗い出し、ユーザーレビューを経て確定する
- 動画制作（既存のRemotion + Playwright + ffmpegパイプラインを流用）

### やらないこと
- **④ウェルカムモーダル**: ①「初めての方へ」カードと役割が重複し、両方を初回訪問時に発火させるとユーザー体験として過剰になるため、①に一本化し見送る
- **英語・繁体中文・韓国語版への展開**: [BOA-230](https://linear.app/boat-ai/issue/BOA-230/ガイドページオンボーディング刷新の多言語版展開)として別途起票済み。日本語版の効果検証後に着手判断
- **A/Bテスト基盤の新規構築**: 施策効果は既存のGA4・Search Console定点観測（`/growth-report`等）で代用する
- **動画のSNS（TikTok/X）への転用**: 別プロジェクト（`sns-marketing-hub`関連）のスコープ
- **オンボーディング表示のユーザー設定画面**: 「二度と表示しない」等の設定UIは作らず、localStorageによる一度きり制御のみとする

## 非機能要件

- モバイル320px〜で表示崩れがないこと（プロジェクト標準、`.claude/CLAUDE.md`参照）
- 動画埋め込みはLCP/CLSに悪影響を与えないこと。自動再生・自動読み込みはせず、サムネイル＋クリック再生とする（V-2で担保）
- 用語「?」ヒントはキーボード操作でフォーカス・実行が可能なこと（既存プロジェクトのアクセシビリティ水準に準拠する程度で足り、新規の高度対応は不要）
- 動画ファイルサイズはページ表示速度に配慮した圧縮を行う（具体的な数値目標は実装時に決定）

## 制約・前提

- 既存コンポーネント再利用を優先する（`.claude/rules/component-reuse.md`）。B-1のlocalStorageフラグ管理は既存`CookieConsent.jsx`と同じパターンを踏襲できる
- データ源: 本機能はDB・Supabaseの変更を伴わない。全て静的コンテンツ＋動画アセットで完結する
- 動画制作は無料ツールのみ（Remotion + ffmpeg + Playwright）を使用し、既存の`sns-video-studio/remotion`パイプラインを流用する。「実データ以外は使わない」原則（`docs/operation/sns-video-producer-prompt.md`）を踏襲する
- 用語ルール: 「競艇」表記禁止を遵守する（`.claude/rules/code-style.md`）
- `/how-to-use`はja専用パス（`src/config/languages.js`の`TRANSLATED_PATHS`未登録）のため、本仕様では翻訳義務は発生しない
- 対象範囲: `/how-to-use`（ガイド刷新）、ホーム画面（B-1カード)、レース詳細ページのデータ出走表・AIデータ分析エリア（B-2ヒント）

## 未確定事項

| 項目 | 内容 | いつ・誰が決めるか |
|------|------|---------------------|
| 用語「?」ヒントの対象語句リスト | データ出走表6列・AIデータ分析内の用語のうち、具体的にどの語句に「?」を付けるか | Claudeが候補を洗い出して提案し、次のレビューでユーザーが確定する |
| 動画題材（使用するレース）の選定条件 | 「指標の差が明確」等の定量的な選定基準 | 動画制作着手時（`/step4`実装フェーズ）にClaudeが具体条件を提示し決定する |
| 動画ファイルのホスティング方法 | `public/`配下に直接配置するか、外部ホスティングを使うか | 動画制作着手時に、ファイルサイズを見た上で決定する |
| B-1カードの「視聴完了」判定 | 動画再生完了イベントで自動的にカードを閉じるか、一度でも開いたら閉じる扱いにするか | 実装時に決定する |
| 用語「?」ヒント・B-1カードの再表示手段 | 常設UI（B-2）は再表示手段が不要だが、B-1カードは一度閉じた後に再度見たいユーザー向けの導線（ヘルプメニュー等）を用意するか | 実装時に検討し決定する。既存のハンバーガーメニュー「使い方ガイド」への導線で代替できる可能性が高い |
