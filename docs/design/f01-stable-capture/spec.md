# 完全版 f01 の崩れない撮影（spec）

- 決定: オーナー 2026-11-04「推奨通りで良い」（完全版のセッションで直接）。正本は hq の `drafts/fp-youtube-type/f01-stable-capture.md`（5d4bd52）
- 方針: 検査を足すより崩れないように作る（オーナー 11/4）

## なぜ
11/3 の f01 の4本（24-09・24-10・19-09・19-10）で③（展開シナリオ）の左の画面が崩れた。f01-capture.mjs が本番 https://www.boat-ai.jp を、クラス名・文言・固定の待ち（300〜2500ms）・座標の決め打ち（上下の 53%/47%・艇番の左 −12px・高さ900 の上限）・時点ボタンの nth で撮っていたため。本番の画面の小さな変更・読み込みの速さで撮影が変わる。

## 形
- 本番のサイトを撮らない。龍神のサイトに撮影用の頁 `/sns-capture/f01/{part}?…` を作り、ローカルの dev サーバーで開く
- 頁は本番と同じ部品を、材料 JSON（materials.json の `api.*`）から作った props で描く。ネットへの読み取りはしない
- 部品は固定の幅の箱（スマホ幅 430 か PC 幅 1280 の中の、本番と同じ部品の幅）に描き、DPR 3 で撮る
- 状態（押す前・押した後・選んだ艇・軸）は URL の引数で決める。クリック・待ち・スクロールが無い
- 頁は描き終えた印と、箱の大きさ・照合の文字・字の最小の大きさ・GOLD の枠とカーソルを置く箱を data 属性で返す。撮る側は箱を1回撮るだけ

章の並べ方は 11/2 18-10 の形（オーナー 11/4「11/2 18-10 の形が正しい」）。②の着順の流れも上・下に切らず全体を1カットにする（座標の決め打ちを無くす）。

## 終わりの条件
- 同じ材料で2回作ると、全章のコマが画素で一致する
- 11/3 の4レースの材料で作り直すと、c3 を含む全章が 11/2 18-10 と同じ見た目
- 本番の見た目を変える PR があっても f01 は壊れない。落ちるのは部品の props が変わったときだけで、撮影用の頁の型の検査（`verify:f01-capture-contract`）で落ちる
  - 例外: GOLD の枠・カーソルの箱は、艇の行と軸のボタンが6つ並ぶこと（部品の子の数・`role="radio"`）に依る。これが変わると頁が `data-f01-error` を出して撮影が止まる（黙って別の物を撮らない。system-architect の審査 P3、2026-11-04）

## 本番に出さない
- ビルドの旗 `VITE_SNS_CAPTURE=1` のときだけ `main.jsx` が頁を読み込む。本番のビルド（Vercel）は旗を付けないので、分岐と頁のコードがビルドから消える
- 頁は `noindex, nofollow`。共通のルーティング（AppRouter）・sitemap・i18n の区分には足さない（ja 専用。利用者に出ない頁）

## 範囲の外
- サムネ・題・締切（別の担当）
- Remotion で全部描く案（取らない）
