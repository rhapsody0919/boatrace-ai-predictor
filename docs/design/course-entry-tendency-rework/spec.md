# 進入コース遷移傾向の再構築 spec

## 種別

UI機能（データ・分析機能を含む複合機能。BOA-284は純粋なデータ・分析機能、BOA-170/BOA-337はUI機能）

## 対応チケット

- [BOA-284](https://linear.app/boat-ai/issue/BOA-284): 現行predictionモデルのcourseRate特徴量がBOA-278の進入コースバグの影響を受けている疑い
- [BOA-337](https://linear.app/boat-ai/issue/BOA-337): BOA-293の進入コース別選手成績データをUIで活用する
- [BOA-170](https://linear.app/boat-ai/issue/BOA-170): [boatAI提案] 会場別 前づけ（進入変更）発生率の表示（本specで当初スコープ「選手個別の前づけ傾向分析」に復元する）

## 背景（3チケットの関係）

1. **BOA-257**（Done、2026-09-15 PR #671でマージ）が、公式Kファイル（`https://www1.mbrace.or.jp/od2/K/{YYYYMM}/k{YYMMDD}.lzh`）経由で実進入コースを取得する仕組みを実装した。`race_results.actual_course_1〜6`として全24会場・2025-12-04〜のほぼ全期間（42,382/42,483件、2026-09-16確認）が既にバックフィル・日次同期済み。艇番との不一致率は1号艇1.1%→6号艇13.5%と物理的に妥当
2. 一方、既存の`race_results.course_1〜6`（旧列、触らない）は艇番と完全一致する不良データで、これを参照する箇所が2つ残っている:
   - **BOA-284**: `scripts/lib/unifiedModel.js`の`courseRate`特徴量（重み21.8、全10指標中最大）は`racer_aggregated_stats.course_race_counts`から算出される。`scripts/analysis/aggregate-racer-stats.js`のうち`course_1〜6`を読む4関数（`calculateCourseRaceCounts`・`calculateAttackDistribution`・`calculateDefenseDistribution`・`calculateCourseEntryTendency`）が汚染されている。**2026-09-19の検証で、`course_race_counts`を実進入コースに直しても予測力は上がらず、複勝予想の的中率がわずかに下がる（-0.42±0.10pt）と判明したため、`course_entry_tendency`以外の3関数は現行を維持する**（FR-1、tasks.md Task 2）
   - **BOA-170**: 「選手個別の前づけ傾向」を可視化する機能。2026-09-12、当時のBOA-257の中間結論（個別レース単位の進入コースは取得不可能）を受けて「会場単位の集計表示」＋「VenueCharacteristicsCardへの統合」に2段階縮小されていた
3. **BOA-293**（Done、PR #683）が対象10会場（常滑・三国・びわこ・尼崎・徳山・下関・若松・芦屋・唐津・多摩川）の会場公式サイトから、選手個別の「枠→実進入コース遷移確率」（直近12ヶ月集計）を日次取得する基盤を構築した
4. `actual_course_N`が全24会場・全期間分そろったことで、**BOA-170を当初スコープ（選手個別の前づけ傾向分析）に復元できる**。自社`race_entries`+`race_results.actual_course_N`から同じ統計を全24会場分、自前で計算できるため
5. **会場別対応（2026-09-19）**: 選手によっては特定の会場でだけ動くため、会場別も見られるようにする。実データ（2025-09-19以降の出走）で粒度ごとの件数を確認した:

   | 粒度 | 組合せ数 | n≥5の組合せ | 中央値n | n≥5で拾える出走 |
   |---|---|---|---|---|
   | 選手×枠番（全国） | 9,561 | 98.9% | 27 | 99.9% |
   | 選手×会場（枠を問わない） | 21,920 | 95.7% | 9 | 98.9% |
   | 選手×会場×枠番 | 118,815 | 6.7% | 2 | 20.0% |
   | 会場×枠番（選手非依存） | 144 | 100% | 最小1,502 | ほぼ全部 |

   選手×会場×枠番は大半が薄いため、5走未満を非表示にすると8割の出走が空欄になる。そこで、走数を必ず併記し、5走未満は薄字の「参考」として出す。あわせて、選手非依存の**会場平均**（会場×枠番）を基準線として添える。会場差も大きい（6枠の枠外進入率は浜名湖18.4%〜びわこ6.5%、江戸川1.2%）

   （2026-09-19訂正: 当初の集計は`actual_course_N`の添字を取り違えて算出していた。`actual_course_N`は「N号艇が入ったコース」（添字=艇番、値=コース）。正しい添字で再集計した値に差し替えた。結論は変わらない）
6. **BOA-293の位置づけの変更**: 会場サイトの数値は「選手の全国12ヶ月集計」で、会場別ではなく走数も載っていない（2026-09-19確認）。会場別の代替にならず、走数を併記する方針とも合わないため、BOA-293は表示には使わず、自前計算の全国値の検証にのみ使う（2026-09-16合意の「10会場は会場データを優先表示」から変更。要確認）

## 機能要件

### FR-1（P0）: `course_entry_tendency`を実進入コースで集計する（BOA-284、範囲を縮小）

`scripts/analysis/aggregate-racer-stats.js`の`calculateCourseEntryTendency`を、`race_results.actual_course_1〜6`（添字=艇番、値=進入コース）で集計する。

**範囲を縮小した理由（2026-09-19、Task 2の検証結果）**: 当初は`course_1〜6`を読む4関数すべてを切り替える予定だった。しかし`course_race_counts`（courseRateの入力）を実進入コースに直しても、予測力（61.3%→61.1〜61.3%）は変わらず、複勝予想の的中率は91.4%→91.0%（-0.42±0.10pt）と有意に下がり、回収率も97.7%→95.6%（-2.1±1.3pt）と下がる傾向だった（2026-03-01以降29,421レースのウォークフォワード比較。「実際に入ったコースが分かる」と仮定した上限でも+0.1ptしか良くならない）。加えて`course_race_counts`は選手ページの「枠番別成績」表にも使われ、切り替えると「枠番」表示の表が実進入コース別に変わってしまう。`attack_distribution`・`defense_distribution`は展開予測の入力で、切り替えの影響が未検証。これらは現行（枠番キー、旧列）を維持し、`course_entry_tendency`のみ切り替える。`course_entry_tendency`には既存の読み手がなく、影響が無い。

**受入基準**:
- [x] `course_entry_tendency`が`actual_course_N`ベースで再計算される
- [x] `course_entry_tendency`は走数（`n`・コース別の回数）を保持し、直近12ヶ月・会場別の内訳を持つ形に変更する（参照元は`aggregate-racer-stats.js`のみで互換性の問題は無いことを確認済み）
- [x] 精度検証（`.claude/rules/analysis.md`）: 実選手3名（3072・3473・4444）の枠番別コース回数を、SQLでの別経路の手計算と突き合わせて完全一致を確認した
- [x] `courseRate`の入力を切り替えた場合の予測力・回収率を前後比較した（`scripts/analysis/compare-course-rate-sources.js`、結果は`data/analysis/course-entry-tendency/`）。効果が確認できなかったため、`course_race_counts`・`attack_distribution`・`defense_distribution`は切り替えない。`unifiedModel.js`の重みも変更しない

### FR-2（P0）: 選手×枠番→実進入コース遷移確率の自前計算（全24会場、フィルタ対応）

`race_entries`+`race_results.actual_course_N`から、選手ごとに「出走した枠番→実際に進入したコース」の遷移確率・進入コースごとの平均ST・1〜6着率を算出する（BOA-293の会場サイトデータと同じ統計量、全24会場分を自社データのみで算出）。

**フィルタ対応（2026-09-16ユーザー指摘で追加）**: 選手によっては特定の会場・グレード・枠番でだけ前づけする癖がありうるため、全国集計1本ではなく、既存選手ページ（PR #686、`RacerPerformanceStats.jsx`）と同じ会場×枠番×グレード×レース種別の4軸で絞り込めるようにする。既存の`aggregateRacerCrossStats`/`aggregateRacerVenueBoatStats`と同じ設計方針（`fixed`＋`groupBy`によるクロス集計）を踏襲し、新規の集計関数を追加する。

**集計パラメータ**（8人パネル決定、2026-09-16。会場別対応で2026-09-19に一部変更）:
- 集計期間: 直近12ヶ月固定（会場ごとの差異は設けない）
- 走数の扱い（変更）: 5走未満でも`null`にせず、走数付きで返す。5走以上を「信頼できる値」、5走未満を「参考」として、表示側が薄字にする（既存`MIN_COURSE_SAMPLES=5`を判定境界として流用。仮の値、未確定事項参照）。フィルタで絞り込むほど走数が減るため、判定はフィルタ適用後の走数で行う

**受入基準**:
- [ ] 全国集計版が、対象選手の枠番ごとの進入コース別の回数・走数・割合を返す（`racer_aggregated_stats.course_entry_tendency`のvenue_code=0の行）
- [ ] 会場別版が、同じ形で会場ごとの値を返す（同テーブルのvenue_code=会場コードの行）
- [ ] フィルタ対応版（例: `aggregateRacerCourseEntryStats(history, venueCode, boatNumber, raceGrade, raceStage)`）が、既存の4軸フィルタと同じ引数形式で絞り込んだ結果を返す
- [ ] 5走未満の枠番も走数付きで返す（`null`にしない）。0走の枠番は「データなし」として区別できる
- [ ] 全24会場の選手で計算できることを実データで確認する

### FR-3（P0・最優先）: レース出走表への統合

レース詳細ページの出走表（データ出走表）に「枠なり率」行を追加する（UIモック v4、2026-09-19了承）。今日のレースの枠番が確定した時点で、その選手が今日の枠番のコースにそのまま入る割合を1つの数値で表示し、走数と会場平均を併記する。掲載場所（出走表の行かタブ化か）自体は[BOA-348](https://linear.app/boat-ai/issue/BOA-348)で見直すため、暫定の位置づけ。

**優先度の根拠**: 8人パネル全会一致で「買い目判断に直結する」として最優先とされた

**受入基準**:
- [ ] 既存のデータ出走表コンポーネント（`src/components/race/raceIndicators.jsx`の指標行として追加、`DataRaceTable.jsx`本体は変更不要。`.claude/rules/component-reuse.md`準拠、詳細は[screens.md](./screens.md)参照）に統合されている
- [ ] 値の解決順: ①選手×今日の会場×今日の枠番（5走以上）→ ②選手×今日の枠番（全国、5走以上）→ ③どちらも5走未満なら、走数が多い方を薄字の「参考」で表示
- [ ] 各セルに、値・走数（例: 常滑 23/25走、全国値の場合は「全国 31/34走」）・会場平均（FR-6）を表示する
- [ ] ②で表示した場合は「全国値」、③は「参考」のタグを付ける。会場平均より20pt以上低い場合は「動く傾向」のタグを付ける（20ptは仮の値、未確定事項参照）
- [ ] 選手の実績が全く無い（0走）場合は「データなし」と表示する
- [ ] BOA-293の`venue_entry_course_stats`は表示に使わない（背景6参照）。自前計算の全国値との突き合わせ検証にのみ使う
- [ ] `/race`は4言語翻訳対象（`TRANSLATED_PATHS`）のため、新規指標のラベル・ツールチップ・タグ文言を4言語同一PRで追加する（`/step1-screens`で判明した追加制約）

### FR-4（P1）: 選手ページへの表示（概要バッジ＋フィルタ連動の詳細セクション）

**前提（2026-09-16、PR #686マージ済み）**: [PR #686](https://github.com/rhapsody0919/boatrace-ai-predictor/pull/686)（BOA-159）で選手ページ（`RacerPerformanceStats.jsx`）が大規模改修された。当初計画されていた4タブ構成（ADR-0062）は**同PR内でADR-0063に置き換えられ撤回済み**（タブUIは廃止）。マージ後の実際の構成は以下（フィルタは会場×枠番×グレード×レース種別、常時表示）:

```
フィルタ（常時表示・最上部）
概要カード（全国勝率・平均ST、フィルタの影響を受けない）
成績ブロック（会場・枠番の固定状況で動的切り替え）
枠番別回収率（過去180日）
決まり手傾向（常時表示、現在のフィルタで絞り込み）
推移（平均ST・平均展示タイムの折れ線、常時表示）
レース一覧（常時表示、ページングあり）
```

**2段構成にする（2026-09-16ユーザー指摘: 特定の会場・グレード・枠番でだけ前づけする選手がいるため、全国集計1本では不十分）**:

1. **概要バッジ**（`RacerGradeBadge.jsx`と同じパターン）: 全国集計（FR-2の全国集計版）による「前づけ傾向あり」の一目シグナル。フィルタの影響を受けない「概要カード」に配置
2. **進入コース遷移傾向セクション**（新規、決まり手傾向・推移・レース一覧と同じ「常時表示セクション」の並びに追加）: FR-2のフィルタ対応版を使い、現在の4軸フィルタ（会場×枠番×グレード×レース種別）で絞り込んだ遷移確率を表示する。既存の決まり手傾向・推移・レース一覧と同じ「フィルタに連動して内容が変わる」体験に揃える

**受入基準**:
- [ ] 概要バッジが「概要カード」（フィルタ非依存の全国勝率・平均STと同じ並び）に追加されている
- [ ] 概要バッジは`RacerGradeBadge.jsx`と同じトーン・配置パターンで実装されている
- [ ] 詳細セクションが決まり手傾向・推移・レース一覧と同じ並びに追加され、現在のフィルタ状態（4軸）で絞り込まれる
- [ ] バッジの判定基準（閾値）を定義する（未確定、実データ分布を見て決める）
- [ ] 詳細セクションは、枠番ごとに「進入したコースの内訳（1〜6コースの積み上げ）・枠なり率（走数）・会場平均」を並べる。会場フィルタが「全会場」の場合の会場平均は全24会場の平均を使う
- [ ] 5走未満の枠番は薄字で「参考」タグ、0走は「データなし」と表示する（非表示にしない）
- [ ] 会場平均より20pt以上低い枠番に「動く傾向」タグを付ける（仮の値）

### FR-5（P2）: 分析タブ新設（`/winning-technique`）

既存の17タブ（`WinningTechniqueAnalysis.jsx`）と同じパターンで、選手横断の前づけ傾向比較タブを追加する。BOA-170当初案の`RacerMaezukeChart.jsx`・`get_race_maezuke_breakdown`相当のコンポーネント/RPCを、FR-2の自前計算ベースで作り直す。掲載場所・ドリルダウンの粒度は[BOA-348](https://linear.app/boat-ai/issue/BOA-348)で見直す（暫定）。

**受入基準**:
- [ ] 既存タブ（`techprofile`/`formranking`等）と同じ選択パターン（会場・レース選択→出走選手の傾向一覧）
- [ ] 出走6選手それぞれについて、進入コースの積み上げバー・枠なり率・走数・会場平均を表示し、「全国値」「参考」「動く傾向」のタグはFR-3と同じ基準で付ける
- [ ] FR-6の会場平均の表を同タブ内に表示する（全24会場）
- [ ] 4言語i18n対応（`/winning-technique`は`TRANSLATED_PATHS`対象のため、`docs/reference/i18n-glossary.md`準拠で4言語キーを同一PRで追加）

### FR-6（P0）: 会場平均（会場×枠番、選手非依存）の算出と基準線表示

全24会場×6枠の「その枠番の艇が、どのコースに入ったか」の分布と、枠なり率・枠外進入率を、選手を問わず集計する（直近12ヶ月）。FR-3・FR-4・FR-5の基準線として使い、FR-5タブでは会場別の一覧も表示する。走数は各組合せ1,500走以上あり、閾値の問題は無い。

**受入基準**:
- [ ] 全24会場×6枠×6コースの回数・走数を、日次または週次のバッチで事前集計してテーブルに保存する（[plan.md](./plan.md)・[ADR-0065](../../adr/0065-venue-course-entry-baseline-precomputed-table.md)参照）
- [ ] FR-3・FR-4・FR-5から、会場コード・枠番を指定して会場平均を取得できる
- [ ] 江戸川の値（6枠で1.2%、他会場の1/5以下）が実態かを確認してから表示する（Kファイルの実データを数レース分突き合わせる）。実態でなく取得由来の問題なら、修正するまで江戸川の会場平均を非表示にする

## スコープ

**やること**:
- `course_entry_tendency`の`actual_course_N`への切り替え（FR-1、courseRateの入力等の他3関数は検証の結果、現行維持）
- 選手×枠番→実進入コース遷移確率の自前計算（全24会場、会場別・走数付き、FR-2）
- レース出走表への統合（FR-3、最優先）
- 選手ページバッジ・詳細セクション（FR-4）
- 分析タブ新設（FR-5）
- 会場平均（会場×枠番、選手非依存）の算出と基準線表示（FR-6）

**着手順序**: FR-1/FR-2/FR-6（データ基盤）→ FR-3（出走表統合、最優先）→ FR-4/FR-5（選手ページ・分析タブ、優先度順）。FR-4はPR #686（2026-09-16マージ済み）で選手ページの構成が固まったため、他FRと並行して着手可能。

**やらないこと**:
- VenueCharacteristicsCardへの統合（2026-09-12の縮小案、8人パネルで撤回）
- BOA-293のスクレイピング対象会場の拡大（10会場のまま、戸田・浜名湖・児島は対象外）。BOA-293のデータは表示に使わない（背景6）
- 掲載場所・導線の最終決定（[BOA-348](https://linear.app/boat-ai/issue/BOA-348)で別途見直す。本specは暫定の3箇所掲載）
- モデルの再学習アルゴリズム自体の変更（重み再計算のみ。Zスコア方式等のアーキテクチャ変更は対象外）
- 過去の`predictions`データの遡及的な再計算・修正
- `course_race_counts`・`attack_distribution`・`defense_distribution`の実進入コースへの切り替え（別チケット。展開予測への影響検証が必要）

## 非機能要件

- 既存のモデル入力（`course_race_counts`・`attack_distribution`・`defense_distribution`）を変更しないこと（本機能でモデルの予測は変わらない）
- 選手ページ・出走表・分析タブでの追加の通信を増やさないこと（選手ページはPR #686と同じく取得済みの履歴を再利用する）
- `/winning-technique`の新規タブは既存17タブと同じUI/UX規約に準拠すること

## 制約・前提

- 既存コンポーネント再利用: `RacerGradeBadge.jsx`（FR-4）、`RacerTechniqueProfileChart.jsx`等の既存分析タブパターン（FR-5）、`raceIndicators.jsx`の指標行（FR-3）を踏襲する（`.claude/rules/component-reuse.md`）
- データ源: `race_entries`・`race_results.actual_course_1〜6`（自社DB）。`venue_entry_course_stats`（BOA-293、10会場）は自前計算の全国値の検証にのみ使う
