⑤と⑥の出遅率は**生の値がほぼ同じ（25.9% と 26.0%）なのに、差は +12.1pt と −10.6pt で評価が正反対**になる。これが本カードの存在理由。数値は実データから探した実例（spec.mdの§参照）。

- 差の符号で色を分ける。**良い方向＝`--color-success-text`、悪い方向＝`--color-error-text`**（どちらも意味トークンでダークモード対応済み）。安定率・抜出は「高いほど良い」、出遅率は「低いほど良い」なので、指標ごとに符号の向きを反転させる
- **ベースラインは `(コース, 級別)` の24セル**から引く。級別はその選手の**現在の級別**（`race_entries.grade`、そのレースの出走表の値）。ラベルに「A1・1コース平均」と級別を明示し、「なぜこの数字と比べているのか」を読めるようにする
- **抜出は率ではなく実回数を主表示にする**（`0回/25走`）。5・6コースは30走あたりの期待回数が0.2〜0.4回で、率にすると「0.0%が並ぶ」か「1回で3.3%に跳ねる」のどちらかになる（[spec.md](./spec.md)の実測）。同コース・同級別の期待回数（`平均 0.3回相当`）を括弧で添え、率は小さく右端に置く
- **1コースの抜出は「—」＋理由を添える**（内側艇が存在しない）。0回とも0%とも出さない
- **Fの走は母数（n）に入れない**。代わりに艇のヘッダに `F1` バッジを出す。安定率が高く抜出が少ない選手が「F持ちで慎重になっている」のか「元から安定している」のかは、この2つを並べて初めて読める
- **カード見出しに集計期間を出す**（`2025-12-03〜2026-09-23（295日）`）。`st_course_baseline.window_start` / `window_end` をそのまま表示し、選手側の集計もこの範囲でフィルタする。「直近1年」と書かない（実データは295日しかない）
- **`n < 6` で小標本の視覚的区別**（既存の `SMALL_SAMPLE_THRESHOLD`・`is-small-sample`）。ST考察だけ別の閾値を持たせない
- `TermHintButton` に3つのキーを追加する（[§7](#7-i18n用語のヒント)）。**★の定義と違い、こちらは自前定義なので説明する**
- 日和にある「ST分布値一覧」「ST履歴（詳細）」は折りたたみで内包する。ST分布は `st_course_baseline.st_histogram`（0.05刻み、実測値は [spec.md](./spec.md)「STの分布」）に選手個人のSTを重ねて描く

#### 3.1.3 直近10走

日和は表（枠・ST・モーター2連・着順の4列×10行）。龍神レーダーは**1走＝1本の帯**にして、10走の流れを一目で見せる。

```
┌─ 直近10走 ────────────────────────────┐
│ 古 ←                              → 新 │
│ ①③ ⑤① ②② ④⑥ ①① ③② ⑤④ ②① ⑥③ ①①  │←上段=進入コース
│ .12 .18 .15 .25 .09 .14 .21 .11 .19 .10 │←下段=ST
│  ■   ■   ■   ■   ■   ■   ■   ■   ■   ■   │←着順で塗り分け
└──────────────────────────────────────┘
```

**帯1本の中身（決定 2026-09-23）**: 進入コース（枠色）／着順／**ST＋そのレースでのST順位を括弧で併記**（例: `.14(1位)`）。**括弧内は「1」ではなく「1位」と単位を付ける**（ユーザー判断 2026-09-23。数字だけだと何の1かが読めない）。3段のまま。

判断の理由:

- **STの絶対値だけでは良し悪しが読めない**。0.14が速いかどうかは、その日の水面・そのレースのメンバーで変わる。同じレースの中で何番目だったかという相対評価が、ファンが実際に使う読み方に近い（ユーザー提案を採用）
- 括弧で同じセルに入れるので、**段を増やさずに情報が1つ増える**。4段にすると1本あたり4要素で詰まって見える
- **モーター2連対率は入れない**（日和は入れている）。モーターは機材の軸で、「この選手の最近の走り」という直近10走の文脈とは別。モータ情報タブ（`MotorWakuStatsGrid`、BOA-283/301）が既に担っている
- 会場（当地かどうか）は、帯をタップしたときに出す。常時表示すると文字が入らない
- 着順の色は**既存の着順表現を流用**（`RaceResult.jsx` の `rr-pos`。スタイルは `src/App.css` にある）。新しい配色体系を作らない

#### 3.1.3b ST分布値一覧・ST履歴（2026-09-23にphase aへ含めると決定）

### 3.2 基本情報タブ（FR-2・FR-4c）

**決定（2026-09-23）: 既存のチップ＋バーは維持し、グリッドに置き換えない。** バー展開の3つ目のタブとして「条件別」を足す。

判断の理由（熱血ボートレースファン視点 × UI/UXデザイナー視点の検討結果）:

- 現状の基本情報タブは既に**2層構造**になっている。①チップ4層（指標／全国・当地／全レース・一般戦・SG・G1／プリセット／期間の折りたたみ）＋ 選手別バー、②**データ出走表**（`DataRaceTable`、行＝指標 × 列＝艇番、金枠で最良値強調）。**②が既に「指標×艇番」のグリッド**である
- ここに「条件×艇番」のグリッドを足すと、1つのタブに**グリッドが2つ**並ぶ。指標の網羅はデータ出走表、条件の比較は新グリッド、という役割分担を毎回読み解かせることになる
- 選択式（チップ＋バー）は「1つの条件を深く見る」ためのUI、グリッドは「複数条件を並べて比較する」ためのUI。**どちらのタスクも実在する**ので、片方を捨てるのではなく階層を分ける
- バーには既に展開機構がある（`rbit-expanded-tabs`、現在「直近5走」「得意会場」の2タブ）。**ここに3つ目のタブ「条件別」を足せば、新しいカードを1枚も増やさずに条件比較ができる**。デフォルト画面は今のまま膨らまない
- 意見が割れた点: ファン視点は「一覧で見たい（タップが増えるのは面倒）」、デザイナー視点は「デフォルト画面の情報量を増やしたくない」。**折衷として、条件比較が本質的に2軸になる枠別情報タブ（コース×期間）はグリッド、基本情報タブ（指標×艇番が既にグリッド）は展開内**に置く

バー展開の3つ目のタブ「条件別」の中身（行＝条件 × 列＝値・n。選んだ1選手のみ）:

```
┌ ① 下條雄太郎 ─────────────────┐
│ [直近5走][得意会場][条件別]  ←3つ目 │
│                                      │

│ 当地        6.95   (n=42)           │
│ 一般戦      7.40   (n=120)          │
│ SG・G1      —      (n=0)            │
│ 初日        6.88   (⚠n=17)          │
```

|---|---|
| 全期間（295日） | **約4.5%**（11,250 / 約250,000行） |
| 2026-09（月別で最良） | 19.0% |
| 2026-08 / 07 / 06 / 05 / 04 | 2.7% / 6.8% / 8.2% / 5.6% / 1.4% |
| 2026-03以前 | 0% |
| **2026-09-21 / 22 / 23（日別）** | **61.5% / 99.4% / 87.2%** |
| 2026-09-16〜20（日別） | すべて0% |

つまり**2026-09-21から安定して入り始めた**（2026-04〜08の値は特定日のバックフィル分と見られる）。したがって:

- **「F持」を過去成績の条件区分（行）として使うのは不可** — 選手ごとに「F持ちで走った過去レース」を集める必要があり、過去の充足率4.5%では母数がほぼ残らない
- **F数・L数を当日の出走表の表示項目として出すのは可能** — 判定に必要なのは「今走る選手の現在のF数」だけで、2026-09-21以降はほぼ揃っている（詳しい出し方は[§3.7](#37-f数の出し方2026-09-23決定)）
- 同じ理由で `weight_kg`（選手の登録体重）・`branch`（出走時点の支部）も当日分は表示可能（data-catalog N14）
- **過去分のバックフィルはユーザーが予定していると確認済み（2026-09-23）**。完了すれば「F持」を条件区分として使えるようになるため、[§3.7](#37-f数の出し方2026-09-23決定)の第3段階を実装する

- 出せない区分（ナイター）と、条件区分としては使えない区分（F持）は**行ごと出さない**。「—」の行を並べない
- **data-catalog N13・N14の記述（「取得なし」）は現状と合っていない**。取得基盤側（BOA-353配下）で更新してもらう必要がある（本specの範囲外）
- FR-4c（`racer_period_stats` の期別成績・能力指数）は「**前期**」の行として足す。前期の平均STは racelist の平均STと一致することが実測で確認済み（data-catalog N13）

### 3.7 F数の出し方（2026-09-23決定）

**「選手の状態」という独立カード（F数・体重・支部を並べるもの）は作らない。** 数値を並べただけで、日和の数値羅列と同じ問題になる（ユーザー指摘）。

#### なぜF数が効くのか（実測で裏付けた）

F持ちの選手は、次にFを切ると長期の出場停止になるため、スタートを慎重に行く。これはファンの経験則だが、**実データで裏付けられた**（2026-04以降、f_countが取れている1,377走）。

| | n | 平均ST | 安定率 | 出遅率 |
|---|---|---|---|---|
| Fなし | 1,007 | 0.163 | 66.6% | 15.7% |
| **F持ち** | 370 | **0.182** | **48.4%** | **26.2%** |

**級別を揃えても効果が残る**（「F持ちはもともとST精度が低い」という交絡の一部を統制）。

| 級別 | Fなしの平均ST | F持ちの平均ST | 差 |
|---|---|---|---|
| A1 | 0.146（n=225） | 0.171（n=114） | **+0.025** |
| A2 | 0.160（n=273） | 0.176（n=81） | +0.016 |
| B1 | 0.170（n=441） | 0.189（n=138） | +0.019 |
| B2 | 0.181（n=68） | 0.201（n=37） | +0.020 |

留保: nが小さく（F持ち計370走）、交絡を完全には統制できていない（F持ちになる選手の性質そのものの影響）。方向は明確だが、画面で因果を断定する書き方はしない。

#### 3段階で出す

1. **識別情報としてのバッジ** — 選手名の隣に「F1」。基本情報タブのバー行と `DataRaceTable` の選手名セル。**カードを増やさない**。色は `--color-error-text`（警告の意味を持たせる）
2. **ST考察の解釈を変える文脈として** — ST考察カードで、F持ちの艇の列にバッジを付ける。安定率が高く出て抜出率が低く出るのは「慎重に行っているから」という読みが成立するため、数字の意味が変わる
3. **バックフィル完了後の本命表示** — その選手の「**F持ち時の平均ST vs 通常時**」。ファンが本当に知りたい「この選手はF持ちだと縮むのか」に直接答える。バー展開の「条件別」タブ（[§3.2](#32-基本情報タブfr-2fr-4c)）に「F持ち時」の行として足す。過去分のバックフィルが前提

体重（`weight_kg`）・支部（`branch`）はF数と性質が違うので**同じカードにまとめない**。体重は `DataRaceTable` の指標行、支部は選手名の近くに置く。

## 5. デザイントークンで表現できる部分／新規CSSが必要な部分

### 5.1 トークンで足りるもの

- 色・余白・角丸・フォントサイズはすべて `src/styles/design-tokens.css` の意味トークン（`--text-primary` / `--text-secondary` / `--surface-card` / `--surface-page` / `--border-hairline` / `--spacing-*` / `--radius-*` / `--font-size-*`）

- 艇番チップは `BOAT_COLORS`（`src/utils/colors.js`）。1号艇（白）・2号艇（黒）は輪郭を付けて背景に沈まないようにする（ピットレポートで確立した扱い）

| ST考察の3行レイアウト | 「値」「コース平均」「差」の3列。モバイルでは2行に折り返す |

### 5.3 日和の「赤・黄セル背景」をどう扱うか

日和は上位2艇をセル背景（濃い赤＝1位、黄＝2位）で強調している。**そのまま持ち込まない**。

理由: `DataRaceTable.css` に「最良値セルの強調はブランドアクセント（金）を使う唯一の箇所」というコメント付きで `drt-best`（金14%背景＋40%インセット枠）が定義されている。赤・黄を新たに導入するとブランドカラー体系（`docs/reference/brand-kit.md`）から外れ、かつ既存の「金＝最良値」という意味づけと競合する。

**方針**: 金の強度で2段階にする。1位＝`color-mix(... 14%)`（既存の `drt-best` と同じ）、2位＝`color-mix(... 7%)`。3位以下は無装飾。実際に2段階が判別できるかは[§8の論点2](#8-モックで確認したい論点)でモックで確認する。
