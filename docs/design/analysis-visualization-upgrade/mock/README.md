# 承認済みモック（phase a）のリポジトリ退避

2026-09-23にユーザー承認を得た設計モックの実体を、リポジトリに退避したもの。

## なぜ退避したか

元は claude.ai の Artifact（<https://claude.ai/artifact/N3e6TSHmoPXzLNX1SSSLZK>）に置かれていた。2026-09-25にClaudeアカウントを切り替えるにあたり、[`docs/setup/claude-account-migration.md`](../../../setup/claude-account-migration.md) の整理では**公開済みArtifactは旧アカウント側に残り、新アカウントからは開けない**。一方 `tasks.md` の冒頭はこのURLを「承認済みモック」として参照しており、切替後は参照先が開けなくなる。

設計の根拠そのものが失われるため、全6アートボードのHTMLと canvas 定義をここに取り込んだ。**以降はこちらが正**とし、Artifactのリンクは履歴として残す。

`.dc.html` は Artifact の Design 型が使う形式で、`<x-dc>` 要素と末尾の `<script type="text/x-dc">` を含む。**ブラウザで直接開いてもレイアウトは再現されない**（`./support.js` というランタイムに依存する）。中身のHTMLとインラインスタイルを読む用途で保存している。

## 実装と食い違っている箇所（モックの方が古い）

モックは承認時点のもので、その後の実装前レビューで**実データと合わないことが判明して設計を変えた箇所がある**。実装が正で、モックは履歴として読むこと。

| モックの記述                                                                  | 実装（正）                                                                                                                                    | 理由                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BasicGrid`: 条件別の値が全行「点」スケール（全国7.34・一般戦7.40・前期7.21） | 全行を自社集計（%）に統一し、「前期」は列から外して別枠                                                                                       | `racer_period_stats.win_rate` は公式勝率点（実測1.07〜8.24）で、`computeRates` の1着率%と単位が違う。**一般戦の公式勝率点は自社で算出できない**（公式の点数計算式を再現できないため）。モックどおりに作ると存在しない数値を出す       |
| `BasicGrid`: 「波5cm超」                                                      | **「波5cm以上」**（`>= 5`）                                                                                                                   | `> 5` は全レースの4.0%しかなく母数が3〜9走で小標本になる。`>= 5` なら11.4%。既存の予想モデル `scripts/lib/turnPrediction.js` が `>= 5` を「荒れ」の閾値に使っている。モックの `n=52` は `>= 3cm`（41.0%）相当でラベルと食い違っていた |
| `BasicGrid`: 「F持ち時 — バックフィル後」                                     | **「F持ち時」「F無し時」の2行を出す**                                                                                                         | 2026-09-25ユーザー判断。充足率が低くても出す。単独だと比較相手が「全国」になり母集団が違って読めないため2行を対にした                                                                                                                 |
| `ResultTab`: 「このレースは3コースまくりで、傾向から外れた1本でした」         | **回数を並べる形**（「確定12Rの決まり手は 逃げ6・まくり4・差し2。1号艇の逃げ率50%。このレースは2コースまくりで、この日1本目のまくりでした」） | 二値判定は全レースの43.5%に「外れた」が付き、最頻以外も複数本あるので「1本」が虚偽になる。首位同数タイの日が8.3%あり判定が実行ごとに反転しうる。**当日のレースは `actual_course_*` が100%NULL**でコース部分が出せない                 |
| `ResultTab`: 「イン逃げ率」                                                   | **「1号艇の逃げ率」**                                                                                                                         | 実装は `rank1 === 1 && winning_technique === "逃げ"` の艇番基準。決まり手が逃げの有効23,892レースのうち `rank1 !== 1` が238件＝1.0%を分子から落としている                                                                             |
| `Main`: コース別成績が6コース×1指標のグリッド                                 | **既定は今日の想定進入コース1本×3指標同時**、全コースは折りたたみ                                                                             | 2026-09-24のローカル確認で「その出走枠以外の情報は不要」との指摘。列を1本にすると横幅が余り3指標を同時に出せる                                                                                                                        |

いずれも `tasks.md` の各Phaseの冒頭に、実測値つきで経緯が書いてある。
