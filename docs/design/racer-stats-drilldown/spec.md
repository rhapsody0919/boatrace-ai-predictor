# 選手ページ 成績内訳ドリルダウン（グレード別・レース種別・レース一覧）

## 種別

UI機能

## 対応Linearチケット

[BOA-159](https://linear.app/boat-ai/issue/BOA-159/将来対応-選手詳細ページへのsgg1混合戦絞り込み機能)（スコープを本仕様に更新済み、状態: In Progress）

## 背景

選手ページ（`/racer/:racerId`）で、2連率・3連率の内訳をグレード別（一般戦/G1/G2/G3/SG）・レース種別（優勝戦/準優勝戦など）でドリルダウンして見たい、というユーザー依頼から出発し、対話を通じて以下にスコープが拡大した。

1. 会場×枠番の既存2軸フィルタに、グレード・レース種別を第3・第4軸として追加
2. 絞り込み結果を「概要（カード）だけでなく、決まり手内訳・時系列推移・個別レース一覧まで深掘りできる」ようにする
3. カード指標を勝率・2連率・3連率・単勝回収率に加え、複勝回収率・平均ST・平均展示タイムまで拡張する
4. 個別レース一覧の各行から実際のレース詳細ページ（`/race/:raceId`）へ遷移できる

選手ページは「選手の概要をまず把握し、次に特定の条件（会場・枠番・グレード・レース種別）でその選手の傾向を深掘りする」という2段階の使われ方をする。情報量過多（BOA-268で既に指摘済み）を避けるため、絞り込み結果はタブ（概要／決まり手／推移／レース一覧）で分割する。UI/UX観点の検討過程は[ADR-0062](../../adr/0062-racer-page-filtered-view-tabs.md)を参照。

既存の `RacerPerformanceStats.jsx` は `getRacerRaceHistory` で過去2年分の履歴を1回取得し、`aggregateRacerVenueBoatStats` でフロント側に再集計する設計（ネットワークI/O追加なしでフィルタ切替できる）。本機能はこの既存設計を維持したまま拡張する。技術方針は[ADR-0061](../../adr/0061-racer-page-grade-stage-filter-approach.md)・[ADR-0062](../../adr/0062-racer-page-filtered-view-tabs.md)を参照。

## 機能要件

### FR-1: グレード軸の追加（優先度: 高）

既存の会場×枠番フィルタに「グレード」フィルタを追加する。

- 選択肢: 全グレード（初期値）/ 一般戦 / G1 / G2 / G3 / SG
- データ源: `races.race_grade`（コード値 `ippan`/`G1`/`G2`/`G3`/`SG`。表記揺れなし）
- 受入基準: グレードを選択すると、他の3軸と同時にAND条件で絞り込まれ、絞り込み結果全体（カード・決まり手・推移・レース一覧）が再集計される

### FR-2: レース種別軸の追加（優先度: 高）

「レース種別」フィルタを追加する。

- 選択肢: 全レース（初期値）/ 優勝戦 / 準優勝戦
- データ源: `race_conditions.race_stage`。「優勝戦」「準優勝戦」の**完全一致**でのみ判定する（他の値は判定不能なため対象にしない）
- 受入基準: 「優勝戦」または「準優勝戦」を選択すると、`race_stage` がその文字列に完全一致するレースのみに絞り込まれる

### FR-3: 4軸同時フィルタ（優先度: 高）

会場・枠番・グレード・レース種別の4つのフィルタは常時表示し、任意の組み合わせで同時に（AND条件で）絞り込めるようにする。

- 受入基準: 初期状態は「全会場」「全枠番」「全グレード」「全レース」（絞り込みなし = 現在の表示と同一、タブも表示しない）

### FR-4: サンプル数閾値の不適用（優先度: 高）

グレード別・レース種別の絞り込み結果には、既存の「5走未満は非表示」というサンプル数閾値ルールを適用しない。1走でも実数のまま表示する。該当レースが0件の場合は既存の「該当する出走がありません」表示を使う。

### FR-5: データ取得の拡張（優先度: 高）

`getRacerRaceHistory` を拡張し、以下を取得・保持する。

- `races.race_grade`
- `race_conditions.race_stage`・`race_conditions.race_title`（レース名。FR-9で使用）
- `race_results.payout_place_1`・`race_results.payout_place_2`（複勝回収率。FR-6で使用）

受入基準: 4軸フィルタのいずれの組み合わせでも、追加のネットワークI/Oなしにフロント側の再集計で結果が出る（既存のI/O最小化設計を維持する）

### FR-6: カード指標の拡張（優先度: 高）

絞り込み結果カードに以下を追加する（既存の勝率・2連率・3連率・単勝回収率はそのまま維持）。

- 複勝回収率（`race_results.payout_place_1`・`payout_place_2`から算出。既存の「枠番別回収率」セクション`getRacerBoatReturnRate`と同じロジックを使う）
- 平均ST（`exhibition_data.start_timing`の平均）
- 平均展示タイム（`exhibition_data.exhibition_time`の平均）

### FR-7: 絞り込み結果のタブ化（優先度: 高）

フィルタが1つ以上選択されている（`vcActive`）場合、絞り込み結果を以下4タブで表示する。詳細は[screens.md](./screens.md)を参照。

1. **概要**: FR-6のカード一覧
2. **決まり手**: 勝利時の決まり手内訳（既存の`showTechniqueSection`/`displayTechniques`をタブ内に移動、ロジック変更なし）
3. **推移**: 平均ST・平均展示タイムの時系列折れ線グラフ（既存の「展示タイムの推移」「STの推移」をタブ内に移動、ロジック変更なし）
4. **レース一覧**: FR-9

受入基準: 初期表示タブは「概要」。タブ切り替えは追加のネットワークI/Oを発生させない。

### FR-8: 勝率・2連率・3連率の時系列化は対象外（優先度: 高、スコープ明確化）

勝率・2連率・3連率は時系列グラフ化しない。理由: フィルタ後のサンプル数が少ない場合（優勝戦2走等）は移動平均が成立せず、既存の`getRacerFormTrend`（`race_entries.win_rate`という公式スナップショット値をそのまま時系列表示するもの）はフィルタ条件下の値ではないため流用できない。「レース一覧」タブ（着順が時系列で見える）で代替する。詳細は[ADR-0062](../../adr/0062-racer-page-filtered-view-tabs.md)を参照。

### FR-9: 個別レース一覧（優先度: 高）

絞り込み条件に合致する個別レースを一覧表示する。

- 表示列: 日付・会場・レース番号・レース名（`race_conditions.race_title`）・グレード・レース種別・枠番・ST・着順・決まり手・単勝配当
- 各行は実際のレース詳細ページ（`/race/{raceId}`、`raceId`は`YYYY-MM-DD-VV-RR`形式）へのリンクとする
- 件数が10件を超える場合はページングする（1ページ10件）
- サンプル数閾値は適用しない（FR-4と同じ）

## スコープ

### やる

- 選手ページの会場×枠番フィルタに、グレード・レース種別を第3・第4軸として追加
- 4軸の同時（AND条件）絞り込み
- 絞り込み結果のタブ化（概要／決まり手／推移／レース一覧）
- カード指標の拡張（複勝回収率・平均ST・平均展示タイム）
- レース詳細ページへのリンク付き個別レース一覧（ページングあり）
- グレード別・レース種別・レース一覧のいずれもサンプル数閾値を適用しない

### やらない

- 既存の「5走未満は非表示」ルール自体の見直し・撤廃（別スコープ。[BOA-335](https://linear.app/boat-ai/issue/BOA-335)に切り出し済み）
- 「優勝戦」「準優勝戦」以外の企画レース名（地方協賛レース等、312種類）の分類・扱い。フィルタの選択肢には含めない
- 会場別・枠番別の既存テーブル自体へのグレード列追加（今回はフィルタ機能のみ、テーブル構造は変更しない）
- 勝率・2連率・3連率の時系列グラフ化（FR-8参照）
- 人気度別の成績（`race_results.popularity_trifecta`。充足率2.9%とデータ不足のため見送り、BOA-263で既に同じ判断が記録済み）
- 天候・風速等のレース条件別成績（充足率は十分にあるが、今回のスコープには含めない。[BOA-336](https://linear.app/boat-ai/issue/BOA-336)に切り出し済み）
- フィルタ未選択時の既存フラット表示（会場別/枠番別テーブル等）の構造変更（[ADR-0062](../../adr/0062-racer-page-filtered-view-tabs.md)参照）

## 非機能要件

- モバイル表示崩れなし（320px〜、既存の会場×枠番フィルタと同水準）
- 既存デザイントークン・既存フィルタUIパターンをそのまま拡張し、新規デザイン要素は最小限（タブUI・レース一覧テーブルのみ新規）にする

## 制約・前提

- 既存コンポーネント再利用: `RacerPerformanceStats.jsx` 内の既存 state（`vcVenue`/`vcBoat`）・`aggregateRacerVenueBoatStats` 関数のパターンをグレード・レース種別・レース一覧・複勝回収率にも拡張する
- 既存の決まり手内訳・展示タイム推移・STの推移は、ロジックを変更せずタブ内に再配置する（[ADR-0062](../../adr/0062-racer-page-filtered-view-tabs.md)参照）
- データ源:
  - グレード: `races.race_grade`
  - レース種別: `race_conditions.race_stage`（完全一致判定）
  - レース名: `race_conditions.race_title`（充足率99.96%）
  - 複勝配当: `race_results.payout_place_1`・`payout_place_2`
  - レース詳細リンク: `raceId`は既存の`src/utils/raceId.js`の規約（`YYYY-MM-DD-VV-RR`）に従う
- **データ期間の制約（実データで確認済み）**: `races.race_grade` も `race_conditions.race_stage`/`race_title` も、2025-12〜2026-01の2ヶ月分は取得不可（該当行が存在しない）。2026-02-03以降は充足率93〜100%
- 優勝戦は完全一致で全期間522件、準優勝戦1431件（全体の約2%）。選手個人単位ではさらに少数になる見込み
- 用語ルール: 「競艇」使用禁止（`.claude/rules/code-style.md`）
