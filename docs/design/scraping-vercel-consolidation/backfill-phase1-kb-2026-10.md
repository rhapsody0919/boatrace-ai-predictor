## 2. 原因の確認（2026-10-01）

いずれも「一括 upsert で列が NULL 上書きされた」ものではない。最初から書かれていなかった欠落だった。2025-12〜2026-10 の全テーブル・全列について、月別の NULL 率を前月と比べた。NULL 上書きと判断できる跳ね方は見つからなかった。

### 2.1 進入（BOA-523）

- 欠落している1,501レースは、2026-09-21 の結果のバックフィル（`backfill-results-by-race-id.js`。会場日ごと DB に無かったものを補った）で新しく作られた行だった。`created_at` は全件9月。
- 結果ページから書く経路には、進入を書く処理が無い。Kファイルの同期は直近4日・既存の行しか見ない（`scrape-results.js:282` の `KFILE_SYNC_LOOKBACK_DAYS=4`）ので、後から入った行を拾わなかった。
- `race_status` との相関は見かけ上のもの。同じ日にバックフィルした行が、たまたま両方に該当しただけ。
- 戻し方: `race_start_timings.entry_course` から復元できる。両方に値がある 9,477艇で突き合わせ、100%一致した。欠落した1,501レースは、全件 entry_course がある。

### 2.2 2連率

- N19（racelist の取り直し）が書く列に、2連率は含まれていない（`racelistBackfillRows.js:17-28`）。N19 の前の実測（2026-09-20）と今とで、充足率は変わっていない。
- 欠落は日単位にまとまっている。2025-12-10〜12-31 と 2026-01-06〜01-31 が 100% NULL。取り込み経路の、期間の穴だった。
- Bファイルの値は正確。2026-01-09 の Bファイルと DB の既存値を42艇で突き合わせ、全件一致した。

### 2.3 同じバックフィルで出た別の欠落（参考）

2026-09-21 にバックフィルした1,476レースは、予測を一度も走らせていない。`races.first_boat_*`・`volatility_*`・`recommended_model` が NULL で、`predictions` も0件。導出データなので、本計画では扱わない（backfill-plan.md §3.1 #18）。

## 3. 前提: K/Bファイルの再取得

手元の控え（`/Users/terukina/boatrace-archive-backup/kb-archive`）にあるのは 2019-04〜2025-12-01 だけ。対象期間は、K/B 合わせて8ファイルしか無い。2025-12-02〜2026-09-30 の K/B 各約303件を、公式（`www1.mbrace.or.jp`）から取り直す。

- 方法: `kb-backfill.js download --from=2025-12-02 --to=2026-09-30 --archive-dir=/Users/terukina/boatrace-archive-backup/kb-archive`
  - 逐次で、3秒以上のジッター付き間隔、夜間窓（22〜06時）、サーキットブレーカーあり。DB には書かない。
  - 控えの場所を明示するのは、worktree の削除で消えないようにするため（2026-09-25 に、worktree ごと控えを失った）。
- 量: 約606リクエスト、約45〜60分、1晩。
- 次に `parse` で中間 JSON を作る（ネットワーク・DB 不要）。
- 実行者: データ取得レーン（公式へのアクセスだけで、本番への書き込みは無い）。

## 4. 項目別の計画

書き込みの規律（全項目共通）:

- **書くのは対象の列だけ**（列の集合をすべての行でそろえる）。NULL の列だけを埋め、既存の値は上書きしない。
- 行の挿入は、行が無いレースだけ。`unchangedRows.js` で、変更のない行は書かない。
- 1文200行以下、1か月単位で実行する。
- 各 CLI は既定で dry-run。件数と、列の集合を出力する。
- 再現テスト（各 PR の verify に入れる）:
  - 書いた行に、対象外の列が含まれない（偽クライアントで、upsert に渡した行のキーの集合を検査する）。
  - 既存の値がある列を書かない。
  - 変異検証で、列の集合を広げると失敗する。
