# レース詳細ページのスマホ幅・色分け統一 spec

種別: UI機能
対応Linearチケット: なし（2026-10-02 ユーザー要望起点。BOA-619 の残りを含む）
棚卸し資料: https://claude.ai/artifact/6GEzVYPNBY5oRV9FJmE3HQ （375px 実測・全8タブ×46セクション）

## 背景・目的

ユーザー要望（2026-10-02）:

1. スマホでレース詳細を開くと、横幅に無駄な余白がある。今節タブのカードは外側に左右それぞれ約50px（2倍のスクショ上）空き、表が狭い。基本情報のデータ出走表は画面端まで使っている
2. 全ての表・グラフで、指標の良し悪しが一目で分かるよう色分けしてほしい。データ出走表（最良値の枠線＋太字、機力↑↓の緑/赤、回収率の緑）を参考にする

実測（375px、本番、2026-09-30 戸田9R と 2026-10-02 児島12R）:

- 今節・直前情報・枠別情報・結果のカードは、外側 28px・内側 41px（片側）。内訳はページ 12 + セクション 16 + カードの枠 1 + カードの内余白 12。表に使える幅は 293px
- データ出走表は画面端まで広げており、表の幅は 367px（BOA-612）
- モータ情報の表は横スクロールで、最初の画面に見えるのは枠番・選手名・モーター番号の3列だけ

コード調査で分かった、色分けの食い違い:

- データ出走表の「調子」は ↑赤・↓青で、同じ表の「機力↑」は緑。向きの意味が逆になっている
- `.motor-ranking-table td.rate` が、値に関係なく全セルを緑にしている（モータ情報・埋め込み分析5つ）
- 最良値の判定が、`bestOf`（raceIndicators.jsx）と別の実装に分かれている。別実装は全艇同値の除外が無い
- 色の直書きが約10箇所ある（VolatilityDisplay の全色、App.css の rgba(201,162,39,…) 3箇所、RaceMeetTab の rgba(67,160,71,0.16) 等）

## 色分けのルール（2026-10-02 ユーザー承認）

| # | ルール | 見た目 |
|---|---|---|
| R1 | 6艇を並べた値は、レース内で最良の値だけを強調する。判定は `bestOf` を共通で使い、全艇同値・値のある艇が無いときは付けない。同値で並んだ最良は全部強調する（2026-10-02 ユーザー承認） | 金の枠線＋太字（`.drt-best` と同じ。`--brand-accent-primary`） |
| R2 | 基準と比べた値（平均との差、上がった/下がった、回収率100%、ボーダー超え等）は、良い＝緑・悪い＝赤。色だけで伝えず、↑↓ または ＋− を必ず付ける | 良い `--color-success-text`、悪い `--color-error-text` |
| R3 | 向きの無い値（進入、決まり手、チルト、体重、調整重量、オッズ、天候・風・波、部品交換）には良し悪しの色を付けない。「注意」の黄（部品交換、進入が変わった、小標本）は今のまま | — |
| R4 | グラフの棒・線は艇色（BOAT_COLORS / BOAT_LINE_COLORS）のまま。良し悪しは値のラベルで示す（最良の値ラベルを R1 の金枠＋太字。展示タイムの棒は最速に「最速」の印） | 棒・線の色は変えない |
| R5 | 比べていないのに緑にしている指定（`td.rate` の一律緑、`.usage-history-rate`）を外す。緑は R2 の「良い」専用 | — |
| R6 | 色はトークン（`src/styles/design-tokens.css`）だけを使う。直書きの色はトークンに置き換える（BOA-450） | ダークテーマでも読める |

最良の向き（高いほど良い / 低いほど良い）は、棚卸しの「主な指標と向き」に従う。代表: 勝率・2連率・3連率・1着率・得点率・回収率・安定率・機力指数は高、ST・展示タイム・ラップ・前検タイム・順位・出遅率・着順は低。

## 機能要件

### FR-1 スマホの横幅（優先度: 高、PR1）

- 767px 以下で、レース詳細ページ（`.race-detail-page-v2`）の余白を次の値にする（2026-10-02、481〜767px の帯もユーザー報告を受けて対象に追加。以前は 480px 以下だけを詰めていて、520px 前後でカードの外側に 24px 残り、展示情報の表が横スクロールになっていた）
  - ページの左右の余白: 8px（以前は 480px 以下 12px、481px 以上 24px）
  - タブを包むセクション（`.prediction-section`）の左右の余白: 0
  - カードの内余白（左右）: 10px。カードの枠線・角丸は残す
  - カードの中の表は、カードの内余白を打ち消してカードの枠の内側まで広げる。グラフと文は内余白の内側のまま（軸のラベルや文が枠に触れないように）
  - データ出走表の行見出しは短縮ラベル（「展示1位率」等）にする（以前は 480px 以下だけ）
- 直前情報の展示情報カード（#1127 で「画面端まで・枠なし」にしたもの）は端まで広げたまま、`--rdp-bleed` を新しい余白（8px）から計算する
- データ出走表（画面端まで、BOA-612）はそのまま
- 受入基準:
  - 320〜767px で、今節・直前情報・枠別情報・モータ情報などのカードの外側の余白が左右とも 8px
  - 375px で、カードの中の表の幅が 357px（375 − 2×(8+1)）
  - 520・600・700px で、展示情報の表が横スクロールせずに6艇が入る
  - 320〜767px のどの幅でも、ページに横スクロールが出ない（`e2e/layout.spec.js`）
  - 768px 以上の見た目は変わらない

### FR-2 色分けの共通部品（優先度: 高、PR2）

- R1 の最良値の判定を `bestOf` に一本化する。別実装（MotorConditionChart の `bestMotor2Rate`、埋め込み分析4つの best 判定）も `bestOf` を使う
- R1・R2 の見た目を共通クラスにする（データ出走表の `.drt-best` / 緑・赤の指定を元にする。新しい色は作らない）
- 受入基準:
  - 全艇同値の列・行で、最良の強調が出ない（再現テストで固定）
  - 同値で並んだ最良は全部に強調が出る（例: 展示タイム 1号艇・6号艇がともに 6.71 なら両方）
  - 共通クラスが参照する色がすべてトークンで、ライト・ダークの両方で定義がある

### FR-3 基本情報タブ（優先度: 高、PR2）

- データ出走表の調子を ↑緑・↓赤にする（`.drt-up` / `.drt-down`）
- 6艇の横棒: 最良の値ラベルに R1
- 条件別: 列ごとに R1。前期: 今期との差に R2（今はクラスだけあって CSS が無い）
- 得意会場: 今の会場の背景を固定の水色からトークンへ
- 埋め込み分析（選手調子・STのズレ・展示タイム推移・選手別決まり手傾向・回収率分析・超展開データ）: R5（一律緑を外す）、Δの矢印を ↑緑↓赤、回収率は100%以上を緑、決まり手の色と1号艇の見出しの直書きをトークンへ、超展開データの凡例「青字」を実際の色に合わせる
- 受入基準: 調子が上がった艇の矢印が緑で「↑」付き。モーターの表・埋め込み分析で、前検タイムや件数のセルが緑にならない

### FR-4 今節・枠別情報タブ（優先度: 中、PR3）

- 今節: 6艇の今節の前検タイムに R1。得点率早見のボーダー超えの直書き rgba をトークンへ。今節のST・展示の判定文に R2。日別の走りの着順を直近の走と同じ色（1着＝金、5・6着＝赤）。推移の線色の直書き hex をトークンへ
- 枠別情報: コース別成績・全コースの成績に R1。ST考察の抜出の行に R2
- 受入基準: 各表で最良の値（同値なら全部）だけが金枠になり、全艇同値なら出ない

### FR-5 モータ情報・直前情報タブ（優先度: 中、PR4）

- モータ情報: R5。展示タイムの推移の縦軸を、速いほど上にそろえる（今節タブのスパークラインと同じ向き）。列の並び（375pxで数値を最初の画面に入れる）は BOA-428 子1（モーターレーン）で行う
- 直前情報: 展示タイムの棒の最速に「最速」の印（R4）。展示情報の「展示タイム1位勝率」「今節の展示」の行に R1
- 直前情報は #1127 のマージ後に着手する
- 受入基準: 展示タイムの最速の艇（同値なら全部）に印が出る

### FR-6 AI予想・オッズ一覧・結果タブ（優先度: 中、PR5）

- AI予想: イン崩れ注意度の直書きの色をすべてトークンへ（ダークテーマ対応）。展開予測の最も高い確率に R1。確定後の検証の的中・不的中に R2（今は CSS が無い）
- オッズ一覧: 濃淡（人気ほど濃い）の色をトークンへ。良し悪しの色は付けない（R3）
- 結果: 1着の行・最速STタグ・払戻の最高額の背景の直書き rgba をトークンへ
- BOA-619 の残り: 広い画面で AI予想・結果の名前と数値が約850〜1100px 離れるのを詰める。AI予想の中央寄せの見出しをページの中央にそろえる
- 受入基準: ダークテーマでイン崩れ注意度の文字が背景と同化しない。1440px で名前と数値の間隔が詰まる

### FR-7 多言語（優先度: 高、全PR）

- 新しく出る文言（「最速」の印など）は `t()` 経由で ja/en/zh-TW/ko を用意する。レース詳細は翻訳対象ページ
- 受入基準: 4言語で新しい文言が表示される

## スコープ

### やること

- レース詳細ページ（`/race/:raceId` と各言語版）の8タブ＋基本情報タブ外の分析セクション
- 最良値の判定の共通化（FR-2）は、同じ部品を使う開催場一覧（`/`）のレースカードの表と、分析ページの表（モーター・埋め込み分析と同じ部品）にも及ぶ
- 上の FR-1〜FR-7

### やらないこと

- 768px 以上の余白の変更（BOA-619 の残りの間隔調整を除く）
- グラフの棒・線を良し悪しの色で塗ること（R4）
- 最下位の値を赤くすること（R1 は最良のみ）
- オッズへの良し悪しの色（R3）
- 分析ページ（WinningTechniqueAnalysis 等）でだけ使う見た目の変更。共有部品を変えると分析ページも変わる箇所は、下の「既定値で決定」に従う
- 直前情報の展示情報の表のはみ出しの修正（#1127 が対応）
- 新しい指標・データの追加

## 非機能要件

- 320〜767px で横スクロールが出ない（`e2e/layout.spec.js` の 375 / 768 / 1024 / 1440 / 1920px と、直前情報の展示情報カードの 320 / 375 / 390 / 520 / 600 / 700px）
- ライト・ダークの両テーマで、追加・変更した色の文字が WCAG AA（4.5:1）を満たす（`scripts/maintenance/check-token-contrast.js` と目視）
- 「競艇」は使わない

## 制約・前提

- 既存の共通部品・トークンを使う（`.claude/rules/component-reuse.md`）。色の直書きはしない（BOA-450）
- データ源は変えない（表示だけの変更）
- `--brand-accent-primary` の金を「最良」に使う。データ出走表のコメントにある「金はここだけ」の意図を、レース詳細全体の「最良＝金」に広げる
- 直前情報タブは #1127（オッズ一覧レーン、`--rdp-bleed` を導入）のマージ後に触る
- BOA-428（モーター比較、モーターレーン）の棒の色も同じルールに従う（オーケストレーター経由で共有）

## 既定値で決定した事項

| 項目 | 既定値 | 根拠 |
|---|---|---|
| 調子の矢印の色 | ↑緑・↓赤（参考の表も変える） | ユーザー承認（2026-10-02）。機力↑緑と向きをそろえる |
| 6艇比較が無いセクション（1艇を掘る表示） | 自然な基準（平均との差、100%、ボーダー）がある値だけ R2。それ以外は色を付けない | 比べる相手がいない値に「最良」は成り立たない |
| 共有部品（MotorConditionChart・埋め込み分析）の変更範囲 | R5（一律緑の除去）・R6（直書きの置き換え）・判定の一本化は部品ごと変える（分析ページにも反映）。余白の変更は `.race-detail-page-v2` の中だけ | 一律緑と直書きは分析ページでも誤りなので、部品で直すのが正しい。余白は依頼がレース詳細に限られる |
| 「最速」等の印の文言 | screens で決める | 見た目と合わせて決める |
| PRの分け方 | PR1 余白 → PR2 共通部品＋基本情報 → PR3 今節・枠別 → PR4 モータ・直前 → PR5 AI予想・オッズ・結果 | ユーザー承認（2026-10-02） |
