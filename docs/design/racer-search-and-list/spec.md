# 選手検索フィルタ拡張・選手一覧ページ 仕様書

## 種別
UI機能（画面・コンポーネントが関わる）。次工程は `/step1-screens racer-search-and-list`。

## 対応Linearチケット
なし。

## 背景
[PR #578](https://github.com/rhapsody0919/boatrace-ai-predictor/pull/578)でヘッダーへの選手名検索UIを実装し、UX改善10件・モバイルレイアウト修正を経てマージ済み。その際、名前以外（支部・身長・体重・級別）でも検索したいという要望が出たが、「まず名前検索のUXを完成させてから」という判断で後回しにしていた。

名前検索完成後、フィルタ拡張の位置づけ（ヘッダー検索の延長 or 独立した一覧ページ）について8人パネルで議論した結果、以下の結論に至った。
- ヘッダー検索は「探して個別ページへ飛ぶ」というジョブに特化させ、フィルタを追加する形で延長する
- 一方で「同じ支部のA1選手だけ見たい」「体重の軽い選手を比較したい」といった一覧・比較のニーズ（特にコアなファン層）が確認できたため、独立した一覧ページ（`/racers`）も今回のスコープに含めて設計・実装する

級別データの取り扱いは[ADR-0023](../../adr/0023-racer-grade-freshness.md)に従い、`racer_profiles.grade_at_scrape`ではなく`race_entries`の選手ごとの最新行を正とする。天才エンジニア視点の事前調査で、勝率も同じ`race_entries`の最新行から取得できる（級別と同じ仕組みに乗せられる）ことが判明した一方、回収率は事前集計が一切存在せず新規の重い日次バッチ投資が必要と判明したため、今回は勝率まで含め回収率は対象外とする判断をユーザーと合意済み。

## 機能要件

### FR1: ヘッダー選手検索へのフィルタ追加（優先度: 必須）
既存の`RacerSearchBox.jsx`に、支部（選択式）・身長範囲・体重範囲・級別（A1/A2/B1/B2）・登録期（選択式、複数選択可）・出身地（選択式、複数選択可）のフィルタを追加する。
- 名前入力とフィルタはAND条件で候補を絞り込む（両方未入力ならフィルタなし）
- 表示件数・結果パネルのレイアウトは既存仕様（最大8件表示、超過時は残件数を案内）を維持する
- 登録期は`racer_profiles.registration_period`（例:「99期」、全1,627人分NULL無し）をそのまま選択肢に使う。支部・身長・体重と同様、`race_entries`のライブ参照や新規キャッシュは不要
- 出身地は`racer_profiles.hometown`（都道府県単位、47種類・全1,627人分NULL無し）をドロップダウンの選択肢に使う。MVPはドロップダウン選択式とし、日本地図から選ぶUIは[BOA-261](https://linear.app/boat-ai/issue/BOA-261/選手一覧ページに日本地図uiで出身地を選べる機能を追加)として別途起票済み（今回のスコープ外）
- 受入基準: 支部・身長範囲・体重範囲・級別・登録期・出身地のいずれか、または組み合わせで検索すると、条件に一致する選手のみが候補に表示される。名前も入力した場合はAND条件で絞り込まれる

### FR2: 選手一覧ページ `/racers` の新設（優先度: 必須）
支部・身長・体重・級別・登録期・出身地・勝率で絞り込み・ソート可能な選手一覧ページを新設する。
- 表示列: 選手名（既存`RacerSearchBox`の支部併記フォーマットを踏襲）・支部・身長・体重・級別・登録期・出身地・勝率・年齢（`birth_date`から算出）
- ソート: 支部・身長・体重・級別・登録期・出身地・勝率・年齢の各列でソート可能。登録期は文字列（「99期」）の辞書順ではなく数値部分を抽出した数値順でソートする（「100期」が「99期」より前に来る辞書順バグを避ける）
- フィルタ: 支部（選択式）・身長範囲・体重範囲・級別（複数選択）・登録期（選択式、複数選択可）・出身地（選択式、複数選択可、ドロップダウン。日本地図UIはBOA-261で別途検討）
- ページネーション: ページ番号方式（50件/ページ）
- 各行から既存の選手個別ページ（`/racer/:racerId`）へリンクする
- モバイル（FR5のカード/行UI）では、行タップの意味を分離する：**行本体（名前・支部・勝率等）をタップすると選手個別ページへ遷移し、右端の▼アイコンをタップすると同じ行のまま詳細項目（身長/体重/登録期/出身地/年齢）を展開・折りたたみする**（画面遷移は発生しない）。この2つのタップ領域は視覚的に分離し、▼の当たり判定は行本体のリンクと独立させる
- 受入基準: フィルタ・ソートの組み合わせで一覧が絞り込まれ、指定した列でソートされる。登録期でソートした際「100期」が「99期」より新しい期として正しい順序で並ぶ。デスクトップは各行クリックで、モバイルは▼以外の行本体タップで該当選手の個別ページに遷移する。モバイルで▼をタップしても画面遷移せず詳細項目が展開/折りたたみされる。50件単位でページ送りできる

### FR3: 選手ごとの最新級別・勝率キャッシュ層の新設（優先度: 必須）
`race_entries`から選手ごとの最新1行（級別・勝率）を取得するロジックを、1,627人分を一括で扱える形に集約する。
- 新規キャッシュテーブル（または`race_history_cache`と同様のJSONBキャッシュ）に、選手ごとの最新級別・勝率を保持する
- 更新は新規スケジュールを増やさず、既存の`calculate-accuracy.yml`（毎日23:30 JST）に相乗りする新規スクリプト（`scripts/daily/update-racer-grade-cache.js`想定、`update-race-history-cache.js`と同じパターン）で行う
- FR1（ヘッダー検索）・FR2（一覧ページ）の両方がこのキャッシュ層を参照する
- 受入基準: キャッシュ更新スクリプトを実行すると、全選手分の最新級別・勝率がキャッシュに反映される。FR1/FR2はこのキャッシュを参照し、選手ごとに`race_entries`をライブでN+1クエリしない

### FR4: URLクエリパラメータでのフィルタ状態共有（優先度: 中）
`/racers`のフィルタ・ソート・ページ状態をURLクエリパラメータ（`useSearchParams`）に反映する。
- 例: `/racers?branch=東京&grade=A1&sort=height&page=2`
- 受入基準: フィルタ・ソート・ページを変更するとURLが更新される。そのURLを直接開くと同じ絞り込み状態が再現される

### FR5: モバイル対応（優先度: 必須）
480px以下ではテーブルではなく、**折りたたみ行（アコーディオン）レイアウト**で一覧を表示する。
- 各行はデフォルトで折りたたみ状態とし、選手名・支部・級別バッジ・勝率のみを1行で表示する（1画面に4〜5人分収まる密度を確保する）
- 行の▼アイコンをタップすると、その行だけ身長・体重・登録期・出身地・年齢を展開表示する（他の行には影響しない）
- 当初はカード型（1選手ごとに項目をグリッド表示）で検討したが、モックアップでのユーザー確認で「1画面に1〜2人分しか入らず50件だとスクロールが長い」との指摘を受け、密度を優先した折りたたみ行に変更した（2026-09-08合意）
- タップ領域の分離はFR2参照（行本体＝遷移、▼アイコン＝展開/折りたたみ）
- 受入基準: モバイル幅（320px〜480px）で横スクロールが発生せず、折りたたみ行の縦積みレイアウトで表示・フィルタ・ソート・ページ送りが可能。▼タップで対象行のみ展開/折りたたみが切り替わり、他の行の状態に影響しない

### FR6: sitemap登録（優先度: 必須）
`/racers`を`scripts/generate-sitemap.js`の`staticPages`に登録する（フローA-4準拠、同一PRで対応）。
- 受入基準: `npm run verify:sitemap`がパスする

### FR7: `/racers`への導線（優先度: 必須）
サイト内から`/racers`へ到達できる導線を2箇所に設ける（直接URLを知らないと到達できない状態を解消する）。
- **ハンバーガーメニュー**: `Header.jsx`のサブメニューに「選手一覧」（仮称）の項目を追加する
- **ヘッダー選手検索パネル**: `RacerSearchBox.jsx`のパネル内から`/racers`へ誘導するリンクを設ける（例: パネル下部に「フィルタで絞り込んで探す」等のリンク。名前検索で見つからない・より詳しく絞り込みたいユーザーの受け皿とする）
- 受入基準: ハンバーガーメニューから`/racers`に遷移できる。ヘッダー検索パネルからも`/racers`に遷移できる

## スコープ

### やること
- FR1〜FR7（上記）
- 4言語i18nキーのうち、UI文言はja版のみ追加（ja-only区分のため）

### やらないこと
- **性別によるフィルタ・表示**: `racer_profiles`をはじめどのテーブルにも性別データが存在せず、スクレイピング元のboatrace.jp公式サイト自体（プロフィールページのdl.list3・ページ全文・画像alt属性を実機照合済み）にも選手個人の性別を示すフィールドが一切無いため対象外（データ不在によるハード制約、実装コストの問題ではない）。唯一近い手がかりの`class="is-lady"`はオールレディース戦（女子限定戦）への出走を示すレース区分マーカーであり、選手個人の属性ではなく未出走の女性選手を判別できないため代替指標としても採用しない
- **出身地の日本地図UI**: フィルタ自体（ドロップダウン選択式、`hometown`は都道府県単位47種でNULL無し）はFR1/FR2に含めるが、クリック可能な日本地図（choropleth）UIは新規のビジュアルコンポーネント開発（既存のLeaflet/react-leafletは緯度経度ピン用で流用不可）のため対象外。[BOA-261](https://linear.app/boat-ai/issue/BOA-261/選手一覧ページに日本地図uiで出身地を選べる機能を追加)として別途起票済み
- **回収率によるフィルタ・ソート**: 事前集計が一切存在せず、新規の重い日次バッチ投資（`race_entries`+`race_results`の大量JOIN・集計、新テーブル設計）が必要なため今回は対象外。需要が確認できれば別途投資判断する
- **多言語対応**: `/racers`はja専用（ja-only）。`TRANSLATED_PATHS`には登録しない
- **一覧ページでのフリーテキスト名前検索**: 名前によるあいまい検索は既存のヘッダー`RacerSearchBox`（FR1で拡張済み）が担当し、一覧ページ側には別途の名前入力欄は設けない
- **無限スクロール**: ページネーションはページ番号方式のみ（FR2参照）
- **選手個別ページ（`/racer/:racerId`）自体の変更**: 今回はリンク先として参照するのみで、個別ページの表示内容は変更しない

## 非機能要件
- モバイル表示崩れなし（320px〜、プロジェクト標準）
- 既存のcolor-contrast（axe-core、WCAG AA）基準を満たすこと。ライト/ダーク両テーマで確認する
- `npm run build`エラーなし、`npm run test:e2e`（`Header`が絡む場合は必須）が全件成功すること
- `npm run verify:sitemap`がパスすること
- 一覧ページの初期表示は、既存`getAllRacersLite()`と同様のクライアントキャッシュ戦略（`withCache`、24h TTL目安）を用い、ページ送り・フィルタ変更時に毎回Supabaseへ問い合わせない

## 制約・前提
- 選手名表示・支部併記のフォーマットは既存`RacerSearchBox.jsx`の表示ロジックを踏襲する（`.claude/rules/component-reuse.md`準拠）
- 級別は[ADR-0023](../../adr/0023-racer-grade-freshness.md)に従い`race_entries`の最新行を正とする。`racer_profiles.grade_at_scrape`は参照しない
- 年齢は`racer_profiles.birth_date`（NOT NULL、全選手保有）から算出する。保存済みの年齢カラムは存在しない
- 新規キャッシュ層（FR3）のバッチスケジュールは、新規ワークフローを増やさず既存の`calculate-accuracy.yml`に相乗りする
- 用語: 「競艇」使用禁止等の用語ルールを新規UI文言にも適用する
- 法的制約: 的中保証を連想させる表現は使わない（該当リスクは低いが新規文言作成時に留意する）
