# 選手個人ニュース機能 仕様書

## 種別

**UI機能**（選手個別ページの新設を含む）

現状boatAIには選手個別ページ（プロフィールページ）が存在しない。本機能で新設し、ニュース表示の受け皿とする。[[racer-fortune-telling]]（占い機能）のStep2（サイトUI化）でも同じ選手個別ページを占い結果の表示先として利用する想定のため、テーブル設計・ページ構造はそちらと共有できるよう意識する。

対応Linearチケット: なし（新規起票は本spec確定後）

種別がUI機能のため、本spec確定後は`/step1-screens`で画面・コンポーネントの洗い出しに進む。

## 背景・目的

TikTok/X実地調査（2026-08-23、[[sns_marketing_phased_strategy_2026_08_22]]）で、予想精度の訴求よりも「選手個人のドラマ性・人間味」の方がエンゲージメントが高いと確認済み。選手個人のニュースをサイト機能として提供し、SNSコンテンツのネタ元にもする。選手をより多く知ってもらう機会を作ることが目的で、予想精度訴求とは別軸のコンテンツ。

## 機能要件

### 1. 選手個別ページの新設（優先度: 高）

- ルート例: `/racer/:racerId`（`racer_id`は`race_entries.racer_id`＝全国共通登録番号）
- 表示する基本情報: 生年月日・支部・級別・出身地等（[[racer-fortune-telling]]で取得する生年月日データと共有）。具体的な表示項目は`/step1-screens`で詳細化する
- 受入基準: 出走実績のある任意の`racer_id`でページにアクセスでき、基本情報が表示される

### 2. 選手ニュースの選定・掲載フロー（優先度: 高）

- 収集方法: **手動選定**。Claudeが都度リサーチして候補ニュースを提示 → ユーザーが承認したものだけ掲載する（自動収集・自動公開はしない）
- 受入基準: 候補提示→ユーザー承認→掲載、という一連の操作が実行できる。実装形態（管理画面UIか、スクリプト+チャット承認か）は`/step2`で決定（下記「未確定事項」参照）

### 3. ニュースの表示（優先度: 高）

- 表示形式: 見出し＋要約＋出典リンク（著作権上、元記事の全文転載はしない）
- 受入基準: 掲載したニュースが選手個別ページ上に、出典リンク付きで表示される

### 4. 検索エンジン露出制御（優先度: 中）

- ニュースまたは占い情報が掲載されている選手のページのみ`sitemap`に登録・インデックス対象とする。それ以外の選手ページは`noindex`にする（出走表等からの内部リンクとしては機能するが、検索エンジンには薄いページとして大量露出させない）
- 背景: 既存の日別レースページ（`/races/YYYY-MM-DD`）が「検索需要ほぼゼロで大半未インデックス」という実績があり（`scripts/generate-sitemap.js:305`）、選手ページ（数千件規模）でも同じ轍を踏むリスクがあるため
- 受入基準: ニュース・占い情報の無い選手ページのHTMLに`noindex`メタタグが出力される。ニュース・占い情報がある選手のみ`sitemap.xml`に含まれる

## スコープ

### やること

- 選手個別ページの新設（基本プロフィール表示）
- 手動選定ニュースの掲載フロー（候補提示→承認→掲載）
- ニュースの要約＋出典リンク表示
- ニュース・占い情報の有無によるインデックス制御（noindex／sitemap登録の出し分け）

### やらないこと

- ニュースの自動収集・自動公開（毎回人の承認が必須。既存のSNS投稿運用と同じ制約）
- 全選手への網羅的なニュース掲載（対象は候補提示され承認されたものに限る。全選手ページ自体は作るが、内容が空の選手も多く存在する前提）
- 選手本人SNSアカウントの継続監視の仕組み化（今回は都度手動リサーチ。監視botのような常時稼働の仕組みは作らない）
- 多言語対応（ja専用ページとする。下記参照）
- 占い結果の表示（[[racer-fortune-telling]]のStep2で別途追加）

## 非機能要件

- **SEO**: ニュース・占い情報がある選手のみインデックス対象（上記「機能要件4」参照）
- **多言語区分**: ja専用（`.claude/CLAUDE.md`の3区分ルール）。`TRANSLATED_PATHS`に登録しない。選手名等の固有名詞には`translate="no"`を付与する
- **モバイル対応**: 既存のモバイル余白・スペーシング基準（`.claude/CLAUDE.md`）に準拠
- 数値目標（回収率影響等）: なし（該当しない）

## 制約・前提

- **著作権**: ニュースの引用は要約＋出典リンクに限定し、元記事の全文転載はしない
- **名誉毀損・誤情報リスク配慮**: 一次情報（公式サイト・選手本人の発信）を確認してから候補化する。自動公開はせず、必ずユーザー承認を経る
- **既存コンポーネント再利用**: `Header`等、既存ページのパターンを踏襲する（`.claude/rules/code-style.md`）
- **用語ルール**: 「競艇」使用禁止（本文・見出し・UI表示テキストは「ボートレース」表記。メタ情報は例外可）
- **データ共有**: 生年月日等の選手基本情報は[[racer-fortune-telling]]で取得するデータ（`racer_profiles`テーブル想定）と共有する前提。両チケットのテーブル設計は`/step2`で整合を取る
- **sitemap反映**: 新規静的ルート追加のため、`scripts/generate-sitemap.js`への対応（動的にニュース・占いありの選手のみ登録するロジック）を同じPRで行う。`npm run verify:sitemap`の対象外ルールも検討する
