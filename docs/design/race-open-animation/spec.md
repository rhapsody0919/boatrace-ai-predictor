# レース荒れ度ムード演出アニメーション - 仕様書

**種別**: UI機能
**対応チケット**: [BOA-195](https://linear.app/boat-ai/issue/BOA-195/レース詳細ページを開いた時の演出動画アニメーションで若年層への訴求力を高める)

## 背景

「各レースを開いた時に、何らかの演出となる動画もしくはアニメーションがあればより、若い世代には刺さると思う」というユーザー発案（2026-08-16）から起票。

過去に類似実装として`FirstMarkAnimation`（展開予測の1マーク着順をSVGアニメーションで可視化）が存在したが、同じ`turnPrediction.patterns`データを参照する`TurnPatternList`（複数候補シナリオの勝者ランキング表示）と数値レベルで食い違い、「よくわからないUX」との指摘を受けて2026-08-14に撤去された経緯がある（`docs/design/first-mark-animation-design.md`、`PredictionPanel.jsx`のコメント参照）。

要件定義の対話の中で、「艇番×決まり手×確率」という多候補データはアニメーションで正確に表現できないという結論に至った。したがって本機能は**具体的な予測内容（艇番・決まり手・確率）を一切表現しない、レースの「荒れ度」を雰囲気で伝えるムード演出**として設計する。TurnPatternListの代替ではなく、その前後に添える補完的な演出と位置付ける。

## 機能要件

### FR1（P0）: イン崩れ指数に応じたムード演出の表示
結果未確定レースの詳細画面（`PredictionPanel.jsx`、App.jsx/RaceDetail.jsx共通）を開いた際、既存の`volatilityPercentile`（イン崩れ指数）に応じたムード演出アニメーションを表示する。

**受入基準**: 結果未確定レースで`prediction.volatilityPercentile`が取得できている場合、アニメーションが表示される。

### FR2（P0）: 具体的な予測内容を表現しない
演出内には艇番・決まり手・確率等、`TurnPatternList`と重複しうる具体的な予測数値・テキストを一切含めない。

**受入基準**: アニメーションのDOM/描画内容に艇番・確率(%)・決まり手名（逃げ/差し/まくり等）の文字列やそれに対応する視覚的な着順表現が含まれない。

### FR3（P1）: イン崩れ指数レベルに応じた演出の強弱
既存の`VolatilityDisplay`が使うイン崩れ指数ラベル（警戒/やや注意/本命有利等）に応じて、演出の強弱・トーンを変える。

**受入基準**: 高ボラティリティ（警戒系ラベル）と低ボラティリティ（本命有利系ラベル）とで、視覚的に異なる演出パターンが再生される。

### FR4（P0）: 実装手段はコード生成のアニメーションのみ
CSS/SVG/framer-motionによるコード生成のアニメーションのみで実装する。動画ファイルの制作・埋め込みは行わない。

**受入基準**: 演出に`<video>`タグ・動画アセットファイルが使用されていない。

### FR5（P0）: 毎回表示
レース詳細ページ（結果未確定レース）を開くたび、毎回演出を表示する。初回のみ表示・スキップボタン等の抑制機構は設けない。

**受入基準**: 同一レースを何度開いても、開くたびに演出が再生される。

## スコープ

### やること
- イン崩れ指数（`volatilityPercentile`・既存ラベル）を基準にしたムード演出アニメーションの追加
- CSS/SVG/framer-motionによる実装（`framer-motion`は既存依存関係を再利用、BOA-194のADR 0014と同じ方針）
- 既存の`VolatilityDisplay`表示条件（結果未確定レースのみ）を踏襲

### やらないこと
- 艇番・決まり手・確率等、具体的な予測内容の可視化（`TurnPatternList`の役割のまま変更しない）
- 動画ファイルの制作・埋め込み
- 会場ごとのブランディング演出（今回は見送り。将来の拡張候補として検討可）
- 展開予測の確度（`turnPrediction`内の最有力候補の確率値）をトリガー基準に含めること（今回は見送り。将来の拡張候補）
- 結果確定済みレースへの表示（既存の`isFinished`表示条件を踏襲し対象外とする）

## 非機能要件

- モバイル表示崩れなし（320px〜）。動画ファイルを使わないため通信量増加は無いが、過度に重いアニメーション（大量DOM要素・高頻度repaint等）によるモバイル体感速度の劣化が無いこと
- `prefers-reduced-motion`環境では演出を抑制する（BOA-194で確立したパターンを踏襲）
- 演出クリック領域が誤操作を誘発しない（BOA-194で発見した「アニメーション対象要素とクリック対象要素の分離」パターンを踏襲）

## 制約・前提

- 新規Supabaseクエリは不要。既存の`prediction.volatilityPercentile`・`prediction.volatilityReasons`（`VolatilityDisplay`が既に使用しているデータ）を再利用する
- `PredictionPanel.jsx`内、`AiAnalysisSection`（またはその近傍、`TurnPatternList`の前後）に配置する想定。App.jsx/RaceDetail.jsx共通コンポーネント経由のため両画面に自動反映される（`.claude/rules/component-reuse.md`準拠）
- 表示条件は既存の`VolatilityDisplay`と同じ「結果未確定レースのみ」に揃える（新規の条件分岐を増やさない）
- 「競艇」表記禁止等、既存の用語ルール（`.claude/rules/code-style.md`）に従う
- 法的・表現上の注意: 演出が「勝敗を保証する・煽る」ような表現にならないよう配慮する（既存のディスクレーパー「参考値であり結果を保証するものではありません」との整合を保つ）
