# 会場ページ レース締切ステータスのライブ表示 仕様書

## 種別
UI機能（画面・コンポーネントが関わる）。次工程は `/step1-screens race-deadline-status`。

## 対応Linearチケット
[BOA-243](https://linear.app/boat-ai/issue/BOA-243/会場ページ-レース締切ステータスのライブ表示受付中まもなく締切締切済み)

## 背景
Xで拡散していた定量ダッシュボード系UIの「未来感」を会場ページに取り入れられないか、という相談から派生。検討の結果、「回収率」等の実質1日単位でしか変わらない数値を疑似ライブで揺らすのは誠実性の問題があるため見送り、代わりに「本当に刻々と変わるもの」として**レースの締切ステータス**を採用する方針に至った（比較モック: [最小/中/最大案](https://claude.ai/code/artifact/4f5fb2dc-c1b8-46a2-b292-4d5c29c5cf0f)、[状態遷移サンプル](https://claude.ai/code/artifact/6b5733c5-68b7-4e2f-bcb5-7db04365ad72)）。

今回は比較モックの**最小案相当**（ヘッダーのLIVEバッジ・ダッシュボードモード等は含まない、各レースカードへのバッジ追加のみ）を実装する。

[BOA-254](https://linear.app/boat-ai/issue/BOA-254/レース中止順延の検出結果をdbに永続化する)（レース中止・順延の検出結果の永続化）が完了済みのため、`race.rawData.cancellationStatus`（`null`/`'tentative'`/`'confirmed'`）が既に取得できる状態にある。本チケットが元々ブロックされていた「中止済みレースを締切前に『受付中』と誤表示するリスク」はこれで解消済み。

## 機能要件

### FR1: レースカードへの締切ステータスバッジ（優先度: 必須）
`RaceCard.jsx`（`src/components/race/`）に、各レースの締切状態を「受付中 / まもなく締切 / 締切済み」の3段階で表示するバッジを追加する。
- 「まもなく締切」は締切（`race.startTime`）5分前から発生する
- 判定は既存の`useNowHHMM`（60秒毎更新、分単位）をそのまま使う。新たに秒単位のポーリング・ページ全体の再レンダー頻度アップは行わない
- 受入基準: 締切5分超前は「受付中」、5分以内は「まもなく締切」、締切時刻を過ぎたら「締切済み」がレースカードに表示される。60秒以内に状態が切り替わる

### FR2: レースカード単位の秒単位カウントダウン（優先度: 必須）
各レースカード内に「次の締切まで 02:00」のような秒単位のカウントダウンを表示する。
- 独立した小コンポーネントとして実装し、秒単位のタイマーをそのコンポーネント内に閉じ込める。`RaceCard`本体やページ全体の再レンダー頻度を上げない設計とする（BOA-254のADR 0041と同じ「レンダー範囲を局所化する」方針を踏襲）
- 締切済み・中止確定のレースではカウントダウンを表示しない
- 受入基準: レースカードに秒単位でカウントダウンする数字が表示され、0になると自動的に「締切済み」表示に切り替わる。他のレースカードの再レンダーを誘発しないことをReact DevTools等で確認する

### FR3: 中止確定レースとの優先度（優先度: 必須）
`race.rawData.cancellationStatus === 'confirmed'`のレースは、FR1/FR2の新バッジ・カウントダウンを表示せず、BOA-254で実装済みの「中止」表示を引き続き優先する。
- `cancellationStatus === 'tentative'`（暫定検知中）のレースは、BOA-254の方針（確定するまで通常表示を維持）を踏襲し、FR1/FR2の通常判定をそのまま適用する
- 受入基準: 中止確定レースのカードに「受付中」等の新バッジが表示されないこと。中止暫定中のレースは通常通り締切ステータスバッジが表示されること

## スコープ

### やること
- `RaceCard.jsx`への締切ステータスバッジ追加（FR1）
- レースカード単位の秒単位カウントダウン子コンポーネント新設（FR2）
- 新規の独立した締切判定ロジック（既存`src/utils/raceStatus.js`の`RACE_STATUS`enumは変更しない、日付+時刻を組み合わせたDate比較で実装）
- 中止確定・暫定レースとの表示分岐調整（FR3）
- 4言語（ja/en/ko/zh-TW）のi18nキー追加

### やらないこと
- ヘッダーのLIVEバッジ＋現在時刻演出（比較モックの中案要素、今回は対象外）
- ダッシュボードモード・複数指標の同時表示（比較モックの最大案要素、今回は対象外）
- レース詳細ページ（`RaceDetailPage.jsx`）・会場グリッド（`VenueGridPage.jsx`/`VenueGridCard.jsx`）への同様の表示展開（今回は`RaceCard.jsx`＝会場ページのレース一覧のみ）
- 投票締切時刻を発走時刻とは別に取得・保持すること（既存データに投票締切時刻は存在せず、`race.startTime`をそのまま締切として扱う。既存の`getRaceStatus()`と同じ前提を踏襲）
- 回収率・的中率等、他の指標の疑似ライブ演出（前回の相談で見送り済み）

## 非機能要件
- モバイル表示崩れなし（320px〜、プロジェクト標準）
- カウントダウン（FR2）の秒単位更新は、当該コンポーネント内の再レンダーのみに限定し、`RaceCard`本体・ページ全体・他のレースカードへの再レンダー波及が無いこと
- 既存の`useNowHHMM`（60秒毎）の呼び出し頻度・箇所は変更しない
- `npm run build`エラーなし、`npm run test:e2e`（`RaceCard`は共通コンポーネントのため実行必須）が全件成功すること

## 制約・前提
- 既存コンポーネント`RaceCard.jsx`をそのまま拡張する（新規コンポーネント化しない、`.claude/rules/component-reuse.md`準拠）。カウントダウン表示のみ新規の小コンポーネントとして切り出す
- `RACE_STATUS`enum・`getRaceStatus()`（`src/utils/raceStatus.js`）は変更しない。新機能は独立した判定関数として実装する（BOA-254調査で確立した方針、`RaceCard.jsx`/`RaceDetailPage.jsx`/`PredictionSection.jsx`/`PredictionPanel.jsx`の4箇所が`===`比較でenumを参照しており、拡張すると副作用が出るため）
- 締切判定は"HH:MM"文字列比較を再利用せず、日付+時刻を組み合わせたDate比較で独立実装する（日付をまたぐ開催があった場合の潜在バグを引き継がないため）
- `race.rawData.cancellationStatus`（BOA-254で追加済み）を参照する。データ取得層（`getPredictions()`）の追加変更は不要
- 用語: 「競艇」使用禁止等の用語ルールを新規UI文言にも適用する
- 法的制約: 的中保証を連想させる表現は使わない（今回は締切状態の表示のみのため該当リスクは低い）
