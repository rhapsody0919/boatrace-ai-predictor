# イン崩れ注意度の作り直しと展開予測の画面からの撤去 spec

種別: UI＋データ・分析機能（画面・RPC・朝のバッチの保存・朝の配信の時刻を含む）
対応Linearチケット: BOA-822（関連: BOA-818 理由文の期間、BOA-815 平均ST の定義、BOA-628 予想の夜の書き直し、BOA-271 龍神ソナー、BOA-430・BOA-831 思考アシスト、BOA-851 /today の注目レースの取りこぼし）

- 決定: 2026-10-12 ユーザー回答（Q1〜Q3 すべて推奨どおり、[decisions.md](./decisions.md)）
- 前提の事実: [inventory.md](./inventory.md)（計算・保存・表示・道連れ）、[today-impact.md](./today-impact.md)（/today と朝の処理）

- 統計検証: [analysis/round1.md](./analysis/round1.md)・[analysis/round2.md](./analysis/round2.md)（第3回は実行中。結果で「未確定」を埋める）
- 批判的検証: [second-opinion-q1-q3.md](./second-opinion-q1-q3.md)

## 位置づけ

- 龍神レーダーは、ブラックボックスの予想をなるべくしない。過去のデータで「どうだったか」を見せる（analogy-finder spec「位置づけ」）
- 展開予測（AIが出す1マークの決まり手の確率）は、龍神ソナーの展開シナリオと思考アシストの展開レンズが過去の実績で同じ問いに答えるので、画面から外す
- イン崩れ注意度は「今日と出走表が近い過去のレース（類似レース）で、1号艇が1着を逃した割合」に置き換える。0〜100 の会場内の順位（指数）はやめる。同じ問い（1号艇が飛ぶか）の数字は、AI予想タブ・一覧・ホーム・/today・思考アシストで同じ値にする
- 「どの量がよく当てるか」の検証（round1・round2）: 類似レースの割合は今の指数より AUC +0.020［+0.008, +0.032］（2026-09-22〜10-10、2,869R）。長い期間では、展開予測の値を抜いて平均ST を直近30走にした指数と区別できない。したがって理由は「当て方は同等以上で、過去の実績を見せる方針に合い、確率に読まれにくい」とし、「よく当たるようになった」とは言わない

## 用語

| 呼び名（画面） | 中身 |
|---|---|
| イン崩れ注意度 | 類似レースで1号艇が1着を逃した割合（%）。件数と基準を添える |
| 類似レース | 龍神ソナーのタブ2と同じ方式（そろえる条件で絞った層の中を、寄与度用モデルの重みの距離で近い順に並べる）の上位400件。会場が今日と同じとは限らない（同じ会場は中央値で約13%）ので「全国」を名前に付ける |
| 基準 | 全国の全レースで1号艇が1着を逃した割合（前日まで） |

「似た」「似ている」は使わない（「類似レース」と書く。glossary）。

### FR-2 イン崩れ注意度の値（P0）

- 値: 類似レース上位400件（展示前）のうち、1号艇が1着でなかったレースの割合。分母は着順のある件数（返還艇の扱いは龍神ソナーのタブ2と同じ）
- 作る所: 龍神ソナーの朝のバッチ（`v16_morning.py`）が類似レースを作るときに、1号艇の非1着数・件数・層の件数を保存する。保存先・読み出し（RPC）は plan で決める（system-architect に当てる）
- 展示後の値: 未確定（統計検証 第3回で展示前より上がるかを確かめてから決める。決めるまでは展示前の値のみ）
- 層が400件未満のレース（約4.2%）: 未確定（第3回で内訳と縮小の効き目を見る）。決まるまでは件数を出し「件数少なめ」の注記
- 値が無いレース（バッチの前・止まった日・欠場で出さないレース）: 注意度を出さず「準備中」等の1行。ほかの値で埋めない（代わりの値を使うかは FR-5・未確定事項）
- 時点の固定: 発走前に保存した値を発走後・確定後も出す（龍神ソナーと同じ）
- 受入基準: 例のレースで、注意度の割合・件数が龍神ソナーのタブ2（件数 400・展示前）の「1着になった艇」の1号艇以外の合計と一致する

### FR-3 イン崩れ注意度の見せ方（P0。置き場所はモックで決める）

- 大きい数字: 「類似レース（全国・400件）で、1号艇が1着を逃したのは {p}%（{k}/{n}件）」と、基準「全国の全レースは {b}%」との比較（棒と点線）
- 段階の言葉: 未確定（第3回で帯の境界を決める。0.7/0.3 の旧閾値は使わない）
- 理由: 最大3つ。v16 の差がつく材料の言い方にそろえる。1つめは「1号艇の全国勝率と、他の艇で一番高い勝率の差」（効き目が一番大きい）。平均ST は期間つきの名前（「平均ST（直近30走）」「平均ST（このコース・直近30走）」）で出し、主な理由にはしない
- 導線: 龍神ソナー（類似レース・差がつく材料）と思考アシスト（ja のみ）へ
- 置き場所の2案（モックで並べ、ユーザーが決める）
  - 案A: AI予想タブを残し、イン崩れ注意度を主役にする（出現パターンは下に残す）
  - 案B: AI予想タブをなくし、基本情報タブの上部に注意度の1行と龍神ソナーへの導線。出現パターンの行き先も決める
- 出現パターン（`OutcomePatternPreview`）はAI予想の本命に依存する予想なので、どちらの案でもその前提で扱いを決める
- 0〜100 のバー（`VolatilityPercentileBar`）・`RaceMoodEffect`・「会場内パーセンタイル」の言葉はやめる
- 4言語（AI予想タブ・基本情報タブは翻訳対象）
- 受入基準: 375px・1440px で大きい数字・件数・基準・理由・導線が出る。0〜100 の数字が出ない。禁止語が無い

### FR-4 思考アシスト「堅い？荒れる？」の見出しの値（P0）

- 見出しの「1号艇の1着」のバーを、FR-2 と同じ値（1着の側に直した 100−p%）にする
- 万舟のバー・級の並びの絵・件数・注記は今の範囲（級の並び）のままにするか、類似レースにそろえるかを、モックで決める（BOA-271 系と同じく見せ方はユーザーが直接決める）
- シート（`RoughSheet.jsx`）は級の並びと類似レースの両方を出しているので、見出しと同じ値がどちらかを明示する
- 龍神ソナーのスライダーで件数を400以外にしたときは「注意度は400件」と出す（数字の食い違いの説明）
- 受入基準: 同じレースで、AI予想タブ（または案Bの置き場所）・一覧・思考アシスト見出しの値が一致する

### FR-5 一覧・ホーム・/today・SNS の値の置き換え（P0）

- レース一覧のバッジと色線、ホームの今日のハイライト（上位・下位）、/today の各行の表示と注目レースの選び方、SNS のネタ・企画の判定を、FR-2 の値に置き換える
- 段階の閾値（今は 0.7/0.3、/today は 50）: FR-3 と同じ帯で統一する（未確定）
- /today の時刻: /today は 05:30 に1回だけ作られ、類似レースは 07:10 起動で後になる。今のままでは新しい値が入らない。案（ダイジェストを後に回す／05:30 は代わりの値で作り後で置き換える／代わりの値のまま）を system-architect に当て、第3回の「代わりの値」の検証と合わせて決める（未確定）
- 受入基準: 同じレースで、一覧・ホーム・/today・AI予想タブの値と段階が一致する（/today で代わりの値を使う案になった場合は、その旨と時刻を出す）

### FR-6 /accuracy を帯ごとの実績ページに作り替える（P1）

- 注意度の帯ごとに、実際に1号艇が1着を逃した割合・件数・ぶれ幅。帯は FR-3 と同じ
- 新しい値の公開日から数える。旧指数の実績は出さない（意味が違う値が混ざるため）。件数が少ない間の表示は決める（未確定）
- 受入基準: 帯ごとの率・件数が DB から数え直した値と一致する（data-accuracy-verifier）

### FR-7 説明の書き直し（P1）

- 公開と同時に書き直す: `/about`、ブログの自然検索上位2記事（rough-race-signals・first-mark-prediction-guide。翻訳版を含む）、HowToUse・FAQ の該当部分、`/today` の説明・用語集（「AIが算出した」をやめる）
- 別チケット（このspecの外）: 展開予測に触れる残りのブログ（ja 41本・4言語65ファイル）、動画13作品、`public/llms.txt`
- 受入基準: 書き直した文に展開予測・0〜100 の指数の説明が残らない。content-qa を通る

## 制約・前提

- データ源: 龍神ソナーの朝のバッチ（`v16_morning.py`、Storage `analogy-v16`、`analogy_v16_snapshots`）。07:10・09:40・13:40 起動（`analogyDispatch.js`）、最長40分
