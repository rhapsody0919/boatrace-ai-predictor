# thinking-assist（BOA-430）引き継ぎ

## コンセプト（ユーザー原文、2026-10-06。spec の土台）
- 初心者から上級者までのありとあらゆる予想スタイルの一助となるサイト
- 既存大手サイト(日和)の数字が多くて迷うという課題を解決したい
- ありとあらゆるセオリーをユーザーが覚えてなくても、必要な時にポンって感じで表示してくれるサイト
- 現状のボートレースにありがちなUI(出走表)をどうすべきか、も議論の一つ。ユーザーはそのUIに慣れているはずだが、数字が多くて脳内処理が増える原因の一つでもある
- 図やグラフ、絵などで新感覚
- ユーザーが見たい情報をタップしたり、深堀したいときに、画面全体がアクティブに図やグラフ、数字などを表示されるようなるイメージ。(ユーザーは表示されるものをただ見るのではなく、深掘りすることが可能なUI/UX)
- 迷わずにユーザーが考えるスタイルで新感覚UI/UXを実現したい

## 2. 2026-10-06 ユーザー回答とコンセプト
- 1〜5 は推奨どおり（ユーザー回答）。ただしユーザーがコンセプト（上）を示したので、コンセプトとの食い違い（下）を案＋推奨でオーケストレーターに返した。回答待ち。回答で 5 と本文の前提の一部が変わりうる
### コンセプトとの食い違い（推奨）
- (a) セオリー: 5 で範囲外にしたが「必要な時にポンと表示」はコンセプトの柱。推奨 = セオリーを出す仕組み（どこをタップすると何が出るか、カードの形、成立率の欄）はモックと本実装の範囲に入れる。成立率は v16 で数えられるもの（スリットの形・進入の型・手がかり・差がつく材料・1号艇の展示タイム）だけ実測で出し、ほかは文だけ（「成立率は準備中」）。セオリーの辞書の拡充・自動検出・データの棚卸しが要る条件（潮位・チルト・起こし位置など）は別チケット
- (b) 出走表の形: 本文は「公式の縦並びを継承」だが、ユーザーは形そのものを議論の対象にしている。推奨 = spec で「出走表の形」を決める論点として立て、モックで2〜3案（公式の縦並び＋数字を図に置き換え／6艇のレーン（スリット・コース）を図で中心に置く／艇カード）を並べてユーザーに選んでもらう。1〜6の上からの並びと公式色は残す（慣れの部分）。数字は最初は少なく、タップで出す
- (c) 4ステップの一本道: 推奨 = 一本道のウィザードにしない。1つの画面（レースの図）を中心に、4つの見方（軸・展開・機力・買い目）を切り替えるレンズにする。初心者には順に案内する「ガイド」を重ねる（同じ画面の上で）。上級者は自由にタップして深掘り
- (d) 「締切前15分」: コンセプトは場面を限っていない。推奨 = 15分は想定場面の一つで、画面の密度（短時間で読める）の制約として扱う。時間で機能を絞らない
- (e) 「生データ主義」と「図・グラフ」: 推奨 = 生データ主義は「モデルの指数・推奨買い目を出さない」の意味に読み替える。集計・順位・図にすることは可（コンセプトの図・グラフと両立させる）
