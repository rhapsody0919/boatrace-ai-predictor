## 11点の結論と v3 での対応

| # | 指摘 | ファンの結論 | v3 での対応 |
|---|---|---|---|
| 1 | 級を名前と一緒に | 苗字の下に級を出す。色分けはしない（F の赤札と競合） | 苗字の下に級（B1 等）を出した |
| 2 | 全ての用語に「?」で説明 | 用語の説明は出す。ただ「?」はセオリーカードで使っていたので、意味が2つになる。パネルの推奨は「項目名の点線下線で意味、? はセオリー専用」 | ユーザーの指定どおり用語に「?」を付けた（押すと意味）。両立させるため、セオリーの入口を「傾向 ›」の札に変え、「?」は用語の意味だけにした。凡例の1行に「?」と「傾向 ›」の違いを書いた。用語は37語（買い目の全列・展示の表の全列・合成オッズ・均等払戻・似たレース等） |
| 3 | 「攻める艇」がなぜ出ているか分からない | 仮定（2コースが凹んだら）が書かれていない。凹むのは本番で13%なので印が強すぎる。消さずに条件付きの言い方に | 札を「凹んだら攻め手 ›」、2号艇の★を「2コース凹みの手がかり（本番で凹むのは13%）」、矢印を点線の「凹んだら攻め」にした。カードの文の冒頭を「2号艇が凹んだら、」にした。本実装では手がかりが当てはまる日だけ出す（v2 は3号艇に決め打ちだった） |
| 4 | 6艇比較の図で、左右どちらが良いか分からない | 向きは項目の自然な向き（ST は左が早い。スリットの絵と一致）のまま、良い方の端に札と薄い色 | 図の良い方の端に「良い」の札、良い方へ薄い色のグラデーション。レンズの最初の図（軸・展開・機力）にも付けた。買い目（オッズ）は良し悪しではないので付けない |
| 5 | 今節の平均着順点の説明 | 項目名から説明。値の横に6艇の順位 | 「?」で配点（1着10点・2着8点・3着6点・4着4点・5着2点・6着1点、F・L・失格は0点。v16 spec A-4 の定義）と「高いほど今節の調子が良い」。値の横に「（6艇で一番高い）」 |

| 9 | どういう選手か・テクニック・X | ページ内で X の投稿を流すのは反対が多い（煽り・誹謗中傷・噂が自サイトの表示として出る）。データから言える特徴の札と、X 検索への外部リンクで代える。評判の言葉はこちらで付けない | 深掘りに「数えた値の札」（例: スタートが早い・今節好調・徳山は初めて。押すと何の値から付けたかが出る）、直近90日の勝ち決まり手、X 検索への外部リンクを、いずれも「案」として描いた。ページ内に X の投稿は出さない |
| 10 | 会場の特徴はどこかに出るか | ヘッダーの会場名から会場のカード。数字3つと文2行に絞り、詳しくは既存の会場ページへ | ヘッダーを「徳山 ›」にし、押すと会場の特徴（水質・型・1号艇の1着・直近1年の決まり手・潮の傾向）を出した |
| 11 | 万舟の「類似レース」「全国で今日と同じ組み合わせ」が分からない | 呼び名を固定し、名前から定義。「同じ組み合わせ」は3連単の組と取り違える | 呼び名を「似たレース」「全国・同じ級の並び」「徳山の全レース」に統一し、「?」で定義。万舟は「似たレース 63件のうち」「全国・同じ級の並び 3,276件のうち」と件数つき。買い目の表の列名「類似」は「似たレース」 |

パネルが出した全体のルール（v3 に反映）:
- 説明の種類を分ける: 「?」＝用語の意味、「傾向 ›」＝過去レースの傾向（セオリーカード）、数字のタップ＝6艇比較
- 良し悪しのある軸は良い方の端に「良い」の札。向きは項目の自然な向きのまま
- 数えた範囲の呼び名は3つに固定し、「呼び名 N件」で出す。並べるときは範囲が違うと書く
- 「当てはまる」は条件が成立したときだけ
- 「もし〜なら」の印は言葉に条件を入れ、点線で描く
- 級・苗字・札は数字に数えない（N-2）。レーンの数字は増やさない

## 質問8 モーターの指標が2連率だけなのはなぜか（調査）
- 結論: 外した理由は、思考アシストにも元にした龍神ソナー v16 にも書かれていない。決めた記録は無い（理由は無い）
- 外す根拠になる事実は3つある（どれも理由として書かれてはいない）:
  - 長期データ（2019-04〜2025-12、kb_archive）に3連率が無い（kb_archive_boats は motor_2rate だけ。`scripts/lib/raceEntriesKbRestore.js:20`）。v16 の数える母集団は長期データを含むので、「差がつく材料」に足すと 2025-12 以降しか数えられない
  - 2連率とほぼ同じ情報: 2026-09 の race_entries 26,911艇で motor_2rate と motor_3rate の相関は 0.883。2連率が6艇で一番の艇が3連率でも一番なのは 69.4%（4,656レース中3,233）
  - 予測への上積みが無いと検証済み（`docs/design/analogy-finder/analysis/` の phase-m-result.md MD-4: 3連率で 0.001 nats/レースを超える改善は無い）
- 出せるデータ: race_entries.motor_3rate は 2025-12-02 以降でほぼ全行にある。思考アシストの今の取得には入っていないので、`getRaceEntryOfficialRatesBreakdown` の select に1列足す（キャッシュの版も上げる）
- 調査からの提案: 2連率と重ならない指標は前検タイム（motor_pretest_stats、引き当たり94.6%）・機力指数・優出数。モータ情報タブ（`MotorConditionChart.jsx`）で既に出している
- 訂正: [fan-panel-mock-v1.md](./fan-panel-mock-v1.md) で「前検の足色はデータ無し」としたのは誤り。前検タイムは motor_pretest_stats にある（周回展示の足色は無い）

## 質問10 会場の特徴はどこかに出る予定か（調査）
- 結論: v2 までは、会場の1号艇の1着率（TC-V1）と今日の風速での1着率（TC-W1）だけで、会場の特徴をまとめて出す場所は無かった。v3 でヘッダーの会場名からのカードを足した
- 既存の部品: 会場のレース一覧ページ（`VenueRaceListPage.jsx`）の `VenueCharacteristicsCard`。中身は枠番別の1着率（過去90日）と全国平均、主な決まり手、水質・型（venues.water_type・cluster）。「もっと詳しく」で2連率・3連率・決まり手の全内訳。本実装はこれを流用でき、新しい集計は要らない
- 数えた期間が違う点に注意: 会場カードは過去90日、v16 の「徳山の全レース」は2019年から。並べるときは期間を書き分ける
- 設計の食い違い: spec の FW-14 は「会場のコース別成績」を挙げていたが、screens の対応表には無かった。会場カードで埋めた
- ビジターガイドは en・ko・zh-TW の観光向けで日本語ページは無い（`AppRouter.jsx:226-231`）

## 要望9 選手の評判・テクニック・X（調査、2026-10-07 時点）
- X の投稿をページに出すことは条件付きで可能。ただし思考アシストの範囲には入れず、出すなら別チケットにするのを推奨
- 費用: X API は従量課金（[pricing](https://docs.x.com/x-api/getting-started/pricing)）。投稿の読み取り1件 $0.005、ユーザーの読み取り1件 $0.010、月300万件まで。出走選手1日約1,000人×10件の試算で月 $1,500 前後。Free/Basic/Pro の廃止（2026-02〜09 に移行）は二次情報（[medianama](https://www.medianama.com/2026/02/223-x-developer-api-pricing-pay-per-use-model/)、[postproxy](https://postproxy.dev/blog/x-api-pricing-2026/)）でだけ確認した
- 規約: 表示はアイコン・表示名・@ユーザー名・時刻のリンク・X のロゴ等が必須で本文の改変は禁止（[Display Requirements](https://docs.x.com/developer-terms/display-requirements)）。X で削除・変更された投稿は24時間以内に追従する。X の外の個人データ（選手 DB）とアカウントを結び付けるには、本人の同意か本人が合理的に予期する用途であることが要る（[Developer Policy](https://docs.x.com/developer-terms/policy)）。選手 DB と X の対応付けが当たるかは法務の判断が要る
- 埋め込み: アカウント・リストのタイムラインは公式のウィジェットで無料で埋め込める（[help](https://help.x.com/en/using-x/embed-x-feed)）。検索結果は埋め込めない。CSP は無いのでブロックはされないが、SPA で描くたびに読み込みが要り、外部スクリプトが CLS と表示速度に効く
- 噂・煽り: 投稿は改変できないので、表示前に言い回しを調整できない。選手ニュースは人手承認が前提（ADR-0022）で、本人の SNS の常時監視は「やらない」と決めている（racer-news-feature spec）。選手の成績を煽る演出は過去に却下されている
- 既存データで代わりになるもの: 選手ページの成績・調子（全国勝率の推移・平均ST・会場別・枠番別・決まり手の傾向・ST の推移・レース条件別）、6選手の勝ち決まり手（`RacerTechniqueProfileChart`、直近90日）。無いもの: まくり型・差し型の判定、コース別の差し・まくり差しの回数
- 別チケットの候補: 案A「選手ページに本人の公式 X タイムラインを埋め込む（手で登録、規約の確認込み）」（API 不要・費用0・作業は小〜中）。案B「X API で選手名を検索して表示」は費用・規約・噂のリスクから非推奨

## ユーザーが決めること（推奨つき）
1. 用語の説明の出し方: (a) v3 のとおり「?」＝用語、セオリーの入口は「傾向 ›」、(b) パネル案の「項目名の点線下線で用語、? はセオリー」。推奨は (a)（ユーザーの指定どおり「?」で引ける。役割は「傾向 ›」と分けたので意味は重ならない）
2. 深掘りに足すモーターの指標: 推奨は「前検タイムを足す。3連率とボート2連率は足さない」（3連率は2連率と相関0.88、上積み無しと検証済み。前検は重ならない情報）。v3 は3つとも「案」で描いた
3. 選手の「数えた値の札」と勝ち決まり手を深掘りに足すか: 推奨は足す（既存データで出せる。評判の言葉は付けない）
4. X: 推奨は「ページ内に投稿を出さず、X 検索への外部リンクだけ」。公式タイムラインの埋め込み（案A）を別チケットで起票するか
5. 会場カードの量: 推奨は v3 のとおり（水質・型・1号艇の1着・決まり手、詳しくは既存の会場ページ）。本実装は `VenueCharacteristicsCard` の取得を流用
