# 開催場一覧ページ再設計 spec

種別: UI機能
対応Linearチケット: なし（ユーザー要望起点、SDDフローで直接作成）

## 背景・目的

ユーザーから「分析を見に行くときに該当レースを探して次に行くのが面倒」というフィードバックを受けた。現状は`/`（トップページ）が`<select>`ドロップダウンで1会場ずつ選ぶ方式（`VenueSelector.jsx`）で、選択した会場のレースのみがカード表示される。個別レースへの専用URLも無く、「予想を見る」ボタンは同一ページ内でstateを切り替えてスクロールする方式のため、他の会場・レースを見るには毎回ドロップダウンを選び直す必要がある。

kyoteibiyori.com・ボートレース公式サイト(boatrace.jp)のUIを参考に、以下の3階層ナビゲーションへ再設計する。

```
会場一覧（24会場、常に固定表示） → 会場別レース一覧（1R〜12R） → レース詳細（分析）
```

調査で判明した前提: `dataService.getRaces()`は既に本日全24会場・全レースをまとめて返す（Edge API `/api/races/today` またはSupabase直接クエリへのフォールバック）。新規スクレイピングなしで実装可能。

## 機能要件

### FR-1 会場一覧ページ（優先度: 高）
- 既存トップページ(`/`)のドロップダウン選択を置き換える
- 24会場を常に固定表示（グリッド）。位置は会場コード順で固定し、日によって並びが変わらない
- 開催中の会場: 大会名（`race_title`）、本日最初の未消化レース時刻、グレードバッジ、時間帯アイコン（モーニング/デイ/ナイター/ミッドナイト）を表示。開催日目（「4日目」等）は実装中に`race_conditions.series_day`/`is_final_day`が未取得（31,004件中0件）と判明したため今回は割愛し、[BOA-226](https://linear.app/boat-ai/issue/BOA-226)として別チケットで対応する（RPCのレスポンスフィールド自体は追加済み、スクレイパー実装待ち）
- 非開催の会場: 「本日開催なし」を表示（次開催の具体的な日付は表示しない。DBに未来日程データが存在しないため。詳細は制約・前提参照。次開催日表示は[BOA-225](https://linear.app/boat-ai/issue/BOA-225)として起票済み）
- 各カードはその会場のレース一覧ページ（FR-2）へのリンク
- 過去日付ページ(`/races/:date`)も同じUIに統一する（該当日付の開催状況を同じグリッドで表示）
- 受入基準:
  - 24会場すべてが同じ配置位置に表示される
  - 開催中/非開催で表示内容が正しく切り替わる（実データと突合して確認）
  - API呼び出し回数は増やさない。ただし`getRaces()`（`get_today_races`RPC）のレスポンスに`race_conditions`由来のフィールド（開催日目等）を追加するクエリ拡張は行う（詳細は制約・前提参照）

### FR-2 会場別レース一覧ページ（新設、優先度: 高）
- 会場一覧の各カードから遷移する中間ページを新設
- 1R〜12Rを一覧表示（既存の`race_grade`・`start_time`等を使用）
- 各レース行から締切時刻・グレード等の基本情報が分かる
- 各レース行をタップするとレース詳細ページ（FR-3）へ遷移
- 受入基準: 会場一覧からタップ→該当会場の全レースが表示され、実際のレース数・締切時刻とDBの生データが一致する

### FR-3 レース詳細ページ（新設・ディープリンク対応、優先度: 高）
- レース単位の新URLルートを新設し、直接アクセス・ブラウザバック・シェア・ブックマークが機能するようにする
- 画面の中身は既存コンポーネント（`PredictionPanel`等）をそのまま流用する。新規UIは作らない
- 受入基準: 新URLを直接開いても該当レースの分析（モデル切替・出走表・展開予測等）が従来通り表示・動作する

### FR-4 多言語対応（優先度: 高）
- FR-1〜3の新規UI文言をja/en/zh-TW/koで翻訳（`t()`経由、直書き禁止）
- `src/config/languages.js`の`TRANSLATED_PATHS`に該当パスを登録
- 用語は`docs/reference/i18n-glossary.md`準拠。新用語が出た場合は先にglossaryへ追記
- 会場名は`venues.*`のi18nキーを使用（`VENUE_NAMES`等の日本語定数を新規に作らない）
- 選手名等の固有名詞要素には`translate="no"`を付与
- 受入基準: 4言語で表示崩れなし。既存の会場ガイド等と用語（会場名表記等）が一致する

## スコープ

### やること
- 会場一覧ページ（トップページ刷新、FR-1）
- 会場別レース一覧ページの新設（FR-2）
- レース詳細ページの新設・ディープリンク対応（FR-3）
- 過去日付ページ(`/races/:date`)を含めた導線の統一
- 4言語i18n対応（FR-4）
- 新規ルートのsitemap登録検討（会場別ページ24件は固定URLのためsitemap登録対象、レース詳細ページは日次で内容が変わる動的コンテンツのため`EXPECTED_EXCLUSIONS`対象を想定。最終判断はstep2）
- e2eスモークテストの追加・既存テストの追随修正

### やらないこと
今回はスコープ外だが、将来的に検討したいとユーザーから明示があったため、いずれも別チケットとして起票済み。今回の設計はこれらを後から追加しやすい形にしておく（詳細は「将来拡張への配慮」参照）。

- 「固い場/荒れている場/イン逃げ率/万舟率」ランキング機能の統合（BOA-171で`/winning-technique`の別タブとして実装済み。今回は重複させない。会場カードへのサマリー統合は[BOA-222](https://linear.app/boat-ai/issue/BOA-222)で起票済み）
- 本日/明日の切り替え機能（[BOA-223](https://linear.app/boat-ai/issue/BOA-223)で起票済み）
- 得点率・モーター部品交換履歴など新規データ項目の追加（[BOA-220](https://linear.app/boat-ai/issue/BOA-220), [BOA-221](https://linear.app/boat-ai/issue/BOA-221)で別スコープとして起票済み）
- 予想モデル・ルールマッチ・イン崩れ指数ロジックの変更
- ガチガチレース検索・穴レース検索等のアラート機能（[BOA-224](https://linear.app/boat-ai/issue/BOA-224)で起票済み）
- レース詳細ページのUI自体の作り直し（既存`PredictionPanel`等をそのまま流用するため対象外）

### 将来拡張への配慮

上記「やらないこと」を後日追加する際に大きな手戻りが出ないよう、今回のFR-1〜3の実装では以下を意識する。

- **会場カード（FR-1）**: バッジ・インジケーターを後から追加できるよう、カード内に固定の余白確保やレイアウト崩れが起きない構造にしておく（BOA-222で会場ランキングサマリーを追加する想定）
- **日付の扱い（FR-1・FR-2）**: 表示日付を固定値でなく props/ルートパラメータとして扱う設計にしておく。本日は`/`が本日固定でも、内部的には「対象日付」を受け取れる形にし、BOA-223（本日/明日切替）追加時にタブ切り替えのみで対応できるようにする
- **会場別レース一覧のデータ構造（FR-2）**: レース単位の属性（逃げ率・展示タイム差等）を後から取得・保持できる形にしておく。BOA-224（アラート機能）でフィルター条件を適用する際にデータ構造の作り直しが要らないようにする

## 非機能要件

- モバイル320px〜で表示崩れなし
- 既存の的中率・回収率の計算ロジックに影響を与えない（今回は表示・遷移導線のみの変更）
- 既存e2eスモークテスト（`e2e/smoke.spec.js`）にデグレなし。新規主要導線（会場一覧→レース一覧→詳細）をテストに追記
- 新規静的ルートは`npm run verify:sitemap`でチェックし、`scripts/generate-sitemap.js`の`staticPages`（多言語対応ページは`LOCALIZED_PAGES`）への登録、または`EXPECTED_EXCLUSIONS`への理由付き登録を行う

## 制約・前提

- データ源: `dataService.getRaces()`（`src/services/supabaseDataService.js`、内部で`get_today_races` RPCを呼ぶ）が本日全24会場・全レースを1回で返す。過去日付は既存の`races`テーブル+`race_date`パラメータで取得可能（現行の`/races/:date`と同じ仕組みを流用）
- **開催日目（`series_day`）・最終日フラグ（`is_final_day`）・大会名（`race_title`）は`race_conditions`テーブルに既存カラムとして存在するが、`get_today_races` RPCのSELECTには未含有。RPC定義（`docs/db-migration/034_get_today_races_unified_volatility.sql`）を拡張してJOINを追加する必要がある（新規スクレイピングは不要、既存データの取得範囲拡張のみ）**
- **非開催会場の「次開催日」は現状DBに存在しない。日次バッチ（`morning-init.js`等）は当日分の`races`しか初期化せず、未来日程データは一切保存されていないため、今回は「本日開催なし」表示に留め、正確な次開催日の表示は見送る（新規スクレイピングが必要なため別チケットで対応）**
- 既存コンポーネント再利用: レース詳細ページは`PredictionPanel`（`src/components/race/`）をそのまま流用する（`.claude/rules/component-reuse.md`準拠）
- 既存`VenueSelector.jsx`は新グリッドに置き換わるため使用箇所が無くなる見込み。他画面からの参照有無を実装時に洗い出してから削除可否を判断する
- 用語ルール（「競艇」使用禁止）・`src/styles/design-tokens.css`のCSS変数使用・`!important`不使用に従う
- 既存コンポーネント再利用: レース詳細ページは`PredictionPanel`（`src/components/race/`）をそのまま流用する（`.claude/rules/component-reuse.md`準拠）
- 既存`VenueSelector.jsx`は新グリッドに置き換わるため使用箇所が無くなる見込み。他画面からの参照有無を実装時に洗い出してから削除可否を判断する
- 用語ルール（「競艇」使用禁止）・`src/styles/design-tokens.css`のCSS変数使用・`!important`不使用に従う
