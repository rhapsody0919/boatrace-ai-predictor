# racer-news-auto-collect 仕様書

## 種別
データ・分析機能（画面変更なし。表示は既存 `/racer/:racerId` の `RacerNewsList` コンポーネントをそのまま使う）

対応チケット: なし

## 背景
[[racer-news-feature]]（`racer_news`テーブル、[ADR-0022](../../adr/0022-racer-news-approval-flow.md)で人手承認制と決定済み）の延長。手動承認が手間である一方、defamation/誤情報リスクへの配慮自体は引き続き必要なため、以下の条件を**すべて満たす場合に限り**人手承認を自動チェックに置き換える例外を設ける。

- 情報源が単一の高信頼性ソース（公式サイト／自社DB）に限定されている
- 内容が事実（数値・順位・級別等）であり要約・解釈の余地が無い
- 自社DBとの整合性チェックで裏付けが取れる

対象外の情報（選手の日常的な近況・人間味のあるエピソード等）は、信頼できる自動取得元が存在しないため、引き続き既存の手動リサーチ→承認フロー（ADR-0022）で扱う。

## 却下した要件

### FR1: 自社DB由来のグレードレース優勝ニュース自動生成（実装後に見送り）
当初「`race_results.rank1`が示す艇番の選手について、そのレースの`races.race_grade`がSG/G1/G2/G3のいずれかであれば`racer_news`へ自動生成する」というFR1を実装・実データ検証まで完了させたが、**ユーザーとの議論の結果、機能として見送ることにした**（2026-08-27）。

理由:
- 実データ検証で1日あたり17件も生成された。中身を精査すると、SG/G1/G2/G3という「グレード」自体はレース単位（予選ヒートも含む）に付与されており、決勝戦（真の優勝）と予選の1着を区別できていなかった
- 「ニュース」と呼ぶに値するのは実質的にトーナメントの優勝（決勝戦制覇）のみで、予選ヒートの1着は既存の番組表・結果表示で十分把握できる情報であり、わざわざ「ニュース」として告知する価値が薄いと判断した
- 決勝戦かどうかを正しく判定するには「その開催（複数日にわたる節）の最終日か」「その日の最終レースか」を会場・グレード・日付でグルーピングする追加ロジックが必要で、当初設計時に意図的に避けた複雑さを結局背負うことになる。そのコストに見合うほどの価値が無いと判断し、実装済みのコード（`scripts/lib/racerNews/gradeRaceWins.js`）と`templates.js`の関連関数は削除した
- FR2（節目記録の取り込み）は月1〜2件と頻度が低く内容が濃いため、「ニュース」として価値があると判断し採用を継続する

### FR5: 会場公式サイトの選手コメント取り込み（実装着手前に見送り）
「選手自身の発言だから低リスクで自動化できる」という前提で設計したが、実装着手時に開催中の複数会場（常滑・徳山・びわこ・福岡等）を実際に調査した結果、「全選手コメント」ページ構造は唐津・芦屋の2会場でしか確認できず、他会場は「レース展望」という**会場スタッフが書いた第三者の分析・予想記事**（1記事内で10人以上の選手に言及する編集コンテンツ）が中心だった。これはFR2で避けた「要約・言い換えリスク」がそのまま当てはまり、当初の低リスク前提が成立しない。また唯一確認できた「選手コメント」形式の2会場（唐津・芦屋）は当時オフシーズンで、実際にコメントが入った状態を検証できていなかった。

ユーザーとの議論の結果、FR5は実装せず見送ることにした（2026-08-27）。今後もし再検討する場合は、唐津・芦屋限定での試験導入、または「レース展望」を対象にした人手承認制への変更のいずれかから検討し直す。

## 機能要件

### FR2: 公式ニュースアーカイブ（レーサーデータカテゴリ）からの節目記録取り込み（優先度: 高）
`boatrace.jp/owpc/pc/site/news/racer/{年}/{月}/`（「レーサーデータ」カテゴリの月別アーカイブ）の一覧を対象に新着記事を検出する。

**実HTML調査で判明した事実（`/step2`時点、要件を訂正）**: 当初想定した「級別発表（勝率ランキング）」記事は実際には「ニュース」カテゴリ（`is-pickup`）に属し、「レーサーデータ」カテゴリ（`is-racer`）ではなかった。実際の「レーサーデータ」カテゴリの記事は`登録第{登録番号}号　{氏名}選手（{支部}支部）{達成内容}達成`という定型見出し（例:「登録第3960号　菊地　孝平選手（静岡支部）2,000勝達成」「登録第3556号　田中　信一郎選手（大阪支部）24場制覇達成」）で、**見出しに登録番号が直接含まれる**。この登録番号は`racer_profiles.racer_id`と完全一致する（実データで確認済み）。氏名のみでの曖昧一致ではなく、登録番号による一意特定が可能。一覧ページのタイトル文字列だけで氏名・支部・達成内容・日付が揃っており、記事本文を個別に取得する必要はない。

受入基準:
- 見出しから登録番号（`racer_id`）・支部・達成内容を抽出できる場合のみ処理対象とする。登録番号を含まない見出し（「選手期別成績に◯年後期のデータをアップ」等、個別選手に関する内容ではない記事）は対象外としてスキップする（エラーにもpendingにもしない）
- 登録番号はあるが支部/達成内容の抽出に失敗した場合（見出しフォーマットの将来的な変化を想定）は、エラーにせずFR3の要確認リストへ記録する
- 抽出した登録番号が`racer_profiles`に存在し、かつ支部が一致することを確認できた場合のみ`racer_news`へ自動投入する。登録番号が存在しない、または支部が一致しない場合はFR3の要確認リストへ
- 既に処理済みの記事は再処理しない（記事URLベースの処理済み管理、[[racer-news-auto-collect]] plan.md 1.2参照）
- `summary`は定型テンプレートで生成する（記事文言の要約・転載はしない）
- 「レーサーデータ」カテゴリ以外の記事は対象外（イベント・キャンペーン等）

受入基準は実データ（2026年7-8月の4記事: 菊地孝平/守田俊介/寺田祥/田中信一郎）で検証済み（実装・検証完了、`/step4`タスク3で対応）。

### FR3: 要確認リストの記録とセッション開始時の提示（優先度: 高）
FR2で自動投入をブロックされた候補を記録し、次回セッション開始時に確認を求める。

受入基準:
- ブロックされた候補は`data/analysis/racer-news-pending-review/`配下にJSON記録する
- 未確認の候補が1件でもあれば、次回セッションの最初の応答でClaudeが自発的に提示し、投入可否を確認する（既存のTikTok/Xツイート下書きの session-start check と同じパターン。`.claude/CLAUDE.md`へのルール追記が必要）

## スコープ

### やる
- `boatrace.jp`公式ニュースアーカイブの「レーサーデータ」カテゴリのみを対象にした節目記録の取り込み（DB整合性チェック付き自動投入）
- 整合性・一意性が取れない候補の要確認リスト化とセッション開始時提示
- GitHub Actions cronによる定期実行

### やらない
- 自社DB（`race_results`）由来のグレードレース優勝ニュースの自動生成（実装後に見送り。上記「却下した要件」参照）
- 会場公式サイトの選手コメント取り込み（実装着手前に見送り。上記「却下した要件」参照）
- 「レーサーデータ」カテゴリ以外の記事（イベント・キャンペーン等）の取り込み
- 選手の日常的な近況・インタビュー的なニュースの自動収集（他に信頼できる自動取得元が存在しないため、引き続き手動）
- FR2（記事要約系）における要約・言い換えによる転載（定型テンプレートのみ）
- 管理画面の新設（ADR-0022の決定を継承）

## 非機能要件
- 生成される文言は既存の表記ルール（「競艇」使用禁止等、`.claude/rules/code-style.md`）に従う
- 自動投入は既存の手動承認フロー（ADR-0022）と共存する。Claudeが手動でリサーチして提示する経路も引き続き有効
- スクレイピング失敗・パース失敗時は、他の日次ジョブに影響を与えない
- 外部サイトへのfetchにはタイムアウトを設ける（`scripts/lib/supabaseClient.js`のundici無期限ハング既知インシデントと同種のリスクへの対策）

## 制約・前提
- データ源: 自社Supabase（`race_entries`/`racer_profiles`）＋`boatrace.jp`公式サイト（スクレイピング）
- 既存`racer_news`テーブルに`status`カラムは無い（ADR-0022の前提を維持。自動投入されたものは「承認済み」と同等に扱う）
- 処理済み記事の状態管理には新規の永続化先を作らず、`racer_news.source_url`の一意性と`pending.json`で代替する（[ADR-0025](../../adr/0025-racer-news-dedup-without-new-table.md)）
- 支部を含む氏名一致では同姓同名の別支部選手と誤認しないよう注意する
