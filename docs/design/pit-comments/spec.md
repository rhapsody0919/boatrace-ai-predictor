## 背景・目的

公式サイトのピットレポート（`https://www.boatrace.jp/owpc/pc/race/pitreport?rno={1-12}&jcd={会場コード2桁}&hd={YYYYMMDD}`）は、SG・G1・G2の一部のレースで、レポーターが選手に取材したコメント（自由記述）と、コメント自信度（★）を掲載する。

ユーザー決定（2026-09-21）: **AIによる言語化はせず、レース詳細のタブに、そのまま表示する。** そのために取得して保存する。公式サイトのコンテンツの再表示については、ユーザーが、出典表記を付けたうえで進めてよいと承認した（2026-09-21。詳細は[§4](#4-公式コンテンツの再表示adr-0067との関係)）。

### 1.2 ページの構造

- 艇ごと（6艇）: 枠番・登録番号/級別・氏名・支部/出身地・年齢/体重・**コメント本文**・**前走**（その日その選手の直前のレース番号。リンク先は`raceresult`）。写真は`/pitreport/{登録番号}-3.jpg`
- **コメント自信度**: コメント本文の末尾に「（コメント自信度・・★★☆）」。括弧は全角と半角が混在。3つ組（★=塗り、☆=空）。実測20ページ・120コメント: ★1つ22件・★2つ94件・★3つ3件、自信度なし1件
- **自信度が付かないコメント**がある: 「【取材者寸評】…」で始まる形式（1/120件）。本文はそのまま保存し、自信度はNULL
- **前走が空**の艇がある（リンクの中身が空。その日まだ走っていない選手と推定。コメント自体はある）
- **レポーター名**: ページ単位（「レポーター：八王子　スゴ六」）。実測では、同じ開催では同じ名前
- コメント本文の長さ: 最短20字・中央値49字・最大115字（120件）。改行（`<br>`）を含むものは、実測では0件だが、パーサーは保持する
- 本文は公式の表記のまま保存する（HTMLの整形用の改行・連続空白は1つの空白にする。全角の空白・記号はそのまま）。末尾の自信度表記だけを分離する

### 1.5 公開後の更新の有無（実測）

**公開後に内容は変わらなかった。** 公開後の内容（コメント本文・★・前走・レポーター）を、同じ解析でハッシュにして比べた。

1. 今日の12R: 14:30（公開を最初に確認）から17:30（発走後60分）まで、9回の取得のハッシュがすべて同一（9f86e2bbdf。3時間）
2. 過去日の3ページ: 10:29〜10:34に取得したページを、約4.5時間後の15:00に再取得して比較した。2026-09-18の12R（d979d76ce0）・同7R（bfe415ab19）・2026-08-28の12R（4a6bcd1fca）は、すべて同一
3. 公開前のページ（未公開）は、11:30と13:30でハッシュが同一（fb9dd0fcf0）

- **確認できた範囲**: 公開後、最長3時間（今日の12R）〜4.5時間（過去日）の間、変更なし。過去日3ページは、公開から数日後の2点の比較で、公開後に内容が変わったとしても、その後の変更は無い。**公開直後（数分〜数十分）の更新は、1点では区別できない**（今日の12Rは、14:30の取得が公開後の最初の観測）
- **履歴の持ち方**: 更新が観測されなかったため、現時点の設計（DBは最新のみ、内容が変わるたびに生HTMLを別パスで保管）の前提を変えない。公開後の再取得は、行わない（取得ジョブは、コメントを検知した時点で完了とする。plan.md §4.1の「最小十分頻度」どおり）。更新が起きる事例が観測されたら、再取得の窓を追加する
- 未確認: 公開後に訂正・追記される事例（1レースあたりの頻度が低い可能性）。他の開催日・SGでの確認は、本番のliveで、`race_pit_reports.updated_at`が`created_at`と異なる行（変更のあった行）を数えて、継続的に検知できる

## 4. 公式コンテンツの再表示（ADR-0067との関係）

**前提（ユーザーの承認、2026-09-21）**: 選手コメントの画面表示は、**出典表記を付けたうえで進めてよい**。以下は、その承認を前提にした要件と、判断の材料（法的見解ではない）である。

### 4.1 ADR-0067の現状維持の範囲と、選手コメントの違い（事実）

| 観点 | ADR-0067が扱っている範囲 | 選手コメント |
|---|---|---|
| 表示するもの | 出走表の選手情報・オッズ・結果の着順・払戻・展示など、**数値・事実データ**を、集計・加工して、または取得値のまま | **レポーターが取材して書いた、自由記述の文章**（1レース最大6件、1件20〜115字） |
| 加工の有無 | 集計・予測・順位など、加工した結果が中心 | **加工せず、そのまま**表示する（ユーザー決定: AIでの言語化はしない）。生の文章の複製になる |
| 公式サイトのポリシー（ADR-0067に本文の要点） | 「サイト上のコンテンツは、本財団および第三者が有する著作権により保護されている」「著作権法が定める場合、または個々のコンテンツに個別の利用条件が示されている場合を除き、…無断で使用（複製、改ざん、頒布などを含む）することはできない」 | 同じポリシーが適用される。ピットレポートのページ本文・フッターに、個別の利用条件の記載は見つからなかった（フッターは「COPYRIGHT © BOAT RACE OFFICIAL WEB ALL RIGHTS RESERVED」と、サイトポリシーへのリンク） |
| 著作物性 | 数値・事実データが中心（ADR-0067は、この点を区別していない） | 自由記述の文章で、レポーター（第三者）が書いたもの。数値より、著作物性が明確（本specの整理で、法的見解ではない） |
| 量 | 全レース・全項目 | SG・G1・G2の対象レース。1日約6〜18レース×最大6件 |
| 保存と再表示の別 | 取得値の保存（解析）と、加工結果・取得値の表示 | 保存（内部）と、**公開する画面への文章の再表示**の両方 |

ADR-0067の「見直しの契機」のうち、次に該当しうる: 「取得・表示の量や範囲が大きく変わる場合」（数値から、第三者の自由記述の文章の、そのままの再表示へ）。ユーザーは、承認の際に、この点を認識したうえで進めると判断した。

### 4.2 承認の範囲と、要件（出典表記）

承認された範囲: **出典表記を付けた、画面への表示**。要件:

1. 出典表記: 「出典: BOAT RACE オフィシャルウェブサイト ピットレポート」を、コメントのセクション内（コメントを読める位置）に常に表示する
2. 該当ページへのリンク: 元のpitreportのURL（`https://www.boatrace.jp/owpc/pc/race/pitreport?rno=12&jcd=05&hd=20260918` の形式。`race_id`から導出する）を、`rel="noopener noreferrer"`・新しいタブで開く。**ユーザーの導線を公式サイトへ戻す**（要約・転載で公式サイトを代替しない）
3. 取得時刻の併記: 「取得: 2026-09-21 15:42」（JST）。`race_pit_reports.created_at`（初めて保存した時刻）を使う。公式サイトの現在の内容と違う可能性がある旨の注記
4. コメントの改変・要約をしない（本文をそのまま表示。文字数を切り詰めない。折りたたみは、全文を隠さず、既定で全文を表示する）
5. レポーター名の表示（案。公式ページの表記のとおり。「レポーター: 八王子　スゴ六」）。第三者の著作者の表示。ユーザー判断（[§4.3](#43-ユーザー判断の材料)）

### 4.3 ユーザー判断の材料

1. **出典表記の位置と大きさ**: 各コメントの下に小さく付ける（見やすさ優先）か、セクションの上部に1つ付ける（表記の重複を避ける）か。案は、セクションの上部にまとめて表示する（1レース1つ）+ 各艇のコメントは無装飾（[screens.md](./screens.md)）
2. **レポーター名の表示の要否**: 公式ページでは表示されている名前（ペンネームに見える）。著作者の表示として付けるか、付けない（ページへのリンクで足りるとする）か
3. **匿名（anon）への公開の境目**: マイグレーション086（SELECTポリシーとGRANT）が、公式サイトの文章を再公開する境目。085（保存）は、公開しない（service_roleのみ）。画面の実装・モック承認の後に、086を適用する
4. **保存する範囲**: 現時点の設計は、最新の内容のみDBに持ち、内容が変わるたびに生HTMLをStorageに保管する（内部用。再配布・公開しない）。生HTMLの保管も、ADR-0067の範囲内かは、Q1の承認（取り直せないページのみ保管）と同様にユーザー判断
5. **ADR-0067への追記**: 承認の記録（[ADR-0067の追記案](../../adr/0067-official-site-content-redisplay-policy.md)）を、ユーザーが確認してマージする
6. **見直しの契機との関係**: 公式・会場から通知・要請があった場合に、コメントの表示を止められるようにする（086のロールバック（ポリシーとGRANTの削除）だけで、匿名の読み取りを止められる設計にした。画面は、コメントが取れない場合、セクションを出さない）
