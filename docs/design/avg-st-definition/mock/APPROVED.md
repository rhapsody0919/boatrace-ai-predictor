# 平均ST の定義と見せ方（BOA-815・BOA-812）承認記録

- 承認日: 2026-10-10
- 承認の流れ: 調査レーンの結論（案A）をユーザーが「推奨（案A）で良い」と承認 → 見せ方3点のモックをユーザーが「推奨どおり」と承認（いずれもオーケストレーター経由）
- モック（Artifact）: https://claude.ai/artifact/QDWDrK17bcKMVmGCqCoHDo
- このフォルダの画像は、承認した案の状態を 375px・1440px で撮ったもの（値は若松 9R 2026-10-09）

## 決めたこと（方針）

1. 平均ST には必ず期間を名前に付ける。名前だけの「平均ST」は出さない
2. 「当サイトに蓄積した全期間」の平均ST は、全画面でやめる
3. データ出走表は公式の出走表の平均ST と一致させる
4. 思考アシストの「このコース」は、5走未満を直近30走で補い、セオリーカードの表示と判定をそろえる

## 名前と値の正本

| 名前 | 中身 | 桁 |
|---|---|---|
| 平均ST（公式） | `racer_period_stats.avg_st`。公式の出走表と同じ期の値（下の「公式の期」） | 2桁 |
| 平均ST（直近30走）／平均ST(30走) | v16 の `st_mean30`: 前日までの30回の出走の窓。F・L は平均から外す。窓の中に3走以上あるときだけ値を出す | 3桁 |
| 平均ST（このコース・直近30走） | v16 の `course_st.course_filled`: 枠なりのレースでその枠を走った直近30走。5走未満は直近30走で補う | 3桁 |
| 平均ST（{会場}・直近30走） | v16 の `course_st.venue` | 3桁 |

選手ページの「直近30走」（`racer_aggregated_stats.avg_st_last_30`）は、v16 と同じ窓（30回の出走、F・L は平均から外す、3走以上）にそろえる。当日の走を含むかどうかだけが違い、選手ページはレースに紐づかないのでそのままにする。

## 公式の期（データ出走表の「平均ST（公式）」）

公式の出走表の平均ST は、勝率と同じ「適用中の期」の値。期は**節の初日**で決まり、節の途中では替わらない（6/27〜7/1 の節の 7/1 は旧期。戸田 2026-07-01 8R で照合。レース日で決めると6艇中4艇が食い違った）。

| 節の初日 | 使う期 | 成績の期間 |
|---|---|---|
| 1〜6月 | (Y, 1) | (Y-1)-05-01 〜 (Y-1)-10-31 |
| 7〜12月 | (Y, 2) | (Y-1)-11-01 〜 Y-04-30 |

本番DB と公式の出走表で照合済み（各6艇が一致）: 若松9R 2026-10-09、2026-07-03 平和島9R（(2026,2)）、2026-06-20 若松9R・2026-05-20 桐生9R（(2026,1)）、2025-12-20 住之江9R（(2025,2)）。

基本情報タブの「前期」（`periodsEndedBefore`、直前に終わった期）とは、5〜6月と11〜12月で値が違う。

## 根拠

- 調査の数値（レース内のスタートの並びとの順位相関）: 公式・前期 0.223、直近30走 0.247、このコース 0.269〜0.272、補正あり 0.296〜0.299（評価 2026-07-01〜10-08）。補正ありは差が小さく、説明できる単純な平均を優先して採らなかった
- 実装の割り振り: データ出走表と選手ページはこのレーン、思考アシストと龍神ソナーは各レーンの今の PR のマージ後にオーケストレーターが割り振る
