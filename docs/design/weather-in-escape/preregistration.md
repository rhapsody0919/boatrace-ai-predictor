# 風向・風速・波高とイン逃げ率（BOA-211）分析の事前登録

BOA-211（気象データとイン逃げ率／イン崩れ率の相関タブ）を実装するかどうかを決めるための分析。
結果を見る前に、定義・比較・判定基準をここで固定する。方法論は `second-opinion-reviewer` で1パス見て、指摘10件を反映した（末尾「レビューの反映」）。

## 1. 前提として確認済みのこと（着順は見ていない）

### 1.1 DB の `race_conditions.wind_direction` は方位ではない

- 公式の直前情報・結果ページの風向アイコン（`is-wind1`〜`16`）は、**スタンドから水面を見た画面上の矢印**。2つのターンマークの絵（`img_corner1_2.png`）が左右に並び、その下に「スタンド」と書かれている。矢印は風が吹いていく向き。`is-wind1`=↑、`5`=→、`9`=↓、`13`=←（公式の画像 `icon_wind1_{n}.png` で確認）
- 同じブロックの `is-direction{d}` が、画面上で北がどちらかを示す（`icon_direction2_{d}.png`。`d=1` で北が上、1つ増えるごとに時計回り22.5°）
- 取得側（`scripts/lib/beforeinfoWeather.js`）は `is-wind{n}` を `北, 北北東, …` の16方位名に置き換えて保存している。名前は方位だが、**中身は画面上の矢印の向き**
- 「北から吹く風は画面上で南へ向かう矢印」なので、Kファイルの方位番号 `k`（北=0、時計回り）から画面上の矢印番号（0始まり）への変換は `r = (k + offset_v) mod 16`、`offset_v = (d_v + 7) mod 16`
- 全24会場の `is-direction` を公式の結果ページ（2026-09-23〜30の各会場1R）から取得し、`offset_v` を出した。これは、2026-02〜09 の DB と公式Kファイル（8方位）を風速2m以上のレースで突き合わせた、会場ごとの最頻のずれと**24会場すべてで一致**した

- 最頻の割合が低い会場（05, 13, 18）でも、次点は最頻の±2で、偶奇は変わらない

### 1.2 水面基準の向き

- ボートは左回り。スタンドから見て右が1マーク、左が2マーク。ホームストレッチはスタンド側
- よって画面上の → （`is-wind5`、DB の値は「東」）が、2マークから1マークへ吹く風＝**追い風**、← （`is-wind13`、DB の「西」）が**向かい風**
- `is-wind17` は無風で、DB では NULL（風速0）
- 間接的な裏付け（レビューで実施、着順は使っていない）: K の風だけで出した会場別の追い風・向かい風の構成比が、会場ガイドの記述（桐生の追い風、尼崎・丸亀の向かい風、徳山の斜め追い風、唐津の朝の向かい風）と5会場すべてで一致。符号が逆なら全て逆になる

## 2. データ

- 公式K・Bファイルの解析済みファイル（`kb-day/v1`）。場所は環境変数 `KB_ARCHIVE_DIR`（既定 `~/boatrace-archive-backup/kb-archive`）の `parsed/`
- 期間: 2020-02-01〜2026-09-30（解析済みファイルがある全期間）
- 除外: 結果の行が無いレース、1コースの艇が分からないレース（進入の欠損・欠場）、1着の艇が無いレース（不成立）、風速・風向が無いレース（風の分析のみ）、波高が無いレース（波高の分析のみ）
- データの使用履歴: 風速・波高と着順の関係は、イン崩れ指数・展開予測（`scripts/lib/turnPrediction.js` の風速5m以上の補正）・MLモデル（`scripts/ml/features.py`）で、同じ期間の DB データを既に使っている。ブログ `public/blog/weather-wind-impact.md` に「追い風はイン有利」の主張もある。**水面基準に変換した風向と着順の組み合わせは、この分析が初めて**。波高の結果は事前の情報が混じっている点を限界として扱う

## 3. 区分

### 3.1 風（主）: 向きの扇形 × 風速

画面上の矢印番号 `r` から、追い風からの角度 `φ = (r − 4) × 22.5°`（−180〜180°に正規化）。

| 区分 | 条件 |
|---|---|
| 向かい風・強 | \|φ\| ≥ 135° かつ 風速 ≥ 4m |
| 向かい風 | \|φ\| ≥ 135° かつ 風速 2〜3m |
| 弱い・横風 | 風速 ≤ 1m、または 45° < \|φ\| < 135°（無風を含む） |
| 追い風 | \|φ\| ≤ 45° かつ 風速 2〜3m |
| 追い風・強 | \|φ\| ≤ 45° かつ 風速 ≥ 4m |

扇形で決めるので、K（8方位）でも DB（16方位）でも同じ定義になり、画面の「追い風4m」と対応する。

### 3.2 風（感度分析、判定には使わない）

追い風成分 `c = 風速 × cos φ` の閾値（≤−4 / −4〜−2 / −2〜2 / 2〜4 / ≥4）による5区分。

### 3.3 波高

0〜2cm / 3〜5cm / 6〜9cm / 10cm以上。**判定は「弱い・横風」のレースに限って行う**（波は風でできるため、風の効果の言い換えを避ける）。10cm以上は強風・高波の中止で欠けたレースの残りだけを見ている点を限界とする。

## 4. 指標と比較

- 主指標: **1コース1着率**（イン逃げ率）。1コースの艇が1着のレースの割合。イン崩れ率は 1 − これ
- 副指標（記録のみ）: 決まり手の構成（逃げ・差し・まくり・まくり差し・抜き・恵まれ）
- **会場内の差 D**: 区分の1コース1着率 − その会場の（その分析の対象の）全レースの1コース1着率（pt）
- **全会場の差 D̄**: 会場内の差を区分の件数で重み付けして平均したもの。会場をまたいで生の率を比べない
- **調整後の差 A**: 各レースの期待値を、会場×月×レース番号帯（1-4R/5-8R/9-12R）×1コース艇の級別（A1/A2/B1/B2）の1コース1着率とし（その層が30件未満なら会場×月）、区分ごとの（実測 − 期待値）の平均
- **信頼区間**: 会場×日をクラスタとし、会場の中で日を復元抽出するブロック・ブートストラップ（1,000回）。判定の機会が風で2つ（強の2区分）、波高で2つなので、Bonferroni で **97.5%** 区間を使う

## 5. 頑健性（記録）

- 期間の分割: 前半（2020-02〜2022-12）と後半（2023-01〜2026-09）の D̄
- 会場ごとの符号: 区分の件数が300以上の会場で、D の符号が D̄ と同じ会場の割合
- 時点: 同じ会場の同じ日の**前のレース**の K の気象で区分した場合の D̄（ファンが買う時点に直前情報で見る値に近い。判定には使わない）
- 3.2 の追い風成分による区分の D̄

## 6. 判定（実装に進む条件）

「向かい風・強」「追い風・強」のどちらかが、次を全て満たせば実装に進む（オーケストレーター経由でユーザーにモックを出す）。

1. |D̄| ≥ 3pt
2. D̄ の97.5%クラスタ・ブートストラップ区間が0をまたがない
3. A が D̄ と同じ符号で、|A| ≥ |D̄| × 2/3
4. 前半・後半の D̄ が同じ符号
5. 区分の件数が300以上の会場のうち、2/3以上で D が D̄ と同じ符号

基準2・4は件数が多いと通りやすく、決め手にならない。実質の決め手は1・3・5。
満たさない場合は BOA-211 を見送り、理由を Linear に記録する。

波高は「弱い・横風」に限った 6〜9cm・10cm以上 について同じ基準で判定し、どちらかが満たせば波高も出す。

## 7. 画面に出すときの決まり（判定に通った場合）

- 画面に出す値は判定した推定量と同じ「会場内の差 D」と、区分の1コース1着率・件数。全会場の値は D̄ と97.5%区間
- 会場別のセル: 件数1,000以上は値と区間を表示、300〜999は「参考値」の注記付きで表示、300未満は件数のみ（n=100で±10pt、3ptの差の区別に約1,000件要るため）
- 「レース時点の風（確定値）による集計で、直前情報の気象は前のレースの値のことがある」と注記する
- 本番で DB の `race_conditions`（16方位）を使って区分する場合は、公開前に、重なる期間（2026-02〜）で同じレースの K 由来と DB 由来の区分の一致率を出すスクリプトを作り、毎晩の検査に載せる（`.claude/rules/analysis.md` 検証ルール3）

## レビューの反映

| 指摘 | 対応 |
|---|---|
| 時間帯・1号艇の実力の交絡 | 調整後の差 A に、レース番号帯と1コース艇の級別を追加 |
| CI・前後半が効かない、会場間のばらつき | 会場×日のブロック・ブートストラップに変更。判定5（会場の符号の一致）を追加 |
| 会場セルのノイズと推定量の不一致 | 表示の下限を1,000（参考300）に上げ、表示する値を判定した D に揃えた |
| 8方位×奇数オフセットで「強」の意味が変わる | 扇形×風速の区分に変更。追い風成分は感度分析に |
| 波高を風で調整していない | 波高の判定を「弱い・横風」に限定。判定する区分を明記 |
| 使用履歴の言い過ぎ | 2章に既存の使用を明記 |
| 時点（確定値と直前情報） | 前のレースの気象で区分した値を記録。画面に注記 |
| 本番の定義との照合 | 7章に照合スクリプトを公開の条件として追加 |
| オフセットの裏付けが10会場のみ、±2の説明 | 24会場で is-direction を取得して一致を確認。±2は時点の違いと説明を修正 |
| 判定の量の不一致・多重性 | 各基準の量を明記。97.5%区間に変更 |
