# レースページ再設計 spec

種別: UI機能
対応Linearチケット: BOA-168

## 背景・目的

回収率・的中率はパリミュチュエル方式の控除率により長期的に75%へ収斂するため、「予想の成績」を強みの中心に据え続けるのは持続不可能。VUPループで実装した13の分析機能を活かし、以下の転換を行う。

- **レース前**: ユーザーが自分で予想するための「データ出走表」を主役にする
- **AI予想**: 「答え」から「仮説」へ降格。名称は「AIデータ分析」とし、コンパクトな1セクションに畳む
- **レース後**: 結果をboatAIの分析データと機械的に照合する「データで振り返る」を表示し、当たりも外れも誠実に検証することで分析データの有用性を実証する

予想モデル本体・イン崩れ指数のロジックには一切触れない（別途、大規模修正として後日実施することがユーザーと合意済み）。

## 機能要件

### FR-1 データ出走表（優先度: 高）
- 出走6選手×分析指標のマトリクスを、AI予想ブロック群より上（ページ上部）に表示する
- レイアウトは転置型（行=指標、列=6艇）。`AttackDefenseTable`の既存パターンを踏襲し、全ビューポートで同一レイアウトとする（横スクロール回避）
- 表示指標（行）:
  1. 級別・全国勝率（`prediction.allPlayers`由来、即時表示）
  2. モーター2連率（`getRaceMotorBreakdown`）
  3. 調子（勝率Δ）（`getRaceRacerFormBreakdown`、↑↓矢印+値）
  4. ST安定度（`getRaceStPredictabilityBreakdown`の`avg_deviation`）
  5. 展示タイム（当日値+過去90日平均との比較）（`getRaceExhibitionTimeBreakdown`）
  6. 決まり手型（`getRaceTechniqueProfileBreakdown`のtop技+勝利数）
  7. 単勝回収率（`getRaceRacerBoatReturnRate`）
- 色分けは**レース内相対順位ベース**（絶対閾値を導入しない。行ごとに最良セルをハイライト）
- 各指標行のラベルから `/winning-technique?venue_code=X&race_id=Y&tab=対応タブ` へディープリンク
- 分析データのロード中は基本行（級別・勝率）のみ即時表示し、残りはプレースホルダ→逐次埋め
- 個別関数の取得失敗時はその行のみ「—」表示（全体を壊さない）
- 受入基準: 本日ページ・過去日付ページの両方で表示される。表示値が生Supabaseクエリでの独立再計算と一致する

### FR-2 AI予想の降格（優先度: 高）
- 既存のAI予想ブロック群（VolatilityDisplay/ModelDescription/ModelSwitcher/PredictionFlash/FirstMarkAnimation/BettingValueSection/AttackDefenseTable/OutcomePatternPreview/PredictionTable）を「🤖 AIデータ分析」という折りたたみセクションに内包する
- 折りたたみヘッダには常時「AIの本命: N号艇 選手名」のコンパクトサマリーを表示
- デフォルトは折りたたみ状態。展開すると既存コンテンツがそのまま表示される（既存機能の削除はしない）
- 受入基準: 既存のモデル切替・展開アニメ等が展開後に従来通り動作する

### FR-3 データで振り返る（優先度: 高）
- レース結果確定後（`prediction.result.finished`）のみ、`RaceResult`の直後に表示
- 勝った艇について、以下を機械的に照合し「✅ データと整合した点」「⚠️ データと違った点」に分類:
  1. 決まり手: 実際の決まり手が勝者の過去90日勝ちパターン上位と一致するか
  2. モーター: 勝者のモーター2連率がレース内上位（1-2位）か下位（5-6位）か
  3. 調子Δ: 勝者の勝率Δが正か負か
  4. 展示タイム: 勝者の当日展示タイムがレース内上位か下位か（計測済みの場合のみ）
  5. 回収率: 勝者の単勝回収率が100%以上か（参考情報）
- AI検証: AI本命の当否を明記。外れた場合は「勝った艇をどのデータが示唆していたか」（整合項目のリスト）を提示。整合項目が無い場合は「データからも読みにくい波乱」と正直に表示
- 判定は全て機械的（レース内順位・一致判定のみ）。恣意的な閾値・文章生成AIは使わない
- 受入基準: 結果確定済みの過去レースで表示され、表示内容が実データと一致する

### FR-4 ブログ記事（優先度: 中）
- 1機能1記事ルールに従い2本: (1)データ出走表の紹介 (2)データで振り返る機能の紹介
- 既存の型（スクリーンショット・FAQ・内部リンク・note/tweetドラフト）に従う

## スコープ

### やること
- `PredictionPanel`内の並び替えとFR-1〜3の新規コンポーネント追加
- i18n 4言語（ja/en/zh-TW/ko）のキー追加
- e2eスモークテスト追加・既存テストの追随修正

### やらないこと
- 予想モデル・イン崩れ指数・スコアリングロジックの変更（後日の大規模修正で実施）
- トップページのレース一覧カード側の変更（レースページに集中、ユーザー指示）
- App.jsx/RaceDetail.jsxの重複解消リファクタ（調査で特定したA〜Iは別チケット化候補。今回はページ側を触らずに済む設計のため見送り）
- 既存PredictionTableの削除（AIデータ分析セクション内に残す。削除可否は未確定事項）

## 非機能要件

- モバイル320px〜で表示崩れなし（転置レイアウトで横スクロールを発生させない）
- 分析関数6本の並列取得はPromise.allSettledで行い、初回ロードでページ全体をブロックしない（基本行は即時表示）
- 既存e2e 30件にデグレなし

## 制約・前提

- 分析関数は全て`raceId`1引数・`withCache`済（30分TTL）。データ出走表と振り返りが同じ関数を呼ぶため2回目はキャッシュヒット
- App.jsxのおすすめページ自動選択パス（App.jsx:82-87）では`selectedRace.id`が無い。`rawData`のdate/placeCd/raceNoから導出フォールバックし、導出不能時は分析行を非表示
- RaceDetailでは`exhibitionData`がpredictionに含まれないが、FR-1の展示行は`getRaceExhibitionTimeBreakdown`が自前で取得するため影響なし
- 用語ルール（「競艇」禁止）・design-tokens使用・`!important`禁止に従う

## 未確定事項（ユーザー確認待ち）

1. **旧PredictionTable（13列の詳細出走表）の扱い**: AIデータ分析セクション内に残す実装とするが、データ出走表と重複感があるため、将来的に削除・統合するかは要判断
2. **AIデータ分析セクションのデフォルト状態**: 折りたたみをデフォルトとするが、既存ユーザーの体験が大きく変わるため、展開デフォルトの方が良い可能性もある
3. **トップページ一覧カードへの展開**: 今回スコープ外としたが、次フェーズでやるか
