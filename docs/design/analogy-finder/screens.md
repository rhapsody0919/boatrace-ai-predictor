## 画面

### S-1 レース詳細 > AI予想タブ（既存画面の拡張）
節「アナロジー・ファインダー」を、既存ブロックの下に足す。中は上から順の1本の流れ（Q1）:

1. **何が効いているか**（寄与度。見出しの下に「寄与度用のモデルの説明で、上の AI予想とは別のモデル」と1行）
   - 1-a **このレースの6艇の差の内訳**（FR-1b）。展示後の段があれば展示後の値、無ければ出走表時点の値に「展示前の値」と付ける。展示後の値のときは、変化の1行（「展示タイムが押し上げたのは4号艇」）と、折りたたみ「展示前の値を見る」
   - 1-b **同じ条件のレース全体の内訳**（FR-1。折りたたみ、Q2）。会場・グレード・ラウンドのスライス、着順タブ、詳細条件、艇番比較、テーマの内訳（実装済みの部品）。各テーマに「全体との差（pt）」、share_sd の2倍未満なら「全体とほぼ同じ」
2. **似ている過去レース**（FR-2）。見出し「寄与度の上位2つのテーマで似ている過去レース」（Q7）
   - 条件チップ4つ（テーマの色で縁取り）。末尾からだけ外せる・戻せる。1-a の上位2テーマのシェアの差が .05 以上なら、上位テーマに当たるチップを強調
   - 似ている理由の一文（件数が主役）。自動で外したときは理由の一文
   - 「ほかのテーマでも絞る」（Q6）: 4条件のチップの下に、ラウンド・グレード・1号艇のモーターのトグル。値は今日のレースのもの（「ラウンド: 予選」「グレード: G1」「1号艇のモーター: 6艇中1〜2位」）。各トグルに「足すと N件」。0件になるものは押せない。今日のレースの値が分からない条件は出さない。並びは 1-a の寄与度の順（ラウンド・グレードは「環境」、モーターは「機力」のテーマ）。ただし「効く順」とは書かない。1つでもオンなら、トグルの下に「この条件は自動では使っていません」と1行
   - 分布4つ（決まり手・1着の艇番・1着の進入コース・よく出た出目）。n と期間。割合は件数÷n（30件未満も出す）
   - 同じ条件の過去レース（新しい順20件）、事故情報の常設注記
3. **組み合わせ**（FR-3）。2 と同じ層。サンキー図・組み合わせ一覧・コールアウト・「1号艇以外が1着」

- 中止確定のレースは節ごと出さない。それ以外（確定後・予想なし・未確定）は出す。予想（predictions）の有無とは切り離す
- 1-a は欠場が分かっているレース、計算できなかったレースでは出さない（1-b は出す）。出走表時点の段を出した後に欠場が分かったレースも、1-a を取り下げて「欠場があったため、このレースの6艇の差の内訳は出していません」と1行出す。1-a の下にモデルの版を小さく出す（2つの段は同じ版で計算する。ADR-0083）2・3 は `get_analogy_similar` が NULL なら出さない
- 条件チップの「外す」「戻す」: 任意の条件がオンのときは `n_by_depth_filtered`（任意の条件を重ねた深さごとの件数）で、行き先が0件になるボタンは押せない。オフのときは `n_by_depth`
- チップの強調（.05 以上、ちょうど .05 を含む）は、1-a で表に出ている段（展示後があれば展示後、無ければ展示前）の上位2テーマで決める
- 1-a の状態（(a)〜(d)・展示後・欠場）は API の `status` で決める（画面は時刻で判定しない。plan「API」）。欠場のときは 1-a の見出し・ラベル・注記を1つも出さず、欠場の1行だけ
- 「1号艇以外が1着のレースだけ」は API を呼び直さず、同じ応答の `trifecta`・`course_flow` を画面で絞る
- データ段の表示: 2 の見出しの下に「出走表 7:30 時点のデータ（前日までの成績）」。確定済みのレースは「（発走前）」を付ける
- App.jsx 側にこの節は置かない（レース詳細のタブにだけ出す）

## ユーザー回答（2026-10-02）
Q1〜Q7 は推奨どおり（Q1〜Q5 はそのとおり、Q6 は作る、Q7 の見出しはこの文言）。ただし「展示が間に合わなかった」のような、システムの失敗を感じさせる言い方は画面に出さない（文言は下の表で確定、2026-10-02 夜）。

## 1-a の段のラベルと注記（2026-10-02 夜 ユーザー承認。推奨案で確定、代案A・B は採らない）
画面に「間に合わない」「失敗」「エラー」の類を出さない。ラベルは「展示前の値」で統一する。

| 状態 | ラベル | 注記 |
|---|---|---|
| (a) まだ展示が終わっていない | 展示前の値 | 展示の後に更新します |
| (b) 展示は終わったが、まだ反映されていない（数秒〜数分。締切前の計算の失敗もこれとして扱う） | 展示前の値 | 展示の結果を反映しています |
| (c) 6艇の展示タイムがそろわず計算しない | 展示前の値 | このレースは展示データがそろっていないため、展示前の値です |
| (d) 締切を過ぎても展示後の値が無い（計算の失敗） | 展示前の値 | なし（事実でない理由を書かない） |
| 展示後 | 展示後 | 小さく「展示 15:32 時点」 |

- 欠場は別の1行（「欠場があったため、このレースの6艇の差の内訳は出していません」）で、上の表の対象外
- ファン4人パネル（仮説）: 20代男性は「待っています」より短い「反映しています／反映中」がよい。20代女性は (c) で理由が無いと「なぜ更新されないのか」と思うので、事実の理由を一言ほしい。30代男性は時刻つきが一番正確。30代女性は「展示前」が既存の展示タブの言葉とそろっていて分かりやすい
- (b) と (d) を分けるのは、計算の失敗に「データがそろっていない」という事実でない理由を付けないため。締切前は (b) と同じに見せ、締切後は理由を書かない
