§9-1 の4点にユーザーが「全て推奨の方法でモックを見てみたい（却下の可能性あり）」と答えたので（handoff-fr2-lane.md §10）、4点とも推奨の形でモック Version 10 を作った。それを、独立したエージェント（second-opinion-reviewer）に第2回の検証として見せた。観点は §9-2。形式は CLAUDE.md「セカンドオピニオン検証」の手順4（自分の結論／指摘／採用・反論）。

## 自分の結論（検証前）
- 構成: A このレースは何で差がつくか → B 似た過去レースはどう決着したか → C 条件を変えて探る。着順は全体で1つ、艇は A・B で共有、会場などの条件は C の中だけ
- A: このレースの6艇の差の内訳（レース内で中心化した |SHAP| のテーマ割合）。艇を選ぶと「出発点」（若松のその艇番の着順率、前日まで、数えた値）と「枠以外で上げ下げしているもの」（矢印と棒、数字なし）
- B: 層別 S*（自動の深さ3、331件）の決着。艇を選ぶと「その艇が1着だった N件では」の5指標を「1号艇以外が1着だったレース」と並べる
- C: 実際の決着（会場×グレード×ラウンドの全組み合わせ）を比べるのが主。補助に「テーマが見込みを動かした量（全国=100）」（test 1年、穴の月を除く、300R 未満は出さない、|指数−100| < 2SD は「全国並み」）
- 7テーマ（環境を「天候・水面」と「グレード・ラウンド・節」に分ける）。シェアは特徴量ごとの |SHAP| の和なので、学習し直しは要らないと判断した
- 代案（艇の六角形・6テーマ・補助なし）は、モック内の切り替えで見られる

数字の出どころ（作業時の scratchpad。モックのソースと一緒に docs/design/analogy-finder/mock-v10/ に残す）:
- 実データ: 本番 DB を読み取りで数えた。マイグレーション 120 の関数本体を SELECT の中に書き写し、母集団は kb＋本体、2019-04-01〜2026-10-02 で 409,638R。120 冒頭の期待値（2019-04〜2026-09 で 409,588R）との差は −281R（−0.07%）。kb 側の −164R は「2着か3着が無いレース」を外した分で、原因を確かめた。本体側の −117R は内訳を確かめていない
- モデル: 寄与度用の本番モデル（版 2026-10-02）。test を学習時のコード（dc6d02084）で作り直し、本番の profiles（全国・全艇・3着順）を差 0.00002 以内で再現できることを確かめてから使った

## 画面に出してよいもの・いけないもの（第2回で更新、採用）
- 出してよい: 第1回で出してよいとしたもの全部。C の実際の決着（前日まで。小さい n では区間か一覧）。参考の率（「参考: ○号艇（○枠）の着順率」、期間・母集団つき、独立した枠）。艇ごとの上げ下げの矢印と棒（テーマ単位の正味。基準は「6艇の平均」と書く）。C の補助の値と SD（実質の差のしきい値と、6艇の値が近い条件・6艇で同じ値のテーマの注記つき）
- 出してはいけない: 第1回で出してはいけないとしたもの全部。特徴量単位の |SHAP| の割合を「内訳」「差の大きさ」と呼ぶこと。1画面で A と C のテーマの量の集計単位が違うこと。主語がモデルでない因果の見出し。2SD だけを根拠にした「全国より大きい／小さい」。補助の値から「SG・G1 では実力が関係ない」「準優・優勝戦は天候が効く」と読める見せ方。例のレース自身や後の日を含めた数え方
