# 風向の基準（本体の風向を K ファイルの方位に直す）

BOA-271 アナロジー・ファインダーの寄与度モデルの特徴量 `wind_x`・`wind_y`（風速×sin/cos(風向の角度)）の、風向の基準をそろえる。ユーザー決定（2026-10-03、オーケストレーター経由）: 案1（本体の風向を K の基準に直す）。

## 問題
- 学習の fit（2019-04〜2025-07）は長期分 `kb_archive_races.wind_direction`。公式の K ファイル（競走成績）のレース見出しの風向で、方位（8方位＋無風）
- test（直近12か月の本体分）と本番の推論は `race_conditions.wind_direction`。`scripts/lib/beforeinfoWeather.js` が直前情報・結果ページの風向アイコン `is-windN` を「1=北 … 16=北北西」と方位名にしたもの
- 実際のアイコンは方位ではない。同じページの方位マーク `<p class="weather1_bodyUnitImage is-directionM">`（会場ごとに北の向きが違う水面の図。CSS は `is-directionM:before` → `icon_direction1_M.png`）に対する向き。補正しないと、test と推論の風が fit と別の座標で入る（補正なしで K と方位が一致するのは全体の 20%）

## 補正

- 検証: 会場ごとの δ=(DB−K) mod 360 の最頻値が、24会場すべてで上の角度と一致する（`build-wind-basis.js` が一致しなければ失敗する）。会場×月のどの組でも最頻値は同じで、時期による変化は無い
- 補正後の不一致は回転のばらつきではない。2R 以降の直前情報は前のレースの時点の気象で、レース時点の K と時刻がずれる。観測時刻のある行（2,833組）は、補正後に K と全件一致する（second-opinion-reviewer の再計算）。このずれ（風速も同じ）は学習（K＝レース時点）と推論（DB）の間に残る

## 決めたこと
| 項目 | 決定 | 理由 |
|---|---|---|
| 回転の値 | 方位マークから決まる固定値（22.5° の倍数） | 推定値（円周平均）は時刻のずれのノイズで真値から最大約8°ずれ、補正後の角度が学習で見ない値（45° 刻みの外）になる |
| 会場の除外 | しない | 当初案の「尼崎を欠損」の根拠（風速3m以上の ±45° 一致率 0.686）は、丸めない平均で補正したための見かけの値。固定値では 0.888 |
| DB の風向が空・風速>0 | K の風向で埋める（本体の全期間、10,280 レース） | 2025-12・01 はほぼ全件が空（K/B の補完は風向を書かない）。他の月の空も K/B の補完で風速だけ入った行。K は方位なので回転しない |
| 置き場所 | `scripts/ml/analogy/wind_basis.json`（`offsets_deg`）。学習の版の `per_race_meta.json` の `wind_basis` に入れ、推論側の JS（`windOffsetFor`）が同じ表で直す | 表の出所を1つにする。表の無い版（2026-10-02 まで）は回転しない |

## 残る注意
- K で埋めたレースは推論では起きない（K は翌日以降）。test の指標が少し楽観側に寄る。一致検査の固定データからは外している
- 画面の直前情報タブの風向表示と、別のモデル（`scripts/ml/features.py`）の風向は、同じ取り違えのまま（別タスク）
- 方位マーク M が変わったら表を直す。`build-wind-basis.js` を実行すると、実データの最頻値との不一致で気づける

## 作り直し
```bash
node scripts/ml/analogy/build-wind-basis.js
```
DB は読み取りだけ。K は `scripts/maintenance/backfill-kb-gaps.js` と同じ解析済みアーカイブを読む。
