# ファンパネル: 2〜6号艇の1着の件数と、押して開く一覧をそろえるか（BOA-833）

ユーザーの判断（原文、2026-10-11）:「今の形で公開し、揃えるのは後ででよいが、そもそもボートレースファンにとって何が価値があるかは考えた？」

前提: 熱血ボートレースファン4人だけ。同じモデルのロールプレイなので結論は仮説。

## 前提の事実（議論とは別。本番 津5R 2026-10-11、全国・同じ組み合わせ、枠なり・どの形でも）

- STEP4 の1着の棒は、1号艇は「構成＋1号艇の級（A1）」の範囲、2〜6号艇は「構成＋その艇の級」の範囲で数えている（BOA-806、ユーザー決定）
  - 1号艇の範囲（NC:2-4-0-0:1A1）: 枠なり 1,852件、2号艇の1着 152件
  - 2号艇の範囲（NC:2-4-0-0:2A2、2号艇が A2 のレース）: 枠なり 1,986件、2号艇の1着 173件
- 棒の札は 173件、押して開く一覧（BOA-823）は1号艇の範囲から出すので 152件。画面は「一覧は1号艇の級でそろえたレースから出している（棒の件数とは集め方が違う）」の1行で断っている
- 3連単・着順の流れ・決まり手・万舟は1号艇の範囲で、一覧と件数が合っている
- 艇ごとの一覧を作る費用（実測からの見積もり）: 艇ごとの範囲は 10/11 で 1,025個。1範囲 25ms 前後の計算（10/10 の計測）＋アップロード 0.03秒／個（10/11 は 3,475個を約104秒）で、朝のバッチ **+約55秒**（10/11 は 579秒、タイムアウト 40分）。Storage は 1個 10〜39KB（gzip）で **+約20〜30MB／日**
- 今の scenario-races（1日 215個・約5MB）も、夜の掃除（verify-analogy-v16 --cleanup）の対象に入っていない。消さないと1年で数GB になる。過去のレースのページを開くと、その日のファイルを読む

## 論点1: 「2号艇が1着 173件 ›」を押したファンが見たいのはどのレースか

**30男**: 押したのは173件の数字。その173件を見たい。152件が出たら「どっちが本当？」になる。BOA-816 の「帯と3連単の数字が合わない」と同じ引っかかり。

**20男**: 2号艇が勝ったレースの実例が見たいのは、今日の2号艇（A2）が差せるかを確かめたいから。2号艇が A2 のレースでないと意味が薄い。1号艇の範囲の一覧だと、2号艇が A1 や B1 のレースも混ざる。

**20女**: 断りの1行は読まない。件数がそろっていれば断りも要らない。

**30女**: 1号艇の範囲の一覧に価値がある場面は、3連単・流れ図と同じレースを見たいとき（1-2-3 などの出目の一覧）。1着の棒の2〜6号艇だけは、棒と同じ範囲の一覧が正しい。

**結論**: 1着の棒の2〜6号艇を押したら、棒と同じ「その艇の級でそろえた範囲」の一覧を出す。件数が棒とそろい、断りの1行も消せる。3連単・流れ図・決まり手・万舟は今のまま（1号艇の範囲で、件数は合っている）。

## 論点2: 費用をどう見るか

**30女**: 朝のバッチが1分増えても、ファンは気づかない。締切に間に合うなら問題ない。

**20男**: 過去のレースのページで一覧が消えても困らない。見るのは今日のレース。古い日の一覧は消してよい。

**結論**: 艇ごとの一覧を作る（+約55秒・+20〜30MB／日）。合わせて、一覧のファイル（scenario-races と艇ごとの一覧）を夜の掃除の対象にして、一定の日数（例: 7日。similar と同じ）より前は消す。消えた日の一覧は「この日の一覧はもう無い」と出す。

## 推奨

案A: 艇ごとの一覧を作る（2〜6号艇の1着の棒を押したら、棒と同じ範囲の一覧）＋一覧のファイルを7日で消す
- 規模: バッチ（boat_scope の範囲で scope_races を書く。1行）・API（`races=1&boat=N`）・画面（2〜6号艇のときだけ艇の一覧を読む、断りの1行を消す）・夜の掃除（2フォルダを足す）・テスト。半日〜1日
- 朝のバッチ +約55秒、Storage は7日分で頭打ち（約 200〜250MB）

案B（今のまま）: 1号艇の範囲の一覧＋断りの1行。費用0だが、173件を押して152件が出る食い違いが残る

案C: 2〜6号艇の1着の棒は押せないようにする。食い違いは消えるが、「1号艇が飛んだレースの実例」という一番見たい所が無くなる
