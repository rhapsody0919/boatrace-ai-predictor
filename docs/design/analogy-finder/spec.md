## 位置づけ

### AI の定義
- 本機能の AI は3つの役割を持つ。①この条件で効いているデータとその大きさ（FR-1）、②過去の似た状況の検索と、その決着の分布（FR-2・FR-3）、③見る順番の整理
- 予想（結論・本命・買い目）を組み立てるのはユーザー（BOA-430 のステップ UI）。本機能はその材料を出す
- title・h1 の「AI予想」は残す（検索流入の86%が「AI」「予想」を含む）
- **サイト内の文言に「AI がやらないこと」のような言及は書かない**（2026-10-01 ユーザー指示）。既存の免責文はそのまま残し、新しい否定形の説明文は足さない

### 2段階の全体計画
1. **本 spec（BOA-271）**: FR-1〜FR-3 を、レース詳細の AI予想タブに**新しい節として追加**する。既存の展開予測・イン崩れ注意度・的中表示は残す（2026-10-01 ユーザー回答 Q1）
2. **次の spec「AI分析タブ全面改修」**（BOA-430 と合わせる）: 展開予測（確率付き上位3候補）を FR-2 の決まり手の比率に、イン崩れ注意度を「類似レースで1号艇が1着になれなかった率」＋1号艇の級別に置き換える。的中判定・的中率の表示（バッジ・RaceCard・/hit-races・ヘッダー「的中」・/races 日別・About 等の「約79%」・夜間バッチ）を撤去する。/accuracy を「AI の役割と限界」ページに作り直すことはしない

## 実装開始の前提条件（Phase U の着手条件）

ユーザー指示（2026-10-01）: 「寄与度の話は、全データを取得できていることを保証した上で実装開始したい」。

1. **データ取得の保証**: 2025-12 以降の本体テーブルの穴を K/B アーカイブで補完し終えていること。計画と完了判定はデータ取得レーンの `docs/design/scraping-vercel-consolidation/backfill-phase1-kb-2026-10.md`（PR #1037）に従う。判定基準は**月別×列の充足率 99% 以上**（2026-10-05 判定予定）。対象は MD-2 で「使う」とした列
2. **Phase M の合格**: MD-5 の合格条件を満たすモデルがあること（2026-10-01 に合格。残りは MD-6 の新しい重みでのやり直し）。満たさない場合は Phase U に進まず、ユーザーに報告する
3. **BOA-627 の完了**（FR-2 の本番表示の前まで）: as-of 特徴量と、表示した類似検索の結果を時点固定で保存できること。FR-1 は条件スライスの集計なのでこの条件を待たずに出せる
4. **pgvector の導入**（MD-6 で k-NN を採った場合のみ）: 本番 DB への `CREATE EXTENSION vector` 等はユーザーが実行する。書き込み SQL だけをまとめて渡し、確認の SELECT は読み取り MCP で Claude が実行する

## モデル設計（Phase M）

既存ワトソン（BOA-103、`scripts/ml/train_watson.py`）の SHAP を流用する前提はやめる。スクレイピング最適化の前に設計されたモデルで、今そろっているデータ（実進入・展示・直前情報・オッズ・体重等）を使っていないため（2026-10-01 ユーザー回答 Q3）。readiness-review の監査結果（単体テスト0件、過学習の兆候 train 60.2% / test 57.1%、gain と SHAP の不整合、CI の品質ゲート無し）は新モデルの設計要件として引き継ぐ。

### MD-1 予測対象
- **主モデル: 艇単位の着順モデル**（レース内の6艇を比べる。1着／2着以内／3着以内のそれぞれ）。FR-1 の寄与度（テーマ別の SHAP）と、FR-2 の距離の重み（k-NN を採る場合）の元になる
- **決まり手・1着の進入コース・出目はモデルで予測しない**。FR-2・FR-3 で類似レースの実績分布として数える。モデルは「何が効いているか」と「何を似ているとみなすか」を決める役割に限る
- 受入基準: 主モデルの対数損失（1着の6クラス）が MD-5 の基準を下回る


**結果（2026-10-01、[phase-m-result.md](./analysis/phase-m-result.md)）**: LightGBM（艇単位の二値、1着はレース内 softmax と温度合わせ）。2019-04〜2026-09 の完全レース 409,588R。拡張窓5分割（test 2022・2023・2024・2025-01〜12-02・2026-04〜09）すべてで基準1に有意に勝った（1着6クラスの対数損失の差 −0.118〜−0.127、CI はすべて0を大きく下回る。モデル 1.191〜1.210、基準1 1.313〜1.330）。train と test の差は 0.038〜0.068。2着以内・3着以内も基準に勝った（F4・F5）。**MD-5 は合格**
- データの穴（2025-12-03〜2026-03-31）は学習・評価から外し、選手の履歴の計算にだけ使った
- 妥協: マシン負荷のため各分割の学習は train の35%を無作為抽出。ハイパーパラメータは2候補×2分割だけ比較

### MD-3 オッズを材料にするかの検証
- **期間はオッズのある 2026-04 以降に限る**（時系列オッズは遡れない）
- 時点: 直前情報時点の as-of に最も近い、締切前の時系列オッズを使う（単勝オッズから求めた暗黙の確率）。締切時オッズ・発走後のオッズは使わない
- 比較: 同じ期間・同じ分割で、オッズ込み／抜きの両モデルを時系列ホールドアウトで比べる。指標は対数損失・Brier・キャリブレーション（10分位）。差はレース単位のペア差のブートストラップ95%CI
- 副作用の評価: オッズ込みのとき、FR-1 のテーマ別シェアで「市場」が他テーマの寄与をどれだけ吸うか（他テーマのシェアの変化）を出す
- 判定（事前に固定）: 込みモデルの対数損失がペア差 CI で有意に良く、かつ他テーマのシェアの順位が大きく崩れない場合に採る。シェアを吸いすぎる場合は、モデルには入れても FR-1 では「市場」を別枠で表示する案をモックで見せる。どちらにも当たらなければ材料にしない
- 受入基準: 判定結果と数字（期間・レース数・指標・CI・シェアの変化）を `docs/design/analogy-finder/analysis/` に残す


**結果: 今回は材料にしない（2026-10-01、再判定の予定あり）**
- 初回（[phase-m-result.md](./analysis/phase-m-result.md)）は「単勝が6艇そろうスナップショット」だけを使い、8,117R（test 4,383R）しか使えなかった。単勝の null は取得の欠落ではなく「その時点で票0」と判明した（BOA-650）ため、null を票0として扱ってやり直した（[md3-v2-result.md](./analysis/md3-v2-result.md)）
- v2: 25,757R（test 13,626R）。時点の中央値は締切12.6分前。票0の艇がいるレースは68.5%
- 事前に決めた比較（2026-04 以降で一から学習、時系列3分割）: 対数損失の差（込み−抜き）−0.00255 [−0.00520, +0.00012]。**CI が0をわずかにまたぐので、ルールどおり材料にしない**。レース単位の差の SD が大きく（0.162）、検出には test 約3.2万R（今の取れ方で約7か月）が要る
- 参考の比較（MD-4 と同じ、主モデル F5 のスコアを土台にした条件付きロジット）: −0.00266 [−0.00352, −0.00173] で有意。票0の艇がいるレースでも同じ大きさ。ε（票0の艇に置く確率）を変えても結論は変わらない
- 込みのときの「市場」シェアは .118。他テーマの順位は変わらない（Kendall τ=1.0）ので、「モデルに入れて市場は別枠表示」の案には当たらない
- 締切に近いほど上積みが大きい（締切0〜60分前で最も近い時点＝中央値4.3分前を使うと、事前比較で −0.00597 [−0.00959, −0.00251]）。ただし直前情報時点の as-of より後になる
- **再判定（結果を見た後で方式を変えないため、ここで固定する）**: 2026-10-02 以降の、まだ使っていないレースだけを test にして、参考の比較（条件付きロジット、ε=0.001、時点は締切10〜60分前で最も近いもの）で判定する。必要な test は約6,100R。判定ルールは同じ（CI 上限<0 なら採る）。採った場合は FR-1 に「市場」を7番目のテーマとして足す。再判定は Phase U の着手を待たせない（必要な test がそろうのは2026-11中旬の見込み）。Phase U は6テーマで始め、採れたら後から足す
- FR-1 は当面6テーマ（「市場」なし）。上の再判定で採れば7テーマにする

### MD-4 遡って取れる未定項目の取る／取らない判定
対象: F/L 数・登録体重・支部（racelist 約4.3万リクエスト）、展示 ST（約15,240リクエスト）、展示進入、オリジナル展示、ピットレポート、公式コンピュータ予想（約2.7万リクエスト）、3連率・気温・水温（補完後の期間のみ）。
- 方法: 各項目がそろっている期間（2026-09-21 以降など）で、入れた／入れないのモデルを時系列ホールドアウトで比べる（対数損失・Brier、ペア差 CI）
- 取得コストに見合う上積みかを、リクエスト数と改善幅で並べて「取る／取らない」と理由を書く
- サンプルが小さく判定できない項目は、その旨と、検出に必要なレース数・期間（検出力の計算）を書く
- 受入基準: 全項目に「取る／取らない／判定不能（必要期間）」のいずれかが付いている


**結果**（主モデルのスコアを土台にした条件付きロジット、艇番の切片あり、日単位の連続ブロック5分割。取る＝CI 上限<0、取らない＝CI 下限>−0.001）:

### MD-5 合格条件（予想なしの単純な基準に勝つこと）
- 基準1（1着艇）: 会場×1号艇の級別の過去の1着艇分布
- 基準2（決まり手）: 会場×1号艇の級別の過去の決まり手分布
- 主モデルは基準1に、FR-2 の方式（MD-6）は基準2に、それぞれ対数損失のペア差 CI で有意に勝つこと。勝てない場合は Phase U に進まずユーザーに報告する
- 過学習の確認: 単一分割でなく、時系列の複数分割（拡張窓）で train と test の差を出す

### MD-6 FR-2 の類似度の方式
- 層別（会場×1号艇の級別×風×グレード、少数の層は親へバックオフまたは Dirichlet 平滑化）と、主モデルの SHAP 重みの k-NN を、時系列ホールドアウトで比べる（決まり手の対数損失・Brier、1着艇・1着の進入コースは参考）
- 判定（事前に固定）: k-NN が層別に対し、決まり手の対数損失でペア差 CI が0をまたがず改善した場合だけ k-NN を採る。それ以外は層別を採る
- 予備結果（ワトソン型の重み、2025-12-02〜2026-10-01 の 46,770R、test 2026-08-01〜10-01 の 9,584R。詳細は [fr2-holdout-result.md](./analysis/fr2-holdout-result.md)）: 事前のルールでは **k-NN の勝ち**。決まり手の対数損失のペア差は k-NN−層別（階層 Dirichlet）が −0.0203 [−0.0257, −0.0147]、事後に足した最良の層別（1号艇の級別を先に置く階層）に対しても −0.0137 [−0.0191, −0.0087]。2026-03 以降に絞った感度分析でも同じ向き。1着艇・1着の進入コースでは差がさらに大きい（−0.094、−0.066）
- ただし予備結果には次の留保があり、新しい主モデルでやり直すときに確かめる
  - 近傍が揃っているのは実質「6艇の勝率の並び」だけ。会場の一致率は 4.8%（ランダム 4.2%）、機力・展示・気象はランダムと同程度。「6テーマで似ている」と画面で説明できる状態ではない
  - 同一会場に限った k-NN は、決まり手では層別と差が無い（−0.0005 [−0.0055, +0.0045]）
  - 決まり手では SHAP 重みと等重みの差が有意でない（本番プール）。1着艇・進入コースでは SHAP 重みが有意に良い
  - k は格子の上限 400 で選ばれた（400 超は未検証）。LambdaRank の early stopping が不安定で、重みの学習し直しで近傍の約2〜3割が入れ替わる（Jaccard 平均 0.72〜0.78）。木の数を固定しても精度は同等なので固定する
  - 層は細かく割るほど悪くなる（1号艇の級別だけの層が、会場×級別×風×グレードより良い）
- 画面の説明と近傍の実態を合わせるため、新しい主モデルでは「会場を揃える制約を入れた k-NN」と「近傍の何が今日と似ているかを出す表示」も比較対象に入れる
- 層別を採った場合、pgvector は導入しない。FR-2 の画面は「類似度スライダー」ではなく「条件の足し引き」になる（screens で両方の形を用意する）

### MD-7 パイプラインの品質
- 特徴量の時系列リーク防止（`shift(1)` 等、as-of の段）を単体テストで固定する
- 週次の再学習に品質ゲートを置く（前回モデルとの指標比較。悪化時は差し替えない）
- SHAP（`pred_contrib`）の集計結果をモデル版つきで永続化する。gain は表示に使わない
- 時系列 CV での最低限のハイパーパラメータ調整は含める

## 機能要件（Phase U）

### FR-1 寄与度（優先度: 高）
- 条件スライス（会場・グレード・ラウンド）ごとに、主モデルの SHAP をテーマ単位で合算し、**テーマ別の寄与の大きさを相対シェアで見せる**。レーダーとテーマ別の棒の両方を出す（2026-10-01 モック v6 のユーザー回答）
- シェア = スライス内の艇の平均 |SHAP| をテーマごとに合算し、全テーマ合計で割った値
- **レースや艇の総合点（0〜100 の「AI指数」等）にはまとめない**。出すのはテーマ間の相対的な大きさだけ
- テーマ: 6テーマ（会場×枠・進入／選手・基礎成績／ST・直前情報／機力／環境／選手・属性）。「市場」は MD-3 の判定で今は外し、2026-10-02 以降のデータで再判定する
- **テーマ数は可変にする**: テーマの一覧（名前・説明・含む特徴量）はモデルの集計結果と一緒に保存し、画面はその一覧から描く（レーダーの軸数・棒の本数・比較表の行数を固定しない）。「市場」を後から7番目として足しても画面のコードを変えずに済むようにする
- 実測のシェア（F5 test 2026-04〜09、1着）: 会場×枠 .345／基礎成績 .380／ST・直前 .142／機力 .051／環境 .027／属性 .056。上位グレード・準優勝戦・優勝戦ほど会場×枠が増え基礎成績が減る（例: 優勝戦 .375／.339）。旧ワトソンの「SG で会場×枠 89.5%」ほどの偏りは無い
- 安定性: seed を変えた5回の再学習で各テーマの SD は 0.002〜0.004、上位3テーマの順位は不変。4位と5位（機力・属性）は5回中2回入れ替わるので、画面では「1〜3位の順位」と「おおよその割合」に意味を持たせ、差が SD の数倍に満たない隣どうしの順位を強調しない
- 着順タブ（1着／2着以内／3着以内）でプロファイルを切り替える（それぞれ別に集計した周辺の値）
- グレード（一般／G3／G2／G1／SG）×ラウンド（予選／準優勝戦／優勝戦／その他）のフィルタ。ラウンドは `getRaceStageCategory`（`src/constants/raceStageConfig.js`）の分類を4区分にまとめる
- 艇番比較（v5 どおり）: 任意の2艇番のプロファイルを重ねる。チャートに数値ラベルは置かず、比較表（テーマ／艇番A／艇番B）で数値を出す
- テーマを押すと個別項目の内訳が開く。似た意味の項目（勝率・2連率・3連率等）はまとめて表示し、個別値は参考である旨を書く（多重共線性）
- n（艇数・レース数）・集計期間・モデル版を常に表示する。n<30 は「小標本」フラグ
- 受入基準: 着順・グレード・ラウンドの切り替えでシェアと n が変わる。総合点の表示が無い。艇番比較の比較表に両艇番の値が並ぶ。テーマを押すと内訳が開く

### FR-2 類似レース（優先度: 高）
- 今日のレースに似た過去レースを集め、その決着の分布を出す。方式は MD-6 の結果で決める
- 出す分布: **決まり手（6分類）・1着艇・1着の進入コース・頻出出目トップ3**。それぞれ n と期間を添える
- **階級ラベル（🔥鉄板級／📌有力／⚖️混戦／🌊大混戦／🌀まだ参考程度）は撤回**し、n と分布の表示にする（言い切りを避ける）
- k-NN の場合: 類似度しきい値スライダー（65〜95%）とソナー画面（中心＝今日、同心円＝類似度、6扇形＝艇番、光点＝過去レース1件、色は艇の公式色）。しきい値を上げると自動でズームする
- 層別の場合: 条件チップ（会場・1号艇の級別・風・グレード）の付け外しで絞り込む
- 光点（または一覧行）と類似レース一覧は双方向にハイライト連動する
- 常設の注記: 「類似の判定には事故情報を含まない」（BOA-279 解消まで）。進入コースの注記は削除
- 表示した結果（モデル版・重み・近傍のレース一覧・算出時刻）は BOA-627 のスナップショットとして保存し、同じレースでは発走前の時点の結果を出す（週次の再学習で近傍が変わっても見せたものを再現できる）
- 受入基準: しきい値（または条件）の変更で件数・分布・n が連動する。階級ラベルが無い。光点と一覧行のクリックが相互にハイライトする

### FR-3 組み合わせ構造（優先度: 高）
2026-10-01 ユーザー回答 Q2「モックのようなサンキー図も作って欲しい。一目でわかる」により範囲に戻した。n が小さい問題は見せ方で解く。
- データは FR-2 と同じ類似レースの集合（しきい値・条件を共有）
- サンキー図: **1着→2着→3着の3段を常に出す**（2026-10-01 ユーザー回答「件数が少なくても全て出してほしい」）。件数が少ないことは隠さず n で伝える（図の下に全体の n、帯タップで各流れの件数）。少ない流れも「その他」にまとめず、艇の公式色のまま薄く描く（3着の段で情報を消さないため）。帯の太さ＝件数、1号艇の白は枠線で背景から区別する
- 帯をタップすると「1-3 xx件・xx%」を出す
- 帯が細すぎてタップしにくい流れは、組み合わせ一覧（下）でも件数を確認できる
- 1号艇が1着の帯が太すぎて他が読めない場合に備え、「1号艇以外が1着のレースだけ」に切り替えられる
- 組み合わせ別の発生率一覧（上位10件、組み合わせ・シェア%・n）
- 干渉効果のコールアウト（例: 4〜6コースのまくりが決まったレースで1〜3号艇が2着に残った割合と、まくりが絡まなかった場合の対比）。艇番ではなく**進入コース**で数える。n が基準未満なら出さない
- 受入基準: 帯の太さが件数に比例する。3段が常に出る。全ての流れが艇の色で描かれ、タップで件数が出る。一覧のシェアの合計が100%に近い（丸め誤差を除く）。コールアウトの数値が実データの集計と一致する

### FR-4（分離）
FR-4（答え合わせ）は [BOA-635](https://linear.app/boat-ai/issue/BOA-635)（予想の過去発生率チェック）に分離した（2026-10-01 ユーザー回答）。

## ファン4人パネル（FR-3 のサンキー図、2026-10-01）
同じモデルのロールプレイなので仮説。正面からの反対は無し。懸念は4件で、FR-3 の要件に反映した。
- 3着の段が出ないレースが多いと3連単派には物足りない → 3段を常に出す（ユーザー回答でも同じ判断）
- 1号艇の白い帯が背景に溶ける、細い帯をタップしにくい → 白に枠線、帯タップで件数・%
- 艇番の流れだけでは 3-4（まくり）と 3-1（まくり差し）の違いが分からない、実戦では一覧の数字を見る → 一覧を併置、決まり手での色分け・絞り込みは screens で検討
- 1号艇の逃げが半分を超える会場では他の流れが細すぎて読めない → 「1号艇以外が1着」への切り替え
