## 位置づけ

### AI の定義
- 本機能の AI は3つの役割を持つ。①この条件で効いているデータとその大きさ（FR-1）、②過去の似た状況の検索と、その決着の分布（FR-2・FR-3）、③見る順番の整理
- 予想（結論・本命・買い目）を組み立てるのはユーザー（BOA-430 のステップ UI）。本機能はその材料を出す
- title・h1 の「AI予想」は残す（検索流入の86%が「AI」「予想」を含む）
- **サイト内の文言に「AI がやらないこと」のような言及は書かない**（2026-10-01 ユーザー指示）。既存の免責文はそのまま残し、新しい否定形の説明文は足さない

### 2段階の全体計画
1. **本 spec（BOA-271）**: FR-1〜FR-3 を、レース詳細の AI予想タブに**新しい節として追加**する。既存の展開予測・イン崩れ注意度・的中表示は残す（2026-10-01 ユーザー回答 Q1）
2. **次の spec「AI分析タブ全面改修」**（BOA-430 と合わせる）: 展開予測（確率付き上位3候補）を FR-2 の決まり手の比率に、イン崩れ注意度を「類似レースで1号艇が1着になれなかった率」＋1号艇の級別に置き換える。的中判定・的中率の表示（バッジ・RaceCard・/hit-races・ヘッダー「的中」・/races 日別・About 等の「約79%」・夜間バッチ）を撤去する。/accuracy を「AI の役割と限界」ページに作り直すことはしない

## 実装開始の前提条件（Phase U の着手条件）

ユーザー指示（2026-10-01）: 「寄与度の話は、全データを取得できていることを保証した上で実装開始したい」。

1. **データ取得の保証**: 2025-12 以降の本体テーブルの穴を K/B アーカイブで補完し終えていること。計画と完了判定はデータ取得レーンの `docs/design/scraping-vercel-consolidation/backfill-phase1-kb-2026-10.md`（PR #1037）に従う。判定基準は**月別×列の充足率 99% 以上**（2026-10-05 判定予定）。対象は MD-2 で「使う」とした列。2026-04〜09 の展示タイム（1,193レース）と気象（1,029レース）の欠けは、設計レビュー（2026-10-01）で見つかり、データ取得レーンが補完計画に足した。K に無い会場日は例外としてユーザーの承認を得る（例外は承認済み一覧に載せる）。近傍の距離（FR-2）はこの2列を使わないので、FR-2 はこの判定を待たない
2. **Phase M の合格**: MD-5 の合格条件を満たすモデルがあること（2026-10-01 に合格。残りは MD-6 の新しい重みでのやり直し）。満たさない場合は Phase U に進まず、ユーザーに報告する
3. **BOA-627 の完了**（FR-2 の本番表示の前まで）: as-of 特徴量と、表示した類似検索の結果を時点固定で保存できること。FR-1 は条件スライスの集計なのでこの条件を待たずに出せる
4. ~~pgvector の導入~~: 不要になった（FR-2 は層別で、条件の列を持つ母集団を SQL で数える。[ADR-0082](../../adr/0082-analogy-strata-counted-in-sql.md)）。本番 DB で要る書き込みは、マイグレーション 118（FR-1、適用済み）・120（FR-2）の適用と、120 の母集団の初回投入。SQL はユーザーが実行する

## モデル設計（Phase M）

既存ワトソン（BOA-103、`scripts/ml/train_watson.py`）の SHAP を流用する前提はやめる。スクレイピング最適化の前に設計されたモデルで、今そろっているデータ（実進入・展示・直前情報・オッズ・体重等）を使っていないため（2026-10-01 ユーザー回答 Q3）。readiness-review の監査結果（単体テスト0件、過学習の兆候 train 60.2% / test 57.1%、gain と SHAP の不整合、CI の品質ゲート無し）は新モデルの設計要件として引き継ぐ。

### MD-1 予測対象
- **主モデル: 艇単位の着順モデル**（レース内の6艇を比べる。1着／2着以内／3着以内のそれぞれ）。FR-1 の寄与度（テーマ別の SHAP）と、FR-2 の距離の重み（k-NN を採る場合）の元になる
- **決まり手・1着の進入コース・出目はモデルで予測しない**。FR-2・FR-3 で類似レースの実績分布として数える。モデルは「何が効いているか」と「何を似ているとみなすか」を決める役割に限る
- 受入基準: 主モデルの対数損失（1着の6クラス）が MD-5 の基準を下回る


**結果（2026-10-01、[phase-m-result.md](./analysis/phase-m-result.md)）**: LightGBM（艇単位の二値、1着はレース内 softmax と温度合わせ）。2019-04〜2026-09 の完全レース 409,588R。拡張窓5分割（test 2022・2023・2024・2025-01〜12-02・2026-04〜09）すべてで基準1に有意に勝った（1着6クラスの対数損失の差 −0.118〜−0.127、CI はすべて0を大きく下回る。モデル 1.191〜1.210、基準1 1.313〜1.330）。train と test の差は 0.038〜0.068。2着以内・3着以内も基準に勝った（F4・F5）。**MD-5 は合格**
- データの穴（2025-12-03〜2026-03-31）は学習・評価から外し、選手の履歴の計算にだけ使った
- 妥協: マシン負荷のため各分割の学習は train の35%を無作為抽出。ハイパーパラメータは2候補×2分割だけ比較

### MD-3 オッズを材料にするかの検証
- **期間はオッズのある 2026-04 以降に限る**（時系列オッズは遡れない）
- 時点: 直前情報時点の as-of に最も近い、締切前の時系列オッズを使う（単勝オッズから求めた暗黙の確率）。締切時オッズ・発走後のオッズは使わない
- 比較: 同じ期間・同じ分割で、オッズ込み／抜きの両モデルを時系列ホールドアウトで比べる。指標は対数損失・Brier・キャリブレーション（10分位）。差はレース単位のペア差のブートストラップ95%CI
- 副作用の評価: オッズ込みのとき、FR-1 のテーマ別シェアで「市場」が他テーマの寄与をどれだけ吸うか（他テーマのシェアの変化）を出す
- 判定（事前に固定）: 込みモデルの対数損失がペア差 CI で有意に良く、かつ他テーマのシェアの順位が大きく崩れない場合に採る。シェアを吸いすぎる場合は、モデルには入れても FR-1 では「市場」を別枠で表示する案をモックで見せる。どちらにも当たらなければ材料にしない
- 受入基準: 判定結果と数字（期間・レース数・指標・CI・シェアの変化）を `docs/design/analogy-finder/analysis/` に残す


**結果: 今回は材料にしない（2026-10-01、再判定の予定あり）**
- 初回（[phase-m-result.md](./analysis/phase-m-result.md)）は「単勝が6艇そろうスナップショット」だけを使い、8,117R（test 4,383R）しか使えなかった。単勝の null は取得の欠落ではなく「その時点で票0」と判明した（BOA-650）ため、null を票0として扱ってやり直した（[md3-v2-result.md](./analysis/md3-v2-result.md)）
- v2: 25,757R（test 13,626R）。時点の中央値は締切12.6分前。票0の艇がいるレースは68.5%
- 事前に決めた比較（2026-04 以降で一から学習、時系列3分割）: 対数損失の差（込み−抜き）−0.00255 [−0.00520, +0.00012]。**CI が0をわずかにまたぐので、ルールどおり材料にしない**。レース単位の差の SD が大きく（0.162）、検出には test 約3.2万R（今の取れ方で約7か月）が要る
- 参考の比較（MD-4 と同じ、主モデル F5 のスコアを土台にした条件付きロジット）: −0.00266 [−0.00352, −0.00173] で有意。票0の艇がいるレースでも同じ大きさ。ε（票0の艇に置く確率）を変えても結論は変わらない
- 込みのときの「市場」シェアは .118。他テーマの順位は変わらない（Kendall τ=1.0）ので、「モデルに入れて市場は別枠表示」の案には当たらない
- 締切に近いほど上積みが大きい（締切0〜60分前で最も近い時点＝中央値4.3分前を使うと、事前比較で −0.00597 [−0.00959, −0.00251]）。ただし直前情報時点の as-of より後になる
- **再判定（結果を見た後で方式を変えないため、ここで固定する）**: 2026-10-02 以降の、まだ使っていないレースだけを test にして、参考の比較（条件付きロジット、ε=0.001、時点は締切10〜60分前で最も近いもの）で判定する。必要な test は約6,100R。判定ルールは同じ（CI 上限<0 なら採る）。採った場合は FR-1 に「市場」を7番目のテーマとして足す。再判定は Phase U の着手を待たせない（必要な test がそろうのは2026-11中旬の見込み）。Phase U は6テーマで始め、採れたら後から足す
- FR-1 は当面6テーマ（「市場」なし）。上の再判定で採れば7テーマにする

### MD-4 遡って取れる未定項目の取る／取らない判定
対象: F/L 数・登録体重・支部（racelist 約4.3万リクエスト）、展示 ST（約15,240リクエスト）、展示進入、オリジナル展示、ピットレポート、公式コンピュータ予想（約2.7万リクエスト）、3連率・気温・水温（補完後の期間のみ）。
- 方法: 各項目がそろっている期間（2026-09-21 以降など）で、入れた／入れないのモデルを時系列ホールドアウトで比べる（対数損失・Brier、ペア差 CI）
- 取得コストに見合う上積みかを、リクエスト数と改善幅で並べて「取る／取らない」と理由を書く
- サンプルが小さく判定できない項目は、その旨と、検出に必要なレース数・期間（検出力の計算）を書く
- 受入基準: 全項目に「取る／取らない／判定不能（必要期間）」のいずれかが付いている


**結果**（主モデルのスコアを土台にした条件付きロジット、艇番の切片あり、日単位の連続ブロック5分割。取る＝CI 上限<0、取らない＝CI 下限>−0.001）:

### MD-5 合格条件（予想なしの単純な基準に勝つこと）
- 基準1（1着艇）: 会場×1号艇の級別の過去の1着艇分布
- 基準2（決まり手）: 会場×1号艇の級別の過去の決まり手分布
- 主モデルは基準1に、FR-2 の方式（MD-6）は基準2に、それぞれ対数損失のペア差 CI で有意に勝つこと。勝てない場合は Phase U に進まずユーザーに報告する
- 過学習の確認: 単一分割でなく、時系列の複数分割（拡張窓）で train と test の差を出す

### MD-6 FR-2 の類似度の方式

> **決定（2026-10-02 ユーザー）: FR-2 は層別 S* で作る。以下の k-NN（knn_p）の結果は経緯として残す。**
> - 経緯: ユーザーの意向（「似ている理由を言葉にできることが主役、類似度の%は補足」「同じような条件の過去レースはありそう」「作り込みが最も大事」）を受け、類似の定義を比べ直した。独立エージェントの比較で最良だった候補⑨（条件で完全一致に絞り、F5 の1着予測分布 P が近い順に1,600件）に、批判的レビューで「展示に依存」「循環（近傍の逃げ% ≒ AI 予測の較正値）」「F5 の学習リーク」「test で軸を選んだ」が指摘された
> - 追加検証 A〜E（AI分析レーン、事前登録あり、縮小版 test 2,003R・cal 2,005R、日×会場クラスタ CI）:

### FR-1 寄与度（優先度: 高）
- 条件スライス（会場・グレード・ラウンド）ごとに、主モデルの SHAP をテーマ単位で合算し、**テーマ別の寄与の大きさを相対シェアで見せる**。レーダーとテーマ別の棒の両方を出す（2026-10-01 モック v6 のユーザー回答）

- テーマ: 6テーマ（会場×枠・進入／選手・基礎成績／ST・直前情報／機力／環境／選手・属性）。「市場」は MD-3 の判定で今は外し、2026-10-02 以降のデータで再判定する

- 着順タブ（1着／2着以内／3着以内）でプロファイルを切り替える（それぞれ別に集計した周辺の値）
- グレード（一般／G3／G2／G1／SG）×ラウンド（予選／準優勝戦／優勝戦／その他）のフィルタ。ラウンドは `getRaceStageCategory`（`src/constants/raceStageConfig.js`）の分類を4区分にまとめる

### FR-2 類似レース（優先度: 高）
**方式: 層別 S*（2026-10-02 ユーザー決定）**。今日のレースと「出走表時点で言葉にできる条件」がすべて同じ過去レースを集め、その決着の分布を出す。AI の予測は AI予想の欄で今までどおり出し、類似レースとは混ぜない（AI の予測を過去の決着で較正した値を別枠で出す案は、今回は作らない）。

- **条件（S* の軸）: 1号艇と他艇の勝率差5帯（境界 −1.91／−1.14／−0.49／+0.19）→ 1号艇の級別 → 会場 → 勝率1位の艇**（2026-10-02 全件で確定、[fr2-strat-result.md](./analysis/fr2-strat-result.md)）。事前登録した11候補から cal の決まり手 LL で前向きに選んだ4軸（α=1000）。4軸目は会場と「1号艇の平均ST順位帯」が僅差で、手順どおり会場を採った。test で会場×1号艇級別に決まり手の LL で −0.0122 [−0.0142, −0.0102] 勝つ。展示・気象・オッズは条件に使わない（出走表時点）
- **件数と戻し方**: 4条件すべて同じ層の件数は中央値311（test）、200件未満が29.5%、0件は無し。**200件未満なら末尾の条件から1つずつ外して親の層を使う**（m=200、cal で選択）。割合は平滑化せず件数÷n で出し、30件未満も出す（2026-10-02 ユーザー回答 Q5。分析で選んだ α'=50 の平滑化は画面では使わない）。表示する層は、4条件のまま 70.5%、「勝率1位の艇」を外す 27.2%、「会場」も外す 2.3%。使う層の件数は中央値545。戻さない階層の推定との精度差は有意でない。画面には、使った条件・外した条件・件数を必ず出す
- **似ている理由の文面（主役）**: 条件そのものを文にし、件数を添える。ルール:
  1. 主語は「今日のレース」ではなく条件: 「1号艇がA1級、勝率差が＋0.2〜1.1、大村、勝率1位が1号艇 ── この4つがすべて同じ過去レース 312件」
  2. 数値の条件は、帯の範囲をそのまま書く（「勝率差が大きい」のような言い換えをしない）。帯の名前を付ける場合も範囲を併記する
  3. 外した条件があれば、外したことと理由を書く: 「同じ条件では 41件と少ないため、『勝率1位の艇』を外して 286件で見ています」
  4. 件数は常に出す。%は補足（分布の中で出す）で、見出しには出さない
  5. 条件にない項目について「似ている」とは言わない（機力・展示・気象など。縮小版の検証で、条件の外に系統的に似ている項目は無かった）
  6. 「AI」「類似度○%」「ほぼ同じ」といった言い方をしない
- 出す分布: **決まり手（6分類）・1着艇・1着の進入コース・頻出出目トップ3**。それぞれ n と期間を添える
- **階級ラベル（🔥鉄板級／📌有力／⚖️混戦／🌊大混戦／🌀まだ参考程度）は撤回**し、n と分布の表示にする（言い切りを避ける）
- **ほかのテーマでも絞る（2026-10-02 ユーザー承認、screens.md Q6）**: 4条件の層の上に、ラウンド（予選／準優勝戦／優勝戦／その他）・グレード（一般／G3／G2／G1／SG）・1号艇のモーター順位帯（6艇のモーター2連率で1〜2位／3〜4位／5〜6位）を任意で重ねられる。値は今日のレースと同じものだけ。足す前に「足すと N件」を予告する。自動の深さの選び方には使わない（検証したのは4条件だけ）ので、足した層は探索用でスナップショットに入れない。今日のレースの値が分からない条件は出さない。0件になる条件は押せない。割合は4条件と同じく件数÷n（30件未満も出す）。ST（1号艇の平均ST順位帯）は後回し（過去30走の集計が要る）
  - 文面: 理由の一文に「さらに『ラウンド: 予選』で絞って N件」を足す。足した条件は検証していないことを、チップの近くに1行で書く（「この条件は自動では使っていません」）。ルール5（条件にない項目について似ているとは言わない）は、足した条件を条件として扱う
- 条件の付け外し: 条件はチップで示し、外すと親の層に広がる（件数が増える）。v6 の件数スライダー（近い順に N 件）とソナー（同心円＝近さの順位）は、層別には距離の順位が無いので作り直す。ソナーを残すなら「中心＝全条件が一致、外の輪＝一致する条件が少ない」の形を候補にし、新しいセッションでモックを作ってユーザーに確かめる
- 類似レース一覧は、同じ層の過去レース（新しい順）。光点・一覧行の双方向ハイライトは、ソナーを残す場合に限る
- 常設の注記: 「類似の判定には事故情報を含まない」（BOA-279 解消まで）
- 表示した結果は BOA-627 のスナップショットとして保存し、同じレースでは発走前の時点の結果を出す（保存するのは、条件の値・自動で選んだ深さ・深さごとの件数・母集団の期間・自動の深さの分布。チップで深さを変えた表示は探索用で、保存した母集団の最終日以前で数え直す。ADR-0082）
- 受入基準: 条件の付け外しで件数・分布・n が連動する。使った条件・外した条件・件数が常に出る。階級ラベルと「類似度○%」が無い

**訂正（2026-10-02）**: この節の以前の版と MD-6 で「一番近い過去レースでも類似度は6割前後で、ほぼ同じ過去レースは無い」と書いたのは誤りだった。これは全次元の重み付き距離という1つの尺度での話にすぎない。出走表時点で言葉にできる少数の条件に絞れば、すべて同じ過去レースは多数ある（縮小版で最細層の中央値約300件、0件の層は無し）。ユーザーの「同じような条件の過去レースはありそう」という見立てが正しかった。

### FR-3 組み合わせ構造（優先度: 高）
2026-10-01 ユーザー回答 Q2「モックのようなサンキー図も作って欲しい。一目でわかる」により範囲に戻した。n が小さい問題は見せ方で解く。
- データは FR-2 と同じ類似レースの集合（しきい値・条件を共有）
- サンキー図: **1着→2着→3着の3段を常に出す**（2026-10-01 ユーザー回答「件数が少なくても全て出してほしい」）。件数が少ないことは隠さず n で伝える（図の下に全体の n、帯タップで各流れの件数）。少ない流れも「その他」にまとめず、艇の公式色のまま薄く描く（3着の段で情報を消さないため）。帯の太さ＝件数、1号艇の白は枠線で背景から区別する
- 帯をタップすると「1-3 xx件・xx%」を出す
- 帯が細すぎてタップしにくい流れは、組み合わせ一覧（下）でも件数を確認できる
- 1号艇が1着の帯が太すぎて他が読めない場合に備え、「1号艇以外が1着のレースだけ」に切り替えられる
- 組み合わせ別の発生率一覧（上位10件と「その他」の1行、組み合わせ・シェア%・n。合計100%）
- 干渉効果のコールアウト（例: 4〜6コースのまくりが決まったレースで1〜3号艇が2着に残った割合と、まくりが絡まなかった場合の対比）。艇番ではなく**進入コース**で数える。n が基準未満なら出さない
- 受入基準: 帯の太さが件数に比例する。3段が常に出る。全ての流れが艇の色で描かれ、タップで件数が出る。一覧のシェアの合計が100%に近い（丸め誤差を除く）。コールアウトの数値が実データの集計と一致する

## ファン4人パネル（FR-3 のサンキー図、2026-10-01）
同じモデルのロールプレイなので仮説。正面からの反対は無し。懸念は4件で、FR-3 の要件に反映した。
- 3着の段が出ないレースが多いと3連単派には物足りない → 3段を常に出す（ユーザー回答でも同じ判断）
- 1号艇の白い帯が背景に溶ける、細い帯をタップしにくい → 白に枠線、帯タップで件数・%
- 艇番の流れだけでは 3-4（まくり）と 3-1（まくり差し）の違いが分からない、実戦では一覧の数字を見る → 一覧を併置、決まり手での色分け・絞り込みは screens で検討
- 1号艇の逃げが半分を超える会場では他の流れが細すぎて読めない → 「1号艇以外が1着」への切り替え

## ファン4人パネル（FR-2 の条件、2026-10-02）
ユーザーの「もっといろんな条件があるはず」を受けて議論した。同じモデルのロールプレイなので仮説。前提として、出走表時点（展示・気象・オッズは使えない）と、5軸目は精度の基準を超えなかったこと（[fr2-strat-result.md](./analysis/fr2-strat-result.md) 4）を伝えた。
- ①思い浮かべる条件（4条件の外）: モーター（4人中3人）、1号艇のST（3人）、グレード・ラウンド（予選と準優・優勝戦は別物。2人）、進入の傾向（前付けする選手がいるか。1人）、当地勝率（1人）、同じ選手が1号艇（1人）。モーター・ST・グレード・ラウンドは候補11軸に入っていて、精度の基準には届かなかった。進入の傾向・当地勝率・選手本人は候補の外
- ②自動か任意か: 割れた。20代男性・30代女性は「自分で足したい」。20代女性・30代男性は「最初は4条件で十分。足すのは折りたたみの奥でいい」。**4人とも、自動の4条件を増やすことには反対しなかった**が、任意で足せることには3人が賛成した
- ③件数の見せ方: 足す前に「足すと 42件」と件数を予告する（4人とも賛成）。200件未満は注意の一文、30件未満は%を出さず件数と一覧だけにする（30代男性の案、反対なし）
- 統合した結論（仮説）: 自動の条件は検証した4条件のまま。その下に「条件を足す」を置き、ラウンド・モーター・ST・グレードを任意で足せるようにする（足した層は検証していないので、件数を予告し、少ないときは%を出さない）。採るかはユーザーが決める（足す場合は母集団の列とモックの追加が要る）

## ユーザー回答（2026-10-02、オーケストレーター経由）
- 件数が30件未満でも%を出す（「出した方が価値が上がる」）。件数は常に添える。少ないときの注意の一文は残してよい（上のファンパネルの「30件未満は%を出さない」は採らない）
- FR-1（寄与度）と FR-2（類似レース）を一貫した体験にする。「寄与度で何が効いているかを見る → 効いている要素で似ている過去レースの結果を見る」流れ。Q1〜5 はこの設計と一緒に決める

### データの裏付け（[fr2-strat-result.md](./analysis/fr2-strat-result.md) 5）
- 言えること: 自動の4条件は、すべて寄与度の上位2テーマに入っている（2つの独立した方法が同じテーマを指す）
- 言えないこと: 「このレースで効いている要素でそろえた」「寄与度の高い順に条件を足すと当てはまりが良くなる」。寄与度のシェアはスライスでほとんど変わらず、3位以下は寄与度の順と当てはまりの順が一致しない。会場単位の相関も有意でない

### 混ぜない線（循環にしないための約束）
- 寄与度は、同じ条件（会場・グレード・ラウンド）のレース全体についての、AI のモデルの説明。このレース1件ごとのものではない
- 類似レースの件数と割合は、過去の実際の結果だけから数える。モデルの予測で、条件を選んだり、並べ替えたり、重みを付けたりしない
- 寄与度は、類似レースの見出し・チップの色・並び順にだけ使う
- 「AI」と書くのは寄与度の欄だけ。似ている理由の一文には書かない（文面ルール6）

### ファン4人パネル（3案、2026-10-02。仮説）
- 20代男性: 案2。「効いているものを見てから絞る」流れが分かりやすく、ST で絞れるのが面白い。案3 はテーマごとに数万件になり、意味が薄い
- 20代女性: 案2 の番号つきの流れが一番分かる。案1 は寄与度の下の文字が多くて読まない。「AI の説明」と「実際の結果」の区別が見出しで分かるとよい
- 30代男性: 案2。ただし寄与度は1着の予測、類似レースは決まり手で、目的が違う。「上位2テーマと重なる」以上のことは言わないでほしい。任意の絞り込みは件数の予告が必須。案3 は平均に近い数字が出るので反対
- 30代女性: 案1 の「寄与度の行を押すとチップが光る」は便利なので、案2 に入れてほしい。地元選手（属性）で絞れないのは残念
- 統合（推奨）: **案2 に案1 のハイライトを入れる**。案3 は3人が反対で不採用。任意の絞り込みの並びは寄与度の順にするが、「効く順」とは書かない

## ファン4人パネル（展示後の寄与度・レースごとの寄与度、2026-10-02。仮説）
前提として、展示の後に出し直せば締切に間に合うこと（[perrace-contribution.md](./analysis/perrace-contribution.md) 3・4）と、展示を入れると寄与度の ST・直前が .063 → .147 に上がることを伝えた。
- ①価値と見るタイミング: 4人とも展示後の値に価値があると答えた。見るのは締切の10〜15分前（20代男性・30代男性は「展示を見てから買う」）。30代女性は朝に1回、展示後にもう1回。20代女性は「展示後に出たことが分かる印が欲しい」
- ②出走表時点と展示後の両方か、置き換えか: 3人が「展示後に置き換えて、展示前と比べた変化を1行で」。30代男性だけ「前後を並べて見たい」。統合: 展示後の値に置き換え、展示前の値は折りたたみで残す
- ③変化の見せ方: 「ST・直前の比重が上がった」だけでは抽象的という意見が2人（20代男性・30代男性）。「展示タイム1位は4号艇（2位と 0.08秒差）」のように、どの艇の何が効いたかまで出すと分かる、という意見。テーマの変化＋効いた艇を1行で出す
- ④レースごとの寄与度（B）の価値: 展示後なら4人とも「レースごとのほうを見る」。スライス単位（条件ごと）は「この会場の傾向」として残す。レースごとの値が AI の予想に見えないよう、「AI のモデルが何を見ているかの説明」と見出しで分ける（20代女性）
- 似たレースへの展示の反映: 20代男性は「展示1位の艇が同じ過去レース」の条件チップが欲しい。ほかの3人は、似たレースは出走表時点のままでよい。今回は入れず、公開後の要望として残す

## 分析の限界（2026-10-02）
- **test（2026-04〜09）は複数回見た**。MD-6 の k-NN、縮小版の追加検証 A〜E、層別 S* の全件での確定（preregistration-2）で、同じ期間を評価に使っている。層別 S* の軸の選択自体は cal で行い、test は事前登録どおり1回だけ見たが、方式の選択（k-NN → ⑨ → 層別）を通じて test の情報が判断に入っている。test の数字は、まったく新しいデータでの値より楽観的でありうる
- 2026-10-01 以降を凍結して後で最終判定する案は、ユーザー判断で採らない（早く出す）。公開後の実データで当てはまりを見る（T3b）
