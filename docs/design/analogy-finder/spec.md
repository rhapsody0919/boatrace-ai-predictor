# アナロジー・ファインダー（寄与度レーダー×類似レース検索）spec

種別: UI機能
対応Linearチケット: BOA-271（関連: BOA-272〜277、BOA-257、BOA-279、BOA-284、BOA-226）

実装レディネスレビュー（論点整理・課題と対応策・ブロッカー・アルゴリズム調査）は[readiness-review.md](./readiness-review.md)を参照。

## 背景・目的

Gemini・Grokとの壁打ち（2026-09-12）で、「予想（的中率・回収率）の土俵では戦わず、分析ツールとして戦う」という方針を確認した（BOA-271本体の背景）。当初案の「レンズ／ルール／カードツリー」（Grok案の3層UI構想）はモックを繰り返す中でユーザー自身の理解が得られず、以下の経緯で破棄した。

1. レンズ切替＋ルール設定＋出走表ダッシュボードを1画面に詰め込んだ初期モック → 「分かりづらい」で却下
2. マインドマップ／フローチャート的なツリー分解（縦アコーディオン→放射状の枝分かれ図） → 形は理解されたが「イメージと違う」で破棄
3. ユーザー自身の発案「データ＋運、取りこぼしか運かを切り分けたい」を起点に、「①寄与度の可視化」「②過去の類似レース検索」という2本立てに再構成 → この方向で継続採用

現在のコンセプトは「アナロジー・ファインダー」（過去の類似事例の検索・可視化による分析ツール）。k近傍法（k-NN）的な非парメトリック推論であり、大域的な予測モデル（`unifiedModel.js`）にはできない「交互作用の自動検出」「説明可能性（個別事例まで遡れる）」「不確実性の直接可視化（類似事例の分布の広がり）」を提供する。

## 機能要件

### FR-1 寄与度レーダー（優先度: 高）
- 実DB調査で確認した約40項目を7テーマ（ST・直前情報／機力／選手・基礎成績／会場×枠の型傾向／環境／選手・身体属性／市場(オッズ)）に分類し、レーダーチャート（7軸）で寄与度を表示する
- 「枠・進入コース」はBOA-257（進入コースのスクレイピングバグ）が解消するまで計算対象外とし、専用の無効表示（グレーアウト＋理由表示）を出す
- テーマをタップ/クリックすると、実DBカラム名（例: `motor_2rate`）付きで個別パラメータの内訳を展開表示する
- 着順タブ（1着／2着／3着）で寄与度プロファイルを切り替える。**これらは独立した周辺分布（marginal）であり、それぞれ別々に集計する**（統計的な位置づけはFR-3参照）
- 艇番比較モード: 任意の2艇番（プルダウンで選択、初期値1号艇×6号艇）の寄与度プロファイルを同一チャートに重ねて比較表示する（実線・破線で系列を分ける）。**チャート上には数値ラベルを置かない**（2系列×7軸＝14個のラベルが必然的に衝突するため）。正確な数値は同一テーマ・同一行で艇番ごとの列を並べた比較表（テーマ名／艇番A／艇番B）で別途表示する（選択的な直接ラベルの原則。チャートは形の比較に専念させる）
- グレード（一般／G3／G2／G1／SG）×ラウンド種別（予選／準優勝戦／優勝戦）のフィルタで寄与度プロファイル・nを絞り込む。**2026-09-14、ワトソン（BOA-103既存モデル）の実データ（TreeSHAP）で検証済み**: 当初モックの仮説（グレードが上がるほどST・機力・環境の寄与度が上がる）は**逆方向**と判明した。実際は一般→G3→G1→SGとグレードが上がるほど「会場×枠の型傾向」（艇番の効果）のシェアが41.8%→69.6%→87.1%→89.5%と増え、「選手・基礎成績」「ST・直前情報」「機力」のシェアは縮む（上位グレードほど選手の実力差が縮み、相対的に枠構造への依存が増えるため）。詳細はreadiness-review.mdブロッカー5参照。実装時は仮説式ではなく実際のSHAP値をそのまま使う。会場クラスタ・個別会場のフィルタは次フェーズ
- nはグレード×ラウンドの現実的な発生頻度を反映して大きく変動する（例: 一般×予選で1,800件規模、G1×優勝戦で1桁、SG×優勝戦で数件）。**n<30の場合は「⚠ 小標本」フラグを画面に明示する**（nを隠さず出す方針の具体化）
- レーダー・比較モードいずれもn（サンプル数）とデータ集計期間（例: 2019-04〜現在）を常に表示する。**nが小さくても隠さず表示する**（これがプロジェクト全体のnの扱いの既定方針）
- 受入基準: 着順タブ・グレード・ラウンドの切り替えでレーダーの形とnが実際に変わる。小標本時にフラグが表示される。艇番比較で任意の2艇番を選択でき、チャートに数値ラベルは出ず、比較表に両艇番の値が並ぶ。テーマクリックで内訳が展開する。「枠・進入コース」は常にグレーアウトかつクリック不可

### FR-2 類似レース検索（アナロジー・ファインダー）（優先度: 高）
- 今日のレース条件を、FR-1と**同じ7テーマ・同じ重み**でベクトル化し、過去の類似レースを検索する（①と②を統計的に結合する設計。類似度計算に使う重みは寄与度分析の結果そのものを使う）
- 類似度しきい値スライダー（65%〜95%）で動的に絞り込む。**しきい値を上げると、表示が自動でズームして残った点の内訳が見やすくなる**（固定の座標範囲だと高しきい値で全点が中心に密集し情報量が失われるため、しきい値を下限としたレンジで都度再スケーリングする）
- 可視化は「ソナー画面」（中心=今日のレース、同心円=類似度、6扇形=艇番、光点=過去の類似レース1件）。光点の色は艇番の公式ゼッケン色（1号艇=白／2号艇=黒／3号艇=赤／4号艇=青／5号艇=黄／6号艇=緑）で、扇形の位置と色の二重エンコードにする
- 見出しは統計用語（信頼区間等）を前面に出さず、体感で分かる階級ラベル（🔥鉄板級／📌有力／⚖️混戦／🌊大混戦／🌀まだ参考程度）で要約する。数値的な詳細（正規近似95%信頼区間、n）は「詳しく見る」で開閉する二段構えにする（IQ・数学リテラシーに関わらず好奇心をくすぐる設計と、データサイエンティストが見ても手を抜いていないと分かる設計を両立させるため）
- 光点・類似レース一覧（下記）の行はクリックで双方向にハイライト連動する（光点クリック→該当行がハイライト＋スクロール、行クリック→該当光点にパルスマーカー表示）
- 「現状の類似度計算には枠・進入コース・事故情報を含まない」旨を常設の注記として表示する（BOA-257／BOA-279解消まで。ユーザー自身が全会場公式サイトを個別に確認し公式データを完全に取得する計画があり、それが完了するまでの暫定表示）
- 受入基準: しきい値変更で件数・シェア・見出し・自動ズームが連動して変わる。光点・一覧行のクリックで相互ハイライトが動作する

### FR-3 組み合わせ構造分析（優先度: 高）
- **統計的な位置づけ**: 1着・2着・3着は独立ではない（6艇中1艇しか1着になれない構造上の制約に加え、展開次第で艇同士が干渉する。例: 外側艇＝4〜6号艇のまくりが決まると、内側艇＝1〜3号艇は引き波・ブロックで2着に残りづらくなる）。FR-1の周辺分布（marginal）だけでは、この干渉効果を検出できない
- **FR-1（周辺分布）とFR-3（組み合わせ）は両方必要**（片方の代替ではない）。周辺分布は安定していて単純な関係を見るのに向き、組み合わせは干渉効果を検出できる代わりに1マスあたりのnが小さくなりやすい。Plackett-Luce（BOA-103アドラー予想で使用中）が個々の強さを使いながら順位全体を組み立てる中間的な発想を取っているのと同じバランス感覚で設計する
- 実際に起きた1着→2着→3着の艇番の流れを**サンキー図**（3列×6ノード、帯の太さ＝実際の頻度）で可視化する。ノードの高さはその艇のその着順での出現数に比例させる
- 組み合わせ別の発生率一覧（頻度順位10件、艇番組み合わせ＋シェア%＋n）を表形式で表示する
- 干渉効果の自動検証コールアウトを表示する（例: 「4-6号艇のまくり系が決まったレースで1-3号艇が2着に残った割合」と「まくりが絡まなかった場合」を対比する一文）。この一文は「1着艇番だけを見ていては分からない」ことを具体的な数字で示す役割を持つ
- 受入基準: サンキー図の帯の太さが実際の頻度と比例している。組み合わせ一覧のシェア%の合計が100%に近い（丸め誤差除く）。干渉効果コールアウトの数値が実データの集計と一致する

## スコープ

### やること
- FR-1〜FR-3（着順タブ1/2/3、グレード×ラウンド種別フィルタ、任意の艇番比較＋比較表、しきい値スライダー、自動ズーム、サンキー図、組み合わせ一覧、干渉効果コールアウト、小標本フラグ）

### やらないこと
- レンズ／ルール／カードツリー（Grok案初期コンセプト）: 破棄済み
- 見せ方比較で検証したA（単純棒グラフ）・B（レーン表示）: 検証の結果、不採用（ソナー＋サンキーの組み合わせを採用）
- 会場クラスタ・個別会場でのフィルタ: 次フェーズ（グレード×ラウンド種別は本スコープに含めた）
- 買い目・本命の提示: 明確に対象外（分析ツールとしての方針、BOA-271本体の合意事項）
- 進入コース・事故情報を使った寄与度・類似度計算: BOA-257／BOA-279解消後の別タスク

## 非機能要件

- モバイル320px〜での表示崩れなし（SVGチャートはviewBoxベースでスケーリングするが、実装時にモバイル実機相当の幅で確認が必要。特にサンキー図・ソナー画面は情報密度が高く、狭い画面での可読性を個別に検証すること）
- 既存の用語ルール（「競艇」禁止）・`design-tokens.css`のトークン使用・`!important`禁止に従う
- サンキー図は6×6×6の組み合わせ次第で帯が密集し視覚的に読みづらくなる場合がある（モック確認時点で221件・99本のSVG要素）。上位の太い帯のみ強調し残りを薄くする等の視覚整理は未確定（下記参照）

## 制約・前提

- データソース: 実DB約40項目（`docs/db-migration/`全マイグレーション・実データpopulation率をSupabase MCPで確認済み。詳細はBOA-271のLinearコメント参照）
- BOA-257（進入コースが艇番と100%一致＝スクレイピングバグ）・BOA-279（事故・アクシデント情報が構造的に未取得）が、FR-1の「枠・進入コース」テーマとFR-2の類似度計算の両方に影響する前提条件。解消が本機能の完全な精度向上の前提になる
- BOA-284（現行`unifiedModel.js`のcourseRate特徴量がBOA-257の影響を受けている疑い）はBOA-257と合わせて検証する
- BOA-226（ラウンド種別=予選/準優勝戦/優勝戦の判定データが実質存在しない、`race_title`での代替も不可と確認済み）が解消するまで、グレード×ラウンド種別フィルタは「グレードのみ」に縮小するか実装を保留する
- 会員登録なし（ログイン不要）を前提にする。艇番比較・しきい値等の設定はlocalStorage等での永続化を想定（BOA-272のカスタム条件式ビルダーと設計思想を合わせる）
- ユーザー自身が全24会場の公式サイトを個別に確認し、進入コース・事故情報を含む完全な公式データを取得する計画が別途進行中（時期未定）。本機能の実装着手判断とは独立に進める

## 未確定事項（ユーザー確認待ち）

1. **既存レースページへの統合方法**: 「データ出走表」セクションを置き換えるか、新規セクションとして追加するか、別ページ・別モードとして新設するか。モック段階では単独ページとして検証しており、統合方法は未確定
2. **会場クラスタ・個別会場のフィルタ**: グレード×ラウンド種別に続く次フェーズとして優先実装が決まっているが、詳細設計は未着手
3. **サンキー図の視覚的整理**: 帯が密集する問題（6×6×6の組み合わせ次第で読みづらくなる）について、確認の結果「今のままで良い」と合意済み。追加対応なし
4. **BOA-277（予想色の強い既存表現の見直し）との統合タイミング**: 本機能が「1着予想」等の既存表現とどう共存・置換していくかは未確定
5. ~~**グレード×ラウンドの寄与度調整式**: モック上の仮説であり、実データでの検証が必要~~ → **2026-09-14検証済み**、仮説と逆方向と判明（readiness-review.mdブロッカー5参照）。実装時は仮説式を撤回し実データ（ワトソンSHAP値）をそのまま使う方針に変更
6. **（新規）「市場(オッズ)」テーマの扱い**: 既存モデル（ワトソン）はオッズを特徴量に含まない設計（ΔR²評価との循環を避けるため）。このテーマだけ寄与度を原理的に算出できない。①ΔR²等の別指標に置き換える／②オッズ込みの別モデル（モリアーティ）を流用する／③テーマ自体を外す、のいずれかの方針決定が必要（readiness-review.md次のアクション#5参照）
