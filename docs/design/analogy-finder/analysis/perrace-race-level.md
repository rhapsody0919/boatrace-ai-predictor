# レース単位モデル＋ SHAP で他艇の寄与を出す案（案a）の検証（2026-10-03、探索的・事前登録なし）

**これは探索的な記述で、事前登録をしていない。** 仮説検定の結論としては使わない。test 期間（2026-04〜09）は ablate.py・finish_targets.py と同じ期間を再び使っている（使い回し3回目）。レース単位モデルのハイパーパラメータ（min_data_in_leaf・木の数）は学習期間の中だけで選び、test は見ていない。

問い: 「6号艇が1着になるには1〜5号艇の不出来も要る。他艇の要素の寄与を見せられないか」。案a＝1レース1行・6艇分の特徴量を入れ、1着の艇（6クラス）を当てるモデルの SHAP で、他艇の特徴量の寄与を出す。

## 1. 今の艇単位モデルに、他艇の情報はどれだけ入っているか

44列の分類（#feature_classes_boat_model）

## 2. レース単位モデル

### 形
- 入力 107列＝レース共通 11列＋6艇×16列（`b{k}_<特徴量>`。艇番は列の位置で表す。`*_diff`・`*_rank`・`b1_*` は入れない）（#race_level_features）。レース共通の11列が test の全レースで6艇同じ値であることを確かめた（#race_common_check_test_races_with_varying_value がすべて0）
- LightGBM multiclass（6クラス）。train.py の PARAMS を流用し、学習期間の 2025-06-01〜10-02 で学習・10-03〜11-02 を検証にした早期終了で min_data_in_leaf {50, 200, 500} から選んだ: **200・48回**（検証 multi_logloss 1.25226）。この設定で学習期間全体で学習し直した（#race_level_training.grid・chosen）。木は 48回×6クラス＝288本

- ペア差（レース単位 − 艇単位）: seed 0 **+0.01263（95%CI +0.00903〜+0.01648）**、seed 1 +0.01518（+0.01136〜+0.01908）（#logloss.race_level_s{0,1}.paired_race_level_minus_boat_level）。**レース単位は艇単位より有意に悪い**。差の大きさは、finish_targets の出走表 → 展示後の差（1.21135 − 1.19993＝0.01142、finish-targets.json#c.win）と同程度で、レース単位モデルの 1.21256 は艇単位の出走表モデル（直前情報なし）より悪い

### クラス6 の上位（#race_level_shap.top_features.class6、平均 |中心化 SHAP|、Spearman は値と SHAP の順位相関）

  - 勝率系は向きが一貫している（他艇が強いほど6号艇の1着を押し下げる、ρ −.90〜−.95）。他艇の **支部コード（カテゴリ）が上位10のうち4つ**を占め、値と寄与の向きが一定でない（ρ −.47〜+.02）

### 3着以内（学習していない、#race_level_shap.top3_design）
- softmax 1本では出せない（6艇のうちどの3艇かの多ラベル）。案: (i) 「k号艇が3着以内」の2値を6本（入力は同じ107列、SHAP は同じ形で分けられる。合計は3に拘束されない）、(ii) 3艇の組の20クラス（C(6,3)）1本（k の確率は k を含む10クラスの和。SHAP は確率の和には加法的でなく近似が要る）、(iii) 1着モデルから Harville（追加学習なし、寄与はアブレーションか一次近似、finish_targets.e と同じ）

## 3. 費用（#cost、#js_treeshap）

計測中の load average は 18.2→10.7（1分）。単発の計測で、負荷の揺れを含む。

| | 学習（6スレッド） | 1R の推論＋SHAP（CPU / 実時間、1スレッド） | 168R | 木 | テキスト / gzip |

| レース単位 1本 | 7.1秒（＋選定の早期終了 3回） | 9.7ms / 1.7ms | 325ms / 345ms | 288 | 984KB / 419KB |

| 艇単位 6本（案B） | — | 59.8ms / 61.5ms | 9,785ms / 10,488ms | — | 5.77MB / 2.48MB |

- 1R のレース単位で CPU 9.7ms・実時間 1.7ms と CPU 時間のほうが大きい（num_threads=1 を渡しても並列に動いた可能性があるが、原因は確かめていない）。168R では CPU と実時間がそろい、レース単位は艇単位 win の約 1/4.5
- 学習時間は前の実行では 5.8秒（レース単位）・10.5秒（艇単位）で、負荷で揺れる。どちらも数秒〜十数秒
- **JS**: `src/utils/analogyTreeShap.js`（master e524a150a）の `compileModel` は `num_class !== 1` を「多クラスのモデルには対応していません」と明示的に拒否する（102〜105行）。試作の `treeshap.mjs` は全木を1つのスコアとして足すので、multiclass をそのまま渡すと6クラスが混ざる
  - dump_model の木は tree_index 順に並び（#js_treeshap.tree_index_class_rule_ok＝true、num_tree_per_iteration 6）、**`tree_index % 6 == k` の木だけを渡すと、クラス1・6 とも Python の pred_contrib と 8桁丸めで一致**（200R、#js_treeshap.class{1,6}）。1クラス分の JS の時間は 0.79ms/R（48本）
  - 本番の JS に入れるには、compileModel でクラスごとに木を分ける改修が要る（未実装）
