## 1. 今の FR-1 の数え方と、レースごとの意味の違い
- 本番の寄与度（`profiles.py`）は、スライス内の艇の |SHAP| の平均で、レース内で中心化していない。中心化しないと、枠番（会場×枠）や1号艇の格のように「どのレースでも同じ方向に効く」部分が毎回大きく出る
- レースごとに「この6艇の差がどこにあるか」を見せるなら、中心化した値が意味に合う

| テーマ | 中心化なし 平均（10%〜90%点） | 中心化 平均（10%〜90%点） |
|---|---|---|
| 選手・基礎成績 | .453（.389〜.514） | .389（.296〜.477） |
| 会場×枠・進入 | .305（.263〜.351） | .364（.300〜.435） |
| ST・直前情報 | .131（.100〜.164） | .151（.111〜.193） |
| 選手・属性 | .049（.036〜.065） | .047（.030〜.064） |
| 機力 | .038（.031〜.046） | .030（.023〜.037） |
| 環境 | .024（.016〜.035） | .020（.014〜.028） |
（perrace.json#uncentered.mean・p10・p90、#centered.mean・p10・p90）

## 2. レースごとにどれだけ違うか
- **1位のテーマ**（中心化）: 基礎成績 60.1%、会場×枠 39.9%。それ以外が1位のレースは0（perrace.json#centered.top1_rate）
- **上位2つ**: 会場×枠 100%、基礎成績 99.8%、ST・直前 0.2%（#centered.top2_rate）
- **3位**: ほぼすべてのレースで ST・直前（#centered.top3_rate 99.9%）。機力・環境・属性が3位以内に入るレースはほぼ無い
- 大きさの幅は、スライス単位（会場別で基礎成績 .34〜.40）より、レース単位のほうが広い（基礎成績 .30〜.48、10%〜90%点）
- つまり、レースごとに変わるのは「基礎成績と会場×枠のどちらが大きいか」と「その大きさ」。**テーマの並び（上位3つとその順以外）は、レースごとにほぼ変わらない**

## 3. 出走表時点で計算するとどうなるか
直前情報（展示タイム・天候・風・波の8列）を欠損にして計算し直した（中心化、perrace.json#racecard_vs_full_centered）。
- 1位のテーマが同じレース 96.4%
- ST・直前のシェアの平均は .151 → .089（平均の絶対差 .062）。会場×枠は .364 → .397、基礎成績は .389 → .411
- 注意: 欠損は「展示前で分からない」の正しい表現ではない。モデルは学習時の欠損（取得漏れ）の扱いで分岐するので、ST・直前の値は「展示が無いときのモデルの扱い」を反映している。出走表時点で出すなら、直前情報を使わないモデルを別に学習するほうが説明として正しい

## 4. 計算の費用
- SHAP の計算は 168R（1,008艇）× 3本で 10秒（load average 約250 の下で1コア、#seconds_168R_x3models）
- 重いのは計算ではなく特徴量の準備。選手の過去30走の ST・成績（日単位でずらす）が要り、これは週次の学習ジョブの export・features.py と同じ処理になる。Vercel では Python が動かないので、GitHub Actions を Vercel Cron から workflow_dispatch で起動する形になる（ADR-0080 の経路。FR-2 では ADR-0082 で外したもの）
- 保存: 1レース1行（版・計算時刻・テーマ別シェア・艇ごとのテーマ別の値）で約1KB、1日約150行、年に約55MB

## 5. スライス単位の「条件による違い」の線引き
- 今の `share_sd` は seed を変えた再学習のばらつき（0.002〜0.007）で、標本のばらつきを含まない。SG優勝戦（n=10R）でも 0.0067 しかなく、差の線引きに使えない
- 標本のばらつきの目安: レース単位のシェアの標準偏差は約 .05（中心化なし、基礎成績の10%〜90%点の幅÷2.56）。スライスの平均の標準誤差は約 .05÷√n。会場別（n≈2,000〜2,500R）なら約 .001 で、会場ごとの差（全体との差が最大で ±3pt 程度）は標本の揺れより十分大きい。SG優勝戦（n=10R）なら約 .016 で、±3pt は揺れの範囲
- 線引きは `profiles.py` でレース単位のブートストラップの SD を出すのが正しい（FR-1 の改修。概算ではなく実測する）
