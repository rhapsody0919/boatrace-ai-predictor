## 結論（草稿）
1. ユーザーの問い「天才データサイエンティストの検証でこうなったのか」への答え: いいえ。今の定義は件数（会場で中央値333件・300件未満46%）と、選んだ艇の級との交絡（9.3pt）で決めた。「1号艇以外の枠の級は効かない」ことを確かめた検証はこれまで無かった。readiness-review の boat_number の重要度（−28.25pt）は選んだ艇自身の艇番で、すべての定義に入っている
2. ファンにとっての価値: 選んだ艇の率（タブ1の大きい数字・カード、タブ3の1号艇の1着率・型の出現率・スリットの形）は、ほかの枠の級を枠ごとにそろえても真の差は1着率で約2pt、3着以内率で約1pt。集まる件数が会場で1/4〜1/14になり、画面の率（生の率）はかえってぶれる（b で Brier +6.8e-4、区間 5.6〜7.8）。会場で集められるレースもほぼ消える（b は会場で300件未満が88%）。ファンの直感どおりの範囲にしても、今日の結果を当てる精度は上がらず、出す数字がぶれ、会場の数字が出なくなる
3. 一方、タブ3の④（どの艇が勝ったか・3連単）のような、1号艇以外の艇の結果は、1〜3号艇の級を枠ごとにそろえると当てやすくなる（1着艇の分布の Brier 相対1.2%改善）
4. 推奨: タブ1・タブ3とも今の定義(a)のまま公開する。spec の Q1 の根拠に今回の検証（枠の並びの効き目は約2pt で、件数の減り方に見合わない）を足す。タブ3④の「1号艇以外の艇の結果」に枠の並びを入れるかは、④で実際に出す値で測り直すチケットを起票して別に決める
5. 実現案と規模（変える場合）: (i) b 6枠: 会場はほぼ全て全国へ、全国でも33%が300件未満 → 2段の切り替え（全国×6枠→全国×a）が要る。範囲キー（v16_defs.py の scope_keys と JS）・事前集計バッチ・範囲の名前・spec/screens・承認済みモックの範囲名の変更。中〜大。(ii) c 1〜3号艇: 全国で17.5%が300件未満、会場は86%が300件未満で、既定はほぼ全国になる。規模は(i)と同じ（キーの作り方だけ違う）
