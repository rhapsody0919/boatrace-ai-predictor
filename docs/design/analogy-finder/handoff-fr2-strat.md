# 引き継ぎ: BOA-271 FR-2（類似レース）を層別 S* で作り直す

新しいセッションで、plan.md の FR-2 部分から作り直すためのメモ。設計ブランチは `feature/boa-271-analogy-finder`（Draft PR #1039）。

## 決まっていること
- **方式**: 層別 S*（2026-10-02 ユーザー決定）。今日のレースと、出走表時点で言葉にできる4条件がすべて同じ過去レースを集め、決着の分布を出す。AI の予測とは混ぜない（AI予想の欄は今までどおり。較正値の別枠は作らない）
- **条件**: 1号艇と他艇の勝率差5帯（境界 −1.91／−1.14／−0.49／+0.19）→ 1号艇の級別 → 会場 → 勝率1位の艇。α=1000（階層 Dirichlet）。根拠は [analysis/fr2-strat-result.md](./analysis/fr2-strat-result.md)
- **小さい層の戻し方**: 200件未満なら末尾の条件から外して親の層へ。表示の割合は親の層に向けて α'=50 で平滑化。画面に使った条件・外した条件・件数を出す
- **似ている理由の文面**: spec FR-2 のルール6つ（条件を主語に、帯の範囲をそのまま、外した条件と理由、件数は常に・%は補足、条件外の項目を「似ている」と言わない、「AI」「類似度○%」「ほぼ同じ」と言わない）
- **出す分布**: 決まり手6分類・1着艇・1着の進入コース・頻出出目トップ3（それぞれ n と期間）。FR-3（サンキー・組み合わせ一覧）は同じ層を使う
- **時点**: 出走表時点（前日までの成績、日単位の as-of）。展示・気象・オッズは使わない
- **母集団の値の約束**（BOA-635 のレーンの依頼 R1〜R4・D-5・D-6、plan の「get_analogy_neighbors」節）: 3連単は本体の `payout_trio` から、F・出遅れ・欠場の ST は NULL、不成立の払戻は NULL、実進入不明は NULL、不成立と1〜3着に返還艇が入るレースは除外、スナップショットは版をまたいで1レース1つ
- **寄与度（FR-1）は実装済み**（PR #1118・#1121・#1122。マイグレーション 118）。FR-2 とは独立

## 作り直すこと（この順を推奨）
1. **ADR-0080 を置き換える ADR を書く**。層別なら距離の行列も近傍の順位も要らない。今日のレースの4条件の値は、出走表（race_entries）と選手の勝率・級別から決まるので、母集団の決着テーブルに条件の値（4列）を持たせ、**SQL の RPC で同じ層を数えるだけ**にできる見込み。その場合、近傍のバッチ（GitHub Actions）・Storage の行列・`api/cron/analogy-dispatch.js` が要らなくなる。確かめること: 今日のレースの勝率差・勝率1位の艇を SQL で作れるか（features.py の定義と一致するか）、RPC の応答時間
   - 引き継げる判断: GitHub Actions の schedule を使わない、出走表時点、pgvector を使わない、表示した結果を BOA-627 で残す
2. **BOA-627 のスナップショットの形**: 層別なら、保存するのは「条件の値・使った層（外した条件）・件数・母集団の最終日（pool_cutoff）」で足りる（同じ条件で pool_cutoff 以前を数え直せば再現できる）。近傍の id の配列は要らない見込み
3. **マイグレーション**: 115（未適用）を層別の形に直し、番号を振り直す。`analogy_models` に FR-2 の列が要るなら 118 に ADD COLUMN。母集団の決着テーブルに条件4列とインデックス。`check-anon-access.js` の一覧の更新
4. **screens と モック**: 件数スライダー（近い順 N 件）とソナー（同心円＝近さの順位）は層別に合わない。条件チップ（外すと広がる）と、ソナーを残すなら「中心＝4条件一致、外の輪＝一致する条件が少ない」の形を候補にモックを作り、オーケストレーター経由でユーザーに確かめる（大規模機能のモック承認ルール）。似ている理由の一文は文面ルールでモックに入れる
5. **受け入れ E2E**（`e2e/acceptance/analogy-finder.spec.js`）を spec・screens の変更に合わせて `acceptance-test-writer` に書き直させる
6. **tasks.md の T3・T7・T8 を書き直し**、`design-reviewer` にかける（`/step4` の事前条件）
7. **BOA-635 のレーンに知らせる**: BOA-635 は RPC `get_analogy_neighbors` の返り値（1〜3着・決まり手・進入・コース順の ST・3連単）を前提に設計している（PR #1093）。RPC の名前・列が変わるなら先に合意する。AI予想タブでの描画位置（T9-1）も共有している
