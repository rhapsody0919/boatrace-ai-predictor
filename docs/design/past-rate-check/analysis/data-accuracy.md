## 結論
- 合格。不一致0件
- 9レース×64選択肢＝576通りで、n・count・除いた件数・%・主文の5項目を比べた。比べたのは、JS の `countPastRate` と、spec FR-1 の式を JS を見ずに書き直した Python（`scripts/analysis/past-rate-check/accuracy-py-count.py`）
- 決着の行5件（本番 DB の race_results の1〜3着から組んだもの）、注記の期間9件、本番の画面の主文1件と振り返りの行2件も一致した

- 切り詰めない層（n_returned = n_total）は5つで、優勝戦3・準優勝戦1を含む
- 切り詰めた層は4つ（n_total 2,057〜6,996）
- 確定済み5レース、発走前4レース

## 妥当性の検査（全レースで成り立った）
- 1号艇: 残る＋飛ぶ＝n、1着 ≤ 残る
- 配当の帯: 3つの和＝n。1,000円・10,000円ちょうどの行も JS と Python で同じ帯
- スリット
  - 2段目 ≤ 1段目
  - 横一線・内3艇そろうは段で変わらない
  - 2形 AND ≤ 各形
  - 横一線＋ダッシュ勢先行は2段目で0件（定義から起きない組）
- 行の性質
  - 新しい順に並んでいる
  - race_id の重複は0
  - 最新の race_date ≤ pool_cutoff < そのレースの日
  - n_returned＝rows の件数
- layer の行と race_results（2025-12 以降の行）
  - 着順・決まり手・3連単（payout_trio）・進入の差は0
  - payout_trifecta（3連複）と比べると全件で違う（列名と券種が逆、D-1）

## 気づいた点（仕様どおりの動き。直していない）
1. **1号艇が欠場（返還）した過去レースは「飛ぶ」に入る**
   - 1号艇が3着以内にいないので、spec FR-1 の式どおりに「飛ぶ」に数えられる
   - spec は F・失格・転覆を「飛ぶ」に入れると書いているが、出走前の欠場には触れていない
   - 影響は2,000件中最大2件（0.1ポイント）
   - 定義を変えるかはオーナー判断（2026-10-18 にオーケストレーターへ報告）
2. **切り詰めない層の期間は pool_from から出る**
   - spec FR-2 のとおり pool_from（2019-04-01）から出るので、実際の最古の行より1か月早く見えることがある
   - 例: 2026-10-17-24-12 は最古の行が 2019-05-29 だが「2019-04〜」と出る

## 確かめていないこと
- 2019〜2025-11 の過去の行と元データの照合（race_results に無い）
- st_by_course の値と元の ST 表の照合
- 本番で、保存した予想の振り返りの行（localStorage の経路）を出すところ
