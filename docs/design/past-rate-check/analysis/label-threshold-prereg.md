# 定番／レアの線の検証 事前登録（BOA-635 T0-1）

結果を見る前に方法を固定する（#1138 の分析ルール）。spec FR-3 の手順1〜8を、実行できる粒度まで具体にしたもの。push の前に second-opinion-reviewer で1パス見て、指摘1〜10を取り込んだ（2026-10-13。指摘11「不合格の型だけラベルを出さない」は判定不能の扱い（下）で一部取り込み、残りは報告に回す）。このファイルを単独のコミットで push してから数値を見る。push の後に変えてよいのは、実装の誤り（このファイルに書いた規則どおりに動いていない）の修正だけで、変えたときは結果の文書に理由を書く。統計のやり直しは3回まで（2026-10-12 ユーザー指示）。

## 問い
画面で「定番」（p ≥ x%）・「レア」（p < y%）と付けたとき、その言葉が実際の発生率と食い違わないか。あわせて、同じ条件の過去レースの割合 p が、全国の割合 q より今日の結果を言い当てるか（上積み）。

## データ
- `scripts/ml/analogy/export_pool.js --daily`（DB と Storage を読むだけ。書かない）で、v16 の列がそろう export を作る。出力先は `ANALOGY_DATA_DIR`（リポジトリ外の一時フォルダ）。`export_manifest.json` の行数と SHA-256 を結果の文書に写す
- export の欠けの照合: 2025-12〜2026-09 の日ごとの races・results・start_timings の行数を本番の DB（読み取り）と照合し、差が1%を超える日を結果の文書に書く
- 母集団: 朝のバッチの `pool` と同じ（`features.build` の `race_ok`（6艇・欠場なし・1着が1艇・1〜3着に返還艇なし）、race_date ≥ 2019-04-01（`POOL_FROM`）、6艇そろい（`race_arrays`））かつ `v16_pool` の `layer_ok`。行の列は `layer_row` と同じ
- 層の条件: 各レースの出走表の時点の値（`features` が作る `cls_name[:,0]`・`nat_win`、round・grade）から `v16_similar.gap_band`・`top_boat`・`layer_conditions` で作る（朝のバッチの `write_race` と同じ）
- 確認: 本体の `race_entries.win_rate`（勝率差の元）がレースの後・期の切り替わり（5月・11月）で上書きされていないか、`updated_at` 等で確かめ、結果の文書に書く。上書きがあれば、その範囲を「層の条件に後の値が入りうる」として明記する

## test レースと比べる行
- test: race_date 2026-04-01〜2026-09-30 で、上の母集団に入るレース
- 比べる行: test レースと条件（`layer_mask`）が同じで、race_date が test レースの日より前の母集団のレースを (race_date 降順, race_id 降順) に並べた先頭最大2,000件。0件のレースは使わない（画面では `empty_layer`）
- 固定データの検査: 朝のバッチが作った本番の layer ファイル（2026-10-06 以降の数レース）と、同じ規則で作った行の race_id の集合が一致することを確かめてから本計算に入る（`pool_cutoff` を合わせる）
- 切り詰め: `n_total > 2,000` を「切り詰めあり」とする

## 選択肢（型と小分け）
判定の式は spec FR-1（1/100秒の整数で比べる）。合否は小分けごとに出し、型の中のすべての小分けが合格（判定不能は下のとおり）したら型の合格とする。

| 型 | 小分け | 選択肢 |
|---|---|---|
| 着順 | 1点 | 120通り |
| 着順 | 流し | 60通り（1着1艇 × 2着は残り5艇から2艇 × 3着は残りの3艇） |
| 1号艇 | — | 1着・残る・飛ぶ の3 |
| 展開 | — | 起点の艇6 × 決まり手4 |
| スリット | 形 | 7形×2段と2形 AND×2段。段で判定が変わらないもの（横一線・内3艇そろう・その2つの組）は1つに数える。定義から同時に起きない組（spec FR-1）は入れない |
| スリット | 自分で作る | 1コース指定12通り（6コース×出る／凹む）と2コース指定60通り（15組×4） |
| 進入 | — | 3〜6号艇 × 3 |
| 配当の帯 | — | 3 |

## 1つの (test レース, 選択肢) で出す値
- p: 比べる行のうち、その型で判定できる行 N の中で一致した割合（丸めない）。N=0 なら使わない
- hit: test レース自身でその選択肢が起きたか（0/1）。test レース自身がその型で判定できない（決まり手・ST・進入・払戻が無い）なら使わない
- q: 全国の割合。test レースの日より前の母集団のうち、その型で判定できるものの中の割合（日ごとの累積で出す）

## 判定（合否）
- 線の組 (x, y) ごと、小分けごとに:
  - 定番の帯: p ∈ [x, x+5)（%）の組の hit の平均が x% 以上なら合格
  - レアの帯: p ∈ [y−2, y)（%）の組の hit の平均が y% 未満なら合格
  - 帯の組が200未満、または帯の組の異なる test レースが100未満なら「判定不能」
- **判定不能のラベルは、その小分けでは画面に出さない**（件数とともにユーザーに報告する）。合否は判定できたラベルだけで決める。判定不能は不合格に数えない
- 点推定で判定する。race_date 単位のブートストラップ（1,000回、seed 20261013、パーセンタイル法）で95%CI を記録する。CI が線を含む帯は結果の文書に「境界」と書く（合否には使わない）
- 線の組の順: (15, 5) → (20, 5) → (15, 3) → (25, 3) → (10, 3)。全小分けが合格（判定不能を含む）した最初の組を採る。どれも合格しなければ線を出さない（spec FR-3 手順6）
- 候補を順に試すので多重比較になる。線の候補は5つに限り、この順を変えない

## 報告（合否に使わない）
切り詰めあり／なしに分けて、小分けごとに:
- (a) 定番・レアが付く組の割合
- (b) 付いた組のうち、p の Wilson 95% 区間（N に対して）が線をまたがない割合
- (c) Brier skill = 1 − mean((p − hit)²) / mean((q − hit)²) と、race_date 単位のブートストラップ95%CI
- (d) 比べる行のうち本体（2025-12-03 以降）の行の割合の中央値と、選択肢ごとの全国の割合を長期の期間（〜2025-12-02）と本体の期間で並べた表
- (e) test の月ごとの帯の発生率（2026-04〜09）
- 採った線で不合格になる小分けがある候補のとき、その小分けだけラベルを出さなければ採れた線があるか（ユーザーの判断材料。規則は変えない）

次のどれかに当たる小分けは、採った線のままユーザーに報告し、相対の線（全国比）に変えるかを戻す（spec FR-3 手順7）: (b) が50%未満、(c) の CI が0をまたぐか点推定が 0.01 未満、(a) で定番かレアの一方が付いた組の95%以上を占める。
