# 過去に発生した割合を見る spec

種別: UI機能（集計は画面側。新しいテーブル・バッチ・API なし。BOA-271 v16 の layer API を読む）
対応Linearチケット: BOA-635（関連: BOA-271 龍神ソナー、BOA-627 時点付きスナップショット、BOA-822 イン崩れ注意度）

確定モック: https://claude.ai/artifact/RHjYWn3GWXYUetEHf6M7aq （Version 3、2026-10-01 ユーザー確認済み）。決定の経緯は BOA-635 のコメント。2026-10-13 のオーナー決定（呼び名・母集団・FR-6 を外す）は [handoff-v16.md](./handoff-v16.md) 2節。

## 位置づけ

- ユーザーが入れた予想が、今日のレースと「同じ条件の過去レース」（下の「データ（土台）」の層。新しい順最大2,000件）で過去に何回起きたかを数えて見せる
- 数えるのはユーザーの予想が過去に起きた回数。AI の当たり外れは数えない
- 呼び方: 機能・ボタンは「過去に発生した割合を見る」。比べる相手は「同じ条件の過去レース」（2026-10-13 オーナー決定）。龍神ソナーの「類似レース」（今日に近い順800件）・思考アシストの類似レース（近い順400件、ADR-0087）とは呼び名で分ける。「類似レース」「似たレース」「あなたの読み」「少数派／多数派」「前例レース」は使わない
- サイト内に「AI がやらないこと」のような否定形の説明文は書かない（2026-10-01 ユーザー指示）
- BOA-627 の保存項目のうち3（ユーザーの読みと発走前の時刻）を、本機能の端末内保存で満たす
- 出すのはレース詳細の AI予想タブ（発走前）と結果タブ（振り返り）だけ。思考アシスト（BOA-430）への埋め込みは今回やらない（2026-10-13 オーナー決定）

## データ（土台）

BOA-271 v16 の朝のバッチ（`scripts/ml/analogy/v16_morning.py`）が作る layer ファイルを、`GET /api/analogy/layer/[raceId]`（`api/analogy/layer/[raceId].js`）で読む。Storage（非公開バケット `analogy-v16`、実行ごとのパス）は上書きされない。

**層（同じ条件の過去レース）**: そろえる条件（1号艇の級別・1号艇と勝率トップの勝率差（5段階）・勝率トップの艇番。今日が優勝戦・準優勝戦ならラウンド、G1・SG なら「G1以上」も）が今日と同じ過去レースの全件。会場は含まない。層の大きさは中央値 7,286件・p90 58,119件（v16 plan の design-reviewer の再現）、ADR-0087 の 36レースでは31レースで2,000件を超えた。大半のレースで新しい順2,000件に切り詰める。会場で 1コース1着率が 43〜63% と違うので、会場を混ぜた層では割合が今日の会場からずれうる。その影響は FR-3 の検証の Brier skill で測る。会場ごとの表示は本機能に無い（YAGNI）

新しい順2,000件を採る理由（ADR-0081）: 問いが「この予想が過去にどれだけ起きたか」なので、同じ条件の過去レースを期間で区切らず新しい順に数えるのが合う。ADR-0087 は思考アシストで (B) 新しい順2,000件を「期間がレースごとにばらつき『最近』の意味が一定しない」として却下したが、本機能は「最近の傾向」を言わない。期間は注記に出す（FR-2）

## 機能要件

### 共通の数え方

- **分母 N**: `rows`（最大2,000件）のうち、その型の判定に要る値がそろっている件数（型ごとに変わる）
- **除いた件数**: 理由ごとに1行ずつ、件数が1以上の理由だけ出す。理由と文言: 展開「決まり手が分からない{k}レースを除く」（`winning_technique` が null）、スリット「スタートタイミングがそろわない{k}レースを除く」（`st_by_course` が null か要素に null）、進入「進入が分からない{k}レースを除く」（`course_by_boat` が null かその艇の要素が null）、配当の帯「払戻が無い{k}レースを除く」
- **ST の比べ方**: ST は `stCent`（`src/utils/analogyScenario.js`、`roundHalfUp(st × 100)`）で1/100秒の整数にしてから比べる。浮動小数のまま `>=` で比べると、差が線ちょうどのレースで判定が割れる（例: JS で 0.15−0.10 = 0.04999…。設計レビュー 2026-10-02 指摘2）。Python の検証スクリプトも同じく整数で比べる
- **件数**: 常に `rows` のすべて（新しい順最大2,000件）を使う。龍神ソナーの件数スライダーとは関係しない
- **割合**: c ÷ N を百分率で小数1桁（四捨五入）。N=0 なら主文・割合・メーター・ラベル・内訳を出さず「同じ条件の過去レースに、この型を判定できるレースがありません」。要約・除いた件数の行・比べた相手の注記は出す
- 1回の判定は1つの型。型をまたいだ組み合わせ（例: 着順かつスリット）はしない。組み合わせはスリットの中の2形まで

### FR-1 6つの型の判定（優先度: 高）

型の並び順は 着順 → 1号艇 → 展開 → スリット → 進入 → 配当の帯（確定）。

| 型 | 入力 | 一致の条件（過去レース1件ごと） | 分母から除く行 |
|---|---|---|---|
| 着順 | 1着（1艇）・2着（1艇、「流す」で複数）・3着（1艇、「流す」で複数） | `rank1 ∈ 1着` かつ `rank2 ∈ 2着` かつ `rank3 ∈ 3着` | なし |
| 1号艇 | 「1着」「残る（3着以内）」「飛ぶ（4着以下）」の1つ | 1着: `rank1=1`／残る: 1 ∈ {rank1,rank2,rank3}／飛ぶ: 1 ∉ {rank1,rank2,rank3} | なし |
| 展開 | 起点の艇（1〜6号艇の1艇）＋決まり手（逃げ・差し・まくり・まくり差し の1つ） | `rank1 = 起点の艇` かつ `winning_technique = 決まり手` | `winning_technique` が null の行 |
| スリット | 7形から1〜2形＋強さ（1段目／2段目）、または「自分で作る」 | 下の「スリットの判定」 | `st_by_course` が null か要素に null を含む行（D-2） |
| 進入 | 艇（3〜6号艇の1艇）＋「3コース以内に入る」「4コース以内に入る」「枠なりのまま」の1つ | 3コース以内: `course_by_boat[艇] ≤ 3`／4コース以内: `≤ 4`／枠なり: `course_by_boat[艇] = 艇番` | `course_by_boat` が null かその艇の要素が null の行（D-4） |
| 配当の帯 | 「堅い（3連単 1,000円未満）」「中穴（1,000〜10,000円未満）」「万舟（10,000円以上）」の1つ | 堅い: 払戻 < 1,000／中穴: 1,000 ≤ 払戻 < 10,000／万舟: 払戻 ≥ 10,000 | 払戻が null の行（D-3） |

補足:
- 着順: 1着→2着→3着の3回タップが既定。「流す」をオンにすると2着・3着を複数選べる（フォーメーション）。1着は常に1艇。同じ艇を複数の着で選ぶことはでき（ボタンは disabled にしない）、同じ艇が2つの着に入る組み合わせは点数に数えない。流さないときに同じ着で別の艇を押すと置き換わる。流すときは押すたびに選択が入れ替わる（もう一度押すと外れる）。3着まで決まって点数が1点以上になるまで判定ボタンは押せない。点数を「1-3,4-2,3,4（4点）」の形で出す。2点以上のときは、一致した過去レースの組み合わせ別の内訳を件数の多い順（同数は組み合わせの昇順）に上位4組、5組目以降があれば「ほか」を付けて出す。区切りは「、」
- 1号艇: 「飛ぶ」には、1号艇がフライング・失格・転覆等で着外になったレースも入る（その艇は3着以内の列にいない。3着以内の列に返還艇がいるレースは D-5 で除かれる）
- 展開: 起点は艇番（号艇）で数える。決まり手の選択肢は4つ（抜き・恵まれは出さない）。キーと DB の日本語の対応は `src/utils/turnPrediction.js` の `TECHNIQUE_NAMES`。結果に「そのとき2着に来た艇」の内訳（艇番ごとの件数、0件の艇は省く、件数の多い順・同数は艇番順、区切り「、」）を出す。これがスジ（2着の艇）にあたる
- 進入: 1・2号艇は選べない（モックどおり）。3号艇の「3コース以内」は枠なりと内への移動の両方を含む
- 配当の帯: 境界は「以上／未満」。1,000円ちょうどは中穴、10,000円ちょうどは万舟

#### スリットの判定
`c[1..6]` = その行の `st_by_course`（コース順の ST）を `stCent` で1/100秒の整数にしたもの。判定は龍神ソナーと共用の `slitForms`（`src/utils/analogyScenario.js`。Python は `scripts/ml/analogy/v16_defs.py` `slit_forms_matrix`）に強さの段の引数を足して使う（今は1段目だけ。2段目の線を足す。二重の実装を作らない）。差の線は強さの段で変わる（`t`）。下の表の秒数は、判定では100倍した整数（0.05秒→5）で使う。

| 段 | 凹み `dent` | カド一撃 `kado` | ダッシュ勢 `out` | 艇身での言い方（案A） |
|---|---|---|---|---|
| 1段目（既定） | 0.05秒 | 0.03秒 | 0.05秒 | 約1/3艇身（カド一撃は約1/4艇身） |

- **定義から同時に起きない2形**（T0-2。1段目: 内3艇そろう＋2コース凹み／カド受け凹み／イン凹み、2コース凹み＋カド受け凹み、2コース凹み＋イン凹み。2段目はこれに 横一線＋2コース凹み／カド受け凹み／イン凹み／ダッシュ勢先行 が加わる）: 押せるかどうかは、そのボタンを押した後に残る2形の組で決める（1形を選んでいるときはその形と、2形を選んでいるときは新しく選んだ方の形と組む。3形目を押すと最も古い形が外れるため。例: 内3艇そろう→カド一撃の順に選んだ後は、2コース凹みを押せる）。同時に起きない組になる形のボタンは disabled にし、ボタンの下に「同時には起きない形です」を出す。2形を選んでいて、2段目に切り替えるとその2形が同時に起きない組になるときは、「約半艇身」のボタンを disabled にする（2026-10-13 オーケストレーター判断、オーナーへは事後報告）。「0件」と「判定できない」を混ぜないため

### FR-2 結果の見せ方（優先度: 高）

- 1行目に入力の要約。型ごとの文言:
  - 着順:「3連単 1-3,4-2,3,4（4点）」（1点も「3連単 1-2-3（1点）」）
  - 1号艇:「1号艇が1着」「1号艇が3着以内に残る」「1号艇が4着以下に飛ぶ」
  - 展開:「3号艇のまくり」
  - スリット:「カド受け凹み＋カド一撃（約1/3艇身以上）」。形は7形の並び順、括弧の艇身は強さの段の言い方（1段目「約1/3艇身以上」、2段目「約半艇身以上」。カド一撃だけ違う艇身は注記で示し、要約には入れない）。強さが効かない形だけなら括弧なし（「横一線」）。自分で作るはコース順に「1コースが凹む・4コースが出る」
  - 進入:「4号艇が3コース以内に入る」「6号艇が枠なりのまま」
  - 配当の帯:「3連単が万舟（10,000円以上）」
- 主文: 回数を最も大きく、% を添える。定番／レアのラベルを横に付ける（FR-3。出すのは小分けごとの表で「出す」のものだけ）。文言（2026-10-02 ユーザー承認）:
  - 切り詰めていない（`n_returned` = `n_total`）:「過去{N}レース中 {c}回（{p}%）」（例「過去1,234レース中 30回（2.4%）」）
  - 切り詰めた（`n_returned` < `n_total`）:「同じ条件の新しい{N}レース中 {c}回（{p}%）」（例「同じ条件の新しい2,000レース中 412回（20.6%）」）。大半のレースはこちら
  - N は型で除いた後の件数。除いた行があれば、その下の行で理由と件数を出す（例「同じ条件の新しい1,968レース中」＋「スタートタイミングがそろわない32レースを除く」）
- 件数が少なくても % とラベルを出す（件数を必ず添える）。出さないのは N=0 のときだけ（2026-10-02 ユーザーの考え「件数が少なくても%を出したほうが価値が上がる」）
- 割合のメーター（横棒、0〜100%）
- 型ごとの内訳（着順の上位4組、展開の2着の艇）
- 除いた件数の行（あれば）
- 比べた相手の注記:
  - 切り詰めていない:「比べた相手: {層の説明文}（{期間}）。定番は{x}%以上、レアは{y}%未満」
  - 切り詰めた:「比べた相手: {層の説明文}のうち、新しい{n_returned}件（{期間}）。定番は…」
  - {層の説明文} は `describeAnalogyLayer(conditions, t, {count: n_total})`（例「今日と同じく、1号艇の級別・1号艇と勝率トップの差・勝率トップの艇番がそろう過去レース7,286件」）。層は全国の会場をまとめているので、期間の括弧に「全国」を足す（例「（全国、2024-03〜2026-10）」）
  - 期間は、切り詰めていなければ `pool_from`〜`pool_cutoff`、切り詰めたら `rows` の race_date の最小〜`pool_cutoff`（数えた行の期間。2,000件は層によって数か月〜約3年分になる）を「2019-04〜2025-11」の形で出す（同じ月なら「2025-11」）
  - ラベルを出さない小分け（FR-3）では「定番は…、レアは…」の文を付けない
- 型や入力を変えたら結果を隠し、ボタンを押し直すまで出さない（モックどおり）
- 別のタブ（オッズ一覧等）へ移って戻ると、入力と結果は消える（タブは見ていないとアンマウントされる。保存は残るので結果タブの振り返りには出る）。受け入れる

受入基準: 主文の N・c・% が FR-1 の数え方と一致する。`n_returned < n_total` で前置きが「同じ条件の新しい」になる。入力を変えると結果が消える。

### FR-3 定番／レア（優先度: 高）

- 割合 p が x% 以上なら「定番」、y% 未満なら「レア」、その間は付けない。p は丸める前の c ÷ N で判定する
- ラベルは型と小分けごとに出すかどうかを決める（T0-1 で判定不能・不合格のラベルは、その小分けでは出さない）。小分けは、着順は入力の `nagashi`（1点／流し）、スリットは `mode`（形／自分で作る）で決まり、ほかの型は型そのもの。注記の「定番は{x}%以上」「レアは{y}%未満」は、その小分けで出すラベルの分だけ書く
- 流しは、T0-1 で確かめる形（1着1艇×2着2艇×3着3艇）以外の形（例 1着1艇×2着5艇×3着5艇）にも同じ小分けのラベルを付ける。確かめていない形を含むことは T0-1 の結果の文書に「言えないこと」として書く
- 検証でどの候補も合格しなかった場合（線を出さない）は、ラベルも注記の「定番は…、レアは…」の文も出さない。検証が済むまでも同じ
- **採った線: x=15、y=5**（T0-1、2026-10-13）。小分けごとに出すラベルは下の「小分けごとのラベル」。初期値（モックの例）は x=15、y=5。線の決め方は Q2（2026-10-02 オーケストレーター判断で下の推奨案を採用）
- 実行の細部（母集団・選択肢・ブートストラップの単位（race_date）・報告の項目）は [analysis/label-threshold-prereg.md](./analysis/label-threshold-prereg.md) が正
- **検証方法（結果を見る前にここで固定する。2026-10-02 設計レビュー指摘3・4・9 を受けて作り直した。T0-1 で実行する前に、この節を単独のコミットで push し、second-opinion-reviewer で1パス見る（#1138 の分析ルール））**:
  1. 比べる行: v16 の層の定義どおりに、test 2026-04〜09 の各レースについて、そろえる条件が同じ層から、そのレースの日より前の母集団で新しい順（同じ日は race_id の降順）最大2,000件を取る（layer ファイルと同じ規則。`v16_similar.py` `layer_conditions`・`layer_mask` と `v16_pool.py` `layer_ok` で作る）
  2. 選択肢: 型ごとに全部並べる。着順は1点（120通り）と代表の流し（1着1艇×2着は残り5艇から2艇×3着は残りから3艇、の全組）。1号艇3、展開 6艇×4、スリットは7形×2段と2形のすべての組×2段、自分で作るは1コース指定（12通り）と2コース指定（60通り）、進入 4艇×3、配当の帯3
  3. 各 (test レース, 選択肢) で、層の行での割合 p、そのレース自身で起きたか（0/1）、全国の発生率 q（同じ日より前の母集団全体での割合）を出す
  4. **判定（合否）: 線のまわりで、言葉と実際が食い違わないこと。** 型ごとに、p ∈ [x, x+5) で「定番」と付いた組の実際の発生率の95%CI の上限が x% 未満なら不合格、p ∈ [y−2, y) で「レア」と付いた組の実際の発生率の95%CI の下限が y% 以上なら不合格。それ以外は合格で、点推定が線の反対側にあって CI が線を含むものは「境界」として合格に数える。CI は race_date 単位のブートストラップ（1,000回）。2026-10-13 に、事前登録の push の後・結果を見る前に、点推定で判定する規則から変えた（理由と、変更前の規則での判定は事前登録の「変更の記録」と結果の文書にある。変更前の規則なら (20, 5) を採っていた）。その帯の組が200未満か、異なる test レースが100未満の型・ラベルは「判定不能」とし、不合格には数えないが、そのラベルはその型では画面に出さない（件数とともにユーザーに報告する）。着順は「1点／流し」、スリットは「形／自分で作る」に分けて判定し、両方の合格で型の合格とする（2026-10-13 second-opinion-reviewer の指摘で追加）
  5. **報告（合否に使わない）**: 切り詰めあり／なしのレースに分けて（切り詰めた層は新しい数か月分しか数えないので、季節の偏りが入りうる）、型ごとに (a) 定番・レアが付く割合、(b) 付いたもののうち、p の Wilson 95% 区間が線をまたがない割合（標本の揺れでラベルが入れ替わりうるものの多さ）、(c) p の Brier skill（q に対する上積み）と CI
  6. 初期値 (15, 5) が全型で合格（判定不能を含む）なら採る。不合格の型があれば、候補 (20, 5) → (15, 3) → (25, 3) → (10, 3) を順に試し、最初に全型で合格した組を採る。どれも合格しなければ線を出さずにユーザーへ報告する
  7. 次のどれかに当たる型があれば、線を採ったうえでユーザーに報告し、その型だけ相対の線（全国比）に変えるかを Q2 としてユーザーに戻す: 5(b) が50%未満、5(c) の CI が0をまたぐか点推定が 0.01 未満（同じ条件の層で比べる意味が薄い）、5(a) で定番かレアの一方が95%以上を占める（例: 3連単1点はほぼ常にレア、1号艇1着はほぼ常に定番になる見込み）
  8. 結果は `docs/design/past-rate-check/analysis/label-threshold-result.md` に残し、採った x・y を本 spec に書き戻し、`docs/knowledge/stat-findings.md` に1行足す
- **小分けごとのラベル**（T0-1 の結果と、手順7に当たる小分けの扱い。2026-10-13 オーナー決定 B: 情報が薄い小分けではラベルを出さない。追加の検証はなし）

| 小分け | 定番 | レア | 理由 |
|---|---|---|---|
| 着順 1点 | 出さない | 出さない | レアが付いた組の100%（常に「レア」）、skill 0.0057 |
| 着順 流し | 出す | 出す | 手順7に当たらない |
| 1号艇 | 出さない | 出さない | 定番が付いた組の100%（常に「定番」）。レアは判定不能 |

| スリット 自分で作る | 出さない | 出さない | レアが95.4%、skill 0.0037 |
| 進入 | 出す | 出す | 手順7に当たらない。定番は T0-1 で「境界」（点推定 13.0% は線の下だが CI 10.7〜15.4% が線を含むので合格。画面の扱いはほかの「出す」と同じ） |

- ラベルを出さない小分けでは、注記の「定番は…、レアは…」の文も出さない。主文の回数・%・メーターはすべての小分けで出す
- 結果タブの決着の行は着順1点と同じ数え方なので、ラベルを出さない

- 別案（今は採らない）: 全国の出現率との比で決める相対の線。上の7でユーザーに戻す余地を残す

受入基準: 採った線と検証の数字（型ごとの線のまわりの実際の発生率・CI・判定不能の件数・ラベルが付く割合・Wilson 区間・Brier skill）が analysis に残っている。画面のラベルが線どおりに付く（境界値 x・y ちょうどのテストを含む）。

### FR-4 発走前と発走後の表示（優先度: 高）

**発走前（AI予想タブ）**

**発走後（結果タブ）**
- 結果タブ（`RaceResult`、確定後だけあるタブ）の払戻の下に「振り返り」（見出し「振り返り」、各行は1つのリストの listitem）を足す。締切は `PredictionPanel` から `RaceResult` に `raceStartTime` を足して渡す

- 比べる相手は今の layer ファイル（同じ `run_id` なら発走前と同じ行の集合。D-6）
- 行1〜: この端末に保存された、締切前に入れた予想を型の順（FR-1 の並び）にすべて出す。{要約} は FR-2 の要約と同じ文言（画面差分 D3、2026-10-02 採用）。`savedAt` が締切以降の Entry は出さない（保存しない仕様の二重の守り）。各行「あなたの予想 {要約} は、過去{N}レース中 {c}回（{p}%）{ラベル}」（前置きは入力したときに保存した `result.truncated` で決める。false なら「過去{N}レース中」、true なら「同じ条件の新しい{N}レース中」）。数字とラベルは保存した値を出す（入力したときに見せたもの。後で線を変えても変わらない）
- 最後の行: 「決着 {1着-2着-3着} は、過去{N}レース中 {r}回（{p}%）」（前置きは今の layer ファイルの `n_returned < n_total` で FR-2 の主文と同じ規則で決める）。決着は `RaceResult` の `buildResultRows` が結果表のために組み立てた着順（返還艇を外したもの）の1〜3着を使う。1〜3着がそろわない、または同着で順位が 1・2・3 にならない（例 1,1,3）ときは決着の行を出さない。数え方は着順の型（1点）と同じで、今の layer ファイルの行から数える。ラベルは付けない（着順1点の小分けと同じ。FR-3）
- 保存した予想が無い（別の端末・30日経過・入力しなかった）ときは、決着の行だけ出す
- 当たり／外れの表示は付けない
- 保存した `snapshot.layerKey` が今の layer ファイルの印と違うときは、振り返りのリストの下に「入力したときから、同じ条件の過去レースが変わっています」を1つだけ出す（Entry のどれか1つでも違えば出す）。印は layer の `conditions`・`n_total`・`n_returned`・`pool_cutoff`・`rows`（全行の全列）から作るハッシュ（`layerKey`、`src/utils/pastRate/layer.js`）で、行の中身が1つでも入れ替われば変わる。run_id では照合しない: racecard の段は締切の10〜50分前にも作り直され、そのとき run_id は変わるが行は同じだった（T0-3、10/06〜10/15 で137レース。2026-10-16 オーケストレーター判断）

受入基準: 締切前に保存した予想が結果タブに型の順で出る。締切後に入れた予想は出ない。保存が無いとき決着の行だけ出る。当たり／外れの文言が無い。`not_saved`・`empty_layer`・`absent` で両タブとも出ない。

### FR-5 端末内保存（優先度: 高）

- 保存先: `localStorage`。キー `boatai-user:past-rate-check:v1`（ユーザーの保存は `boatai-user:` 接頭辞にする master の慣習。データキャッシュは `boatai:` 接頭辞で、更新ボタンとあふれ時の掃除は値がキャッシュの形（`{data, timestamp}`）のキーだけを消す（`supabaseDataService.js` の `readCacheEntry`、BOA-665）。値の形でも区別できるが、接頭辞も分けておく）
- 値: `{ "v": 1, "entries": [Entry, …] }`
- Entry:

| 項目 | 型 | 中身 |
|---|---|---|
| `raceId` | string | `YYYY-MM-DD-VV-RR` |
| `type` | string | `order`／`boat1`／`tenkai`／`slit`／`entry`／`payout` |
| `input` | object | 型ごとの入力（下の表）。表示用の要約文は保存しない（言語を切り替えても再生成できるように） |
| `savedAt` | string | 入力した時刻（ボタンを押した時刻、ISO 8601、端末の時計） |
| `snapshot` | object | `{ runId, poolCutoff, layerKey }`（layer の `run_id`・`pool_cutoff` と、入力したときの layer の印）。BOA-627 のスナップショットは (raceId, runId) で指す。振り返りの照合に使うのは `layerKey` だけ（FR-4）。`runId`・`poolCutoff` は記録用 |
| `result` | object | `{ n, count, excluded: [{ reason: "technique" \| "st" \| "course" \| "payout", count }], label: "standard" \| "rare" \| null, truncated: boolean }`（入力したときに見せた数字・ラベル・前置き） |

| type | input |
|---|---|
| order | `{ first: number, second: number[], third: number[], nagashi: boolean }` |
| boat1 | `{ outcome: "win" \| "top3" \| "out" }` |
| tenkai | `{ boat: number, technique: "nige" \| "sashi" \| "makuri" \| "makurizashi" }`（`TECHNIQUE_NAMES` のキー。表示は i18n） |
| slit | `{ mode: "pattern", patterns: ("flat" \| "wall" \| "d2" \| "d3" \| "kado" \| "d1" \| "dash")[], level: 1 \| 2 }` または `{ mode: "custom", courses: (-1 \| 0 \| 1)[] }`（-1 凹む、0 指定なし、1 出る） |
| entry | `{ boat: 3..6, target: "within3" \| "within4" \| "waku" }` |
| payout | `{ band: "low" \| "mid" \| "high" }` |

- 保存するとき: ボタン「過去に発生した割合を見る」を押して結果を出したとき。入力の途中では保存しない
- 締切後は保存しない: 押した時刻が締切（`getDeadlineDate(raceId, raceStartTime)`）以降なら保存しない。締切が分からないレースは、レースが確定していなければ保存する。時刻は端末の時計で判定する（時計が遅れている端末では締切後の入力が保存されうる。影響はその端末の振り返りだけなので受け入れる）
- 1レース×1型につき最新の1件（同じレース・同じ型の既存を置き換える）
- 30日で消す: `savedAt` から30日を過ぎた Entry を、読み込み（AI予想タブの部品の表示時・結果タブの振り返りの表示時）と書き込みのたびに取り除く
- 書き込みの直前に読み直してから、置き換えて書く（別のタブで保存した分を上書きで消さないため。同時に押した場合は後に書いた方が勝つ。それは受け入れる）
- 件数の上限: 1,000件。超えたら `savedAt` の古いものから消す
- 失敗の扱い: localStorage が使えない（プライベートモード・容量超過・無効化）、または中身が壊れている（JSON として読めない・`v` が違う・`entries` が配列でない）ときは、機能そのもの（判定・表示）は動かし、保存と振り返りだけをしない。壊れた値は読み込み時に捨てて作り直す。Entry 単位で形が違うもの（必須項目の欠け・`snapshot.runId`・`snapshot.layerKey` が文字列でない・`result.truncated` が boolean でない・`type` が6つ以外・`input` の形が型と合わない・`savedAt` が時刻として読めない）は、その Entry だけ捨てる。実装前の版の保存は無いので、移行の読み替えはしない。エラーは console に出し、画面には出さない
- 会員登録・サーバー送信はしない

受入基準: 押すたびに同じキーへ保存され、同じレース・型は1件に置き換わる。30日を過ぎた Entry が次の読み込みで消える。締切後に押しても保存されない。localStorage が例外を投げても結果は出る。更新ボタン（`clearCache()`）の後も保存が残る。

## スコープ

### やること
- FR-1〜FR-5 の設計（spec・screens・plan・tasks）
- 定番／レアの線の検証と、スリットの出現率（tasks T0、分析のみ）

### やらないこと
- 新しいテーブル・バッチ・API（layer ファイルと API は BOA-271 v16 にある）
- 思考アシスト（BOA-430）への埋め込み（2026-10-13 オーナー決定で今回外す。判定・数え方・保存は React に依存しない純粋関数にするので、後から呼べる。部品の props に埋め込み用の口は作らない）
- 型をまたいだ組み合わせ（着順かつスリット 等）
- サーバー側への予想の保存・会員登録・端末間の同期
- 当たり／外れ、的中率の表示
- スリットの「自分で作る」の強さの段（0.05秒固定）

## 非機能要件
- モバイル 375px で横スクロールなし（`npm run test:layout` の5幅）。スリットの7形の絵は1列で縦に並べる（モックどおり）
- 判定は最大2,000行の配列を数えるだけなので、ボタンを押してから100ms 以内に結果を出す（通信なし。行の取得は部品を出すときに1回）
- 用語ルール（画面内で「競艇」禁止）、`design-tokens.css` のトークン、`!important` 禁止、ダークモード
- i18n: 翻訳対象（4言語）。AI予想タブ・結果タブと同じ扱い
- a11y: 型の切り替えは tablist、艇のボタンは `aria-pressed`、結果は `aria-live="polite"`、スリットの絵は `role="img"` と説明の `aria-label`
- 新しい集計を含むため、実装後に `data-accuracy-verifier` で、画面の件数と layer ファイルの行を別の手段（Python）で数えた値の一致を検証する

## 制約・前提
- データ源: BOA-271 v16 の layer API。D-1〜D-6 が前提
- 層の条件は出走表時点の値（1号艇の級別・勝率差・勝率トップの艇番・ラウンド・グレード）。展示・気象・会場は使わない
- 会員登録なし、端末内保存のみ
- 法的: 既存の免責文（投票は日本国内在住・20歳以上、結果を保証しない）をそのまま使う。本機能で新しい免責文は足さない
- 既存部品: 艇の色は `src/utils/colors.js` の `BOAT_COLORS`、艇番の表示は `BoatBadge`、スリットの判定は `slitForms`・`stCent`、スリットの絵は龍神ソナーの `SlitShapeIcon`（screens）

## 既定値で決定した事項（ユーザーが後から覆せる）
| 項目 | 既定値 | 根拠 |
|---|---|---|
| 比べる行 | v16 の層（会場を含まない）の新しい順最大2,000件、呼び名「同じ条件の過去レース」 | 2026-10-13 オーナー決定。ADR-0081 |
| 分母 | 型ごとに判定できる行だけ。除いた件数を理由つきで出す | 判定できない行を「不一致」に数えると割合が下がる |
| 切り詰めの判定 | `n_returned < n_total` | 上限の値に依存しない（handoff 3節） |
| スリットの組み合わせ | AND、最大2形、強さは共通の1段、既定は1段目 | モックの実装どおり |
| 自分で作る | 7形と排他、差は6艇平均から0.05秒 | モックの実装どおり（3状態化は D2、2026-10-02 採用） |
| 進入の判定 | 選んだ1艇のコースだけを見る。枠なり＝その艇のコースが艇番と同じ | モックの実装どおり |
| 展開 | 条件は起点の艇＋決まり手。2着の艇は内訳 | 確定モック |
| 着順 | 3着まで決まって判定。1着は1艇 | 確定モック（3回タップ） |
| 発走後の AI予想タブ | 入力は使えるが保存しない | 結果を見てからの入力を「あなたの予想」として振り返りに出さないため |
| 保存のタイミング | 結果を出したとき | 入力途中の状態を予想として残さない |
| 30日の起点 | 入力時刻 | レース日より単純で、端末の時計だけで決まる |
| スナップショットとの紐づけ | (runId, poolCutoff, layerKey) を保存し、layerKey で照合 | run_id は行が同じでも締切前の作り直しで変わる（T0-3）。行の中身の印で比べれば、本当に変わったときだけ注記が出る |
| 保存キー | `boatai-user:past-rate-check:v1` | ユーザーの保存の接頭辞の慣習 |
| 振り返りのラベル | 入力したときのラベルを保存して出す。決着の行は今の線 | 「入力したときに見せたもの」を再現する（設計レビュー指摘11(d)） |
| 取得失敗の表示 | 両タブとも `InlineFetchError`（再試行つき）。0行・取得中・`not_saved`・`empty_layer`・`absent` は出さない | `frontend-data-fetch.md` の3 |
| 結果タブの振り返り | 保存した型をすべて。無ければ決着の行だけ。当たり／外れなし | 画面差分 D3（2026-10-02 採用） |
