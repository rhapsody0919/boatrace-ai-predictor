# 過去に発生した割合を見る spec

種別: UI機能（集計は画面側。新しいテーブル・バッチ・API なし）
対応Linearチケット: BOA-635（関連: BOA-271 類似レース、BOA-627 時点付きスナップショット、BOA-430 思考アシスト）

確定モック: https://claude.ai/artifact/RHjYWn3GWXYUetEHf6M7aq （Version 3、2026-10-01 ユーザー確認済み）。決定の経緯は BOA-635 のコメント3件。

## 位置づけ

- ユーザーが入れた予想が、今日のレースの「類似レース」（BOA-271 FR-2 の近傍）で過去に何回起きたかを数えて見せる
- 数えるのはユーザーの予想が過去に起きた回数。AI の当たり外れは数えない
- 呼び方: 機能・ボタンは「過去に発生した割合を見る」。比べる相手は「類似レース」（BOA-271 の見出しと同じ）。「あなたの読み」「似たレース」「少数派／多数派」「前例レース」は使わない
- サイト内に「AI がやらないこと」のような否定形の説明文は書かない（2026-10-01 ユーザー指示）
- BOA-627 の保存項目のうち3（ユーザーの読みと発走前の時刻）を、本機能の端末内保存で満たす

## 実装開始の前提条件

1. BOA-271 Phase U の T1（マイグレーション115 の本番適用）・T3（近傍のバッチ）・T5-2（`analogyService.js`）が済み、`get_analogy_neighbors` が本番で近傍を返していること。BOA-271 の「実装開始の前提条件」（K/B 補完の判定 等）をそのまま引き継ぐ
2. BOA-271 側で、母集団の決着の約束（下の「データの約束」D-1〜D-4）がマイグレーション115 と `export_pool.js` に入っていること
3. 定番／レアの線の検証（下の FR-3、tasks T0）が済んでいること。画面に線を出すのはその後

## データ（土台）

`get_analogy_neighbors(race_id)`（BOA-271、マイグレーション115）の返り値だけで数える。1行＝近傍の過去レース1件、近い順に最大800行。

| 列 | 使う型 |
|---|---|
| `rank1`・`rank2`・`rank3` | 着順・1号艇・展開（2着の内訳） |
| `winning_technique`（6分類） | 展開 |
| `course_by_boat`（[1号艇のコース, …, 6号艇のコース]） | 進入・スリット（今日の艇番とは無関係。過去レースのコース順をそろえるのに使うのは `st_by_course` 側） |
| `st_by_course`（[1コースのST, …, 6コースのST]） | スリット |
| `payout_trifecta`（3連単の払戻。D-1） | 配当の帯 |
| `model_version`・`asof_stage`・`asof_at` | 保存（スナップショットとの紐づけ） |

### データの約束（BOA-271 の母集団に求めること。2026-10-02 にオーケストレーター経由で BOA-271 レーンへ依頼）
- **D-1** `analogy_pool_outcomes.payout_trifecta` は3連単の払戻。本体の `race_results` は `payout_trifecta`＝3連複・`payout_trio`＝3連単と名前が逆転しているため、取り違えると配当の帯がすべてずれる。列名を `payout_3tan`（`kb_archive_races` と同じ）に変えることを推奨した。名前が変わった場合は本 spec の列名も読み替える
- **D-2** `st_by_course` は、フライング・出遅れ・欠場のコースを NULL にする（数値のままだとフライングの艇が「速いST」に見え、カド一撃などが過大に出る）。判定元は本体 `race_start_timings.is_flying`・`is_late_start`、長期 `kb_archive_boats.is_flying`
- **D-3** 3連単の払戻は、不成立・特払いのレースで NULL（不成立の¥100を払戻として入れない。`race_results.race_status`）
- **D-4** `course_by_boat` は、実進入が分からない艇を NULL にする（艇番で埋めない。BOA-523 の欠落期間で「枠なり」に化けるため）

## 機能要件

### 共通の数え方

- **分母 N**: 近傍800件のうち、その型の判定に要る値がそろっている件数（型ごとに変わる）。決着が無い近傍（LEFT JOIN で `rank1` が NULL）はどの型でも除く
- **除いた件数**: 800 − N が1以上なら、結果の下に理由つきで出す（例:「スタートタイミングがそろわない8レースを除く」）
- **件数**: 常に近傍800件すべてを使う。BOA-271 の件数スライダー（100／200／400／800件）とは連動させない（**ユーザー確認中 Q1。推奨案**）
- **割合**: c ÷ N を百分率で小数1桁（四捨五入）。N=0 なら割合と定番／レアを出さず「この型を判定できる類似レースがありません」
- 1回の判定は1つの型。型をまたいだ組み合わせ（例: 着順かつスリット）はしない。組み合わせはスリットの中の2形まで

### FR-1 6つの型の判定（優先度: 高）

型の並び順は 着順 → 1号艇 → 展開 → スリット → 進入 → 配当の帯（確定）。

| 型 | 入力 | 一致の条件（近傍1件ごと） | 分母から除く近傍 |
|---|---|---|---|
| 着順 | 1着（1艇）・2着（1艇、「流す」で複数）・3着（1艇、「流す」で複数） | `rank1 ∈ 1着` かつ `rank2 ∈ 2着` かつ `rank3 ∈ 3着` | なし（決着がある近傍すべて） |
| 1号艇 | 「1着」「残る（3着以内）」「飛ぶ（4着以下）」の1つ | 1着: `rank1=1`／残る: 1 ∈ {rank1,rank2,rank3}／飛ぶ: 1 ∉ {rank1,rank2,rank3} | なし |
| 展開 | 起点の艇（1〜6号艇の1艇）＋決まり手（逃げ・差し・まくり・まくり差し の1つ） | `rank1 = 起点の艇` かつ `winning_technique = 決まり手` | なし |
| スリット | 7形から1〜2形＋強さ（1段目／2段目）、または「自分で作る」 | 下の「スリットの判定」 | `st_by_course` に NULL を含む近傍（D-2） |
| 進入 | 艇（3〜6号艇の1艇）＋「3コース以内に入る」「4コース以内に入る」「枠なりのまま」の1つ | 3コース以内: `course_by_boat[艇] ≤ 3`／4コース以内: `≤ 4`／枠なり: `course_by_boat[艇] = 艇番` | その艇の `course_by_boat` が NULL の近傍（D-4） |
| 配当の帯 | 「堅い（3連単 1,000円未満）」「中穴（1,000〜10,000円未満）」「万舟（10,000円以上）」の1つ | 堅い: 払戻 < 1,000／中穴: 1,000 ≤ 払戻 < 10,000／万舟: 払戻 ≥ 10,000 | 払戻が NULL の近傍（D-3） |

補足:
- 着順: 1着→2着→3着の3回タップが既定。「流す」をオンにすると2着・3着を複数選べる（フォーメーション）。1着は常に1艇。同じ艇が2つの着に入る組み合わせは点数に数えない。3着まで決まって点数が1点以上になるまで判定ボタンは押せない。点数を「1-3,4-2,3,4（4点）」の形で出す。2点以上のときは、一致した近傍の組み合わせ別の内訳を件数の多い順に上位4組と「ほか」で出す
- 1号艇: 「飛ぶ」には、1号艇が失格・転覆等で着外になったレースも入る（着順の列にいないため）
- 展開: 起点は艇番（号艇）で数える。決まり手の選択肢は4つ（抜き・恵まれは出さない）。結果に「そのとき2着に来た艇」の内訳（艇番ごとの件数、0件の艇は省く）を出す。これがスジ（2着の艇）にあたる
- 進入: 1・2号艇は選べない（モックどおり）。3号艇の「3コース以内」は枠なりと内への移動の両方を含む
- 配当の帯: 境界は「以上／未満」。1,000円ちょうどは中穴、10,000円ちょうどは万舟

#### スリットの判定
`c[1..6]` = その近傍の `st_by_course`（コース順の ST、秒）。差の線は強さの段で変わる（`t`）。

| 段 | 凹み `dent` | カド一撃 `kado` | ダッシュ勢 `out` | 艇身での言い方（案A） |
|---|---|---|---|---|
| 1段目（既定） | 0.05秒 | 0.03秒 | 0.05秒 | 約1/3艇身（カド一撃は約1/4艇身） |
| 2段目 | 0.08秒 | 0.05秒 | 0.08秒 | 約半艇身（カド一撃は約1/3艇身） |

| 形 | 条件 | 強さ | 全国の出現率（1段目／2段目） |
|---|---|---|---|
| 横一線 | max(c1..c6) − min(c1..c6) ≤ 0.06 | 効かない | 14.6% |
| 内3艇そろう | max(c1,c2,c3) − min(c1,c2,c3) ≤ 0.02 | 効かない | 15.4% |
| 2コース凹み | c2 − min(c1,c3) ≥ dent | 効く | 32.8%／13.6% |
| カド受け凹み | c3 − min(c2,c4) ≥ dent | 効く | 26.0%／12.0% |
| カド一撃 | min(c1,c2,c3) − c4 ≥ kado | 効く | 14.9%／8.0% |
| イン凹み | c1 − c2 ≥ dent | 効く | 12.1%／5.2% |
| ダッシュ勢先行 | (c1+c2+c3)/3 − (c4+c5+c6)/3 ≥ out | 効く | 15.2%／7.1% |

- 2形を選んだら両方を満たす近傍を数える（AND）。3形目を選ぶと最も古く選んだ形が外れる（モックどおり、最大2形）
- 強さの段は選んだ形すべてに同じ段を使う。横一線・内3艇そろうだけを選んだときは強さの選択を隠す（**画面差分 D1、ユーザー確認中**）
- 「自分で作る（1艇ずつ）」: 各コースを「指定なし→出る→凹む」の3状態で切り替える（**画面差分 D2、ユーザー確認中**。モックの「そろう」は実際には条件なしとして動いていたため）。6艇平均 a = (c1+…+c6)/6 として、出る: a − c_k ≥ 0.05、凹む: c_k − a ≥ 0.05。指定したコースすべてを満たす近傍を数える。1コースも指定していなければ判定ボタンは押せない。7形とは排他（どちらか一方）
- 1艇身 ≒ 0.13秒（公式の艇の全長 289.5cm ÷ 最高速度 時速約80km）。スリット付近はまだ加速中で、実際の1艇身はこれより少し長い秒数になる（モックの注記どおり画面に書く）
- 全国の出現率は形の一覧に添える。出典: 2026-03〜09 全国 30,546R（本番 ST・コース順、F・出遅れを除く。BOA-635 コメント 2026-10-01）。本 spec 作成時に `race_start_timings`（同期間、6艇の ST がそろい F・出遅れなし、2,951R）で再現し、各形で1ポイント以内（横一線 13.6%、内3艇 14.6%、2コース凹み 32.1%／13.6%、カド受け凹み 26.4%／12.3%、カド一撃 15.2%／8.0%、イン凹み 12.4%／5.2%、ダッシュ勢 15.0%／7.1%、1コース1着 54.9%）。画面に出す値は実装時に K/B 補完後のデータで出し直し、`docs/design/past-rate-check/analysis/` に記録して固定する（tasks T0-2）

受入基準:
- 固定の近傍データ（テスト用）で、6つの型すべての一致件数・分母・除いた件数が上の式どおりになる（`verify-past-rate-count.js`）
- スリットで2形を選ぶと件数が各形の件数以下になる。3形目を選ぶと最も古い形が外れる
- 着順の点数表示が、同じ艇を含む組み合わせを数えない

### FR-2 結果の見せ方（優先度: 高）

- 1行目に入力の要約（例:「3連単 1-3,4-2,3,4（4点）」「カド受け凹み＋カド一撃（約1/3艇身以上）」）
- 主文:「過去{N}レース中 {c}回（{p}%）」。回数を最も大きく、% を添える。定番／レアのラベルを横に付ける（FR-3）
- 割合のメーター（横棒、0〜100%）
- 型ごとの内訳（着順の上位4組、展開の2着の艇）
- 除いた件数の行（あれば）
- 比べた相手の注記: 「比べた相手: 類似レース{N}件（今日と条件が近い過去のレース、{期間}）。定番は{x}%以上、レアは{y}%未満」。期間は BOA-271 FR-2 と同じ表記（母集団の最古〜`pool_cutoff`）
- 型や入力を変えたら結果を隠し、ボタンを押し直すまで出さない（モックどおり）

受入基準: 主文の N・c・% が FR-1 の数え方と一致する。入力を変えると結果が消える。

### FR-3 定番／レア（優先度: 高）

- 割合 p が x% 以上なら「定番」、y% 未満なら「レア」、その間は付けない
- x・y は検証で決めて固定する。初期値（モックの例）は x=15、y=5。**線の決め方はユーザー確認中 Q2（推奨案を下に書く）**
- **検証方法（推奨案。結果を見る前にここで固定する）**:
  1. 対象: 2026-04〜09 の test 28,185R（BOA-271 MD-6 と同じ母集団・同じ近傍の方式 knn_p、k=800）。近傍は BOA-271 Phase M の分析環境で作り直す
  2. 型ごとに全選択肢を並べる（着順は3連単120点の1点ずつ。流しは選択肢が多すぎるので1点で代表させる。1号艇3、展開 6艇×4、スリットは7形×2段と2形の組み合わせ（強さが効く形どうし）、進入 4艇×3、配当の帯3）
  3. 各 test レース×各選択肢で、近傍での割合 p と、そのレース自身でその予想が起きたか（0/1）を出す
  4. 判定: 「定番」と付く (レース, 選択肢) の、実際に起きた割合が x% 以上、「レア」と付くものが y% 未満であること。型ごとに判定し、レース単位のブートストラップ95%CI も記録する（判定は点推定で行う）
  5. 初期値 (15, 5) が全型で満たせば採る。満たさない型があれば、事前に並べた候補 (20, 5) → (15, 3) → (25, 3) → (10, 3) を順に試し、最初に全型で満たした組を採る。どれも満たさなければ線を出さずにユーザーへ報告する
  6. あわせて型ごとに「定番が付く割合・レアが付く割合」を出す（例: 1号艇の「1着」はほぼ常に定番、3連単1点はほぼ常にレアになる見込み。絶対値の線なので当然の結果で、そのまま出す）
  7. 結果は `docs/design/past-rate-check/analysis/label-threshold-result.md` に残し、採った x・y を本 spec に書き戻す
- 別案（不採用の推奨）: 全国の出現率との比で決める相対の線。基準率の保存と、画面での説明（「全国より多い」）が増える

受入基準: 採った線と検証の数字（型ごとの実際の発生率・CI・ラベルが付く割合）が analysis に残っている。画面のラベルが線どおりに付く（境界値 x・y ちょうどのテストを含む）。

### FR-4 発走前と発走後の表示（優先度: 高）

**発走前（AI予想タブ）**
- AI予想タブの一番上に置く。見出し「あなたの予想」、型の切り替え6つ、入力、ボタン「過去に発生した割合を見る」、結果
- 出す条件: 中止確定でない、かつ `get_analogy_neighbors` が1行以上返す（スナップショットがある）。どちらかを満たさなければ部品ごと出さない（BOA-271 の節と同じ）。予想（predictions）の有無とは切り離す（BOA-271 FR の T9-1 と同じ）
- 発走後（確定後）も AI予想タブで使える。ただし締切後の入力は保存しない（FR-5）

**発走後（結果タブ）**
- 結果タブ（`RaceResult`、確定後だけあるタブ）に「振り返り」を足す
- 比べる類似レースは発走前のスナップショット（RPC は締切後に作り直さない。ADR-0080）
- 行1〜: この端末に保存された、締切前に入れた予想を型の順にすべて出す（**画面差分 D3、ユーザー確認中**）。各行「あなたの予想 {要約} は、過去{N}レース中 {c}回（{p}%）{ラベル}」。数字は保存した値を出す（入力したときに見せたもの）
- 最後の行: 「決着 {rank1-rank2-rank3} は、過去{N}レース中 {r}回（{p}%）{ラベル}」。着順の型と同じ数え方で、今の RPC の返り値から数える
- 保存した予想が無い（別の端末・30日経過・入力しなかった）ときは、決着の行だけ出す
- 当たり／外れの表示は付けない
- 不成立のレース（`race_status = 'no_race'`）では振り返りを出さない
- 保存したスナップショット（`model_version`・`asof_stage`・`asof_at`）と今の RPC の返り値が違うときは、決着の行の下に「入力したときと比べた類似レースが変わっています」と出す（通常は起きない。運用で近傍を作り直したときの保険）

受入基準: 締切前に保存した予想が結果タブに型の順で出る。締切後に入れた予想は出ない。保存が無いとき決着の行だけ出る。当たり／外れの文言が無い。

### FR-5 端末内保存（優先度: 高）

- 保存先: `localStorage`。キー `boatai:past-rate-check:v1`（リポジトリの既存キー `boatai:visited-before` 等と同じ `boatai:` 接頭辞・kebab-case。モックの案 `boatai.pastRateCheck.v1` から表記だけ変えた）
- 値: `{ "v": 1, "entries": [Entry, …] }`
- Entry:

| 項目 | 型 | 中身 |
|---|---|---|
| `raceId` | string | `YYYY-MM-DD-VV-RR` |
| `type` | string | `order`／`boat1`／`tenkai`／`slit`／`entry`／`payout` |
| `input` | object | 型ごとの入力（下の表）。表示用の要約文は保存しない（言語を切り替えても再生成できるように） |
| `savedAt` | string | 入力した時刻（ボタンを押した時刻、ISO 8601、端末の時計） |
| `snapshot` | object | `{ modelVersion, asofStage, asofAt }`。`analogy_snapshots` の一意制約（race_id, asof_stage, model_version）と同じ組で BOA-627 のスナップショットを指す。RPC は `snapshot_id` を返さないので、この組を使う（マイグレーション115 は変えない） |
| `result` | object | `{ n, count, excluded }`（入力したときに見せた数字） |

| type | input |
|---|---|
| order | `{ first: number, second: number[], third: number[], nagashi: boolean }` |
| boat1 | `{ outcome: "win" \| "top3" \| "out" }` |
| tenkai | `{ boat: number, technique: "逃げ" \| "差し" \| "まくり" \| "まくり差し" }`（値は DB の `winning_technique` と同じ日本語。表示は i18n） |
| slit | `{ mode: "pattern", patterns: string[], level: 1 \| 2 }` または `{ mode: "custom", courses: (-1 \| 0 \| 1)[] }`（-1 凹む、0 指定なし、1 出る） |
| entry | `{ boat: 3..6, target: "within3" \| "within4" \| "waku" }` |
| payout | `{ band: "low" \| "mid" \| "high" }` |

- 保存するとき: ボタン「過去に発生した割合を見る」を押して結果を出したとき。入力の途中では保存しない
- 締切後は保存しない: 押した時刻が締切（`getDeadlineDate(raceId, startTime)`、`src/utils/raceDeadlineStatus.js`）以降なら保存しない。締切が分からないレースは、レースが確定していなければ保存する
- 1レース×1型につき最新の1件（同じレース・同じ型の既存を置き換える）
- 30日で消す: `savedAt` から30日を過ぎた Entry を、読み込み・書き込みのたびに取り除く
- 件数の上限: 1,000件。超えたら `savedAt` の古いものから消す（30日×1日数十レースでも収まる量。localStorage の容量対策）
- 失敗の扱い: localStorage が使えない（プライベートモード・容量超過・無効化）、または中身が壊れている（JSON として読めない・`v` が違う）ときは、機能そのもの（判定・表示）は動かし、保存と振り返りだけをしない。壊れた値は読み込み時に捨てて作り直す。エラーは console に出し、画面には出さない
- 会員登録・サーバー送信はしない

受入基準: 押すたびに同じキーへ保存され、同じレース・型は1件に置き換わる。30日を過ぎた Entry が次の読み込みで消える。締切後に押しても保存されない。localStorage が例外を投げても結果は出る。

### FR-6 BOA-430 への埋め込みを見越した部品の境界（優先度: 中）

BOA-430（思考アシスト）では Step2（展開・スリット）と Step4（買い目）に同じ部品を埋め込む（2026-10-01 ユーザー回答。別画面は作らない）。BOA-430 の spec はまだ無いので、本 spec では境界だけ決め、BOA-430 側の具体は BOA-430 で決める。

- 判定・数え方・ラベル・保存は React に依存しない純粋関数にし、部品の外から呼べるようにする
- 画面の部品は次の props を受ける
  - `neighbors`（RPC の行の配列）、`raceId`
  - `types`（出す型の部分集合と順。既定は6つ全部）。例: BOA-430 Step2 は `["tenkai", "slit"]`、Step4 は `["order"]`
  - `value`・`onChange`（任意。型と入力を外から持つ制御モード。Step4 の買い目カートから着順を流し込む用）
  - `persist`（既定 true。保存するか）
- データ取得（`useAnalogyNeighbors`）は部品の外で行い、`neighbors` で渡す。BOA-271 の節と同じ近傍を共有する

受入基準: `types` を渡すとその型だけ・その順で出る。`value` を渡すと内部の入力を使わない。`persist=false` で保存しない。

## 非機能要件
- モバイル 375px で横スクロールなし（`npm run test:layout` の5幅）。スリットの7形の絵は1列で縦に並べる（モックどおり）
- 判定は800行の配列を数えるだけなので、ボタンを押してから100ms 以内に結果を出す（通信なし）
- 用語ルール（画面内で「競艇」禁止）、`design-tokens.css` のトークン、`!important` 禁止、ダークモード
- i18n: 翻訳対象（4言語）。AI予想タブ・BOA-271 の節と同じ扱い
- a11y: 型の切り替えは tablist、艇のボタンは `aria-pressed`、結果は `aria-live="polite"`、スリットの絵は `role="img"` と説明の `aria-label`
- 新しい集計を含むため、実装後に `data-accuracy-verifier` で、画面の件数と実データ（近傍の行を SQL で数えた値）の一致を検証する

## 制約・前提
- データ源: `get_analogy_neighbors`（BOA-271、マイグレーション115）。D-1〜D-4 が前提
- 近傍は出走表時点の1段だけ（ADR-0080）。展示・気象は距離に入らない
- 会員登録なし、端末内保存のみ
- 法的: 既存の免責文（投票は日本国内在住・20歳以上、結果を保証しない）は AI予想タブにあるものをそのまま使う。本機能で新しい免責文は足さない
- 既存部品: 艇の色は `src/utils/colors.js` の `BOAT_COLORS`、艇番の表示は BOA-271 T5-1 で切り出す `BoatBadge` を使う

## 既定値で決定した事項（ユーザーが後から覆せる）
| 項目 | 既定値 | 根拠 |
|---|---|---|
| 分母 | 型ごとに判定できる近傍だけ。除いた件数を理由つきで出す | 判定できない近傍を「不一致」に数えると割合が下がる。BOA-271 plan の「決着が無い近傍は数えず件数を出す」と同じ流儀 |
