# 過去に発生した割合を見る spec

種別: UI機能（集計は画面側。新しいテーブル・バッチ・API なし）
対応Linearチケット: BOA-635（関連: BOA-271 類似レース、BOA-627 時点付きスナップショット、BOA-430 思考アシスト）

確定モック: https://claude.ai/artifact/RHjYWn3GWXYUetEHf6M7aq （Version 3、2026-10-01 ユーザー確認済み）。決定の経緯は BOA-635 のコメント3件。

## 位置づけ

- ユーザーが入れた予想が、今日のレースの「類似レース」（BOA-271 FR-2 の近傍）で過去に何回起きたかを数えて見せる
- 数えるのはユーザーの予想が過去に起きた回数。AI の当たり外れは数えない
- 呼び方: 機能・ボタンは「過去に発生した割合を見る」。比べる相手は「類似レース」（BOA-271 の見出しと同じ）。「あなたの読み」「似たレース」「少数派／多数派」「前例レース」は使わない
- サイト内に「AI がやらないこと」のような否定形の説明文は書かない（2026-10-01 ユーザー指示）
- BOA-627 の保存項目のうち3（ユーザーの読みと発走前の時刻）を、本機能の端末内保存で満たす

## 実装開始の前提条件

1. BOA-271 Phase U の T1（マイグレーション115 の本番適用）・T3（近傍のバッチ）・T5-2（`analogyService.js`）が済み、`get_analogy_neighbors` が本番で近傍を返していること。BOA-271 の「実装開始の前提条件」（K/B 補完の判定 等）をそのまま引き継ぐ
2. 下の「母集団の約束」D-1〜D-6 が本番の `analogy_pool_outcomes` で守られていること（BOA-271 T2-3 の pytest と、本機能の T0-3 の実測で確かめる）
3. 定番／レアの線の検証（下の FR-3、tasks T0）が済んでいること。画面に線を出すのはその後

## データ（土台）

`get_analogy_neighbors(race_id)`（BOA-271、マイグレーション115）の返り値だけで数える。1行＝近傍の過去レース1件、近い順に最大800行。画面の部品は、BOA-271 の `useAnalogyNeighbors(raceId)` が返す行の配列（RPC の返り値の行そのまま、近い順）を受け取る。取得経路（`/api/analogy/neighbors/[raceId]`、失敗時は PostgREST の RPC 直読み）と応答の形は BOA-271 plan の「API」節に従う。

| 列 | 使う型 |
|---|---|
| `rank1`・`rank2`・`rank3` | 着順・1号艇・展開（2着の内訳） |
| `winning_technique`（6分類） | 展開 |
| `course_by_boat`（[1号艇のコース, …, 6号艇のコース]） | 進入・スリット（今日の艇番とは無関係。過去レースのコース順をそろえるのに使うのは `st_by_course` 側） |
| `st_by_course`（[1コースのST, …, 6コースのST]） | スリット |
| `payout_3tan`（3連単の払戻。D-1） | 配当の帯 |
| `model_version`・`asof_stage`・`asof_at` | 保存（スナップショットとの紐づけ） |

### 母集団の約束（BOA-271 の母集団の前提。2026-10-02 に依頼し、BOA-271 のマイグレーション案115・plan.md「値の約束」に反映済み（PR #1039 e3f55d553）。tasks T2-3 の pytest で固定される）
- **D-1** `payout_3tan` は3連単の払戻（列名は `kb_archive_races.payout_3tan` と同じ）。本体の `race_results` は `payout_trifecta`＝3連複・`payout_trio`＝3連単と名前が逆転しているので、母集団には `payout_trio` を入れる。取り違えると配当の帯がすべてずれる（BOA-271 で反映済み、PR #1039 e3f55d553）
- **D-2** `st_by_course` は、フライング・出遅れ・欠場のコースを NULL にする（数値のままだとフライングの艇が「速いST」に見え、カド一撃などが過大に出る）。判定元は本体 `race_start_timings.is_flying`・`is_late_start`、長期 `kb_archive_boats.is_flying`・`is_late_start`
- **D-3** 3連単の払戻は、不成立・特払いのレースで NULL（不成立の¥100を払戻として入れない。`race_results.race_status`）
- **D-4** `course_by_boat` は、実進入が分からない艇を NULL にする（艇番で埋めない。BOA-523 の欠落期間で「枠なり」に化けるため）
- **D-5** `rank1`〜`rank3` に返還艇（F・L・欠）が入るレースと、不成立のレースは、決着なし（母集団に入れないか rank を NULL にし、分母から除く）。本体の `race_results.rank*` は返還艇も公式の並びのまま入っている（`RaceResult.jsx:236-246`。上位3着に返還艇が入るのは 2026-03〜09 の 32,858R 中16R）。`race_results.race_status` は 2026-09-20 より前でほぼ NULL なので、返還艇の判定は `race_start_timings.is_flying`・`is_late_start`・`finish_mark` も使う（設計レビュー 2026-10-02 指摘6・10。BOA-271 へ依頼）
- **D-6** 1レースのスナップショットは版をまたいで1つ。近傍のバッチの「スナップショット未作成」はレース単位で判定する（版の切り替え後に同じレースへ2つ目を作らない）（設計レビュー 2026-10-02 の未再現の疑い。BOA-271 へ依頼）

## 機能要件

### 共通の数え方

- **分母 N**: 近傍800件のうち、その型の判定に要る値がそろっている件数（型ごとに変わる）。決着が無い近傍（LEFT JOIN で `rank1` が NULL、または D-5 の不成立）はどの型でも除く
- **除いた件数**: 理由ごとに1行ずつ、件数が1以上の理由だけ出す。理由と文言: 決着なし「決着が分からない{k}レースを除く」、スリット「スタートタイミングがそろわない{k}レースを除く」、進入「進入が分からない{k}レースを除く」、配当の帯「払戻が無い{k}レースを除く」。1件の近傍に複数の理由があるときは、決着なしを先に数える（型ごとの理由は決着がある近傍の中で数える）
- **ST の比べ方**: ST は `Math.round(st × 100)` の整数（1/100秒）にしてから比べる。浮動小数のまま `>=` で比べると、差が線ちょうどのレースで判定が割れる（例: JS で 0.15−0.10 = 0.04999…）。30,546R で、浮動小数のままだと内3艇そろう 15.4%→10.9%、2コース凹み 32.8%→29.1% にずれる（設計レビュー 2026-10-02 指摘2、手元で再現）。Python の検証スクリプトも同じく整数で比べる
- **件数**: 常に近傍800件すべてを使う。BOA-271 の件数スライダー（100／200／400／800件）とは連動させない（Q1、2026-10-02 オーケストレーター判断で推奨案を採用。ユーザーへは事後報告で、異論があれば直す）
- **割合**: c ÷ N を百分率で小数1桁（四捨五入）。N=0 なら主文・割合・メーター・ラベルを出さず「この型を判定できる類似レースがありません」。要約と除いた件数の行は出す
- 1回の判定は1つの型。型をまたいだ組み合わせ（例: 着順かつスリット）はしない。組み合わせはスリットの中の2形まで

### FR-1 6つの型の判定（優先度: 高）

型の並び順は 着順 → 1号艇 → 展開 → スリット → 進入 → 配当の帯（確定）。

| 型 | 入力 | 一致の条件（近傍1件ごと） | 分母から除く近傍 |
|---|---|---|---|
| 着順 | 1着（1艇）・2着（1艇、「流す」で複数）・3着（1艇、「流す」で複数） | `rank1 ∈ 1着` かつ `rank2 ∈ 2着` かつ `rank3 ∈ 3着` | なし（決着がある近傍すべて） |
| 1号艇 | 「1着」「残る（3着以内）」「飛ぶ（4着以下）」の1つ | 1着: `rank1=1`／残る: 1 ∈ {rank1,rank2,rank3}／飛ぶ: 1 ∉ {rank1,rank2,rank3} | なし |
| 展開 | 起点の艇（1〜6号艇の1艇）＋決まり手（逃げ・差し・まくり・まくり差し の1つ） | `rank1 = 起点の艇` かつ `winning_technique = 決まり手` | なし |
| スリット | 7形から1〜2形＋強さ（1段目／2段目）、または「自分で作る」 | 下の「スリットの判定」 | `st_by_course` に NULL を含む近傍（D-2） |
| 進入 | 艇（3〜6号艇の1艇）＋「3コース以内に入る」「4コース以内に入る」「枠なりのまま」の1つ | 3コース以内: `course_by_boat[艇] ≤ 3`／4コース以内: `≤ 4`／枠なり: `course_by_boat[艇] = 艇番` | その艇の `course_by_boat` が NULL の近傍（D-4） |
| 配当の帯 | 「堅い（3連単 1,000円未満）」「中穴（1,000〜10,000円未満）」「万舟（10,000円以上）」の1つ | 堅い: 払戻 < 1,000／中穴: 1,000 ≤ 払戻 < 10,000／万舟: 払戻 ≥ 10,000 | 払戻が NULL の近傍（D-3） |

補足:
- 着順: 1着→2着→3着の3回タップが既定。「流す」をオンにすると2着・3着を複数選べる（フォーメーション）。1着は常に1艇。同じ艇を複数の着で選ぶことはでき（ボタンは disabled にしない）、同じ艇が2つの着に入る組み合わせは点数に数えない。流さないときに同じ着で別の艇を押すと置き換わる。流すときは押すたびに選択が入れ替わる（もう一度押すと外れる）。3着まで決まって点数が1点以上になるまで判定ボタンは押せない。点数を「1-3,4-2,3,4（4点）」の形で出す。2点以上のときは、一致した近傍の組み合わせ別の内訳を件数の多い順（同数は組み合わせの昇順）に上位4組、5組目以降があれば「ほか」を付けて出す。区切りは「、」
- 1号艇: 「飛ぶ」には、1号艇がフライング・失格・転覆等で着外になったレースも入る（その艇は3着以内の列にいない。3着以内の列に返還艇がいるレースは D-5 で除かれる）
- 展開: 起点は艇番（号艇）で数える。決まり手の選択肢は4つ（抜き・恵まれは出さない）。結果に「そのとき2着に来た艇」の内訳（艇番ごとの件数、0件の艇は省く、件数の多い順・同数は艇番順、区切り「、」）を出す。これがスジ（2着の艇）にあたる
- 進入: 1・2号艇は選べない（モックどおり）。3号艇の「3コース以内」は枠なりと内への移動の両方を含む
- 配当の帯: 境界は「以上／未満」。1,000円ちょうどは中穴、10,000円ちょうどは万舟

#### スリットの判定
`c[1..6]` = その近傍の `st_by_course`（コース順の ST）を1/100秒の整数にしたもの。差の線は強さの段で変わる（`t`）。下の表の秒数は、判定では100倍した整数（0.05秒→5）で使う。

| 段 | 凹み `dent` | カド一撃 `kado` | ダッシュ勢 `out` | 艇身での言い方（案A） |
|---|---|---|---|---|
| 1段目（既定） | 0.05秒 | 0.03秒 | 0.05秒 | 約1/3艇身（カド一撃は約1/4艇身） |
| 2段目 | 0.08秒 | 0.05秒 | 0.08秒 | 約半艇身（カド一撃は約1/3艇身） |

| 形 | 条件 | 強さ | 全国の出現率（1段目／2段目） |
|---|---|---|---|
| 横一線 | max(c1..c6) − min(c1..c6) ≤ 6 | 効かない | 14.6% |
| 内3艇そろう | max(c1,c2,c3) − min(c1,c2,c3) ≤ 2 | 効かない | 15.4% |
| 2コース凹み | c2 − min(c1,c3) ≥ dent | 効く | 32.8%／13.6% |
| カド受け凹み | c3 − min(c2,c4) ≥ dent | 効く | 26.0%／12.0% |
| カド一撃 | min(c1,c2,c3) − c4 ≥ kado | 効く | 14.9%／8.0% |
| イン凹み | c1 − c2 ≥ dent | 効く | 12.1%／5.4% |
| ダッシュ勢先行 | (c1+c2+c3) − (c4+c5+c6) ≥ 3 × out | 効く | 15.2%／6.7% |

- 2形を選んだら両方を満たす近傍を数える（AND）。3形目を選ぶと最も古く選んだ形が外れる。選択中の形をもう一度押すと外れる（モックどおり、最大2形）
- 形のキー（保存に使う）: 横一線 `flat`、内3艇そろう `wall`、2コース凹み `d2`、カド受け凹み `d3`、カド一撃 `kado`、イン凹み `d1`、ダッシュ勢先行 `dash`
- 強さの段は選んだ形すべてに同じ段を使う。横一線・内3艇そろうだけを選んだときは強さの選択を隠す（画面差分 D1、2026-10-02 採用）
- 「自分で作る（1艇ずつ）」: 各コースを「指定なし→出る→凹む」の3状態で切り替える（画面差分 D2、2026-10-02 採用。モックの「そろう」は実際には条件なしとして動いていたため）。合計 S = c1+…+c6 として、出る: S − 6×c_k ≥ 30（6艇平均より0.05秒以上速い）、凹む: 6×c_k − S ≥ 30。指定したコースすべてを満たす近傍を数える。1コースも指定していなければ判定ボタンは押せない。7形とは排他（どちらか一方）
- 1艇身 ≒ 0.13秒（公式の艇の全長 289.5cm ÷ 最高速度 時速約80km）。スリット付近はまだ加速中で、実際の1艇身はこれより少し長い秒数になる（モックの注記どおり画面に書く）
- 全国の出現率は形の一覧に添える。出典: 2026-03〜09 全国 30,546R（本番 ST は `race_start_timings`、コース順は `race_results.actual_course_1..6`（i号艇のコース）、6艇の ST がそろい F・出遅れなし、整数で比較）。2026-10-02 に本番 DB で上の表の値を再現した（1段目7値と2段目 13.6／12.0／8.0 は BOA-635 コメントどおり、2段目のイン凹み 5.4%・ダッシュ勢 6.7% は初版の 5.2／7.1 を訂正。1コース1着 55.5%）。初版は `race_start_timings.entry_course` を使ったが、この列は 2026-08 までほぼ空で 2,951R（うち9月が60%）にしかならず、母集団として誤りだった（設計レビュー 2026-10-02 指摘5）。画面に出す値は実装時に K/B 補完後のデータで出し直し、`docs/design/past-rate-check/analysis/` に記録して固定する（tasks T0-2。コース順の源は本体 `race_results.actual_course_*`、長期 `kb_archive_boats.course`）

受入基準:
- 固定の近傍データ（テスト用）で、6つの型すべての一致件数・分母・除いた件数が上の式どおりになる（`verify-past-rate-count.js`）。固定データには、各形で差が線ちょうど（0.05・0.02・0.06・0.03 等。浮動小数で割れる組 0.15/0.10、0.21/0.16 を含む）の行を入れる
- スリットで2形を選ぶと件数が各形の件数以下になる。3形目を選ぶと最も古い形が外れる
- 着順の点数表示が、同じ艇を含む組み合わせを数えない

### FR-2 結果の見せ方（優先度: 高）

- 1行目に入力の要約。型ごとの文言:
  - 着順:「3連単 1-3,4-2,3,4（4点）」（1点も「3連単 1-2-3（1点）」）
  - 1号艇:「1号艇が1着」「1号艇が3着以内に残る」「1号艇が4着以下に飛ぶ」
  - 展開:「3号艇のまくり」
  - スリット:「カド受け凹み＋カド一撃（約1/3艇身以上）」、強さが効かない形だけなら「横一線」、自分で作るは「4コースが出る・1コースが凹む」（コース順）
  - 進入:「4号艇が3コース以内に入る」「6号艇が枠なりのまま」
  - 配当の帯:「3連単が万舟（10,000円以上）」
- 主文:「過去{N}レース中 {c}回（{p}%）」。回数を最も大きく、% を添える。定番／レアのラベルを横に付ける（FR-3）
- 割合のメーター（横棒、0〜100%）
- 型ごとの内訳（着順の上位4組、展開の2着の艇）
- 除いた件数の行（あれば）
- 比べた相手の注記: 「比べた相手: 類似レース{M}件（今日と条件が近い過去のレース、{期間}）。定番は{x}%以上、レアは{y}%未満」。M は RPC が返した近傍の行数（通常800。型ごとの分母 N とは別）。期間は近傍の `race_date` の最小〜最大を「2019-04〜2025-11」の形で出す（RPC は `pool_cutoff` を返さないため。設計レビュー 2026-10-02 指摘12）
- 型や入力を変えたら結果を隠し、ボタンを押し直すまで出さない（モックどおり）

受入基準: 主文の N・c・% が FR-1 の数え方と一致する。入力を変えると結果が消える。

### FR-3 定番／レア（優先度: 高）

- 割合 p が x% 以上なら「定番」、y% 未満なら「レア」、その間は付けない
- x・y は検証で決めて固定する。初期値（モックの例）は x=15、y=5。線の決め方は Q2（2026-10-02 オーケストレーター判断で下の推奨案を採用）
- **検証方法（結果を見る前にここで固定する。2026-10-02 設計レビュー指摘3・4・9 を受けて初版から作り直した）**:
  - 初版の「定番と付いた全体の実際の発生率 ≥ x」は、もともと発生率の高い選択肢（1号艇1着・1号艇の逃げ・2コース凹み）で埋まるので、近傍の質や線の位置と関係なく通り、線を選べなかった。線のすぐそばの選択肢（横一線 全国14.6%、カド一撃 14.9%、イン凹み2段目 5.4%）は、N=800 の標本の揺れ（p=15% で標準偏差 約1.3ポイント）だけで定番と無印が入れ替わるが、初版はそれを測れなかった
  1. 近傍: BOA-271 の本番の定義（出走表時点の1段、ローリングは日単位でずらす。BOA-271 T0-4・T0-5 の後）で、test 2026-04〜09 の各レースに近傍800件を作る。Phase M の MD-6 の近傍（直前情報入り・レース単位のずらし）は使わない
  2. 選択肢: 型ごとに全部並べる。着順は1点（120通り）と代表の流し（1着1艇×2着は残り5艇から2艇×3着は残りから3艇、の全組）。1号艇3、展開 6艇×4、スリットは7形×2段と2形のすべての組×2段、自分で作るは1コース指定（12通り）と2コース指定（60通り）、進入 4艇×3、配当の帯3
  3. 各 (test レース, 選択肢) で、近傍での割合 p、そのレース自身で起きたか（0/1）、全国の発生率 q（近傍の母集団全体での割合）を出す
  4. **判定（合否）: 線のまわりで、言葉と実際が食い違わないこと。** 型ごとに、p ∈ [x, x+5) で「定番」と付いたものの実際の発生率が x% 以上、p ∈ [y−2, y) で「レア」と付いたものの実際の発生率が y% 未満。点推定で判定し、レース単位のブートストラップ95%CI を記録する。その帯の件数が200未満の型・ラベルは「判定不能」とし、不合格には数えない（件数は記録する）
  5. **報告（合否に使わない）**: 型ごとに (a) 定番・レアが付く割合、(b) 付いたもののうち、p の Wilson 95% 区間が線をまたがない割合（標本の揺れでラベルが入れ替わりうるものの多さ）、(c) p の Brier skill（q に対する上積み）と CI
  6. 初期値 (15, 5) が全型で合格（判定不能を含む）なら採る。不合格の型があれば、候補 (20, 5) → (15, 3) → (25, 3) → (10, 3) を順に試し、最初に全型で合格した組を採る。どれも合格しなければ線を出さずにユーザーへ報告する
  7. 次のどれかに当たる型があれば、線を採ったうえでユーザーに報告し、その型だけ相対の線（全国比）に変えるかを Q2 としてユーザーに戻す: 5(b) が50%未満、5(c) の CI が0をまたぐ（近傍で比べる意味が薄い）、5(a) で定番かレアの一方が95%以上を占める（例: 3連単1点はほぼ常にレア、1号艇1着はほぼ常に定番になる見込み。着順は既定の型なので、主な入力の大半に「レア」が付く）
  8. 結果は `docs/design/past-rate-check/analysis/label-threshold-result.md` に残し、採った x・y を本 spec に書き戻す
- 別案（今は採らない）: 全国の出現率との比で決める相対の線。基準率の保存と、画面での説明（「全国より多い」）が増える。上の7でユーザーに戻す余地を残す

受入基準: 採った線と検証の数字（型ごとの線のまわりの実際の発生率・CI・判定不能の件数・ラベルが付く割合・Wilson 区間・Brier skill）が analysis に残っている。画面のラベルが線どおりに付く（境界値 x・y ちょうどのテストを含む）。

### FR-4 発走前と発走後の表示（優先度: 高）

**発走前（AI予想タブ）**
- AI予想タブの一番上に置く。見出し「あなたの予想」、型の切り替え6つ、入力、ボタン「過去に発生した割合を見る」、結果
- 出す条件: 中止確定でない、かつ `get_analogy_neighbors` が1行以上返す（スナップショットがある）。どちらかを満たさなければ部品ごと出さない（BOA-271 の節と同じ）。取得に失敗したときは、部品の位置に `InlineFetchError`（再試行つき）を出す（`.claude/rules/frontend-data-fetch.md` の3。「無い」と同じ表示に倒さない）。取得中は何も出さない予想（predictions）の有無とは切り離す（BOA-271 FR の T9-1 と同じ）
- 発走後（確定後）も AI予想タブで使える。ただし締切後の入力は保存しない（FR-5）

**発走後（結果タブ）**
- 結果タブ（`RaceResult`、確定後だけあるタブ）に「振り返り」（見出し「振り返り」、各行は1つのリストの listitem）を足す。近傍の取得に失敗したときは `InlineFetchError`（再試行つき）、近傍が0行のときは出さない
- 比べる類似レースは発走前のスナップショット（RPC は締切後に作り直さない。ADR-0080）
- 行1〜: この端末に保存された、締切前に入れた予想を型の順にすべて出す（画面差分 D3、2026-10-02 採用）。`savedAt` が締切以降の Entry は出さない（保存しない仕様の二重の守り）。各行「あなたの予想 {要約} は、過去{N}レース中 {c}回（{p}%）{ラベル}」。数字とラベルは保存した値を出す（入力したときに見せたもの。後で線を変えても変わらない）
- 最後の行: 「決着 {1着-2着-3着} は、過去{N}レース中 {r}回（{p}%）{ラベル}」。決着は `RaceResult` が結果表のために組み立てた着順（返還艇を外したもの）の1〜3着を使う。1〜3着がそろわない（返還艇が上位にいて3着まで決まらない等）ときは決着の行を出さない。数え方は着順の型（1点）と同じで、今の RPC の返り値から数える。ラベルは今の線で付ける
- 保存した予想が無い（別の端末・30日経過・入力しなかった）ときは、決着の行だけ出す
- 当たり／外れの表示は付けない
- 不成立のレース（`race_status = 'no_race'`）では振り返りを出さない
- 保存したスナップショット（`model_version`・`asof_stage` は文字列、`asof_at` は時刻として比べる。表記の違い「Z」「+00:00」で食い違わないように）と今の RPC の返り値が違うときは、決着の行の下に「入力したときと比べた類似レースが変わっています」と出す（通常は起きない。運用で近傍を作り直したときの保険）

受入基準: 締切前に保存した予想が結果タブに型の順で出る。締切後に入れた予想は出ない。保存が無いとき決着の行だけ出る。当たり／外れの文言が無い。

### FR-5 端末内保存（優先度: 高）

- 保存先: `localStorage`。キー `boatai-user:past-rate-check:v1`。`boatai:` で始めない: `supabaseDataService.js:138` のデータキャッシュは `boatai:` を接頭辞にしており、更新ボタン（`dataService.clearCache()`、`App.jsx:65`・`VenueGridPage.jsx:103`）が `boatai:` で始まるキーをすべて消し、容量超過時の掃除（`_cleanupOldCache`）も `boatai:*` の半分を消すため（設計レビュー 2026-10-02 指摘1。既存の `boatai:visited-before`・`boatai:cookie-consent` も同じ理由で消えている。別スコープで起票）
- 値: `{ "v": 1, "entries": [Entry, …] }`
- Entry:

| 項目 | 型 | 中身 |
|---|---|---|
| `raceId` | string | `YYYY-MM-DD-VV-RR` |
| `type` | string | `order`／`boat1`／`tenkai`／`slit`／`entry`／`payout` |
| `input` | object | 型ごとの入力（下の表）。表示用の要約文は保存しない（言語を切り替えても再生成できるように） |
| `savedAt` | string | 入力した時刻（ボタンを押した時刻、ISO 8601、端末の時計） |
| `snapshot` | object | `{ modelVersion, asofStage, asofAt }`。`analogy_snapshots` の一意制約（race_id, asof_stage, model_version）と同じ組で BOA-627 のスナップショットを指す。RPC は `snapshot_id` を返さないので、この組を使う（マイグレーション115 は変えない） |
| `result` | object | `{ n, count, excluded: [{ reason, count }], label: "standard" \| "rare" \| null }`（入力したときに見せた数字とラベル） |

| type | input |
|---|---|
| order | `{ first: number, second: number[], third: number[], nagashi: boolean }` |
| boat1 | `{ outcome: "win" \| "top3" \| "out" }` |
| tenkai | `{ boat: number, technique: "nige" \| "sashi" \| "makuri" \| "makurizashi" }`（`src/utils/turnPrediction.js` の `TECHNIQUE_NAMES` のキー。DB の `winning_technique`（日本語）とはこの表で対応させる。表示は i18n） |
| slit | `{ mode: "pattern", patterns: ("flat" \| "wall" \| "d2" \| "d3" \| "kado" \| "d1" \| "dash")[], level: 1 \| 2 }` または `{ mode: "custom", courses: (-1 \| 0 \| 1)[] }`（-1 凹む、0 指定なし、1 出る） |
| entry | `{ boat: 3..6, target: "within3" \| "within4" \| "waku" }` |
| payout | `{ band: "low" \| "mid" \| "high" }` |

- 保存するとき: ボタン「過去に発生した割合を見る」を押して結果を出したとき。入力の途中では保存しない
- 締切後は保存しない: 押した時刻が締切（`getDeadlineDate(raceId, startTime)`、`src/utils/raceDeadlineStatus.js`）以降なら保存しない。締切が分からないレースは、レースが確定していなければ保存する。時刻は端末の時計で判定する（時計が遅れている端末では締切後の入力が保存されうる。影響はその端末の振り返りだけなので受け入れる）
- 1レース×1型につき最新の1件（同じレース・同じ型の既存を置き換える）
- 30日で消す: `savedAt` から30日を過ぎた Entry を、読み込み（AI予想タブの部品の表示時・結果タブの振り返りの表示時）と書き込みのたびに取り除く
- 書き込みの直前に読み直してから、置き換えて書く（別のタブで保存した分を上書きで消さないため。同時に押した場合は後に書いた方が勝つ。それは受け入れる）
- 件数の上限: 1,000件。超えたら `savedAt` の古いものから消す（30日×1日数十レースでも収まる量。localStorage の容量対策）
- 失敗の扱い: localStorage が使えない（プライベートモード・容量超過・無効化）、または中身が壊れている（JSON として読めない・`v` が違う・`entries` が配列でない）ときは、機能そのもの（判定・表示）は動かし、保存と振り返りだけをしない。壊れた値は読み込み時に捨てて作り直す。Entry 単位で形が違うもの（必須項目の欠け・`type` が6つ以外・`input` の形が型と合わない・`savedAt` が時刻として読めない）は、その Entry だけ捨てる。エラーは console に出し、画面には出さない
- 会員登録・サーバー送信はしない

受入基準: 押すたびに同じキーへ保存され、同じレース・型は1件に置き換わる。30日を過ぎた Entry が次の読み込みで消える。締切後に押しても保存されない。localStorage が例外を投げても結果は出る。

### FR-6 BOA-430 への埋め込みを見越した部品の境界（優先度: 中）

BOA-430（思考アシスト）では Step2（展開・スリット）と Step4（買い目）に同じ部品を埋め込む（2026-10-01 ユーザー回答。別画面は作らない）。BOA-430 の spec はまだ無いので、本 spec では境界だけ決め、BOA-430 側の具体は BOA-430 で決める。

- 判定・数え方・ラベル・保存は React に依存しない純粋関数にし、部品の外から呼べるようにする
- 画面の部品は次の props を受ける
  - `neighbors`（RPC の行の配列）、`raceId`
  - `types`（出す型の部分集合と順。既定は6つ全部）。例: BOA-430 Step2 は `["tenkai", "slit"]`、Step4 は `["order"]`
  - `value`・`onChange`（任意。型と入力を外から持つ制御モード。Step4 の買い目カートから着順を流し込む用）
  - `persist`（既定 true。保存するか）
- データ取得（`useAnalogyNeighbors`）は部品の外で行い、`neighbors` で渡す。BOA-271 の節と同じ近傍を共有する

受入基準: `types` を渡すとその型だけ・その順で出る。`value` を渡すと内部の入力を使わない。`persist=false` で保存しない。

- i18n: 翻訳対象（4言語）。AI予想タブ・BOA-271 の節と同じ扱い
