# モーターの推移の線に何を描くか（2026-11-24）

オーナーの方針（2026-11-24）「時系列で表せる指標は6艇を重ねた時系列でも比べる。モーターも、会場の入れ替えを考えて時系列で」に先立つ確認。data-scientist が検証した。スクリプトは `scripts/analysis/motor-trend-window/`、結果は `data/analysis/motor-trend-window/result.json`・`result-racer-motor-change.json`。選手の線の検証は `racer-form-window.md`。

## データと作り方
- 入力: `data/ml/dataset.csv`・`start_timings.csv`（2026-09-14 に書き出した本番の写し、2026-02-18〜09-14。本番には接続していない）
- 写しに `motor_number` が無い（`scripts/ml/export-training-data.js` は読むが書き出さない）。出走表のモーター2連率・3連率は節の中で固定、世代の初めは全艇0、という性質から「累積の2連対数／走数」の予想と次の節の表示を突き合わせ、節ごとに基をつないだ（`reconstruct.py`）
- 再構成の品質: 節×艇 10,629 のうち次の節へつながった割合 83.4%。鎖の走から数えた累積2連率と公式の2連率の相関 0.935。本物の motor_number では確かめていない（近似）
- 対象: 世代の初めが写しの期間に入る16会場。予測の検定は、その節より前に50走以上ある467基・14会場。試す期間は 2026-08-01〜09-14、区間は日ごとのブートストラップ（1,000回）の95%

### 展示タイム（レース内の平均との差、6,941行）
基準と公式の累積2連率に、基の直近N走の展示の平均を足すと N20 −0.00144［−0.00224, −0.00057］、N30 −0.00129［−0.00205, −0.00048］。世代の累積は −0.00006 で効かない（理由は未検証）。

### 選手のモーターの替わり方
節の中でモーター2連率の表示が変わるのは 0.47%（21,859 選手×節）、続けて同じ会場の節は 1.1%。選手のモーターが替わる所はほぼ全て節の境。その節のモーターを選手の基準に足すと、素の2連率 −0.00055、会場・節の中の順位 −0.00091［−0.00143, −0.00039］（2連対、37,679行）。順位の3区分の実際と見込みの差は 下位 −1.9pt・中位 −0.8pt・上位 +2.0pt。

## 言えること・言えないこと
| 線 | 描くか | 見せ方 |
|---|---|---|
| モーター2連率・3連率 | 公式の累積を節ごとの点で | 窓の率は公式と当てる力が同じで上下の7〜9割が偶然なので描かない。描き始めは目安で20走（偶然の幅 ±21pt。根拠はこの表の N20、閾値の折れ目は無い） |
| 残差の50走（機力指数と同じ考え方） | 今は描かない | 公式を上回る唯一の窓だが基準の約0.1%。出せるのは入れ替えから約90日後 |
| 展示タイムの平均 | 直近30走で描く | 24走たまってから。選手の30走に合わせる |
| 選手の線の「モーターが替わった所」 | 節の境に、その節のモーターの会場内順位（上・中・下） | 素の2連率より順位が効く |

「調子」「好調」とは書かない（効き目は基準の0.1〜0.3%）。

## 残る検証（本番の読み取りが要る）
1. 本物の motor_number で再構成を確かめる。`race_entries`・`races`・`race_results`・`exhibition_data`・`venue_motor_start_dates` を会場×motor_number×日付の順に書き出し、同じ3本を回す（SQL の案は PR の本文）
2. 世代の後半（半年〜1年）。今回は入れ替えから3〜6か月の基だけ
3. 公式の走数が写しより1〜2多い補正が多い（+1 が476件・+2 が233件）。写しの抜けか、公式の数え方（欠場・F）の違いか
4. 前の節の成績が次の節の表示に入らない（1節遅れる）つなぎが 618件（5.8%）。docs の「2節目の初日から入る」と合わない場合がある
