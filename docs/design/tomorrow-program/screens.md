# 明日の出走表 screens

spec: [spec.md](./spec.md)。種別: UI機能。色はトークン（`src/styles/design-tokens.css`）と `GRADE_CONFIG`・`BOAT_COLORS` のみ。新しいクラスは `.tomorrow-` で始める（全ページの CSS が1つのバンドルに入るため）。

## 画面

| # | 画面 | 区分 | 役割・主要素 |
|---|---|---|---|
| S1 | トップ（`/`、`VenueGridPage` の本日ビュー） | 既存の拡張 | 会場グリッドの上に「本日 M/D / 明日 M/D」タブ。本日タブは今と同じ。明日タブは S1-b の会場グリッドと公開状況の案内を出す |
| S2 | 明日の出走表（会場ごと、新しいルート） | 新規ページ | 会場名・節名・日次・「M/D HH:MM 時点（JST）の公式番組表」の注記。1R〜12R を縦に並べ、各レースは見出し（R番号・締切予定 HH:MM（JST））と C5 の表（当日のデータ出走表と同じ部品）と表の下の案内。レース詳細へは遷移しない。パンくず: ホーム → 明日の開催 → 会場 |

S2 のパスは `/step2` で決める（候補: `/tomorrow/:venueCode`。`/venue/:venueCode` の配下に置くと本日の会場ページと混ざる）。翻訳対象のため `TRANSLATED_PATHS` に登録し、sitemap は内容が日替わりのため対象外（`EXPECTED_EXCLUSIONS`）を想定。

## コンポーネント

| # | コンポーネント | 新規/既存 | 役割 | 根拠・方針 |
|---|---|---|---|---|
| C1 | `DayTabs`（仮）| 新規（`src/components/race/`） | 「本日 / 明日」の2択タブ。選択状態を URL に持つ（`?day=tomorrow`。共有・戻るで状態を保つ） | `RaceTabs` はレース詳細の多タブ用（遅延マウント・横スクロール・フェード）で、2択には過剰。2択の切替は既存に無いので新規。barrel export に追加 |
| C2 | `VenueGrid` | 既存 | 24会場の固定グリッド。明日タブでもそのまま使う | 並び・列数・レスポンシブは本日と同じにする（レイアウトを二重に持たない） |
| C3 | `VenueGridCard` | 既存の拡張 | 明日用の表示を足す: 出走表あり（グレード・節名・日次・1R締切予定、リンクは S2）／出走表準備中（B に会場はあるが未掲載、リンクなし）／明日開催なし（B に会場が無い。BOA-225 の次開催日を併記）／公開前（B 未公開、「—」） | 本日の「開催中/非開催」と同じ骨格（名前・バッジ行・節名・状態行）に状態を足す。`mode`（today/tomorrow）を props で受ける。カードを別に作ると高さ・余白がずれる |
| C4 | `TomorrowPublishNotice`（仮） | 新規 | 明日タブの上の1行案内。公開前「明日の出走表は14時ごろから順に公開されます」、公開途中「n / m 会場の出走表を公開中」 | 1か所でしか使わないため S1 内に置いてもよい。i18n キーは `tomorrow.*` |
| C5 | `DataRaceTableView`（仮） | 既存から切り出し | S2 の1レース分の6艇の表。当日の「データ出走表」（`DataRaceTable`）の表示部分を切り出したもの（艇が列・指標が行、同じ行の並び・色分け）。明日は前日に値がある行だけ（当日体重・F/L バッジは出さない）。表の下に「展示・当日体重・F/L は当日朝から」 | 2026-10-02 ユーザー承認（当日と同じ部品）。当日の DataRaceTable は View を使う形に変えるだけで見た目は不変 |
| C6 | `Breadcrumb`・`Header`・`Footer` | 既存 | S2 の枠 | 全ページ共通 |

## データ取得（画面側）

| 箇所 | 取得 | 方針 |
|---|---|---|
| S1 明日タブ | 明日の会場別の出走表の有無と 1R 締切（新テーブルの集約。RPC か軽い select かは `/step2`）＋ `race_series`（節の期間・グレード・節名） | 明日タブを開くまで取得しない（本日タブの速度を変えない、spec 非機能要件） |
| S2 | 1会場分の明日の出走表 ＋ `racer_profiles` の正式名 | 選手名は正式名、未登録は B の名前 |

## デザイントークンで表現できる部分 / 新規 CSS

- トークンで足りる: 文字色（`--text-primary`・`--text-secondary`）、面（`--surface-card`・`--surface-page`）、罫線（`--border-hairline`）、強調（`--brand-accent-primary`）。グレードは `GRADE_CONFIG`、艇番は `BOAT_COLORS`
- 新規 CSS が要る: C1 のタブの形（2択のセグメント、`.tomorrow-` 接頭辞）。C5 の表は既存の `.drt-`（DataRaceTable.css）をそのまま使い、新規 CSS は作らない
- ダークモードでも読めることを Playwright で確認する（`component-reuse.md`）

## 共通化の判断

- 「App.jsx と RaceDetail.jsx の両方に必要」なパターンは無い（S1 はトップだけ、S2 は新ページだけ）
- 会場カード（C3）は本日と明日で共通。日付の扱いは venue-list-redesign の「対象日付を props で受ける」方針に沿う
- 6艇の表（C5）は将来「過去日の番組表」等に流用できるが、今は1か所なので汎用化しない（YAGNI）
