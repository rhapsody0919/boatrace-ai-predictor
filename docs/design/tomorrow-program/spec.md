# 明日の出走表（前日の番組表の取り込みと「明日」タブ） spec

種別: UI機能（データ取得を含む。UI は `/step1-screens` で画面を洗い出す）
対応Linearチケット: [BOA-223](https://linear.app/boat-ai/issue/BOA-223)

## 背景・目的

トップの開催場一覧（`src/pages/VenueGridPage.jsx`）は本日分しか出せず、翌日の開催と出走表を前日の夜から確認できない。kyoteibiyori.com は「本日/明日」の切り替えを持つ（`docs/proposal/competitor-kyoteibiyori/11-top-page.md`）。`docs/design/venue-list-redesign/spec.md` でスコープ外として切り出した項目。

当初案（節データ `race_series` だけで会場・節名を出す）はユーザーが「出走表が出ないなら意味が薄い」と判断し、前日の番組表を取り込んで明日の出走表まで出す案に決まった（2026-10-02、オーケストレーター経由）。

### 調査で確かめた事実（2026-10-02）

| 取得元 | 公開の時刻 | 中身 |
|---|---|---|
| 公式 `race/index?hd=明日` | 16:55 には公開済み | 会場・節名・日次 |
| 公式 `racelist?hd=明日` | 17:01 時点で締切予定時刻のみ。選手は未公開 | — |
| 公式 B ファイル（番組表 `bYYMMDD.lzh`） | 前日14時台に初公開。会場ごとに順に埋まり、夜まで更新（10/2 16:42 時点で13会場中8会場が12R×6艇、残りは「データ更新待ち」の文言のみ） | 下記 |

- B ファイルの項目（`scripts/lib/kbFileParser.js` の `parseBText`）: レース番号・種別・距離・締切予定時刻（発走時刻は無い）、節名・日次、艇番・登番・名前（4文字で切れる）・年齢・支部・体重・級別・全国勝率/2連率・当地勝率/2連率・モーター番号/2連率・ボート番号/2連率・今節成績（生の文字列）。無い: 3連率・F/L・平均ST・グレード
- `parseBText` は「データ更新待ち」の会場を空の会場として返し、「待ち」と「開催なし」を区別しない
- 前日分を `races`・`race_entries` に入れることはできない。朝の初期化（`scripts/lib/racesInit/job.js:98-106`・`:247-250`）が「races に行がある会場＝初期化済み」として会場ごと丸ごとスキップし、race_entries の作り直し・展示・予想・race_conditions が作られなくなる。`morning-init.js` のフェイルセーフ、0件監視（`scripts/lib/scrapeJobs/monitor.js`）、選手の最新行を引く画面（`src/services/racerService.js:34` 等）、sitemap にも波及する
- モーター2連率が 0 の行: 10/3 分では唐津（4日目）だけで72艇中37艇。他の途中日の会場（3日目・4日目）は0件。新モーター期の公式値と見られる（欠損ではない）

## 機能要件

### (a) 翌日の番組表の取得（データ取得）

#### FR-A1 B ファイルの翌日分を新テーブルに取り込む（優先度: 高）
- 新テーブル `tomorrow_program`（名前は `/step2` で確定）に、B ファイルの翌日分の全項目を、レース単位・艇単位で保存する
- 新しい Vercel Cron（共通ラッパ `scripts/lib/scrapeJobs/` 経由、registry 登録）で、前日14時台〜23時台に定期実行する。全会場がそろうまで、未取得の会場だけを取り直す（catch-up）
- 「データ更新待ち」の会場は、空の会場として書かない（待ちとして扱い、次の実行で取り直す）。`parseBText` に待ちの判定を足す
- `(対象日, 会場, R, 艇番)` で冪等に upsert する。変更の無い行は書かない。バルク upsert では全行の列をそろえる（キー集合の違う行を混ぜると NULL で上書きされる既知の落とし穴）
- races・race_entries には書かない
- 受入基準:
  - 本番で、対象日の B ファイルに載った全会場×12R×6艇が入っている（`.claude/rules/data-acquisition.md` §2-A。期待件数=節データで開催のある会場数×12×6、中止・欠場を除く。充足率99%以上を実測クエリで示す）
  - 各行に取得時刻（`created_at`・`updated_at`）があり、土日を含む直近5日で「公開から取り込みまでの遅れ」を実測できる（§2-B）
  - 0件の実行・全会場がそろわないまま時間帯を過ぎた日を検知し、既存の Slack 通知に流す（§2-C）
  - 「データ更新待ち」の会場が、開催なしとして書かれない（再現テストで固定）

#### FR-A2 名前の補完（優先度: 中）
- B の名前は4文字で切れるため、登番から `racer_profiles` の正式名を引いて表示用に使う。未登録の選手（新人等）は B の名前のまま
- 受入基準: 4文字を超える名前の選手が、正式名で表示される（実データで1件以上確認）

#### FR-A3 古い行の掃除（優先度: 低）
- 対象日を過ぎた行を、既存の掃除の仕組み（`scrape-cleanup`）と同じ方法で消す
- 受入基準: 対象日の翌日以降に、その日の行が残らない

### (b) 「明日」タブの UI

#### FR-B1 トップに「本日 / 明日」タブ（優先度: 高）
- トップ（`/`）の会場グリッドの上に「本日 M/D」「明日 M/D」のタブを置く。常に表示する
- 「明日」は常に JST の今日+1（0時〜5時も同じ）
- 明日タブの会場カード:
  - 出走表が入った会場: 節名・グレード（`race_series`）・日次・1R の締切予定時刻
  - 節はあるが出走表がまだの会場: 「出走表準備中」
  - 節が無い会場: 「明日開催なし」（BOA-225 の次開催日が分かれば併記）
- B ファイルの公開前は「明日の出走表は14時ごろから順に公開されます」を出す
- 受入基準: 14時前・公開途中・全会場公開後・0〜5時の4つの状態で、会場カードの表示が上の規則どおりになる（E2E、時計を固定）

#### FR-B2 明日の出走表（会場ごと）（優先度: 高）
- 明日タブの会場カードから、その会場の明日の出走表（全レース）へ遷移する。URL を持つ新しいルート（パスは `/step1-screens`・`/step2` で確定）
- 各レース: レース番号・締切予定時刻（JST と明記）・6艇の 艇番・選手名・級別・全国勝率・当地勝率・モーター（番号・2連率）。その他の項目（2連率・ボート・年齢・支部・体重・今節成績）を出すかはモックで決める
- 前日時点の情報であることを明記する（「前日○時○分時点。欠場・選手交代は当日の出走表で確認してください」）
- レース詳細・予想・分析への遷移は出さない（races に行が無いため）
- 受入基準: 実データで、ある会場の明日の出走表が公式の B ファイルと全艇一致する（データ精度の検証）

#### FR-B3 多言語（優先度: 高）
- 翻訳対象（ja/en/zh-TW/ko）。トップと会場ページが翻訳対象のため揃える
- 文言は `t()` 経由。選手名・節名に `translate="no"`。時刻は JST を明記
- 新しいルートを `TRANSLATED_PATHS` に登録する。用語は `docs/reference/i18n-glossary.md` に従う
- 受入基準: 4言語で表示崩れなし（375/768/1024/1440/1920px）

## スコープ

### やること
- (a) B ファイル翌日分の取り込み（新テーブル・マイグレーション・Cron・監視・再現テスト）
- (b) トップの「本日 / 明日」タブと、会場ごとの明日の出走表ページ（4言語）

### やらないこと
- races・race_entries への前倒し投入
- 明日のレースの予想・分析・レース詳細ページ
- 前日分と当日朝の出走表の差分表示（欠場・選手交代の検知）。日付が変わったら本日タブが正
- 公式の出走表ページ（racelist）の翌日分の取得（前日夕方に選手が出ないため）
- 過去日の番組表のバックフィル（「明日」を見る機能なので不要）

## 非機能要件

- 取り込みの遅れ: B ファイルに会場の出走表が載ってから、30分以内に画面に出る（Cron の間隔は `/step2` で決める。15〜30分ごとを想定）
- 取得先への負荷: 1回の実行で B ファイルを1回だけ取得する（LZH 1ファイル、約17KB）
- 書き込み量: 1日あたり最大 24会場×12R×6艇=1,728行。変更の無い行は書かない（Disk IO 予算への影響は `/step2` で見積もる）
- 表示: 320px〜で崩れない。横スクロールを出さない（`e2e/layout.spec.js` の5軸）
- 既存の本日タブの表示・速度を悪化させない（明日タブを開くまで明日のデータを取得しない）

## 制約・前提

- 実行基盤は Vercel Cron（ADR-0066）。LZH の展開は既存の `kfile_sync`（`api/cron/kfile-sync.js`）と同じ仕組みを使う
- マイグレーションはユーザーが本番に適用する。新テーブルは同じファイルで RLS を有効にし、匿名には SELECT のみ（`verify:migration-rls`）。適用後に `APPLIED.md` へ記録し、その後に Cron を有効化する
- 完了の定義は `.claude/rules/data-acquisition.md` §2（件数・タイミング・継続監視）。tasks.md に3行のテンプレートを入れる
- 既存部品の再利用: 会場グリッド（`VenueGrid`・`VenueGridCard`）、グレード（`GRADE_CONFIG`）、色はトークンのみ（`.claude/rules/component-reuse.md`）
- 用語: 画面内に「競艇」を出さない
- 法的表示: 予想を出さないため、AI 予想のディスクレーマーは不要。前日時点の情報である旨は FR-B2 で明記する

## 既定値で決定した事項

| 項目 | 既定値 | 根拠 |
|---|---|---|
| 明日タブの表示 | 常に表示、「明日」は JST の今日+1 | オーケストレーター判断（2026-10-02）。時刻で導線が消えると分かりにくい |
| 未公開と開催なしの区別 | `race_series` の節の期間で区別（出走表準備中 / 明日開催なし） | 同上。既に匿名で読め、新しい取得が増えない |
| 多言語 | 翻訳対象（4言語） | 同上。トップと会場ページが翻訳対象 |
| 名前の切れ | `racer_profiles` で補完、未登録は B の名前 | 正式名は既存表の読み取りだけで得られる |
| 保存する項目 | B の全項目を保存し、表示はモックで決める | 取り込みで捨てた項目は後から戻せない |
| モーター2連率の 0 | 生の値のまま保存。表示（0.0 か「—」か注記か）はモックで決める | 10/3 分では唐津だけ（新モーター期の公式値と見られる） |
| 当日朝との差分 | 扱わない。前日時点のスナップショット | 依頼範囲は「前日から見られる」こと |
| 明日の出走表からの遷移 | レース詳細へは遷移しない | races に行が無い |
| Cron の時間帯 | 14時台〜23時台、未取得の会場だけ取り直す | 公開が14時台に始まり夜まで更新される |
| 古い行 | 対象日を過ぎたら消す | 用途は前日の表示だけ |
