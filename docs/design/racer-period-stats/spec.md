# 仕様: 選手ページの場別・期別・進入コース別・優勝戦の集計の表（GS00 案2）

このファイルは GS00 案2 の「集計の表の土台」の仕様。fan（期別成績）と月間スケジュールの取り込みは [plan.md](./plan.md) §1〜§13、集計の表の設計は plan.md §14、決定は [ADR-0104](../../adr/0104-racer-career-stats-two-layer-tables.md)。画面（選手ページの新しい表示）は別の PR で、この表を読む。

## 1. 目的

- GS00: 選手ページを、艇国データバンクを使っていた人の受け皿にする（オーナー、2026-10-28 に案2を「進めて良い」）
- 公式の期別成績（fan、`racer_period_stats`）に無いもの（会場別・優勝戦の一覧・期ごとの進入コース別の着の内訳を本体の期間まで）を、着順の生の記録から数えて表に持つ
- 画面は件数の表を読むだけにし、選手ページを開くたびに生の記録（kb 221万行）を読まない

## 2. 出すもの（この PR は表と書き手まで）

| 材料 | 表 | 単位 | 期間 |
|---|---|---|---|
| 場別 | `racer_venue_stats` | 選手×会場×グレード×優勝戦か | 2019-04-01〜（kb＋本体） |
| 期別 | `racer_term_stats` | 選手×期（5〜10月・11〜4月）×グレード×優勝戦か | 同上 |
| 進入コース別 | `racer_course_stats` | 選手×進入コース×期 | 同上 |
| 優勝歴 | `racer_championships` | 優勝戦に出た艇（優勝は着 01） | 同上 |
| 計算の記録 | `racer_career_meta` | 層（kb・main）ごと | — |

- どの表も、着のコード（01〜06・F・L0・L1・K0・K1・S0・S1・S2・00、知らないコードは other_code）ごとの件数だけを持つ。率・勝率は持たない
- 勝率・出走の数え方は `src/pure/racerCareerStats.js`（BOA-1193、Codex）の純関数で、読み手の側が計算する

## 3. 定義（一次情報で確定したもの）

- 公式の勝率（official-data-spec、fan と3期 4,673人で全員一致、BOA-1193 の本文）
  - 勝率 ＝ Σ着順点 ÷ 出走。小数第3位を四捨五入
  - 着順点: 一般・G3 は 10/8/6/4/2/1、G1・G2 は +1、SG は +2
  - 優勝戦はさらに 1〜3着 +1、4〜6着 +2
  - 出走: 着のコードが 01〜06・F・L1・K1・S1・S2（F・L1・K1・S1・S2 は0点）。L0・K0・S0・00・NULL は数えない
- 優勝戦の判定: `src/pure/raceStageConfig.js` の `isFinalStage`（v2）。`kb_archive_races.stage_kind` は使わない（GP優勝戦・サントリー優・王座決定戦・賞金女王決定を落とす）
- グレード: kb は `kb_archive_venue_days.race_grade`、本体は `races.race_grade`、無ければ `race_series.grade`。次は書き手がレースごとに決める
  - QC/QCシリーズ: トライアルに出た選手とつながるレースが G1、残りが G3
  - CC/レディースCC: 最終日の 12R に出た選手とつながるレースが SG、残りが G2（推定。照合の関門の勝率で確かめる）
  - 唐津 2024-10-12〜14 のバトルトーナメント: G1
  - どれにも当たらず元の値も無いレースは `unknown`（勝率の点が決まらない。件数は数える）
- 期: 5〜10月は その年の 5/1、11〜12月は その年の 11/1、1〜4月は 前の年の 11/1 を `term_start` にする（公式の期別成績の算出期間）
- 境目: kb は race_date ≤ 2025-12-02、本体は ≥ 2025-12-03（`scripts/lib/kbArchiveBoundary.js`。kb-backfill.js・venueTechniquePeriod.js もここから読む）
- 未照合: 2019〜2023-10 と 2025-05〜12-02 の勝率の定義、CC の組の分け方、優出に S0・K0・L0 を含めるか。照合の関門（§6）で確かめる

## 4. 見せ方の注意（画面の PR への申し送り。data-scientist、[analysis/display-scope.md](./analysis/display-scope.md)）

- 「通算」と言わない。「2019年4月以降」と期間を書く
- 「年別」と言わない。期は 5〜10月・11〜4月。2期を足すなら「5月〜翌4月」と書く
- `term_start = 2018-11-01` の期は kb に 2019-04 の1か月しか無い。期として出さない（画面は 2019-05-01 以降の期だけを出す）
- 本体の今の期（2026-05〜）は公式の期別成績が未公開。当サイトの集計であることを書く
- 進入コース別は、どのセルにも進入数を添える。10走未満は率を出さない、10〜29走は「参考」
- 「未計算」（`racer_career_meta` に行が無い、または main の `report.full_computed_at` が無い）と「0回」を分ける。読み取りの失敗は InlineFetchError で出し、「優勝0回」に化けさせない

## 5. 統計検証

- 材料と言える範囲は data-scientist の検証（2026-10-28）: [analysis/display-scope.md](./analysis/display-scope.md)・`data/analysis/racer-period-stats/period-stats-display-scope.json`。この PR は表の土台で、新しく画面に出す数字は無い。画面の PR で、場別・優勝歴の言える範囲を足す

## 6. 照合の関門（完了の前に必ず通す）

- `scripts/maintenance/verify-racer-career-gate.js`（manual、claude_ro）
- 選手×期（2019-05-01〜2025-11-01 の14期）で、2つの層を足した値を `racer_period_stats` と比べる
  - 出走・1着・2着・勝率（BOA-1193 の純関数 isCareerStart・careerFinishPoints・careerWinRate。名前が違えば関門が止まる）← `racer_term_stats`
  - 優勝・優出 ← `racer_championships`（優出は S0・K0・L0 を含める・含めない の両方で一致の数を出す）
  - 進入コース別の着のコード（c1〜c6 の p1〜p6・f・l0・l1・k0・k1・s0・s1・s2）← `racer_course_stats`
- 一致しない選手の一覧を完了報告に出す。全期・全選手が一致するまで画面に出さない（一致しない理由が説明でき、オーナーが出すと決めたものを除く）

## 7. データ取得の完了の定義（`.claude/rules/data-acquisition.md`）

この機能は外部サイトを取得しないが、本番 DB に書く集計なので、同じ3つで完了を判定する。

- [ ] 本番実測: 期待件数（算出根拠: kb は `racer_career_meta.fingerprint.boats_by_year` の艇の行数＝`kb_archive_boats` のうち着のコードがある行の数、main は本体の着のコードがある艇の数。各表の行数は §8 の見積り）に対し、過去分を含めて充足率99%以上であることを実測クエリで確認する（照合の関門の一致率もここに添える）
- [ ] タイミング実測: 可変データではない（確定した着順の集計）。main 層は「前日までの着のコードが当日 23:30 の計算で入っている」ことを、直近5日（土日を含む）の `racer_career_meta.computed_at`・`source_to` で確かめる（欠けは2%以内）
- [ ] 継続監視: 毎晩のジョブ（`racer_career_main`）の成否と最終成功からの経過が scrape-monitor で日次に計測され、失敗・未実行・kb の指紋の変化で Slack に通知されることを確認する

## 8. 書き込みと Disk IO の見積り

本体（main）は 2026-10-31 の本番の読み取り（2025-12-03〜、着のコードがある 307,602艇・1,639人）で数えた。kb は system-architect の再審査の値（場別 81,222行の実測、期別・進入コース別・優勝戦は推計）。

| 項目 | kb（推計） | main（実測、11か月） |
|---|---|---|
| 場別（選手×会場×グレード×優勝戦か） | 81,222行（実測、system-architect の再審査） | 30,480行 |
| 期別（選手×期×グレード×優勝戦か） | 約5.7万行 | 8,266行 |
| 進入コース別（選手×コース×期） | 約13.5万行 | 18,703行 |
| 優勝戦の出走 | 約3.4万行 | 4,650行 |
| 合計 | 約31万行 | 約6.2万行 |

- 1行は約120B（件数の16列＋キー＋行の頭）。初回の書き込みは kb が約37MB、main が約7.5MB（索引と WAL を入れて kb 約95MB・main 約20MB、推計）
- 初回の読み取り: kb は `kb_archive_boats` 412MB と `kb_archive_races`・`kb_archive_venue_days` を1回（半月ずつ約160回の RPC。半月で本文 約0.5〜0.8秒・2.9MB、再審査の実測）
- 毎晩: 対象の選手は約700〜950人（2026-10-27〜29 の実測で 945人）。RPC は 50人ずつ約19回（1回目 5.6秒、2回目以降 0.34〜0.54秒の実測）。読む艇は約18万行（共有バッファの読みが主）。変わる行は約5〜6千行・1MB 未満（推計）
- Disk IO の予算には小さい。ただし kb の初回は夜（開催の後）に流し、前後でダッシュボードの Disk IO を記録する
