# ご意見ボックス（site-feedback-box）spec

- 種別: UI機能
- 元の依頼: オーナー 2026-11-23「開発者としてどんな機能を追加すればいいか迷っている。質問箱のようにユーザーにどんな機能が欲しいか聞いたり、1から5の星の評価だったり、ユーザーの声を聞きたい。自由にコメントを書けて、そのコメントを見て次に開発するものを議論できる仕組みが欲しい」「ログインなしで気楽に書き込める」「わかりやすいところに配置」「必須の作業は最小限に」
- Linear: なし（会話での依頼で直接）
- 表: `docs/db-migration/208_site_feedback.sql`（本番に当ててから画面を出す。下の「出す順番」）

## 目的

次に何を作るかを決める材料として、ファンの声（欲しい機能・使いにくいところ・データの誤り）を、ログインなし・匿名で集める。

## 今あるもの（2026-11-23 に調べた）

| 入口 | 中身 | 足りない点 |
|---|---|---|
| `/contact` | Google フォームの埋め込み（ja 専用） | フッターの一番下からしか行けない。集まった声が DB に無い |
| 龍神ソナーの「画面の中の声」（`analogy_feedback`） | 2択＋理由＋200字。レース詳細のソナーの下 | ソナーについてだけ。10/09〜10/26 の17日で14行 |

サイト全体の要望の入口・星の評価・右下の部品は無かった。

## 決めたこと

| 点 | 決定 | 理由・決めた人 |
|---|---|---|
| ログイン | なし・匿名 | サイトにログインが無い。手間を足すと集まらない（オーナー） |
| 必須の入力 | 内容だけ。種類・満足度は任意 | 必須の作業を最小限に（オーナー） |
| 公開 | しない。読むのは運営だけ | 公開するなら公開前の確認が要る |
| AI の読み取り | `claude_ro` には読ませない。読むのは service_role だけ | 自由記述に名前・連絡先が書かれうる（オーナー 2026-11-23） |
| 保存の期限 | 置かない（行が1,000を超えたら見直す。名前・連絡先を見つけたらその都度消す） | 龍神ソナーの声と同じ（オーナー 2026-11-23） |
| プライバシーポリシー | 文案を作って別の PR で出す。画面の公開より先に入れる | オーナー 2026-11-23 |
| 入口 | 右下の浮かぶボタン。`links` を渡すフッター（ホーム・お問い合わせ等の `App` のページ・ContentHub・データ分析・会場ガイド・ガイド）にも同じパネルを開く入口。レース詳細・ブログ記事・選手・/today はフッターを描かないので、右下のボタンだけ | どの画面でも同じ場所にあり、思いついた画面でそのまま書ける |
| 形 | 押すと入力パネル（600px 以下は下からのシート、それより広いと右下の小窓） | チャットの形（返事を待たせる）にしない。開発者が1人で即答できない |
| 評価 | 星 1〜5 を任意で1つ | 依頼の「1から5の星」 |
| 種類 | 送る人が選ぶ（任意）。自動の分類はしない。4つは仮で、集まった声を見て見直す | |
| 言語 | ja・en・zh-TW・ko | 全言語のページに出る部品なので、4言語の文を持つ |

## 機能要件

| # | 要件 | 受入基準 |
|---|---|---|
| R1 | 右下のボタン | 右端・下端から 16px。文字は「ご意見」、読み上げの名前は「ご意見・ご要望を送る」。地はカードの色、枠と文字は金（金の塗りは「選択中・最良」の意味で使っているので塗らない） |
| R2 | 読むのを邪魔しない | 下へ読み進めている間（向きが変わった位置から 8px 以上下へ、かつ先頭から 80px より下）はアイコンだけ（48px の丸）。40px 以上上へ戻すか、先頭から 40px 以内で文字が戻る |
| R3 | 既存の固定表示と重ねない | Cookie の確認が出ている間は、ボタンもフッターの入口も出さない。ブログ記事の「先頭へ戻る」が出たら、その上に 12px 空けて置く。768px 以下のレース詳細（下部ナビあり）は、ナビの上 12px にアイコンだけで置き、下へ読み進めている間は隠す。z-index は 800（メニュー・シート・下部ナビ・トーストより下） |
| R4 | 出さない画面 | `/admin/*`・`/share/*`・`/race/:id/assist`（言語の接頭辞つきも）。ボタンもフッターの入口も出さない |
| R5 | パネルの中身 | 上から、見出し・説明・内容（必須、500字まで、文字数の表示）・種類（任意の1つ: 欲しい機能／使いにくいところ／データの誤り／その他）・満足度（任意の星 1〜5）・送る・保存する物の注記 |
| R6 | 送る | 内容の前後の空白を除いて1〜500字なら送る。空で押したら送らずに「内容を書いてください」を出し、入力欄へフォーカスを移す。送っている間は「送っています…」で、もう一度押しても送らない（ボタンは `aria-disabled`。`disabled` にするとフォーカスがパネルの外へ落ちる）。種類・星のラジオの上の Enter では送らない（選んだつもりの Enter で誤って送らない） |
| R7 | 送った後 | 見出しが「受け取りました」に替わり、お礼・返信できない断りとお問い合わせページ（`/contact`、ja 専用なので接頭辞なし）へのリンク・「もう1件書く」「閉じる」。閉じて開き直すと空から始まる（画面を移って閉じた場合も） |
| R8 | 送れなかったとき | 「送れませんでした。時間をおいてもう一度押してください」を出し、書いた内容・選んだ物は残す。書き直し始めたら消す。GA4 に `site_feedback_send_failed`（`error_code` だけ。本文は送らない）を送る |
| R9 | 閉じ方 | ×・Esc・背景のクリック。書きかけは残る。別の画面へ移ったら閉じる（戻る→進むで開き直さない）。利用者が閉じたら開いた入口へフォーカスを戻す（画面を移って閉じたときは戻さない）。日本語の変換を取り消す Esc では閉じない |
| R10 | キーボード・読み上げ | `role="dialog"`。Tab はパネルの外へ出ない。種類・星は本物のラジオ（Tab は1か所、矢印キーで動く。選んだ物をもう一度押すか Space で外れる）。パネルの中の押せる部品は 44px 以上（フッターの入口は並びのリンクと同じ大きさ） |
| R11 | スマホ | 指で触る端末は、開いた瞬間に入力欄へフォーカスしない（キーボードで全体が隠れない）。キーボードが出たら、その高さだけシートを持ち上げる（指で拡大している間は持ち上げない）。入力欄は 16px（iOS が拡大しない）。シートを開いている間は後ろをスクロールさせない（広い幅の小窓では止めない。スクロールバーが消えて本文が横にずれるため） |
| R12 | 送る1行 | `kind`・`comment`・`rating`・`page_type`・`lang`・`client_key`。URL（レース・選手の番号）は送らず、ページの種類だけ（`src/pure/siteFeedback.js` の `feedbackPageType`）。保存してある識別番号が uuid の形でなければ作り直す（そのブラウザから二度と送れなくならないように） |
| R13 | 計測 | `site_feedback_open`（`feedback_entry`: button／footer、`feedback_page_type`）、`site_feedback_send`（`feedback_kind`、`feedback_rated`、`feedback_page_type`）、`site_feedback_send_failed`（`error_code`、`feedback_page_type`）。GA4 は Cookie に同意した人だけなので、件数は下限。DB の行と混ぜない |

## 出す順番（仕組みで守る）

db-apply は master にあるファイルしか当てず、本番の配備は1日3回の定時（ADR-0106）。画面と表を1つの PR にすると「マージ → 次の定時より先に db-apply」の競争になり、負けると全員の送信が「送れませんでした」になる。そこで PR を分け、画面を全画面につなぐ PR だけを表の適用の後にする（2026-11-25、tinaba の #3296〜#3298 を 300行・5ファイルの線で分け直した）。

| 順 | PR（枝） | 中身 | 表の前に入れてよいか |
|---|---|---|---|
| 1 | 表（`claude/site-feedback-db-v2`） | `208_site_feedback.sql`・台帳の行・`verify-site-feedback-migration.js`・この spec | ―（オーナーがマージ） |
| 2 | db-apply | オーナーが Actions で起動して承認する。成功すると台帳が「適用済み」になる | ― |
| 3 | ポリシー（`claude/privacy-feedback-storage-v2`） | プライバシーポリシーの追記 | 可（文だけ） |
| 4 | 部品（`claude/site-feedback-pure`・`-form`・`-fields`・`-panel`・`-button`） | 決まりの純関数・識別番号・送信と入力の状態・訳・パネル・ボタン。どこからも描かないので画面に出ない | 可 |
| 5 | つなぐ（`claude/site-feedback-mount`） | `AppRouter.jsx` で全画面に置く・E2E。`verify-site-feedback-gate.js` が、画面と表の列挙のずれ・台帳で `208_site_feedback.sql` が適用済みでないことで赤になる。E2E が /privacy に保存の記載が無いことで赤になる | 不可（2・3 の後） |
| 6 | フッターの入口（`claude/site-feedback-footer`） | `links` を渡すフッターの「ご意見・ご要望を送る」 | 不可（5 の後） |

## スコープ

やる: 上の R1〜R13、表、検査、E2E。

やらない（別に決める）:

- 集まった声を読む画面（`/admin`）と、週のまとめへの取り込み（`claude_ro` は読めないので、service_role のスクリプトで要約を作る形になる）
- 投稿の公開・返信、質問箱の形（公開して答える）
- GA4 のカスタムディメンションの登録（`feedback_*`・`error_code`）
- ヘッダーのメニューへの入口
- 声の状態（読んだ・起票した）を持つ表（匿名が書く表は足すだけにし、状態は service_role だけの別の表に持つ）

## 確かめていないこと

- 実機（iPhone Safari・Android Chrome）でのキーボードとシートの動き。Playwright では画面のキーボードが出ない
- AdSense の画面下の帯（アンカー広告）が下に出た回の重なり
- 予想の画面（/picks・/holmes・/poirot）は、ページの種類が `other` になる。分けるなら CHECK を広げるマイグレーションを先に当てる
- 荒らしに気づく道（2026-11-25、system-architect の P2）: 表は `claude_ro` から読めないので、hq・Claude は件数も読めない。187（龍神ソナーの声）の「荒らしの行は表に残るので見つけて消せる」はこの表では成り立たず、全体の上限で正規の声が止まり続けても、手がかりは GA4 の `site_feedback_send_failed`（Cookie に同意した人だけ）しか無い。件数だけを読む口（時間ごとの件数のビューを `claude_ro` に読ませる、または service_role の件数の集計を週のまとめに入れる）を、つなぐ PR の前に作るかはオーナーが決める
- 集まる件数。ソナーの声の実績（17日で14行）より多いか少ないかは、出してみないと分からない。連投の上限（24時間10行・10分30行）もその実績からの目安
