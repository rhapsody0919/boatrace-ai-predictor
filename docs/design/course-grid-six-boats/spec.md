# 6艇の想定コース別成績と、予想動画の材料の置き場所（spec）

承認: [APPROVED.md](APPROVED.md)（2026-11-04、案A）。モック: [mock/mock.html](mock/mock.html)。

目的: 予想の YouTube 動画が使うのに龍神で見にくい・無い材料（選手本人のコース別成績・全選手との差・モーターの素性・今節の平均ST）を、レース詳細の今あるタブの中で、ほかの値と同じ数え方で読めるようにする。新しいタブは作らない。

## 1. 画面と値の定義

### 1.1 枠別情報タブ: 6艇の選手本人のコース別成績（新、タブの先頭）

- 行: 艇番の順に6行。並べ替えはしない
- 想定コース: 枠なり（艇番＝コース）。見出しの下に「進入コースで数えています」と断る（今の `wakuInfo.wakuNariAssumption` と同じ扱い）
- 期間の切り替え: 「直近3期」（既定）と「当地」の2つ

| 列 | 直近3期 | 当地 |
|---|---|---|
| 1着率 | 想定コースの Σp1 ÷ Σ進入（直近3期を足してから割る） | 今の1艇ずつの表の「当地」行と同じ値（`buildTodayCourseRows` の `local`。当社データ 2025-12〜、実進入コース） |
| 差 | 1着率 − 全選手の同じコースの1着率（pt、小数1桁、符号つき） | 1着率 − その会場の同じコースの1着率（同じ期間） |
| 平均の値 | 全選手の同じコースの1着率（1.2） | その会場の同じコースの1着率（1.2） |
| 2連対 | (Σp1+Σp2) ÷ Σ進入 | 今の表の当地行の2連対率 |
| 3連対 | (Σp1+Σp2+Σp3) ÷ Σ進入 | 今の表の当地行の3連対率 |
| 進入 | Σ進入 | 今の表の当地行の走数 |

- 直近3期のデータ元は公式の期別成績 `racer_period_stats`（2026-11-04 の決定、Orchestrate 段階1。選手ページの「進入コース別成績（公式）」と同じ取り方）
  - 決定の理由: 照合が要らない／選手ページの「直近3期」と同じ値になる（同じ言葉で違う値が出ない）／オーナーの決定「公式の期3つ」に合う
  - 各選手の行は `getRacerAllPeriodStats(racerId)` の行を、`calc_to` がレースの日より前の期だけに絞り、`src/utils/racerOfficialPeriodStats.js` の `buildCourseRows`（出走のある新しい3期を合算）に通す。過去のレースで、その日より後に終わる期を入れない
  - 2026-11-04 のレースなら、公開済みの新しい3期＝集計 2024-11-01〜2025-04-30・2025-05-01〜2025-10-31・2025-11-01〜2026-04-30。公式の 2026-05〜10 の期は取り込まれていない（最新の `calc_from` は 2025-11-01）ので1期古いが、取り込まれれば自然に新しくなる
  - 出走の無い期を飛ばした選手は、選手ページと同じく古い期を使い、行に「出走のない期を除く」の印を出す（`contiguous: false`）
  - 画面に期の開始と終了の日付を出す（例「2024/11/01〜2026/04/30」）
- 進入（Σ進入）は公式の `c{n}_entries`。率は (Σc{n}_p1 …) ÷ Σc{n}_entries（`buildCourseRows` と同じ）
- 全選手の同じコース平均（直近3期）: 同じ表の同じ3期（`calc_to` < レースの日の新しい3期）の、出走のある全選手の Σc{n}_p1 ÷ Σc{n}_entries（コースごと、走の重みの平均。選手ごとの率の平均ではない。B2 を含む）
  - 出どころは RPC `get_course_win_rate_baseline(p_race_date, p_venue_code)`（マイグレーション、Claude、BOA-1290）。1期約1,640行×3期をフロントで読むと1000行の上限で5ページ要るので採らない。期ごとの JSON は取り込みのたびの作り直しが要り、当地の窓が毎日動くので採らない
- 会場の同じコース平均（当地）: 当地の行と同じ期間・同じ数え方（実進入コース）の会場の値。同じ RPC が返す（§6）
- 当社の集計 `racer_course_stats`（マイグレーション 190）から作る形は後の改善（BOA-1289）。照合の関門を通してから切り替えを考える（§3）
- 行を押すと、下の1艇ずつの表がその選手に切り替わる（今の `focusedBoat`／`onFocusBoat` を使う。タブ間で共有されている選んだ艇と同じ）

### 1.2 進入が少ない艇（件数の線）

| 想定コース | 灰色の ⚠ にする進入数 | 出典 |
|---|---|---|
| 1 | 10走未満 | docs/knowledge/stat-findings.md（2026-10-28）: 公式のコース別成績で選手差の信頼性0.5に要る進入数（全選手の中で比べるとき）1着率 1コース10・2〜4コース約30・5コース42・6コース67 |
| 2〜4 | 30走未満 | 同上 |
| 5 | 42走未満 | 同上 |
| 6 | 67走未満 | 同上 |

- 灰色の行は率を灰の字で出し、差は「—」にする（平均の値は出す）
- **10走未満は、どのコースでも1着率・2連対・3連対を出さない**（「—」と進入数だけ）。選手ページの `COURSE_RATE_MIN_ENTRIES = 10`（`src/utils/racerOfficialPeriodStats.js`）と同じ
- 線は直近3期と当地で同じものを使う。信頼性0.5の値は公式の期別成績（直近3期の合算と同じ型）で測ったもので、当地（当社データ 2025-12〜）では測っていない
- 注記: 「進入数が少ない艇（1コース10・2〜4コース30・5コース42・6コース67走未満）は、率が偶然でぶれやすいので灰色にして差を出しません。10走未満は率も出しません。」

### 1.3 差（|z|）の扱い

- 差に色を付けない（緑・赤・太字・矢印を使わない。モックの CSS の `.up`・`.down` は使わない）
- 差の向きを言葉で言わない（「上回る」「強い」「弱い」「得意」「苦手」を書かない）。数字と「pt」だけ
- |z|（差÷標準誤差）を計算しても画面に出さず、印・並びにも使わない。件数の線は §1.2 の進入数だけで決める
- 注記: 「差＝全選手の同じコースの1着率との差（色は付けません）。同じタブの ST 考察は「同じ級別の平均」と比べています。」

### 1.4 枠別情報タブ: 1艇ずつのコース別成績（今の表）

- 期間・条件の行の先頭に「直近3期」を足す。値は §1.1 の6艇の表の同じ選手・同じコースと同じ（同じ純関数の結果を使う）
- 今の行（全期間＝当社データ 2025-12〜／直近3ヶ月／直近1ヶ月／当地／一般戦／SG・G1）は変えない。今の `gridRows.current` は「全期間」の意味で、今期ではない（`src/components/race/basicInfoStats.js` の `matchesPeriod`）

### 1.5 基本情報タブ: データ出走表の「枠番」行の差し替え

- 今: 「枠番勝率（直近1年）」＝`predictions.feature_contributions.racerStats` の `wakuRaceCounts`（艇番で数えた1着数/出走数。`src/components/race/raceIndicators.jsx` の `wakuRateOf`）
- 後: 「想定コース1着率」＝§1.1 の直近3期の1着率と同じ値。表示は「58% 63/108」（率は整数%、1着数/進入）。§1.2 の灰色・⚠・10走未満の「—」を同じに当てる。最良の金枠は灰色の艇を候補から外す
- 行の注記: 「想定コース1着率は直近3期・進入コースで数えています」。表の注記（`dataTable.note`）の「枠番勝率」の語も差し替える
- AI用のコピー（`src/hooks/useAiCopyText.js`）の同じ行も同じ値・同じ名前にする
- これで BOA-302（艇番基準と進入コース基準の混在）のうち、データ出走表と枠別情報の食い違いが解ける

### 1.6 モータ情報タブ

- 6基の表: 機番の横に札「交換N」。N＝この節の初日からこのレースの展示までに記録された部品交換の回数（`exhibition_data.parts_changed` の部品の数。プロペラ `propeller_change` は数えない）。0回は「交換0」。札を押すと部品の名前が開く
  - 注記: 「回数の多少の良し悪しは示しません（効き目は未検証）」。色を付けない
- 使用履歴: 各節の行に、節のグレードのバッジ（SG・PG1・G1・G2・G3・一般。レース見出しの格のバッジと同じ形）と、その節で優勝戦に乗った「優出」・勝った「優勝」の印を足す
  - グレードの出どころ: その節のレースの `races.race_grade`
  - 優出・優勝: その節の優勝戦（`race_conditions.race_stage` で判定。既存の `getVenueMotorChampionshipHistory` と同じ `isFinalStage` を使う）にこのモーターで出走したら優出、`race_results.rank1` がこのモーターの艇なら優勝
  - 並びは今のまま新しい順

### 1.7 今節タブ: 6艇の今節の推移の平均ST

- ST の表示のとき、右端の「前走」の下に灰の小さな字で1行「平均0.15・3位（7走）」
  - 平均: この節のこのレースより前の走の ST の平均（F・出遅れの走は除く。今の `buildMeetTrend` の `st.meetAvg` と同じ除き方）
  - 順位: 平均を出した艇の中の速い順。同じ値は同じ順位
  - （N走）: 平均に使った走の数
- 平均に使える走が3走未満の艇は出さない（「2走のため出さない」）。その艇は順位にも入れない
- 強調・色を付けない。注記1行: 「今節平均ST（フライングの走は除く）と6艇の中の速い順。3走未満は出しません。今節の平均STの効き目は未検証の参考の値です。」
- 根拠: 平均ST（直近30走・1コース）は勝率と一緒に見ると1号艇の非1着にほぼ効かない（AUC −0.003、stat-findings.md）。今節の平均ST の効き目は測っていない

### 1.8 1号艇・2号艇の選手の過去（置き場所だけ）

- 置き場所: 枠別情報タブの「1コースが逃げたとき」（`NigeSimulationCard`）の直前
- 値・何走から出すか・色・区切りは BOA-1280 の答えの後に決める。動画の区切り（10・20・50%）は使わない
- この spec の起票では作らない

## 2. 統計検証（この spec の時点で言えること）

| 材料 | 言えること | 言えないこと | 根拠 |

## 3. 後の改善の前提: 当社の集計（racer_course_stats）の照合の関門

`scripts/maintenance/verify-racer-career-gate.js`（manual）を 2026-11-04 に実行した結果（既定の期 2019-05-01〜2025-11-01、選手×期 22,559）: **関門は通っていない（終了コード 1、不一致 400件）**。

| 期 | 選手 | 不一致 | うち進入コース別の着のコード |
|---|---|---|---|
| 2019-05〜2025-05 の13期 | 1,552〜1,625 | 0〜49（勝率だけ。2019-11・2020-11・2021-11・2022-05・2023-05・2025-05 で各48〜49） | **0** |
| 2025-11-01（kb と main をまたぐ期） | 1,643 | 111 | **111**（いずれも当社の着の数が公式より少ない。出走の差は110人で計141走） |
| 2026-05-01 | — | 照らせない | 公式の期別成績（`racer_period_stats`）にこの期がまだ無い（最新は 2025-11-01） |

- 当社の集計で直近3期（走り終えた期の新しい3つ＝2025-05・2025-11・2026-05）を出すなら、関門を通っているのは 2025-05 の1期だけ
- 2026-11-04 の決定で、最初は公式の `racer_period_stats` から出す（§1.1）。この関門は、当社の集計へ切り替えるときの前提（racer-period-stats spec §6「全期・全選手が一致するまで画面に出さない」）で、画面の起票の前提ではない
- 通すために要ること（Claude）
  1. 2025-11-01 の期の 111人・141走の欠けの原因を調べて直す（kb の 2025-11-01〜12-02 と main の 2025-12-03〜04-30 のどちらで欠けているか。当社の結果が無いレースの多くは `cancellation_status='confirmed'` の中止で、それだけでは説明できていない）
  2. 公式の 2026-05-01 の期（2026年後期の級別の元）が `racer_period_stats` に入ったら、`--to=2026-05-01` で関門を回す
  3. 当社の集計の進入数を公式の `c{n}_entries` と一致させる（着のコードの和だと 2025-05 期の1コースで 1,449/1,493人＝97%一致、外れる44人は当社が多い）。関門に進入数の照合を足す
  4. 勝率の不一致（各期48件前後）は進入コース別の値には関係しないが、関門全体は落ちたまま。racer-period-stats の担当の起票で扱う

## 4. i18n の区分

- 区分: 翻訳対象（レース詳細は `TRANSLATED_PATHS` にある主要導線）。`.claude/rules/i18n-new-pages.md`
- 文言は全て `t()` を通し、4言語（ja・en・zh-TW・ko）のキーを同じ PR で足す。キーは今の名前空間に足す: 枠別情報 `wakuInfo.*`、データ出走表 `dataTable.*`、モータ情報 `analysis.motor.*`、今節 `meetTab.*`
- `scripts/maintenance/verify-jsx-japanese.js` が JSX の直書きの日本語を落とすので、文言のキーを先に入れてから画面の起票に進む
- 選手名には `translate="no"`
- 新しい語（直近3期・想定コース1着率・全選手の同じコース平均との差・交換N・優出・優勝）の訳は `docs/reference/i18n-glossary.md` に合わせる。無い語は glossary に足す（docs の別の変更）

## 5. 出さないもの

- 1着率の順の並び替え（艇番の順だけ）
- 差の色・向きの言葉・|z|（§1.3）
- 同じ級別の平均との差（49〜108走要る）
- 進入10走未満の率
- 今節の平均ST の強調・色、3走未満の艇の平均と順位
- 部品交換の回数の良し悪し・色
- 逃がし率・被まくられ率の値（BOA-1280 の後）と、動画の区切り（10・20・50%）
- 今の期（走っている途中の期）の値を直近3期に混ぜること
- タブの上の6艇の要約に足すこと（2026-11-01 オーナー決定「艇番・名前・級別だけ」）
