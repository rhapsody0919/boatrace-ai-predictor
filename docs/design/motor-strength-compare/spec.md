# モーターの強さをひと目で比べる（spec）

- 種別: **UI機能**（データの取得・集計は増やさない。参考UIの列は保存済みのテーブルで足りる）
- Linear: [BOA-428](https://linear.app/boat-ai/issue/BOA-428)
- 次の工程: `/step3`（plan.md 作成済み）

## 背景

ユーザー要望（2026-09-25）。公式 BOATRACE アプリの「モーター」ランキング画面（2026-09-18 蒲郡10R）を参考に、次の2つがほしい。

1. 出走するモーターの中での強さを、ひと目で比べたい（レース単位）
2. モーターランキングのように、会場の全体を俯瞰したい（会場単位）

参考UIの構成: 順位 / 機番 / 2連率（横棒の塗り） / 優出 / 優勝 / 前検タイム / 今節使用者。機番・2連率・優勝・前検で並べ替えられ、同じ値は同じ順位。

### 調べて分かったこと（前提）

- レース詳細の「モータ情報」タブには、6艇の表が既にある（`src/components/analysis/MotorConditionChart.jsx:616-720`）。列は自社2連率（期間切替）・公式2連率（節時点）・3連率・前検・1着率・機力指数・優出・優勝で、最良の行は強調される。**足りないのは、数字を読まずに差が分かるバーと、会場内で何位かの一覧表示**
- 会場内順位は計算できる（`getVenueMotorRanking`、`src/services/supabaseDataService.js:3101-3184`）。同じ値は同じ順位（BOA-529）、過去レースは `asOfDate` で、その日以前で最新のスナップショット（BOA-521）。今の表示はドリルダウン（1基単位）だけ
- 前検タイム: `motor_pretest_stats`（`docs/db-migration/090_motor_pretest_stats.sql`）。行は節の全選手単位
- モーターの入れ替えをまたぐ混在（BOA-329）は解決済み（`src/utils/motorGeneration.js`、`venue_motor_start_dates`）
- 会場公式サイトの値（`venue_motor_stats`）は、取得していない会場がある（戸田・平和島。会場サイトにモーター成績のページが無い。`scripts/lib/venueMotorStats/venueConfig.js`）。ADR-0067:21 は「浜名湖・宮島も除外」と書くが、`venue_motor_stats` は浜名湖・宮島も毎日取得している（2026-10-02 設計レビューで判明。下の「未確定事項」）。取得している会場も、会場によって取れる列が違う（全列 NULL 許容）
- データは匿名で読める（076・095）

## 機能要件

### FR-1（子1、優先度 高）出走6艇のモーター相対比較

- 対象はそのレースに出走する6基
- 公式2連率（節時点、`race_entries.motor_2rate`。出走表・公式アプリと同じ数字）を、6基の中での横棒（データバー）で出す。最大の値を棒の全長にする（Q1）
- 各行に「会場内◯位／◯機中」を添える（同じ値は「◯位タイ」、BOA-529 と同じ表記）
- 受入基準:
  - 375px で、6基のバーと順位が横スクロールなしで見える
  - バーの長さの比が、値の比と一致する（E2E で、最大の行が全長・他の行が値に比例することを測る）
  - 会場内順位が `getVenueMotorRanking` の結果と一致する（データ精度検証）
  - 過去レースでは、そのレースの日以前のスナップショットの順位を出す

### FR-2 全国平均との比較 — 作らない（Q2）

### FR-3（子3、優先度 中）会場モーターランキング

- 分析ツール（/winning-technique）の新しいタブに置く（Q3）
- 会場の全モーターを1つの表で並べる
- 表の上に出典（各会場の公式サイトのモーター成績）とデータの日付を書く（Q4）。ADR-0067 に追記する
- 列: 順位・機番・2連率（横棒）・優出・優勝・前検タイム・今節使用者（既定値で決定。下記）
- 機番・2連率・優勝・前検の見出しで並べ替えられる。同じ値は同じ順位
- 今節使用者の名前から選手ページへ移れる
- 受入基準:
  - 直近の節で使われたモーター（`motor_pretest_stats` の会場の最新日）が、すべて一覧にある（DB のスナップショットの件数との一致では、スナップショット自体の欠け（丸亀）を検出できないため。2026-10-02 設計レビュー）
  - 並べ替えで、同じ値の行が同じ順位になり、次の順位が飛ぶ（1, 2, 2, 4）
  - 375px でページ全体に横スクロールが出ない（表の中だけ横スクロール）
  - 表の上に出典と取得日（`scraped_date`）を「取得日」と明記して出す（データの時点とは読ませない。会場によっては節ごとにしか中身が変わらない）

## スコープ

### やる
- FR-1・FR-3
- 既存部品（`MotorConditionChart.jsx` の6艇表）の改修。分析ツールの「モーター調子」タブにも同時に効く

### やらない
- モーター単体のページ（機番は既存のドリルダウンへリンクする）

## 非機能要件

- レイアウト: 375 / 768 / 1024 / 1440 / 1920px で横スクロールなし（`e2e/layout.spec.js`）
- 多言語: 翻訳対象（分析ツールと同じ区分）。子1・子3とも4言語のキーを足す
- クエリ: 子1は会場内順位を6基分まとめて引く +2本（スナップショットの日付・会場全体。会場×日付でキャッシュ。plan.md で +1本から改めた）
- パフォーマンス: 子3の表（約60行）の並べ替えは、クライアント側で即時

## 制約・前提

- 用語: 画面に「競艇」を使わない（`.claude/rules/code-style.md`）。選手名に `translate="no"`
- モーターの2連率・3連率には、乗った選手の実力が混ざる（`src/components/racer/RacerMotorStatusCard.jsx:15-17` の既存判断）。ランキング・バーにも同じ注記を付ける
- 会場公式サイトの値の再表示は、ADR-0067 に追記して出す（Q4）。表に出典と日付を書く
- 投票・AI 予測の結果保証の表記: この機能は予測ではないので、追加のディスクレーマーは不要（既定値）

## モック確認での決定（2026-10-02、オーケストレーター経由）

| 項目 | 決定 |
|---|---|
| バーの出どころ（BOATRACE 公式2連率）と会場内順位の出どころ（会場公式サイトの2連対率）が違う点 | 注記で出どころを書く形でよい |
| バーの色 | レース詳細UI統一レーンの共通ルール（ユーザー承認済み）に合わせる: 棒・線は艇色のまま。良し悪しは値ラベルで示す。最良は金枠＋太字（同じ値の最良は全部）。差のある値は緑/赤に ↑↓・＋− を必ず付ける |
| 見た目・列の並び・注記の文言 | モックのまま |

色のルールの当てはめ:
- 子1（6艇表）: 棒は各行の艇色。6基で最大の公式2連率の値ラベルを金枠＋太字にする（同じ値の最大が複数あれば全部。2026-10-02 ユーザー承認、UI統一レーンの `bestOf` が艇の集合を返す形に変わる）。2連率・順位は「差」の値ではないので緑/赤は使わない
- 子3（会場ランキング）: 行に艇が無いので、棒は中立の色（意味トークン）。2連率が1位の値ラベルを金枠＋太字にする（同率1位は全部）

## 設計レビューを受けた決定（2026-10-02）

| 項目 | 決定 | 根拠 |
|---|---|---|
| 「◯位タイ」の表記 | 「17位タイ/60」。同値でなければ「20位/60」。子3の順位の列は「17」だけ（同値は同じ数字） | 児島 9/30 7R の69・22・68号機はそれぞれ2基同値（設計レビューで再現） |
| 子1 の注記の文言 | 「会場内順位は、{{venue}} 公式サイトのモーター成績（取得日 {{date}}）の2連率で数えた順位です」 | spec と screens の文言の食い違いを1つにそろえる |
| 出典の日付 | 「取得日」と書く | `scraped_date` は取得日で、児島の中身は 9/23 から変わっていない。データの時点と読ませない |
| 子3 の使用者・前検 | 会場の最新の `motor_pretest_stats.race_date` 1日分から取る（節の全選手がそろう）。その日が今日でなければ、列見出しを「直近の節の使用者（{{date}}）」にする | 出走表の1日分だと、節のモーターの最大約25%が欠ける。10会場は今日レースが無い |
| 子3 の機番リンク | そのモーターが今節走った直近のレースの `race_id` を付けてドリルダウンへ。今節使われていないモーターはリンクにしない | `?motor=` だけではドリルダウンが開かない（選択中のレースの6艇にいるときだけ開く） |
| 子3 の並べ替え | 機番は昇順、2連率・優勝は降順、前検は昇順の固定（押しても向きは変わらない）。値の無い行は常に末尾。順位の列は、並べている列の値で付け直す（機番で並べたときだけ2連率の順位） | 参考UIの「▼」は向き固定 |
| 子3 の初期の会場 | URL の `venue_code`、無ければ会場選択の既定（今日開催している最初の会場） | 既存の分析タブと同じ |
| 取得の失敗 | 「データが無い」と区別し、エラーを出す（出典を差し替えて出走表の値だけの一覧にしない。子1 は順位の列を畳まずエラーの印を出す） | 一時的なエラーで、児島が違う出典の一覧として出るのを防ぐ |
| 日付の表記 | 子1 の注記・子3 の出典とも「取得日 2026/9/30」（年つき）にそろえる | 2つの画面で同じ日付を同じ文字列で出す |
| 取得失敗の表示 | 子1: 会場内順位のセルを「取得できませんでした」（列は残す）。子3: 表の代わりに「モーター成績を取得できませんでした」（`role="alert"`） | 文言を固定する |
| 会場サイトの値を出さない会場（戸田・平和島・浜名湖・宮島）の子1 | 会場内順位の列を畳む（出さない） | 会場サイトの値が無く、公式2連率は今節のモーター分しか無いので「◯機中」の母数が会場全体にならない |
| 出走数 0 のモーターの会場内順位 | 順位に入れない（「-」、母数にも数えない） | 入れ替え直後で2連率 0 が「集計前」。唐津で走っていないモーターが「40位タイ」と出ていた（データ精度検証） |
| 最良の印の判定 | 表示する1桁の値で判定する | 生の値だと、同じ「38.3」に見える2艇の片方にだけ印が付く |
| 値の無い行の順位（子3） | 並べ替えた列の値が無い行は、順位を「-」にして末尾 | |
| 棒の順と順位の順の食い違い | 注記の形のまま（モック確認の決定）。件数を記録する: 9/15〜10/01 で会場内順位を出すレース（戸田・平和島・浜名湖・宮島を除く）2,136レースのうち476レース（22%）で6基の中に逆転する組があり、74レース（3.5%）で金枠のモーターと順位最良のモーターが別（データ精度検証で再集計） | ファン評価で指摘されたときの判断材料 |

## 浜名湖・宮島の扱い（2026-10-02、ユーザー判断、オーケストレーター経由）

浜名湖・宮島（会場サイトに明示的な著作権条項がある、ADR-0067:21）は、会場サイトの値（会場内順位・優出・優勝）を出さない。BOATRACE 公式の値だけで出す（戸田・平和島と同じ扱い）。取得を止めるかは [BOA-681](https://linear.app/boat-ai/issue/BOA-681) で別に判断する。

以下、「会場サイトの値を出さない会場」は戸田・平和島（データが無い）と浜名湖・宮島（出さない）の4会場を指す。「データの無い会場」と書いた箇所はすべてこの4会場に読み替える。
