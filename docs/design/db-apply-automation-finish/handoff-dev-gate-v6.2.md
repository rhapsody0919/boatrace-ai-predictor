## v6.2 で決めること

1. **「途中に挿す」の扱い**: 配列への要素の追加を、末尾だけでなく途中・先頭への挿入も許すか（既存の要素が同じ字句・同じ順で全部残り、増えたのは丸ごとの要素だけ）。許すと 398 本（42.1%）
2. **期待値の配列を許す対象から外すか**: 関数の呼び出しの引数の中にある配列（`check(…, [期待値])`）への追加は、既存の期待値の意味を変える（期待値の集合を広げて検査を緩める）ことがある。外す形（引数の中の配列は owner、変数に代入した配列・`Object.freeze([...])` の中の配列だけ許す等）と、その本数を比べる。名前の除外は効いていないので、残すか消すかも決める
3. **判断28 の 30/60 の確認**: 過去31日で、30 で知らせるのが3回、60 で止めるのは0回（過去に審査の App の APPROVE は0件なので、マージの日で代えて数えた）。この数で推奨を確定する
