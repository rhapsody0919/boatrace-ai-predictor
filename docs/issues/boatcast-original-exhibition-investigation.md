# BOATCASTのオリジナル展示データ取得元調査（BOA-281）

[BOA-281](https://linear.app/boat-ai/issue/BOA-281)（周回・周足・直線タイムの取得可否）の取得元候補として、BOATCAST（boatcast.jp / race.boatcast.jp）を調査した。[ADR-0067](../adr/0067-official-site-content-redisplay-policy.md)の要件（新規取得元は着手前に規約本文を確認する）に基づく。

## 結論

**条件付きで使える。** 規約上、自動取得の明示的な禁止は無い。オリジナル展示データ（一周/半周ラップ・まわり足・直線）が、レース単位のテキストファイルとして、過去日分も含めて取得できる。条件は次の3点。

1. 取得負荷: 2025-12-03以降の全レース分は約44,700リクエストになる。逐次・間隔2秒以上・複数夜に分割し、spec に負荷見積りを書く（ADR-0067）
2. 規約の再確認: 運営は一般財団法人BOATRACE振興会で、公式サイト（boatrace.jp）と同一趣旨のサイトポリシー。ADR-0067の現状維持の判断の範囲に収まる。ただし本ファイルは法的見解ではない
3. 戸田・浜名湖・宮島（ADR-0055で会場サイトのToS制限により除外済み）のデータもBOATCASTには載っている。取り込むかはユーザー判断（BOATCAST側の規約は同一だが、会場側の著作権条項との関係は未確認）

## 確認した規約・ポリシー

対象: https://boatcast.jp/static/sitepolicy/index.html（2026-09-20取得。プライバシーポリシーはCookie関連のため対象外）

- 運営: 一般財団法人BOATRACE振興会
- 著作権: コンテンツは当会・第三者の著作権で保護。著作権法が定める場合、または個別の利用条件が示されている場合を除き、私的使用等の範囲を超える無断使用（複製・改ざん・頒布を含む）は不可。boatrace.jpのサイトポリシーと同一の文言
- 禁止事項: 「不正アクセス、大量の情報送受信及び大量のアクセスなど、本サイトの運営に支障を与える行為」。自動取得そのものを禁止する記載は無い
- API・データ提供・商用利用に関する条項は無い。有償のAPIも見つからなかった
- robots.txt: 存在しない（403のエラーページが返る。CloudFront配下の未配置ファイルと同じ挙動）

## BOATCASTとは

- 運営: BOATRACE振興会。公式のWeb映像サービス（LIVE・リプレイ・レース情報）。2021-10提供開始
- レース詳細画面（race.boatcast.jp）の「直前情報」に「オリジナル展示データ」タブがある。公式の展示タイム（全会場共通）に加え、会場が独自に計測・公開する一周・まわり足・直線等を表示する（[BOATCAST通信vol.4](https://www.boatrace.jp/owpc/pc/site/news/2025/07/44414/)）

## データの所在と形式

画面はSPAで、データはレース単位のTSVテキスト（`Content-Type: text/plain`、`Cache-Control: no-cache`、CloudFront配信）。画面のJS（`/assets/js/OriginalDisplayData.js`）から特定した。

```
https://race.boatcast.jp/txt/{jo}/bc_oriten_{yyyymmdd}_{jo}_{rr}.txt
  jo: 会場コード2桁（boatrace.jpと同一体系）  rr: レース番号2桁
```

```
data=
1	3                  ← 1行目: 計測状態(1=計測あり, 2=計測不可) / 項目数
一　周	まわり足	直　線   ← 項目名（会場により異なる）
1	岡部　　大輔	19.25	4.63	8.10   ← 枠番, 選手名, 各値
```

- 存在しないファイルは403（HTMLのエラーページ）になる。403=そのレース・会場のデータ無し
- 同画面は`/hp_txt/{jo}/bc_j_tkz_...txt`（直前情報: 展示タイム・チルト・体重・調整重量）も参照する。今回は取得していない

## 過去日の取得

- 2025-12-03、2025-12-15、2025-06-14（住之江1R）でファイルが存在した。DBの`races`は2025-12-03から始まるため、2025-12以降の全期間を埋められる見込み。それ以前も取れる可能性がある（遡及限度は未特定）
- ファイルの`Last-Modified`が翌0時台になっており、日次で再生成された確定版が置かれている可能性がある。当日の随時更新かどうかは未検証（画面側は当日のみ60秒間隔でポーリング）

## 既存データとの関係

- `exhibition_data`の展示タイムは公式beforeinfoの値。BOATCASTの`bc_j_tkz`側にも同じ展示タイム・チルト・体重があり、重複する。オリジナル展示データ（`bc_oriten`）は周回・まわり足・直線で、現状DBに列が無い。補完関係
- 取得先を公式サイトの別ページ（会場サイト）にする案と比べ、BOATCASTは全会場が同一URL構造・同一フォーマットで、会場別スクレイパーが不要

## 負荷と実装難易度の見積り

- 過去分: `races`が44,676件（2025-12-03〜、292日）。1レース1リクエストで約44,700回。1.5秒間隔でも約18.6時間、2秒間隔なら約24.8時間。江戸川等の403も含む。複数夜に分割し、429/503で即時中止する
- 日次: 1日あたり約12〜13会場×12R＝約150回。2秒間隔で約5分。発表タイミング（前検・直前）に合わせるかは要設計
- 実装難易度: 低。JSONではなくTSVの固定形式で、認証・トークン・クッキーは不要。会場別に項目が異なるため、保存は`(race_id, boat_number, kind, value)`のような縦持ちか、項目名を保持する設計が要る（DDLは本調査の範囲外）
- 文字コードはUTF-8。全角スペースを含む選手名・項目名は正規化が必要（表示用途では枠番で`race_entries`と突合する）

## 今回の調査で行ったアクセス

37回（UA `BoatraceAIBot/1.0`、逐次、2秒間隔）。429/503は無し。403は6回（robots.txt、常滑の非開催日、江戸川、2025-11-15の大村、URL組立てミスによる無効なURLが2回）。403の実体はいずれも未配置ファイル（S3/CloudFrontの標準挙動）で、レート制限やUAブロックではない。
