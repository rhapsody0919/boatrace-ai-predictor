# noteパイプラインのclaim対象が全件blog依存でブロックされている

## 現象（2026-10-08確認）

`sns-pipeline-note.md`のポーリング実行で`getClaimableTopicTargets()`が返す
claim可能な8件（platform='note'、`sns_topic_targets.status='pending'`）すべてが、
「2. ブログ本文の生成状況を確認（依存関係チェック）」で`platform='blog'`の
下書きが見つからず、claimしたターゲットを`pending`に戻すだけで毎回終了している。

対象の`sns_topics.id`と、それぞれの`platform='blog'`ターゲットの状態:

| topic_text（要約） | 作成日 | blogターゲット状態 |
|---|---|---|
| 桐生 1コース勝率 | 2026-09-05 | `skipped`（恒久ブロック） |
| イン崩れ警戒TOP5（平和島8R・桐生1R等） | 2026-09-05 | `skipped`: premise-stale |
| 桐生 逃げ決まり手構成比 | 2026-09-05 | `skipped`: データ検証で主張が裏付けられず |
| 福岡4R（イン崩れ） | 2026-09-13 | `pending`（約1ヶ月放置） |
| 下関12R・常滑7R（イン崩れ） | 2026-09-14 | `pending`（約1ヶ月放置） |
| 蒲郡1R（イン崩れ指数100%） | 2026-09-06 | `skipped`: daily-auto型の当日ダイジェスト由来 |
| 桐生1R（イン崩れ注意度99%） | 2026-09-09 | `pending`（約1ヶ月放置） |
| 福岡3R（イン崩れ指数100%） | 2026-09-12 | `pending`（約1ヶ月放置） |

## 問題点

1. **`skipped`の4件**: blogパイプラインが生成しないと恒久的に決定済みのため、
   noteパイプラインの依存関係チェックが永久にFalseになる。claim→pending復帰の
   空ループが今後も毎回（1時間おき）繰り返される。
2. **`pending`の4件**: いずれも`daily-auto`型（「本日」を含む特定日のイン崩れ
   指数ネタ）で、対象日（9/9〜9/14）から約1ヶ月経過した現在もblog側で未生成。
   今generateしても「本日」が実際には1ヶ月前のレースを指す、premise-stale状態に
   なる可能性が高い（イン崩れ警戒TOP5がblog側で実際にこの理由でskipされている
   のと同種の問題）。

## このセッションでの対応

- 定期実行の制約（1回1件・blog未生成ならclaimを戻す）に従い、最も古い1件
  （桐生1コース勝率、`sns_topic_targets.id = c87b8198-e3f3-49d4-91b1-fe694e05e379`）
  をclaim→依存確認→`pending`復帰のみ実施。note下書きは生成していない
- 残り7件には触れていない（claimしていない）

## 未対応・要判断

- `skipped`な3件（桐生1コース勝率・逃げ決まり手・蒲郡1R）に紐づくnoteターゲットは、
  blog側の判断が覆らない限り永久に生成されない。`markTopicTargetSkipped()`等で
  noteターゲット自体も`skipped`にする/しないはユーザー判断が必要
  （note単独で生成する設計変更の余地もあるため、機械的に決めない）
- `pending`な4件（福岡4R・下関12R常滑7R・桐生1R・福岡3R）は、blogパイプライン側が
  なぜ約1ヶ月間これらを処理していないかの原因調査が別途必要（本ドキュメントは
  noteパイプライン実行中に気づいた副次的な発見であり、blog側の深掘りはしていない）
