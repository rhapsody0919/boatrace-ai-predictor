# ADR 0063: 選手ページ フィルタの配置転換・会場×枠番クロス集計・常時表示化

## ステータス

採用

## 背景

[ADR-0062](0062-racer-page-filtered-view-tabs.md)でタブ化を実装・レビュー・PR化（#686）した後、ユーザーからモック確認を経て2件の追加フィードバックがあった。

1. **フィルタの発見性が低い**: フィルタは「会場別成績」「枠番別成績」「枠番別回収率」等、6セクション分スクロールした先（`RacerPerformanceStats.jsx`旧558行目付近）にあり、ユーザーが「組み合わせで検索できる」ことに気づきにくい
2. **会場だけ選んだ場合に一覧性が失われる**: 旧設計は「フィルタ未選択（一覧表示）」と「フィルタ1つ以上選択（タブの単一結果）」の二値切り替えだった。しかし「唐津だけ選んで、唐津での枠番別の傾向を一覧で比較したい」という中間的なニーズ（会場は固定、枠番はまだ決めていない）に応えられない

天才UI/UXデザイナー・熱血ボートレースファンの視点で検討した結果（対話内で実施、Artifactモックで反復確認済み）、以下の設計に転換する。

## 決定

### 1. フィルタの配置転換

フィルタ（会場・枠番・グレード・レース種別）を「成績・調子」見出しの直下・最上部に移動し、常時表示する。全国勝率・平均STカードはフィルタの影響を受けない「選手の現在の勢い」として、フィルタの直下に維持する。

### 2. 会場×枠番のクロス集計（新規集計ロジック）

会場・枠番の2軸は、どちらかを固定したら**固定していない方を一覧化**する。

| 会場 | 枠番 | 表示 |
|---|---|---|
| 全 | 全 | 会場別一覧＋枠番別一覧（既存と同じ2テーブル） |
| 固定 | 全 | その会場限定の枠番別一覧（1テーブル） |
| 全 | 固定 | その枠番限定の会場別一覧（1テーブル） |
| 固定 | 固定 | 単一カード（勝率・2連率・3連率・単勝/複勝回収率・平均ST・平均展示タイム、旧「概要」タブと同内容） |

グレード・レース種別はこのクロス集計の対象外（一覧化しない、絞り込み専用の軸のまま）。理由: グレードは5値・レース種別は3値で、会場（24会場）・枠番（6枠）と異なり「一覧で比較する」価値より「絞り込んで見る」価値の方が高いとユーザーとの検討で確認済み。

### 3. 一覧テーブルの行クリックでフィルタに反映（新規、双方向連携）

会場別一覧・枠番別一覧（クロス集計後のものも含む）の各行をクリック可能にし、クリックするとその値（会場名・枠番）が対応するフィルタに反映される。「一覧を見て気になった行から深掘りする」という導線を提供する。

### 4. 決まり手・推移・レース一覧のタブ廃止、常時表示化

[ADR-0062](0062-racer-page-filtered-view-tabs.md)で導入した4タブ（概要／決まり手／推移／レース一覧）を廃止する。「概要」は上記2のクロス集計ブロックに統合される。「決まり手」「推移」「レース一覧」は一覧化せず、常に「現在選択されている全フィルタ条件（会場・枠番・グレード・レース種別）」で絞り込んだ単一の内訳として、タブ切り替えなしに常時表示する。

## 却下した選択肢

- **タブ構成を維持し、フィルタの位置だけ上に移動する**: フィルタの発見性は改善するが、「会場だけ選んだ場合に一覧性が失われる」という2番目の問題は解決しない。ユーザーの指摘は表示構造自体（一覧⇄単一結果の二値設計）に向いていたため却下
- **グレード・レース種別も一覧化する（会場×グレードのクロス集計等）**: 軸が増えるほど一覧の組み合わせ数が増え（会場×グレードで24×5通り等）、実装・表示の複雑さに対して価値が見合わない。BOA-263が既に「会場×グレードの横断分析」を別の独立タブとして提供しており、選手個別ページでの重複実装を避ける意味もある
- **決まり手・推移・レース一覧を折りたたみ（アコーディオン）にする**: BOA-268の「情報量過多」指摘への対策として検討したが、モック確認でユーザーが「それで良い」と常時表示のまま承認したため見送り。将来的に情報量過多が問題になった場合の代替案として記録は残す

## 影響

- `aggregateRacerVenueBoatStats`（[ADR-0061](0061-racer-page-grade-stage-filter-approach.md)で追加）は「会場×枠番どちらも固定」の単一集計用として維持し、新たに「会場または枠番の一方が未固定の場合にグループ化配列を返す」集計関数（例: `aggregateRacerCrossStats`）を追加する
- `RacerPerformanceStats.jsx`の`vcTab` state・タブUI（ADR-0062で追加）を削除し、成績ブロックを`vcVenue`/`vcBoat`の固定状況で分岐する表示ロジックに置き換える
- 既存の会場別/枠番別テーブル（unfiltered時のみ表示だった）に行クリックハンドラを追加し、クロス集計後の一覧テーブルにも同じインタラクションを持たせる
- レース一覧・決まり手・推移は表示条件が「タブ選択中」から「常時（フィルタが何であれ）」に変わるため、ページの縦の長さは全体的に伸びる。BOA-268の懸念とのトレードオフだが、ユーザーが優先度として一覧性・発見性を選んだ判断として記録する
