# ADR-0109: PR の大きさの線（300行・5ファイル）は機械で数え、超えた PR は重い道に回す

## 状況

- AGENTS.md の安全の6点の5は「1つの PR は差分300行・5ファイル以内、超えそうなら止める」。数字の根拠を書いた ADR は無く（`docs/adr/` に「300行」の記述なし）、数え方（試験・訳・注釈・消した行を数えるか）も決まっていなかった
- 会場ページの刷新（#3304・その前の #3303）で、作り手は自分で数え、線に収めるために置き場の決まりを曲げた。新しい計算を `src/pure` でなく `src/pages` の Parts に置いた、承認された文言の訳のキー（4言語分）を足さず既存のキーを流用した、注釈を削って315行を300行にした（300行に合わせる直しが3回）、新しい e2e の spec（86行）も行数に数えた
- 線は「レビューできる大きさ・壊れたときの範囲を狭く」の代わりの物差しなのに、正しい形（試験・訳・注釈）にするほど罰が重くなっていた（BOA-1718、system-architect の審査で「直してから採る」）

## 決定

1. **線の数字は変えない**（300行・5ファイル）。根拠は無い（目安）が、動かす根拠も無い（オーナー 2026-11-24）
2. **作り手は数えない。機械が数える**。数え方の正本は `scripts/maintenance/prSize.js`（git から読む入口は `prSizeGit.js`。`verify-pr-size.js` が試験し、PR の数を表示する。#3324）。数えない物は少なく決め、ほかは全部数える（知らない置き場は数える側に倒れる）
   - 新しく足した e2e の spec と、同じ PR で台帳に tier=ci で足した `scripts/maintenance/verify-*.js`、`verify-registry.json` の項目の追加だけ（既存の試験の変更・helper・verifyData は数える）
   - 試験のファイルに本体を置く抜け道は数える: 試験でない変更ファイルの足した行に試験の名が出る、試験を経由して読む、試験の置き場から数える置き場への改名（先の全部の行）
   - ja 以外の locale の行の追加だけで、足したキーの集合が同じ PR の ja の同じファイルと同じとき（ja は数える）
   - 空行と、コードのファイルの注釈だけの行
   - 消しただけの行（数えるのは足した行。死んだコードを消す PR を罰さない。目安、根拠なし）
   - 線の外の PR: 移すだけ（`prLaneMoveOnly.js` の判定）と記事の PR（`scripts/content/check-content-pr.js` が通す物）。それぞれの判定をそのまま呼ぶ
3. **超えた PR は落とさず、pr-lane で重い道（人が見る）に回す**（オーナー 2026-11-24 の (ii)。`config/pr-path-rules.json` の規則、BOA-1718 の続きの PR）。窓口・オーナーの大きな PR を止めないため。作り手は起動の契約（AGENTS.md の5）で、超えそうなら分ける・分けられなければ止める
4. **着手の前に見積もって分ける**。置き場の決まり（`src/pure`・訳のキー・注釈）を曲げないと収まらないなら分ける。「置き場を優先して本文に1行書けば超えてよい」はしない（自己申告の抜け道になる）

## 結果

- 正しい形（試験・訳・注釈）にしても罰が増えない。#3304 は 201行・4ファイル、#3303 は 157行・4ファイルと数え直され、どちらも線の中（`verify-pr-size.js` の試験）
- 残る誘因: 新しい計算を `src/pure` に置くと pr-lane の H3 で重い道になる。線を直しても `src/pure` を避ける誘因は残る（H3 は変えない。PR 本文の自己点検で見る）
- 数え方を変えるのは `prSize.js` と試験の変更（pr-lane の H1・判定の守りとして人が見る）
- 差分で数えるので、試験のファイルに本体を置いて次の PR で import を足す形（2つの PR に分ける）は捕まえられない。依存の向きの関所に「src・api・scripts/lib から試験を import しない」を足すのが本筋（未着手）

## 戻し方

- pr-lane の大きさの規則を `config/pr-path-rules.json` から外せば、線を超えても重い道にならない（数え方の verify は表示だけなので残してよい）
