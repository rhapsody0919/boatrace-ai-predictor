# ADR 0092: 自動送信を止めるリンクは、item ごとの使い捨ての token で、管理画面の認証を通さない

## ステータス
提案中（docs/design/sns-pdca-loop/plan.md §3）

## 背景
spec A6 は「スマホから1タップで止める」。事前通知は Slack に送る。管理画面と管理 API は HTTP Basic 認証（`requireAdminAuth`）で、Slack のアプリ内ブラウザでは資格情報を覚えていないことがあり、毎回の入力が要る。署名付きのリンクの仕組みは今は無い。

## 決定
- item ごとにランダム 32 バイトの token を作り、DB には SHA-256 だけを保存する（153 `stop_token_hash`）。リンクは `/api/sns-stop/<token>`、期限は止められる期限の30分後
- GET は確認の画面（対象と「この投稿を止める」ボタン）を返すだけで、止めるのは POST。Slack のリンクの先読み（unfurl）で止まらないようにする
- このリンクでできるのは「その item を止める」ことだけ。送る・再開する・モードを変える操作は管理画面（Basic 認証）だけ

## 却下した選択肢
- **管理画面へのリンクにして Basic 認証を通す**: スマホで毎回パスワードの入力が要る場面があり、締切前の短い時間に止められない恐れがある
- **Slack のボタン（インタラクティブメッセージ）で止める**: Slack アプリの作成と署名検証の受け口が要り、今の Webhook だけの構成から大きく増える
- **GET で即座に止める**: Slack・メールのリンクの先読みで勝手に止まる

## 影響
- リンクが漏れた場合に第三者ができるのは、その投稿を止めることだけ（投稿が出ないだけで、安全側）
- 止めた記録に `stopped_via='link'` を残し、誰が押したかは区別しない
