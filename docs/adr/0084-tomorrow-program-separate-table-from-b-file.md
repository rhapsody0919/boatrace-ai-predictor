# ADR 0084: 翌日の出走表は B ファイルを別テーブル tomorrow_program に取り込む

## ステータス
提案中（BOA-223。取得元と置き場所はユーザーが2026-10-02に決定、方式の詳細はこの ADR）

## 背景
トップに「明日」タブを足し、翌日の出走表を前日の午後から見せる（docs/design/tomorrow-program/spec.md）。前日の夕方に選手まで載っている取得元と、その置き場所を決める必要がある。

2026-10-02 の実測:
- 公式サイトの出走表ページ（racelist?hd=明日）は、17:01 時点で締切予定時刻だけ。選手は「データはありません」
- 公式 B ファイル（番組表）は14時台に初公開、会場ごとに夜まで順に埋まる。選手・級別・勝率・モーター・締切予定がある
- 朝の初期化（scripts/lib/racesInit/job.js:98-106・247-250）は「races に行がある会場＝初期化済み」として会場を丸ごとスキップする

## 決定
B ファイルの翌日分を、新テーブル `tomorrow_program` に Vercel Cron（15分ごと、JST 14:00〜23:45、Last-Modified が変わったときだけ解析）で取り込む。画面は `tomorrow_program`・`race_series`・`racer_profiles` を直接 select する。races・race_entries には書かない。

## 却下した選択肢
- **races・race_entries に前倒しで入れる**: 朝の初期化が会場ごとスキップし、race_entries の作り直し・展示・予想・race_conditions が作られなくなる。0件監視（monitor.js）・GitHub 側のフェイルセーフ（morning-init.js）・選手の最新行を引く画面（racerService.js:34 等）・sitemap にも翌日の行が混ざる。判定箇所を5か所以上直す必要があり、予想と的中の流れに影響して戻しにくい
- **B ファイルを閲覧のたびに読む API（DB に保存しない）**: 変更は少ないが、閲覧ごとに外部サイトへアクセスし、速さと可用性が取得元に依存する。取得時刻と件数が残らないため、data-acquisition.md の完了条件（件数・タイミング・監視）を満たせない。新規の取得は Vercel Cron で行うという ADR-0066 とも食い違う
- **公式の出走表ページ（racelist）を前日に取る**: 前日17時でも選手が未公開で、目的を満たさない
- **節データ（race_series）だけで会場・節名を出す**: 当初の推奨案。ユーザーが「出走表が出ないなら意味が薄い」と判断し却下（2026-10-02）
- **会場・レース・艇の3表に正規化する**: 1日最大1,728行で、画面は会場単位で丸ごと読む。表を分けても読み書きが増えるだけ

## 影響
- 当日の流れに触れないため、予想・監視・朝の初期化のリスクは無い
- 名前が4文字で切れるため、画面で racer_profiles を引く読み取りが1本増える
- 前日時点のスナップショットで、当日朝の欠場・選手交代は反映されない（画面で明記する。差分表示はやらない）
- B ファイルの「データ更新待ち」の判定を parseBText に足す。既存の呼び出し元は影響を受けない
