# ADR 0088: 会場の決まり手を直近1年と直近90日で並べるため、期間ごとの集計を毎日の表に持つ

## ステータス
採用（2026-10-07。値の決定はユーザー「P-2 推奨どおり」。実装方法は、採用後に RPC から表に変えた。理由は「却下した選択肢」の1つ目）

## 背景
思考アシストの会場の特徴のシートに、会場の決まり手の割合を出す。

ファン4人（discussion-panel、実装の都合を伏せた）の結論で、ユーザーが推奨どおり決めた内容:
- 直近1年を主にする（徳山 2,592件）
- 直近90日（612件）を並べる
- 2つの割合のぶれ幅が重ならない決まり手にだけ「最近↑／↓」を付ける
- 季節別・直近3年・全期間は出さない

既存の `winning_technique_stats` の扱い:
- 会場×1着の枠番×決まり手の直近90日だけを持つ
- 毎日 `scripts/daily/update-winning-technique-stats.js` が `race_results` から作る
- 分析ページ（WinningTechniqueChart など）が読む

直近1年を数える条件:
- 新しい表（`races`×`race_results`、2025-12-03〜）と長期の表（`kb_archive_races`、〜2025-12-02）をつなぐ必要がある
- `kb_archive_races` は匿名に読ませていない（RLS 有効、ポリシーなし）

モックの「直近1年 2,196レース」は誤りだった。新しい表だけを数えていた。正しくは2,592レース。

## 決定
新しい表 `venue_technique_period_stats` を作る（マイグレーション 134）。

表の中身:
- 会場×期間（90日・365日）×決まり手の、件数と期間の総レース数
- 書くのは毎日の `update-winning-technique-stats.js`（service_role）。既存の処理の後に、会場ごとの期間の集計を足して書く
- 長期の表は、期間に 2025-12-02 以前が含まれる間だけつなぐ
- 数えるレースの除外は既存と同じ（中止・不成立・1着なし・決まり手なし）

画面の扱い:
- この表を読み、直近1年を主、直近90日を薄い帯で並べる
- 「最近↑／↓」は `wilsonInterval` で2つの割合のぶれ幅が重ならないときだけ付ける

## 却下した選択肢
- **読み取り専用の RPC `venue_winning_technique_counts`（ユーザーに推奨した最初の案）**
  - 長期の表は匿名に読ませていないので、SECURITY INVOKER では匿名から数えられない
  - SECURITY DEFINER にすると匿名から呼べるが、DEFINER の関数を匿名に公開するのは規則で禁じている（`verify-migration-rls` 7、マイグレーション 113）
  - 採用の後、マイグレーション案を書く段階で分かった（作る側の確認の抜け）
- **既存の `winning_technique_stats` に直近1年の列を足す**
  - 行は会場×枠番×決まり手で、直近90日に出ていない決まり手（1年には出ている）の行が、90日の件数0で増える
  - その表を読む既存の分析ページに0%の行が出る
- **長期の表に匿名の SELECT を付けて RPC で数える**: 生の長期データ全体を匿名に開くことになり、決まり手の集計のためだけには広すぎる

## 影響
- 新しい表が1つ（約290行、毎日書き直す）。RLS 有効、匿名は SELECT のみ
- 本番への適用はユーザー（`docs/db-migration/134-runbook.md`）。適用は書き手の PR のマージより前に行う。マージ後にワークフローを1回手動で動かすまで、画面は決まり手の節を出さない
- 既存の表・既存の分析ページ・BOA-271 のバッチには影響しない
