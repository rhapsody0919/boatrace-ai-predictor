# ADR 0017: 龍神レーダー デザイントークンのコントラスト自動検証方式

## ステータス
採用

## 背景
ブランドビジュアル刷新のロールアウト方針確認時、ユーザーから「背景色と文字色が被って見えないとか、そういうのを可能な限りテスト等で防止してほしい」との要望があった。深紺×金・生成り×銀のような低コントラストになりやすい組み合わせを多用するため、機械的な検証手段を決める必要がある。

## 決定
2段階のハイブリッド方式を採用する。

1. **静的トークンペア検証スクリプト**（`scripts/maintenance/check-token-contrast.js`）: `design-tokens.css`の主要な意味トークン（背景/文字色）の組み合わせをリスト定義し、WCAG相対輝度計算でコントラスト比を算出、通常テキストで4.5:1未満を検知する。外部依存を増やさずNode単体で完結し、トークンを追加・変更するたびに高速に実行できる
2. **`@axe-core/playwright`を既存の`e2e/smoke.spec.js`に追加**: 実際にレンダリングされたページ（ライト/ダーク両テーマ）に対してアクセシビリティスキャンを実行し、静的リストでは見逃す「実コンポーネントの組み合わせで生じるコントラスト不足」を検知する

## 却下した選択肢
- **静的スクリプトのみ**: トークン単体の組み合わせは検証できるが、半透明背景の上に重なるテキストなど、実際のコンポーネントでの適用結果までは検証できない
- **axe-core + Playwrightのみ**: 基盤フェーズ（トークン定義のみでまだ画面が存在しない段階）では検証対象がなくフィードバックが遅い。ブラウザ起動を要するため実行速度も遅い

## 影響
新規npm依存として`@axe-core/playwright`を追加する。既存の`npm run test:e2e`実行フローに組み込むことで、CLAUDE.mdの「影響範囲が広い変更ではE2Eスモークテストを実行する」という既存運用にそのまま乗せられる。
