# ADR 0087: 思考アシストの類似レースの割合を、どの件数で数えるか

## ステータス
提案中（ユーザーの判断待ち。spec D-34 の「層の全件」を見直すため）

## 背景
思考アシストは、類似レース（v16 の層）の1号艇の1着・万舟・決まり手・よく出た3連単・組ごとの件数を出す。spec D-34 で「類似レースの件数は層の全件」に決まった。根拠は「例のレース（徳山10R、層63件）では v16 の既定 min(400, 層) と同じ値」だった。

plan で本番の API を確かめると、層は多くのレースで大きい。2026-10-07 の36レースのうち31レースで層が2,000件を超え、最大は58,312件だった。2,000件以下は G1 と準優勝戦・優勝戦の5レースだけだった。

画面が読める行には上限がある。
- similar API の `neighbors`: 似ている順の上位800件
- layer API の `rows`: 新しい順の2,000件

層の全件の集計を返す API は無い。

## 決定（推奨。ユーザーの判断で確定する）
**(C) 龍神ソナーと同じく、似ている順の上位 min(400, 層) 件で数える。**
- `neighbors` の先頭から min(400, n_layer) 件を `aggregateNeighbors` で数え、万舟は `payout_3tan >= 10000` を数える
- 画面には「類似レース {n}件（似ている順の上位）」と書く。用語の「?」に、層の件数と「龍神ソナーの類似レースと同じ数え方」を書く

## 却下した選択肢
- **(A) v16 のバッチに、層の全件の集計（1着・万舟・決まり手・3連単）を足す**
  - D-34 の文どおりの値になる。層の条件が同じレースは集計を使い回せるので、計算は軽い
  - ただし BOA-271 の別レーンのバッチと API の変更が要る。spec の「新しいバッチの変更はやらない」にも反する
  - 龍神ソナーの類似レース（上位400件）と、同じ呼び名なのに値が違うことになる
- **(B) layer API の新しい順の2,000件で数える**
  - 今の API で取れる
  - ただし層が2,000件を超えるレースでは「直近2,000件」になり、層の全件でも似ている順でもない。説明が増え、どちらの定義とも合わない
- **(D) 層の件数が800件以下（`neighbors` に全件ある）のときだけ層の全件で、超えたら (C)**
  - 準優勝戦・優勝戦では D-34 どおりになる
  - ただしレースによって数え方が変わり、「数え方は2つ」の説明が条件つきになる

## 影響
- (C) なら、用語の「?」の「龍神ソナーの類似レースと同じ」（D-20）がそのまま成り立つ。新しいバッチ・API は要らない
- 例のレース（層63件）は D-34 のときと同じ値（63件・1号艇の1着 34件・万舟 11件）
- D-34 の「層の全件」は、(C) を採るなら書き直す
