# ADR 0009: 新AI予想モデルのスコアリング方式

## ステータス
採用

## 背景
`docs/design/ai-model-redesign/spec.md`で、新モデルは既存の非公開モデル（シャーロック/ワトソン/アドラー/マイクロフト/モリアーティ）のロジックを参考にするのみでゼロから実装する方針が決まった。一方、実装のベースとなるスコアリング手法（統計的ヒューリスティック／機械学習／条件付きロジット）は未確定だった（spec.md未確定事項）。

この判断は、FR6（各艇のAIスコアに根拠バッジを表示する説明可能性要件）とFR9（月次固定パラメータ運用、自動再学習は行わない）の両方に直接影響するため、技術選定として整理する。

## 検討した選択肢

### A. 統計的ヒューリスティック（加点式）
現行3モデル（`calculateStandardScoreV2`等）と同型。各特徴量に統計分析で導いた係数を掛けて加算し、スコアを算出する。

- 適合点: 係数の大小がそのまま「どの指標が寄与したか」になるため、FR6の根拠バッジ（例:「全国勝率↑ モーター2連率↑」）を素直に実装できる。月次でのパラメータ再チューニング（FR9）も係数の手動調整で完結し、学習パイプラインが不要
- 不適合点: 特徴量間の非線形な相互作用（例:「モーター2連率が高くても、コースが不利なら効果が薄れる」等）を表現しづらい

### B. 機械学習（LightGBM等、ポアロV2と同型）
勾配ブースティング木で1着/2着/3着確率を学習する。

- 適合点: 非線形な相互作用を自動的に学習でき、`docs/design/poirot-ml-models.md`にバックテスト実績がある
- 不適合点: 「なぜこのスコアか」を人間可読な形で出すにはSHAP値等の後付け説明が別途必要で、FR6の根拠バッジ実装が複雑化する。学習データセット構築・再学習パイプラインの運用コストが高く、FR9の「月次固定パラメータ、自動学習は行わない」という運用方針と相性が悪い。開発体制（未確定、spec.md参照）次第では継続運用が難しい

### C. 条件付きロジットモデル（シャーロックと同型）
Benter式の二段階オッズ結合（統計モデル×市場オッズ）を用いる。

- 適合点: 統計的に厳密で、オッズ結合（EVフィルタ）との親和性が高い
- 不適合点: 実装・チューニングに統計的知識が要り、根拠バッジのような「艇ごとの寄与度」を直感的な言葉に変換するには追加の変換ロジックが必要。ゼロから実装する場合、Aより開発コストが高い

## 決定
**A（統計的ヒューリスティック）を基本方式として採用する。** 各艇のスコアは特徴量×係数の加算式とし、寄与度が高い上位2〜3因子をFR6の根拠バッジとしてそのまま表示する。

ただし、1マーク展開パターンとの条件付き構造（FR2）は、単純な加算式ではなく「パターンごとに異なる係数セット」を適用する形で、Cの発想（条件付き）を部分的に取り込む。これは新規の機械学習パイプラインを必要とせず、パターン別に係数をチューニングするだけで実現できる。

Bの機械学習アプローチは今回は採用しない。ただしバックテスト（FR10）の結果、統計的ヒューリスティックでは回収率100%超えの目標（spec.md非機能要件）に届かない場合は、将来的な再検討課題として残す。

## 却下した選択肢
- B（機械学習）: 上記の通り、説明可能性要件（FR6）と月次固定運用（FR9）に対する不適合が大きく、今回は不採用
- C（条件付きロジット）をそのまま採用: ゼロから実装する場合の開発コストがAより高く、根拠バッジとの相性でAに劣後するため、発想のみ部分的に取り込むに留める

## 影響
- `scripts/lib/`配下に新モデルのスコアリングロジックを実装する際、既存3モデルの係数設計（`calculateStandardScoreV2`等）のコードパターンを土台に、1マーク展開パターン別の係数セットを追加する構成になる
- 機械学習ライブラリ（LightGBM等）の新規導入は不要。既存のNode.js実装のみで完結する
- バックテストで回収率目標に届かない場合、係数の再チューニング（月次運用の範囲）で対応し、それでも不十分なら機械学習導入を再検討する

## 追記（2026-08-13、実装詳細の更新）
「A（統計的ヒューリスティック）を採用する」という決定自体は変わらないが、実装詳細（v3、Task8）は当初の「生値×固定係数の加算式」から「比較対象グループ内でのZスコア化×予測力ベースの重み」に変更した。理由: `analyze-indicator-predictive-power.js`（2026-08-12）で11指標の実際の予測力を検証したところ、当初の固定係数が予測力と逆相関する箇所があった（`courseRate`が最強なのに係数最小、`form`が最弱なのに係数最大級）。値のレンジが指標ごとに大きく異なる（勝率0-10 / モーター0-100% / ST0.05-0.3秒等）ため、生値に固定係数を掛ける方式では正しい重み付けが困難と判断し、Zスコア化に変更した。

また、2026-08-13の方針転換（spec.md改訂履歴参照）で3連単は補助的な参考情報に格下げされ、「回収率100%超え」は必須の受入基準ではなくなった。3連単でのA案（統計的ヒューリスティック）の実績はEV>=1.2フィルタで回収率78.8%（1週間分検証）。一方、複勝はコース別勝率という単一指標（Zスコア化すら不要な単純な順位比較）の方が複合スコアより精度が高いことが判明し（的中91.9%・回収146.0%）、複勝についてはA案の「複数指標を組み合わせる」という発想自体を採用していない。
