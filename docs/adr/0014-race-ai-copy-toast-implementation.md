# ADR 0014: race-ai-copy機能のトースト通知実装方式

## ステータス
採用

## 背景
BOA-194（race-ai-copy機能）でコピー成功時のフィードバックとしてトースト通知が必要。既存コードベースにトースト/通知コンポーネントは存在しない（調査済み、`Toast`/`toast`/`snackbar`等のgrep結果0件）。実装方式として (a) 軽量な自作コンポーネント (b) 外部ライブラリ（`react-hot-toast`, `react-toastify`等）導入 の2案を比較する必要がある。

## 決定
**軽量な自作コンポーネント**（`src/components/Toast.jsx`、`framer-motion`の`AnimatePresence`でフェードイン/アウト）を採用する。

- `framer-motion`は既に依存関係にあり（`PredictionPanel.jsx`で使用中）、追加バンドルコストなしで実装可能
- 要件は「コピー成功」の単一パターンのみで、キュー管理・複数種別（成功/エラー/警告）・アクションボタン付き通知等の高度な機能は不要
- シンプルな`useState`ベースの表示/非表示制御＋`AnimatePresence`で十分要件を満たせる

## 却下した選択肢
- **`react-hot-toast`等の外部ライブラリ導入**: 機能は豊富だが、単一の成功通知のみという要件に対して過剰（YAGNI）。新規依存追加によるバンドルサイズ増加、将来のライブラリメンテナンス負荷のデメリットが要件に見合わない

## 影響
- 汎用設計にしておけば今後別機能（他のコピー機能・保存完了通知等）でも`Toast`コンポーネントを再利用できる
- 複数のトーストを同時表示するキュー機能が将来必要になった場合は、この時点でのシンプル実装を拡張する
