# ADR 0023: オンボーディング用操作キャプチャ動画の配信方式

## ステータス
採用

## 背景
`docs/design/onboarding-guide-revamp/`で、ガイドページ（`/how-to-use`）とホーム画面の初回訪問者向けカードに、操作フロー（会場選択→レース選択→AI分析）を紹介する30〜60秒の動画を埋め込むことになった。動画ファイルをどこに配置し、どう配信するかを決める必要がある。

既存のSNSマーケティング動画（TikTok/X向け）は`sns_drafts`テーブル経由でSupabase Storageに保存されている（ADR 0019, 0022）が、これは投稿前レビュー・承認フロー用の内部管理目的であり、今回のように全訪問者が閲覧する公開ページに直接埋め込む用途とは性質が異なる。

## 決定
動画ファイル（圧縮済みmp4、サムネイル画像）は**`public/videos/`配下に直接配置**し、`GuideVideoPlayer`から素の`<video>`タグで配信する。Vercelの静的ホスティング・CDN配信にそのまま乗るため、追加のインフラ・アカウント・コストが発生しない。

ファイルサイズはffmpegでの圧縮（解像度・ビットレート調整）で数MB程度に収め、`preload="none"`により訪問者がクリックするまでダウンロードが発生しないようにする（LCP/CLSへの影響を避ける、`spec.md`の非機能要件）。

## 却下した選択肢
- **Supabase Storageに配置し署名付きURL/公開URLで配信**: 既存のSNS動画管理と保存場所を統一できる利点はあるが、全訪問者アクセスによる読み出し帯域（egress）がSupabaseプラン課金に乗る。公開ページの静的アセットを外部ストレージ経由にする必然性が無く、無料で完結する`public/`配置を上回るメリットが無いため却下
- **YouTube等の外部動画プラットフォームに埋め込み**: 帯域・サイズの心配が無くなる利点はあるが、（1）外部ドメインへの依存が増える、（2）関連動画・広告等の望まない要素が埋め込みプレーヤーに表示されうる、（3）自社サイトのUI・ブランドと統一感のあるプレイヤー体験を作れない、という理由で却下。動画の性質（数十秒の操作説明、サイト内で完結させたい）にも合わない
- **CDN型の動画専用ホスティング（Cloudflare Stream等）の新規導入**: アダプティブビットレート配信等の高度な機能は不要な規模（30〜60秒・数本程度）であり、新規の有料サービス依存を増やすだけで見合わない。プロジェクト全体の「無料ツールのみで完結させる」方針（`docs/operation/sns-video-producer-prompt.md`）とも整合しない

## 影響
- リポジトリに動画バイナリが含まれるようになる。本数が少ない（当面1〜2本）うちは問題にならないが、今後動画を増やす場合はリポジトリサイズとVercelのデプロイサイズ上限に注意する
- 動画の差し替え・更新は通常のPRフロー（ファイル差し替え＋コミット）で行える。Supabase等の別管理画面を経由しないため運用がシンプル
- 多言語版（[BOA-230](https://linear.app/boat-ai/issue/BOA-230/ガイドページオンボーディング刷新の多言語版展開)）で動画を複数言語分用意する場合も、`public/videos/{locale}/`のような配置で同じ方式を継続できる見込み
