# ADR-0111: 選手ページの回収率の全国の基準を、毎晩数え直す小さな表に持つ（選手ページの通算の比べに限る）

## 状況

- 選手ページの「枠番別回収率」（単勝・複勝、#3523・#3532）と「3着以内のレースの3連単配当」（#3535 を作り直し中）に、意味づけ（基準と比べる棒、`src/pure/compareBaseline.js`、2026-11-26 オーナー承認）を入れる。比べる相手の「全国の同じ枠番の平均回収率」と、その1走あたりのばらつきが DB に無い
- 2026-11-26 オーナー「3連単のやつはすすめて」。数字だけの版は出さず、基準との比べと一緒に出す
- 置き場の比較は docs/design/racer-return-baseline/db-draft.md（system-architect 2026-11-26）。既存の 059・067・094 は粒度・定義・直書きの期間が合わず、都度の RPC は anon の時間の上限、静的 JSON は人手の更新で古くなる

## 決定

1. 新しい小さな表 `racer_boat_return_baseline`（主キー scope・boat_number、全国の枠番1〜6と全体の行0）に、走数と払戻の合計・二乗の合計を持つ。率は持たず、読み手の純関数で出す（ADR-0104 決定2: 率でなく件数を持つ）。窓は実測の列に持つ（ADR-0068）
2. 毎晩の Vercel Cron（共通ラッパ `createScrapeCronHandler`、ADR-0066 改訂1）から、集計の RPC `compute_racer_boat_return_baseline(p_from, p_to)` を月ごとに呼んで足し、全部を数え直して upsert する。1か月分の集計は 416ms（2026-11-26、本番の読み取りで EXPLAIN ANALYZE）
3. **この表は選手ページの通算の比べにだけ使う**。基準にそのレースより後の結果が入るので、レース詳細・予想・事前の判定には使わない（ST 考察の st_course_baseline が日付を持たず、過去のレースに後の結果が入った型を繰り返さない）。表の COMMENT にも書く
4. 回収率には良し悪しの色も偶然の判定も付けない（#3530 の承認「回収率の色は外す」、まれな大きな払戻で分布の裾が重い）。位置だけを棒で出し、言葉は検証済みの事実「回収率は先の期に続かない」（docs/knowledge/stat-findings.md）に寄せる
5. 表は RLS を有効にし、anon・authenticated に SELECT だけ。書き手は service_role だけ。RPC は service_role だけが呼べる

## 結果

- 過去の分の取り込み（BOA-1719）の後も、毎晩の数え直しで基準に自動で入る。期間を直書きしない
- 適用（db-apply）、vercel.json の crons の行、共通ラッパの mode を live にするのはオーナー。それまで画面は基準を出さず、値と走数だけを出す（基準が無いことを「平均並み」と見せない）
- 730日分の所要時間は月ごとの合計で約10秒の見込み（1か月 0.4秒×24）。関数の時間の上限の中

## 戻し方

画面は権限エラーで基準を出さない形に戻るだけで壊れない。vercel.json の crons の行を外し、表と RPC を DROP する。
