# ADR 0003: 会場写真の保管方式

## ステータス
採用

## 背景
spec.mdの要件4で、CC0/CCライセンスのフリー素材を会場ごとに追加する（ユーザー承認済み、見つからない会場は画像なしで許容）。画像を実際にどう配信するかの方式を決める必要がある。

## 決定
ライセンスを確認できた画像は実装時にダウンロードし、`public/images/venues/{slug}.jpg`としてリポジトリに保管して自ホスト配信する。各会場データに `image: { src, alt, credit, creditUrl }`（画像がない場合は`image: null`）を持たせ、`credit`にライセンス種別と出典を明記する。

## 却下した選択肢
- **外部URLを直接参照（hotlink）**: 実装コストは最小だが、Wikimedia Commons等の外部ホストへの実行時依存が生まれる。URL構造の変更・ホットリンク制限・表示速度低下（外部ホストのレイテンシ）のリスクがあり、本番サイトの表示安定性を外部要因に委ねることになる
- **画像なし（絵文字・アイコンのみ）**: 実装コストは最小でリスクもないが、ユーザーが明示的に「フリー素材を確認して使用」を選択しているため、この案は不採用（要件4の対応不足になる）

## 影響
- リポジトリに画像バイナリが追加されるため、リポジトリサイズが増加する（会場ごとに数百KB程度を想定、最適化してWebP等の軽量フォーマットを検討）
- 画像のライセンス確認はClaudeが実施するため、人手確認より誤判定リスクが相対的に高い（spec.mdの制約に明記済み、ユーザー了承済み）
- ライセンス出典（`credit`）はUI上にも表示し、法的要件を満たす
