# ADR 0062: 選手ページ フィルタ後詳細ビューのタブ化

## ステータス

採用

## 背景

[ADR-0061](0061-racer-page-grade-stage-filter-approach.md)でグレード・レース種別フィルタの実現方式を決めた後、ユーザーから追加要望があった: レース一覧（実際のレースへのリンク付き）、決まり手内訳、カード指標の拡張（複勝回収率・平均ST・平均展示タイム）、時系列推移。

`RacerPerformanceStats.jsx`は既にBOA-268で「8セクションで情報量過多」と指摘されている。フィルタ選択時に表示される要素（カード・決まり手傾向・展示タイム推移・STの推移）に加えて新規のレース一覧を単純に縦積みすると、フィルタを1回押すだけで画面が大きく縦に伸び、「概要を見る」と「深掘りする」の境界が失われる。

## 決定

**フィルタ（`vcActive`）選択時の詳細ビューのみをタブ化する。フィルタ未選択時の既存フラット表示（会場別/枠番別テーブル、unfiltered版の決まり手傾向・推移グラフ）は変更しない。**

タブ構成: 概要（カード）／決まり手／推移（平均ST・平均展示タイム）／レース一覧。

既存要素の再配置（新規ロジックではない）:
- 「決まり手」タブ = 既存の`showTechniqueSection`/`displayTechniques`（579-623行目）をそのままタブ内に移動
- 「推移」タブ = 既存の「展示タイムの推移」（627-653行目）・「STの推移」（655-681行目）をそのままタブ内に移動
- いずれも表示条件（`vcData.n > 0`等）・グラフ実装（recharts `LineChart`）は変更しない

新規実装が必要な部分:
- タブUI本体（新規 state、`RacerPerformanceStats.jsx`内）
- 「レース一覧」タブ（新規、`getRacerRaceHistory`が既に保持する`raceId`から`/race/{raceId}`へのリンクを生成）
- カードへの複勝回収率・平均ST・平均展示タイムの追加（`aggregateRacerVenueBoatStats`の集計拡張）

## 却下した選択肢

- **単純に縦積みで追加する**: 実装は最も簡単だが、フィルタ操作1回で画面の情報量が跳ね上がり、BOA-268の「情報量過多」指摘を悪化させる。ユーザーとの検討（天才UI/UXデザイナー・熱血ファン視点）で「概要と深掘りを分けたい」という結論に至ったため却下
- **フィルタ未選択時も含めて画面全体をタブ化する**: 既存のフラット表示（会場別/枠番別テーブル等）の構造・実装を変更する必要があり、影響範囲が今回のBOA-159のスコープを超えて既存の安定した表示にまで及ぶ。今回はフィルタ選択時に新たに出現する情報だけをタブ化し、既存部分への影響を最小化する
- **勝率・2連率・3連率も推移グラフ化する**: [ADR-0061](0061-racer-page-grade-stage-filter-approach.md)策定後の追加検討で判明した制約により却下（別記）。フィルタ後のサンプル数が少ない場合（優勝戦2走等）は移動平均が成立せず、既存の`getRacerFormTrend`（`race_entries.win_rate`という公式スナップショット値をそのまま時系列表示）はフィルタ条件下の値ではないため流用できない。レース一覧タブ（着順が時系列で見える）で代替する

## 影響

- `RacerPerformanceStats.jsx`の`vcActive`分岐ブロック内のJSXを再構成する（タブ切り替えで表示/非表示を制御する`vcTab` stateを追加）。unfiltered分岐（`vcActive === false`）のJSXは変更しない
- レース一覧タブは`aggregateRacerVenueBoatStats`が絞り込み後に保持しているレコード配列をそのまま一覧化するため、新規の集計ロジックは不要（既存の集計で使っている中間データを露出するだけ）
- 複勝回収率の計算は、既存の「枠番別回収率」セクション（`getRacerBoatReturnRate`、`race_results.payout_place_1/2`を使用）と同じロジックを`aggregateRacerVenueBoatStats`に追加する。この関数は`payout_win`のみ取得している`getRacerRaceHistory`の返り値を使うため、`payout_place_1`・`payout_place_2`も取得列に追加する
