# ADR 0053: 今節成績データの取得方式（racelistスクレイピング vs 自社導出計算）

## ステータス
採用

## 背景

[BOA-291](https://linear.app/boat-ai/issue/BOA-291)は当初、日和・公式サイトの「今節成績」表示（節内の日別進入・着順・ST履歴）を再現するため、`racelist`ページから直接スクレイピングする方針で起票された。しかし、当該データの構成要素（進入コース・着順・ST）は、既に`race_results`・`race_start_timings`・`race_entries`として自社が確定結果取得時に取得済みのものと重複している。今節成績とは要するに「同じ節の過去レース分の自社データを選手・日付でまとめて表示したもの」であり、ゼロから新規スクレイピングすべきか、自社データの集計クエリで代替すべきかの判断が必要になった。

## 決定

**自社`race_results`等からの導出計算を採用する**（過去日分）。当日分は`race_results`が確定次第、同じ導出クエリで自動的に反映される設計にする。

理由:
1. 二重管理を避けられる。同じ事実（あるレースの進入・着順・ST）を2つの経路（自社スクレイピング＋racelistの今節成績表示）で保持すると、食い違いが発生した際にどちらが正か判断するコストが生じる
2. 新規スクレイピング対象を1つ減らせる（サーバー負荷・実装コストの両面で有利）
3. 「得点率」のみは公式の加重ルールに基づく派生値のため自社実装が必要だが、進入・着順・STという生データ部分は既に確定済み

## 却下した選択肢

**racelistページから直接スクレイピングする案**: 公式の表示ロジックをそのまま信頼できる利点はあるが、以下の理由で却下:
- 自社データとの二重管理になる
- `racelist`は現状1日1回（当日races テーブルが空の場合のみ）しか取得しておらず、当日の途中経過を反映するには追加の頻繁なスクレイピングが必要になり、[BOA-313](https://linear.app/boat-ai/issue/BOA-313)が解決しようとしている問題を新しい対象で再現するリスクがある
- 進入コースは[BOA-257](https://linear.app/boat-ai/issue/BOA-257)のバグの影響を受けるため、racelistのスクレイピングでも自社データでも同じ精度上の課題を抱える。スクレイピングにしても精度上の優位性は無い

## 影響

- 導出クエリの実装コストは、当該節・当該選手の`races`（`series_day`列、BOA-226実装が前提）・`race_results`・`race_entries`のJOINロジックとして`supabaseDataService.js`に追加する
- 得点率の計算ルールは別途一次情報源（boatrace.jpの公式ルール説明ページ等）で確認し、自社実装する必要がある
- 当日分の信頼性は`scrape-results.js`（BOA-313 Phase 2でVercel Functions移行予定）の結果取得の信頼性に完全に依存する。Phase 2が完了するまでは、結果取得の欠落がそのまま今節成績当日分の欠落として現れる
