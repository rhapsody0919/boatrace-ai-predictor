# ADR 0001: 会場別ビジターガイドの schema.org 型選定

## ステータス
採用

## 背景
会場別ビジターガイド（全24会場化・SEOフル拡充、venue-guide-expansion）で構造化データ（JSON-LD）を出力する。検索結果でのリッチリザルト表示・検索エンジンの文脈理解を狙うが、boatAIは公営競技（ボートレース）の予測サービスであり、Google広告ポリシー上ギャンブル関連コンテンツの扱いに注意が必要。会場ガイド自体は「観光客向け訪問ガイド」として位置付けている（BOA-133の設計方針）ため、構造化データもこの文脈に沿う型を選ぶ必要がある。

## 決定
`TouristAttraction` を採用する。一覧ページは `ItemList`（各要素に `TouristAttraction` を内包）、一覧・地域ハブ・詳細の3階層ナビゲーションには `BreadcrumbList` を併用する。

## 却下した選択肢
- **`LocalBusiness` / `SportsActivityLocation`**: 「営利事業所」としての文脈が強く、賭博場を営利ビジネスとして構造化データ上明示することは、Google広告ポリシー（ギャンブルコンテンツの扱い）上のリスクを不必要に高める。またboatAI自体が会場の運営主体ではないため実態とも合わない
- **`Article` + `FAQPage`**: 編集コンテンツとしての文脈は表現できるが、地図・アクセス情報等の場所特有のリッチリザルト（住所・営業情報）を狙えず、観光ガイドとしての検索表示メリットが薄い
- **構造化データなし**: 実装コストは最小だが、spec.mdの要件5（schema.orgマークアップ）を満たさない

## 影響
- `VenueStructuredData` コンポーネントは会場データの `name`, `description`, `region` 等から `TouristAttraction` のJSON-LDを組み立てる。緯度経度等の`geo`プロパティは現時点でデータがないため省略可（将来追加時に拡張）
- Googleリッチリザルトテストでの継続的な妥当性確認が運用上必要（sitemap更新と同様、変更時に確認する運用ルールを設ける）
