# ADR-0112: guard-weakening の赤を警告へ下げる型は2つ（rule_change_kept・deleted_code）だけ

## 状況

- guard-weakening（`scripts/maintenance/guard_weakening/`）は守りの試験を弱める変更を止める判定器で、11/26 から ruleset の必須の check
- 11/19 のオーナーの決定で、旧の試験が PR の木で通らない形（old_red）は、どの型でも通さない（excused にしない・赤）作りだった
- その結果、普通の PR が通れない形が2つ出た
  - 振る舞いを変えて試験も直す PR（rule_change）。定義の上で前段の PR に分けられない。赤のまま9本がマージされ、関所が効いていなかった（コードの健全さの点検 2026-11-25）
  - 死んだコードとその試験を一緒に消す PR（#3565）。「分けよ」（split）になるが、試験だけを先に消すと「弱め」、本体だけを先に消すと旧の試験が落ち、行き場が無い。オーナーが赤を承知でマージした
- 型の決まりはこれまで判定器の注釈にしか無かった

## 決定

1. 赤を警告へ下げる型（`WARN_OUTCOMES`）は次の3つだけ。どれも excused には入れず、龍神の CI では `警告` の行になり、run.py の終了は0
   - `incomparable`（11/20、比べられない。判定の場所で回せない verify）
   - `rule_change_kept`（11/25 オーナー、A2、#3483）: rule_change のうち、旧が落とす変異が1つ以上あり、新が落とす数が旧以上で、確かめの形の数（static_fewer）も弱い側へ動いていない物
   - `deleted_code`（11/27 オーナー）: split のうち次を全部満たす物
     - PR で名前ごと無くなった最上位の宣言（関数・class・変数。@babel/parser で取る）がある
     - PR が新しい最上位の名前・新しいファイルを足していない
     - 消した行（25字以上）が PR の足した行に字のまま出ない（移していない）
     - この verify の製品で、名前の残る宣言を書き換えていない（消した物の中身を呼び出し元へ書き戻す道を塞ぐ）
     - base の本文で、消した宣言の行の変異を除くと、旧の verify が落とす変異が1つ以上あり、それを新の verify が全部落とす（回し直して揺れた物は落とさない側に数える）
     - 時間の予算（600秒、目安・根拠なし）の内に終わる
2. 解析できない本文がある・条件の1つでも外れるときは、今までどおりの型（split 等）の赤
3. 型を足す・条件を緩めるときは、この ADR に追記する（判定器の注釈だけで決めない）

## 結果

- 振る舞いを変える PR と死んだコードの片付けが、必須の関所を通れる
- 警告は弱めていない証明ではない。変異は40件の標本で、比べるのは base の本文（PR が足した本体は掛からない）。警告の出た PR は、マージする人（窓口、H5 はオーナー）が差分の verify の変わり方を見る
- 消した物がほかで使われていないかは、build と他の verify が落とす前提（判定器は見ない）

## 戻し方

`verify_guard.py` の `WARN_OUTCOMES` から型を外す。外した型はその日から赤に戻る。
