### アプリ内公式文言の使い分け（2026-09-01確定）

サイト内には役割の異なる2つの公式文言が存在する。どちらも正しい使い分けであり、統一は不要:

- **`nav.logoTagline`**（ヘッダーロゴ下・フッター・チャネル素材共通）: 「ボートレースを見える化。迷ったら、データを信じる。」— ブランドの詩的なタグライン。note/X/TikTok等のチャネル素材はこちらを使う
- **`<title>`タグ・OGP description**（`useSocialMeta.js`・`common.json`の`meta.title`）: 「龍神レーダー - 無料のボートレースAI予想＆データ分析」— SEO・検索結果表示向けのキーワード重視の説明文。**変更しない**（検索順位・CTRへの影響が読めないため、変更するなら別途SEO施策として慎重に検討する）
- 2026-09-01時点で`introBannerText`・`footerText`は「無料のボートレースAI予想＆データ分析」から`logoTagline`に統一済み（PR参照）。`<title>`・OGP descriptionは意図的に未変更

### YouTube / ブログ / note カバー画像・サムネイル

新機能の実画面スクリーンショットが撮れるネタ（新機能・データ知見系）はスクリーンショットをそのまま使う（ロゴ・CTAは意図的に含めない、装飾目的の画像は不要というルールと整合、`.claude/CLAUDE.md`フローA-3参照）。**実画面が無いネタ（会場特性・成績等）向けのフォールバック**として`DataQuoteCard`（[`sns-video-studio/remotion/src/DataQuoteCard.jsx`](../../sns-video-studio/remotion/src/DataQuoteCard.jsx)）を新設した（2026-09-02）。ブログ/noteカバー画像（1200×630）・YouTubeサムネイル（1280×720）を1つのコンポーネントで兼用する。

- **採用（2026-09-02、3回のレビューを経て確定）**: 実ロゴ（`/logo-light.png`）を前景・フル不透明度でキャンバス右端に大きくブリード配置（幅はキャンバスの50%）。左側にブランドロックアップ（アイコン＋「龍神レーダー」＋タグライン）を常設し、その下に見出し・データを配置
- **却下の経緯1（header-eそのまま流用）**: note ヘッダー画像で採用済みのheader-eパターン（ロゴをブリード配置しゴールド単一ウェイト見出し）をそのまま流用したところ、header-eは「龍神レーダー」固定5文字向けのテンプレートで、可変長の動的見出し文と大きな前景ロゴが同じ帯域を取り合い衝突した。またサイト名・タグラインが画面から消えていた（「サイト名とサブタイトルが入っていない」と却下）
- **却下の経緯2（ロゴを低不透明度の背景テクスチャに格下げ）**: 衝突は解消したが「主役感が無い・空間が間延びして見える」「見出しは常にゴールドで」という指摘で却下。ロゴは前景・フル不透明度のまま幅だけ絞る方針に変更した
- **既存の却下事項（継続）**: 六角形の紋章イラスト（`RadarDecoration`）は使わない（noteヘッダー・アイコン制作時とは別に、本コンポーネントでも「二度と使わないでほしい」と明示却下）

**制作ルール（必須、2026-09-02確定）**:
1. **サイト名（龍神レーダー）とタグライン（ボートレースを見える化。迷ったら、データを信じる。）を必ず含める**。ブランドロックアップとして左上に常設し、他要素で隠れないようにする
2. **見出し（headline）の文字色は必ずゴールド**。白は使わない
3. **可能な限り、見出しの根拠となる実データの数値（レース数・日数等、例:「13,386レース」「直近90日」）を`statValue`/`statLabel`として含める**。数字が無い定性的なネタ（会場特性の説明等）はcaptionのみでよい
4. **見出しの改行崩れ（熟語・単語の途中で折り返る）を起こさない**。`DataQuoteCard`は`textFit.js`の`fitHeadline()`で自動的にフォントサイズを縮小し、助詞・句読点等「切ってよい文字」の直後でのみ折り返す。新しいテキストブロックを追加する際もこの仕組みを使う（生の`<div>{text}</div>`で複数行になりうるテキストを描画しない）

視覚素材（画像・動画）のルールは上記各節を参照。本文・構成のルールは以下に一元化されている。着手前にこのファイル（ビジュアル）と合わせて必ず確認する:

- **ブログ本文の構成・文字数・FAQ・note/Xセット生成ルール**: `.claude/CLAUDE.md`フローA-3「新機能リリース時のブログ記事ルール」
- **ネタ駆動パイプラインでの自動生成時の執筆手順・品質自己レビュー**: [`docs/operation/content-multi-channel-pipeline-prompt.md`](../operation/content-multi-channel-pipeline-prompt.md)
- **公開前の品質チェック6項目**（数値整合性・現行仕様整合性・検索意図網羅性・用語表記・多言語一貫性・構造要件）: `.claude/CLAUDE.md`「ブログ記事の公開前品質チェック」

1. **新規制作の着手前に本ファイルのギャラリーを確認する**（[`docs/design/content-ops-flow/spec.md`](../design/content-ops-flow/spec.md) C2）。既存の採用実例と矛盾する独自デザイン（新しいロゴバッジ、実ヘッダーと異なるフォント処理等）を作らない
2. **承認されたら、その場でギャラリーに追記する**（C3）。追記せずに次のタスクへ進まない
3. **却下された案も理由付きで残す**。同じ失敗（独自紋章の再発明、環境依存の絵文字使用等）を将来のセッションが繰り返さないようにする
