## 技術ルール（フォーマット横断で適用、2026-09-03新設）

以下は特定のチャネル・コンポーネントに紐づく「採用実例」ではなく、**静止画・動画を問わずテキストを描画するあらゆる箇所に適用される技術的な必須ルール**。チャネル別ギャラリーの1エントリに埋もれて見落とされないよう、独立した節として切り出している。新しいコンポーネントを書く前に必ずここも確認する。

### 見出し・キャプション等、可変長テキストの折り返し・サイズ

**熟語・単語の途中で改行崩れを起こさない。横方向にはみ出す・切れることも許容しない。** 実装は[`sns-video-studio/remotion/src/textFit.js`](../../sns-video-studio/remotion/src/textFit.js)の`fitHeadline(text, { maxWidth, maxLines, fontFamily, fontWeight, maxFontSize, minFontSize })`を使う。`canvas.measureText`で実際のグリフ幅を計測し、(1) 指定行数以内に収まる最大フォントサイズを自動選択、(2) 折り返しが必要な場合は助詞・句読点等「切ってよい文字」の直後のみを改行位置にする。**新しいテキストブロックを追加する際は、静止画（`remotion still`）・動画（Remotionコンポジション）を問わず必ずこれを使う。生の`<div>{text}</div>`で複数行になりうる可変長テキストを描画しない。**

- **同じ問題が過去3箇所で3通りに個別対応されていた実績（2026-09-03発覚、教訓）**: (1) `DataQuoteCard.jsx`（カバー画像/サムネイル）は`fitHeadline()`で正しく対応済み。(2) TikTok/X動画テンプレート（`*CM.jsx`）は`whiteSpace: "nowrap"`で1行に強制するのみで、動的なフォントサイズ縮小が無く長文で横にはみ出すリスクが残る。(3) note埋め込み動画（`noteVideoShared.jsx`の`SceneHook`）は「13文字を超えたら`titleFontSize`を80pxに手動で縮小する」という目視調整の目安値に頼っていた。**(2)(3)は新規制作分から`fitHeadline()`に統一する**（既存の投稿済み動画・登録済みテンプレートの遡及的な作り直しは行わない。実害は小さいというBOA-232と同じ判断基準）
- 動画コンポジションでの呼び出し方は静止画と同じ（`fitHeadline()`はフレーム非依存の純粋な文字幅計算のため、`useCurrentFrame()`等のRemotionフックとは独立して呼べる）。返り値の`lines`配列を行ごとに`<div>`でマップし、`fontSize`をそのまま適用する

### 主要ビジュアル要素の左右バランス（事故的な偏り防止）

**フレーム内の主要ビジュアル要素（棒グラフ・比較図・数値カード等）は、根拠のある意図的デザインでない限り、必ずflexの`justifyContent: "center"`等でフレーム中央（左右バランスが取れた位置）に配置する。** 要素サイズ・本数が可変でも中央からずれないよう、固定`left`/`right`のpx指定ではなく中央基準のflexレイアウトにする。チャネル・フォーマットを問わず適用する（X/TikTok/YouTube/note共通）。

- **対象外（意図的デザインとして確立済みのもの）**: `sns-video-producer-prompt.md`ルール11の「案A」（会場攻略・データ一覧型のHookシーンで、巨大な順位数字を画面左端からはみ出させる配置）は対象外。これは「全要素を中央揃えで均等に並べる」初期案がTikTokプロフィールグリッドの縮小表示（横幅120px程度）で潰れて視認できないと複数回却下された末に、2026-08-24に複数回のレビューを経て意図的に採用されたデザイン判断であり、事故的な偏りではない。同様に`SceneHookDiagonal`（対角分割Before/After型）も設計として左右非対称にしている。**新しい非対称配置を「意図的デザイン」として追加する場合は、この節または該当パイプライン文書に採用理由・日付を明記してから使う**。理由の記載が無い非対称配置は、レビュー漏れの事故として中央寄せに直す
- **同じ事故が繰り返されている実績（教訓）**: (1) 2026-08-31、`VenueRankingCM.jsx`の`SceneHook`で「左端はみ出しの非対称配置がバランス悪い・右側の余白が目立つ」という指摘を受け、主要な見出しグループ（順位数字＋会場名）を中央寄せに修正したが、この教訓は該当コンポーネントにしか反映されなかった。(2) 2026-09-05、X承認待ち動画（venue-featureパイプライン、2値の最高値vs最低値比較）で同じ「左に偏り右側が空白」が再発。原因は、venue-featureパイプライン（`docs/operation/sns-pipeline-x.md`）がmasterへコードをコミットしない疎結合Routineのため、既存の使い回しコンポーネント（`VenueRankingTemplate`）でカバーしていない新しい形状（2値だけの比較）が必要になるたびにその場限りのコードが書かれ、レビューも再利用もされていなかったこと
- **恒久対策**: 2値比較（最高vs最低等）の可視化には`SceneHookCompareTwo`（`VenueRankingCM.jsx`）を新設し、中央寄せをコード側で固定した。新しい比較ビジュアルの形状が必要になった場合も、その場で書き捨てるのではなくこのファイルに再利用可能なコンポーネントとして追加し、該当パイプライン文書から参照する（`fitHeadline()`と同じ「書き捨てず共通化する」パターン）。加えて、コードの共通化だけでは全チャネル・全フォーマットを機械的にカバーしきれないため、`sns-video-producer-prompt.md`「セルフレビュー チェックリスト」（全チャネル・全フォーマットの生成Routineが毎回実行する）にも左右バランスの確認項目を追加した

### シーンのフック強度均一化（Shorts一覧クリック率対策、2026-09-10新設）

**YouTube Shorts一覧・Shorts棚は、API経由で設定したカスタムサムネイル（`thumbnails.set`）を表示しない既知のプラットフォーム制約がある**（Google Issue Tracker等で報告済み。`docs/operation/sns-pipeline-youtube.md`のcover_image_path運用はこの表示面には効かない）。代わりに、YouTube側が動画本編内から任意のフレームを自動選択して表示する。**動画を構成する全シーンが「単体でサムネイルに切り取られてもクリックに値する」状態になっている必要がある。**目的はブランド表記ではなくクリック率であることに注意する（ロゴを足すだけでは解決しない）。

**構成原則**: 全シーンを「①上部に強い見出し・メッセージ、②データ（グラフ・表・数字・実画面スクショ等）」の2要素で構成する。「①のみ」（問いかけだけ）も「②のみ」（データだけで見出しが弱い）も避ける。**1位の数値を見出しとは別枠でさらに巨大化する「ヒーロー数値」の追加は、リストの1行目と情報が重複して間延びするだけなので採用しない**（2026-09-10、実装後のレビューで却下）。①の見出し自体を`fitHeadline()`で大きく強調するのが正しい対応。

**ルール**: シーンの主役テキスト（①の見出し）は、常に画面幅の**10%以上**・**GOLD(`#d4af37`)またはWHITE(`#f8fafc`)+fontWeight 900以上**で表示する。「説明だけ」「問いかけだけ」の単独シーンを作らない。情報を削るのではなく、数字・断定文・強調記号とセットにして視覚的な強さをHookシーンと揃える。

**判定基準（数値化する。主観で判定しない）**: 以下のいずれか1つでも該当すれば「弱いシーン」とする。
1. 主役テキストのフォントサイズが画面幅の10%未満
2. 主役テキストの色がGOLD/WHITE+900のいずれでもない（ACCENT・GREEN・WARN等を主役色に使っている）
3. fontWeightが800未満の文字が、そのシーンで最も大きい文字として使われている
4. シーン内に数字・断定文・強調記号のいずれも無く、説明文・問いかけ文のみで構成されている

**参照実装（既存トークンの範囲で基準を満たしている例）**: `AshiyaCM.jsx`の`SceneStat`（GOLD・130px・fontWeight900の単一数値）、`VenueRankingCM.jsx`の`SceneHook`（案A、巨大順位数字＋会場名）、`OutcomeDistributionCM.jsx`/`ReturnRateCM.jsx`の`SceneHook`（GOLD・200px超の単一数値）。新しいシーンを作る際・既存シーンを直す際は、まずこれらのパターンを流用する。

**追加の視認性技法（グリッドの極小サイズまで縮小されても崩れないようにする、任意採用）**:
- **縁取り（袋文字）**: `-webkit-text-stroke`で主役テキストに背景色（NAVY）の輪郭を追加する。色・フォントは変えないためbrand-kit逸脱にならない
- **対決構図（VS）**: 比較データを棒グラフではなく左右対決構図で見せる案。brand-kit.mdに前例のない新しい表現パターンのため、採用する場合はこの節への追記とセットで判断する（現時点では未採用）

**「②データ」を何で埋めるかはシーンの型ごとに最適解が異なる。全型に同じ手法を横展開しない**（2026-09-10、ユーザー指摘。「共通化すべきことと型固有に実装すべきことを混同しない」のがこのプロジェクトの設計思想）:

| シーンの型 | ②データの最適解 |
|---|---|
| ランキングリスト（TOP5/WORST5等、全会場の生データを保持） | **背景に全会場の実データバーチャートを低不透明度で敷く**（`VenueRankingCM.jsx`の`AllVenuesBackdrop`、SceneHookの背景チャートと同じ考え方）。装飾ではなく実データなので「24会場を分析している」という説得力も補強される |
| 少数比較（2〜3値の対決、SceneHookCompareTwo等） | 全会場データが無いため背景チャートは不適。**該当する分析ツールの実画面スクリーンショットを貼る**のが最優先（下記「実画面スクショの積極活用」参照）。VS構図は未採用のまま |
| エンゲージメント質問（データを伴わない問いかけ） | 見出し自体を巨大化（技術ルール参照）。背景の埋め方は型ごとに個別検討 |
| 実例紹介・CTA等 | 既存の「名前＋巨大数値」等の構成を維持しつつ、可能な範囲で実画面スクショを添える |

**実画面スクショの積極活用（2026-09-10追加）**: 龍神レーダーのShorts動画の目的は「こういうデータが見える」「可視化されていて見やすい」「買い目の参考になる」という**プロダクト自体のPR**である。抽象的なデータビジュアライゼーション（棒グラフ等の自作グラフィック）よりも、**実際の分析画面のスクリーンショットを積極的に使う方が、製品の使いやすさを直接訴求できる**。これは新機能ネタに限定されていた既存ルール（フローA-3「実画面スクリーンショットが撮れるネタはスクリーンショットをそのまま使う」）を、Shorts動画全般（特に②を埋める場面）に拡張する方針。具体的な組み込み方（どのシーンにどのタブのスクショを使うか等）は型ごとに個別検討し、この節に実例を追記していく。

**2026-09-10監査結果（初回、26ファイル・全コンポジション対象）**: ほぼ全ファイルで「Hookシーンのみ基準を満たし、本編中盤のランキング/データシーンとCTAシーンは26〜54px程度のテキストのみで基準未達」という共通パターンが判明した。加えて`ToolCM.jsx`・`ToolShowcaseCM.jsx`・`YoungPersonaCM.jsx`はGOLDを一切使わずACCENT/GREENを主役色にしており色基準にも抵触。`AboutHeroCM.jsx`は全10シーンが基準未達（Captionコンポーネント共通の構造的要因）。`NoteExplainerCM.jsx`/`NoteExplainerLanguageSwitcherCM.jsx`/`RaceInsightYoutubeCM.jsx`（1920×1080横型）・`OnboardingFlowCM.jsx`（サイト埋め込み専用の可能性）はShorts棚の対象外の可能性が高く、本ルールをそのまま適用すべきか要確認として対象外にした。ファイル別の詳細な監査表・改善案は[`docs/reference/shorts-hook-strength-audit-2026-09-10.md`](./shorts-hook-strength-audit-2026-09-10.md)を参照。

- **恒久対策・実施済み**: `VenueRankingCM.jsx`の共通シーン（`SceneTop5`/`SceneWorst5`/`SceneVenueBars`/`SceneCTA`）を基準を満たすよう修正した。これら4関数は同ファイル内20コンポジションが共有しているため、1箇所の修正で20コンポジション全てに波及する（`fitHeadline()`と同じ「書き捨てず共通化して直す」パターン）
- **未対応（バックログ）**: 上記以外の個別`*CM.jsx`（`AboutHeroCM`・`ToolCM`・`ToolShowcaseCM`・`YoungPersonaCM`等）は、既存投稿済み動画の遡及的な作り直しは行わず（BOA-232と同じ判断基準）、**新規制作・再利用時にこの節の基準で書き直す**運用とする
- **マスコット掛け合い型（`MascotCM.jsx`）は対象外・削除済み**（2026-09-10）: A/B/Cキャラクター比較テストの勝者判定が保留のまま運用終了となったため、キャラクター主導のシーン構成（掛け合い・吹き出し）自体を今後の検討対象から外し、YouTube/X/TikTok向け9コンポジションとファイルを削除した。このフォーマットは今後復活させない前提
- 新規テンプレート作成時・既存テンプレート流用時は、`sns-video-producer-prompt.md`「セルフレビュー チェックリスト」でこの基準の確認を行う（要追記）

### 新しい技術ルールを見つけたら、他フォーマットへの伝播を都度確認する

ある1つのチャネル・コンポーネントで技術的な安全策（今回の`fitHeadline()`のような）を発見・実装した際は、その場で「他のチャネル・フォーマットにも同じ問題が起きうるか」を確認し、起きうるならこの節に一般化して追記する。逆に、新しいコンポーネントを書く際はこの節を必ず確認し、既知の技術ルールを再発明・劣化コピーしない（2026-09-03、ユーザー指摘を受けて運用原則化）。

### 企画（キャンペーン）型X投稿カード（2026-09-09、企画型SNSパイプライン新設）

- **採用**: [`sns-video-studio/remotion/src/CampaignEntryCard.jsx`](../../sns-video-studio/remotion/src/CampaignEntryCard.jsx)（買い目・収支カード）＋[`CampaignDataExcerptCard.jsx`](../../sns-video-studio/remotion/src/CampaignDataExcerptCard.jsx)（データ出走表・展開予測の抜粋カード）。1080x1350（4:5縦型）、2枚1組でX投稿に添付する
- **動画ではなくテキスト+静止画像2枚にした理由（2026-09-09、ユーザー確認済み）**: 企画型パイプラインの他の投稿（会場特性・成績等）は動画（9:16、`sns-video-producer-prompt.md`）が基本だが、企画型は金銭シミュレーション結果を扱う趣旨のため、動画演出より実データの正直な提示を優先した
- **内部スコア・独自算出値は一切見せない（重要な方針）**: 龍神レーダーは「AI予想を当てるサービス」ではなく「分析ツール」としてPRする方針。買い目を決めた根拠は、内部の計算式（`scripts/lib/campaignVolatilityModel.js`）のスコア値ではなく、分析ツールに実在する項目名（勝率・モーター2連率・展開予測の決まり手等）だけで書く。2枚目のカードも「データ出走表」「展開予測」という実際のUI機能名をそのまま見出しにし、末尾に「このデータは龍神レーダーの分析ツールで毎レース無料で見られます」という誘導文を入れる
- **却下の経緯（1st案: 内部スコアの積み上げ棒グラフ）**: 各艇のスコアを「出走表データ由来」「展開予測ボーナス由来」に色分けした積み上げ棒グラフを提案したが、「内部のロジックは出す必要はない、分析ツールとしてPRしたい」という理由で却下された。実データの抜粋（勝率表・展開予測の1着候補）に差し替えた
- ブランドトークンは`--ryujin-navy-*`/`--ryujin-gold-*`ではなく、既存の動画テンプレートと同じ`noteVideoShared.jsx`のNAVY(`#0f2c46`)/GOLD(`#d4af37`)/WHITE(`#f8fafc`)を使う（サイトCSSのトークンとは意図的に別管理、動画・静止画アセット全体でこちらに統一済み）

**v4改訂（2026-09-09、実際に生成した1件目の投稿を見た上でのデザイン改善）**: 実物を確認したところ「ゴールドが使われておらず地味・バズらない」「見出し〜フッター間に意図しない空白がある」との指摘を受けた。天才デザイナー・天才マーケター2視点での診断: ①ゴールドがロゴ横の点にしか使われていない（ブランドの主色が装飾扱い）、②`flex:1 + justify-content:center`で縦中央寄せしていたため内容が短い日ほど空白ができる、③核心の数字（例:イン崩れ注意度99%）が本文中に埋没し視線が止まらない、④発走時刻が無く「今すぐ見に行く」切迫感が無い。対応:
- 見出しをゴールドに変更（白は使わない、DataQuoteCardと同じ方針をこちらにも適用）
- 選定基準の指標値を`heroStat`として大きなゴールド数字で独立表示（例:「99% イン崩れ注意度」）。中央寄せをやめ上詰めレイアウトに変更し、空いた余白をここに充てた
- `raceLine`に発走時刻を追加（`races.start_time`、切迫感を出す目的）
- 最有力買い目（`picks[0]`）にゴールド枠、カード上端にゴールドの帯を追加（2枚目のデータカードにも同じ帯を追加し2枚のセットで統一感を出す）。フッターの区切り線もゴールドに変更（ただし通算収支の色は勝敗を表す意味トークン（緑=プラス／赤=マイナス）のまま維持し、ブランド色で上書きしない）
- 併せて、2枚目（データ抜粋カード）でCTA文言がキャンバス下端で見切れる不具合（`marginTop:"auto"`による下端押し出し＋固定パディングの組み合わせが実際の6艇分の出走表＋展開予測3件と合わせるとキャンバス高を超えていた）を発見・修正した
- 実装: [`CampaignEntryCard.jsx`](../../sns-video-studio/remotion/src/CampaignEntryCard.jsx)・[`CampaignDataExcerptCard.jsx`](../../sns-video-studio/remotion/src/CampaignDataExcerptCard.jsx)

**v5改訂（同日、2026-09-09）**: 「スマホで見ることが多いはずなので縦型にしてほしい」との指摘を受け、キャンバスを16:9横型（1200x675）から4:5縦型（1080x1350）に変更した。単純な引き伸ばしではなく、増えた縦の余白を使って買い目3点を横並びから縦積みに変更し（本命に「本命」バッジを追加）、見出し・heroStat・出走表・展開予測カードのフォントサイズも拡大した。フッターは`marginTop:"auto"`でカード下端に固定し、内容量の変動があっても中央に不自然な空白ができない設計にしている。

### アプリ内公式文言の使い分け（2026-09-01確定）

サイト内には役割の異なる2つの公式文言が存在する。どちらも正しい使い分けであり、統一は不要:

### YouTube / ブログ / note カバー画像・サムネイル

新機能の実画面スクリーンショットが撮れるネタ（新機能・データ知見系）はスクリーンショットをそのまま使う（ロゴ・CTAは意図的に含めない、装飾目的の画像は不要というルールと整合、`.claude/CLAUDE.md`フローA-3参照）。**実画面が無いネタ（会場特性・成績等）向けのフォールバック**として`DataQuoteCard`（[`sns-video-studio/remotion/src/DataQuoteCard.jsx`](../../sns-video-studio/remotion/src/DataQuoteCard.jsx)）を新設した（2026-09-02）。ブログ/noteカバー画像（1200×630）・YouTubeサムネイル（1280×720）を1つのコンポーネントで兼用する。

- **採用（2026-09-02、3回のレビューを経て確定）**: 実ロゴ（`/logo-light.png`）を前景・フル不透明度でキャンバス右端に大きくブリード配置（幅はキャンバスの50%）。左側にブランドロックアップ（アイコン＋「龍神レーダー」＋タグライン）を常設し、その下に見出し・データを配置
- **却下の経緯1（header-eそのまま流用）**: note ヘッダー画像で採用済みのheader-eパターン（ロゴをブリード配置しゴールド単一ウェイト見出し）をそのまま流用したところ、header-eは「龍神レーダー」固定5文字向けのテンプレートで、可変長の動的見出し文と大きな前景ロゴが同じ帯域を取り合い衝突した。またサイト名・タグラインが画面から消えていた（「サイト名とサブタイトルが入っていない」と却下）
- **却下の経緯2（ロゴを低不透明度の背景テクスチャに格下げ）**: 衝突は解消したが「主役感が無い・空間が間延びして見える」「見出しは常にゴールドで」という指摘で却下。ロゴは前景・フル不透明度のまま幅だけ絞る方針に変更した
- **既存の却下事項（継続）**: 六角形の紋章イラスト（`RadarDecoration`）は使わない（noteヘッダー・アイコン制作時とは別に、本コンポーネントでも「二度と使わないでほしい」と明示却下）

**制作ルール（必須、2026-09-02確定）**:
1. **サイト名（龍神レーダー）とタグライン（ボートレースを見える化。迷ったら、データを信じる。）を必ず含める**。ブランドロックアップとして左上に常設し、他要素で隠れないようにする
2. **見出し（headline）の文字色は必ずゴールド**。白は使わない
3. **可能な限り、見出しの根拠となる実データの数値（レース数・日数等、例:「13,386レース」「直近90日」）を`statValue`/`statLabel`として含める**。数字が無い定性的なネタ（会場特性の説明等）はcaptionのみでよい
4. **見出しの改行崩れを起こさない**。上記「技術ルール（フォーマット横断で適用）」の`fitHeadline()`ルールに従う（`DataQuoteCard`は実装済み）
