# ファンの反応（オーナーとファン役が良し悪しとしたこと）

SNS 動画・ブログ・画面について、オーナーの評価とファン役（`discussion-panel`）の議論で決まったこと。ファン役は同じモデルのロールプレイなので仮説扱い。表現の可否は [glossary.md](glossary.md)、数字の言い方は [number-wording.md](number-wording.md)、動画の見た目は [video-composition.md](video-composition.md)。書き方は [README.md](README.md)。

## オーナーが求めるもの（SNS 動画）
- 到達点は1レースの全貌解説。BOA-430 の思考の型（条件→軸→展開→機力）を龍神のデータで解き明かす。短い読み方解説だけのものは不可（2026-10-10、オーナー、hq の memory project_sns_race_full_picture）
- 1号艇だけでなく2〜6号艇の有力艇も詳しく。選手名を入れる（初出は艇番＋フルネーム、以降は艇番＋名字）（2026-10-11、オーナー）
- ただの数値の羅列は見づらい。図・グラフで見せ、文字は少なく（2026-10-11、オーナー）
- 冒頭は結論から（例「1着は堅い、2着は割れる」）（2026-10-11、オーナー）
- 展示後に知りたいのは直前情報（展示タイム等）。展示ST は当てにならない（2026-10-11、オーナー。根拠の数字は stat-findings.md）
- 前付けの可能性は、その選手の過去の進入の割合で示す（2026-10-11、オーナー。列は data-definitions.md「生データの所在」）
- 展示後版の締めは着ごとの見立て（1着・2着・3着まで）で、展示前の分かれ目からの差を札に出す。決め台詞で締めない。「展示を見て、こう変わった」は表現が微妙（2026-10-12 オーナー。2026-10-11 ファン役 v8・v9b の「材料がどう変わったかの要約」を置き換え）

## ファン役の評価（SNS 動画、蒲郡12R v7〜v11）
- 展示前版で「展示上位なら何%」を出しても順位が未確定なので答えにならない。今日の分かれ目（どの艇とどの艇の差を見るか）と今節の足を示す（2026-10-11、ファン役 v7）
- 展示後に価値があるのは、今節と比べた展示順位の上下。展示後にしか言えない（2026-10-11、ファン役 v7）
- 相関の模式図（展示ST 0.08）はファンに伝わらない。展示ST は隅の注記1行で足りる（2026-10-11、ファン役 v7）
- 展示前版の「展示で確定」の空欄は情報ゼロと受け取られる。後編（展示後版）への誘導に使う（2026-10-11、ファン役 v8）
- 空欄の多い場面は、20代は飛ばし、30代男は宿題として受け取る（割れた点）（2026-10-11、ファン役 v8）
- 展示前に「今節ずっと上位」と出した選手は、展示後に変化（今日の順位）を札で並べる（2026-10-11、ファン役 v9d）
- 締めの札は展示の事実だけ。全国の割合・効き目が未検証の材料を入れない（v9b・v10・v11 で3回違反。v11 は hq の指示で 46%・41% とリング交換を入れてファン役に止められた）（2026-10-12、ファン役 v10・v11）
- 直前予想のカバーには展示の情報を1つ入れる。展示前と同じだと見る理由が無い（2026-10-12、ファン役 v11）

## ブログ
- 検索で来た人への答えは、UI の名前の列挙でなく実例の数字から入る（2026-10-11、ファン役のブログ新記事の評価）
- 注意書きは1節に。冒頭・FAQ で繰り返すと読み手が離れる（2026-10-11、同）
- 会場記事の風の表は、方位（北東など）がどの区分（追い風・向かい風・横風）に当たるかを書かないと、直前情報と結び付けられない（2026-10-13、蒲郡・徳山・大村・下関のファンのレビューで同じ指摘、下関は P1）

## 思考アシスト（流しの相手）
- 2着以内・3着以内は「流しの相手をどれにするか」に使う。1艇の数字より6艇の並びが要る（2026-10-11、ユーザーの指摘とファンパネル、docs/design/thinking-assist/boa831/fan-panel-nagashi.md）

## イン崩れ注意度（BOA-822）
- 0〜100 の指数は「確率」に読まれる（99 が崩れる確率99%に見えた、BOA-706）。件数・基準つきの過去の実績の割合の方が伝わる（2026-10-11、ファン役、docs/design/in-collapse-caution/fan-panel-scope.md）
- 同じ問い（1号艇が飛ぶか）の数字は、画面が違っても同じ値にする。違うと一番混乱する（2026-10-11、同）
- 1レースの当たり外れより、帯ごとの実績の方が信用される（2026-10-11、同）
- 1号艇が飛ぶかの数字は、タブを開かなくても見える場所（基本情報の上部）に1段で出す方が届く（2026-10-12、ファン役、docs/design/in-collapse-caution/fan-panel-mock-v1.md）
- 理由が1つの材料だけのときは「ほかの材料はどこで見るか」を1行添える（2026-10-12、同）
- 帯ごとの実績のページは公開直後に空に見える。公開前の検証の値を区別して並べると信用される（2026-10-12、同）

## 選手を題材にした SNS
- 選手個人の成績（級・体重・年齢など）を題材に、突き放した言い方＋リアクション文字・フラッシュ・集中線で笑いを盛る動画は、3回作り直しても「煽りに見える」「選手へのリスペクトがない」で全部却下。同じデータでも文字だけで事実を述べる投稿は指摘されていない。ユーモアは制度・ルール・観戦する側のあるあるなど実在の個人と結びつかない題材にする（2026-09-07 オーナー、memory feedback_humor_content_respect_risk）

## 機能の選び方
- 次に作る機能は、初心者向けの基礎より、既存のファン（分析・スジ舟券・進入予想など実践的な内容に反応する層）向けを優先する（2026-08-04 オーナー承認、memory vup_feature_analysis_skill）

## AI 評価の限界
- AI に評価させると規約違反・誤り・敬意を欠く表現の検出には使えるが、伸びるかの予測には使えない（LLM が A/B の勝ちを当てるのは約65%、ペルソナを付けるとさらに下がり、提示の順で55%が逆になる）（2026-10-06、memory project_ai_multi_venture_ops_2026_10_05、hq の調査）
