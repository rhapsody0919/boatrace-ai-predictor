# SNS 動画の構成と画面配置

縦型 Shorts（1080×1920 想定）の構成・字幕・図・配置・動き・音。中身の良し悪しは [fan-reactions.md](fan-reactions.md)、数字の言い方は [number-wording.md](number-wording.md)、完成物の検査と計画の扱いは [video-qa.md](video-qa.md)。制作の手順は `docs/operation/sns-video-producer-prompt.md`。書き方は [README.md](README.md)。出典の「v3」等は蒲郡12R の Shorts の版。

## 構成
- 最初の画面は sns-hub の規則どおりタイトル（カバー）にし、レース名・締切時刻を出す（2026-10-12、オーナー v10f）
- 同じ図（スリット図）の使い回しは1本で1回まで。何度も出すと中身が無く見える（2026-10-11、オーナー v6）
- 締めで別の画面を見せるときは、字幕をその画面の内容に切り替える（2026-10-11、デザイナー役 v9e）
- 台本の注記と字幕を分けて書く。内部メモが画面に出る事故があった（v3「思考アシストは別投稿で」）（2026-10-11、オーナー v3）
- 「今日」「本日」は当日のレースにだけ使う。2〜8日前のレースを「今日は危険」と書いた9本を作り直した。的中の動画は当日開催・当日の結果に限る（2026-08-23 オーナーの指摘、memory sns_marketing_phased_strategy_2026_08_22）
- 実画面の無い題材のカバー・サムネイル（DataQuoteCard）は、見出しをゴールド固定、ロゴは前景の不透明のまま縮めて名前の表記を必ず置く。ロゴを薄い背景に下げる案は「間延び」で不採用（2026-09-02 オーナー、memory content_multi_channel_pipeline_2026_09_01、sns-video-studio/remotion/src/DataQuoteCard.jsx）

## 字幕と文字
- 見出しに当たり前の事実（例「1着は1号艇が多い」）を置かない。その場面で初めて分かること（例「1号艇が勝つとき、2着は割れる」）を見出しにする（2026-10-12、オーナーの12R v12dへの指摘）
- 文字が多いのは不可。字幕は1場面2つまで・16字以内、動きに合わせて1つずつ出す。数値は図の中に大きく（2026-10-11、オーナー v3〜v5）
- 字幕1枚あたりの読速は8字/秒以内。画面に出ている数値は字幕から外して短くする（2026-10-12、デザイナー役 v10c〜f）
- 字幕が1艇を名指しする間はその行を明るく他を薄くし、字幕1枚ごとに名指しと強調を一致させる（1枚の間に強調を移すなら字幕も分ける）。最長の棒と名指しの艇が違うときは必須（2026-10-12、デザイナー役 v10・v10c〜f）
- 字幕と常設の注記を同じ文にしない（2026-10-11、デザイナー役 v9b）
- 見出しと小見出しを同じ意味で重ねない（2026-10-11、デザイナー役 v8）
- 小見出しを消すときは、図の数値の意味（何の率か）が見出しか軸に残るか確かめる（2026-10-11、デザイナー役 v9b）
- 静止画の見出しは熟語の途中で折り返さない（「徹底分析」→「徹」/「底分析」）。canvas.measureText で実測して字を縮め、助詞等の位置でだけ改行する（2026-09-02、memory content_multi_channel_pipeline_2026_09_01、sns-video-studio/remotion/src/textFit.js）
- SVG 内の fontSize を画面の px と直接比べない。viewBox と実描画サイズから実効 px を求め、完成フレームで確認する（2026-10-14、2026-10-14-daily-shorts-2026-10-14-19-11.md）
- オーナー確定の字幕は、表示形式・文字サイズ・改行を変えても文言を保持する。変更案は先に報告で提案し、制作側の判断で問いを置き換えない（2026-10-15、2026-10-15-caption-fix.md）
- 数値を足した長い答えは句の区切りで折り返し、数値と単位を一組で目視する。文字幅だけの自動改行は「70%」を行またぎにする（2026-10-15、2026-10-15-caption-fix.md）
- 熟語内の改行はページ単位のサムネイルでは見えない。完成 MP4 の原寸とスマホ幅で確認する（2026-10-16、2026-10-16-split-full-rounds.md）

## 図
- スタート隊形はサイトの部品（SlitShapeIcon・SlitHint）を使い、隊形の呼び名（イン凹み・カド一撃等、サイトの文言）を大きく見せる（2026-10-11、オーナー v3〜v5）
- 流れ図（サンキー）は1艇分だけだと何の図か分からない。見出し・列名・艇名を付ける（2026-10-11、オーナー v3〜v5）
- 展示の場面は「何を見るか」だけでなく判断の基準を数字で出す（例: 展示タイム上位1〜2位なら40%、下位なら22%）（2026-10-11、オーナー v6）
- 判断待ちの値を空欄の目盛りで見せない。分岐は両方の場合の結果（上位なら40%／下位なら22%）で図にする（2026-10-11、デザイナー役 v8）
- 展示ST から作るスリット隊形は、展示の判断材料として描かない（本番ST との相関0.08、stat-findings.md）（2026-10-11、デザイナー役 v6）
- 展示タイムの棒はサイトと同じく「最も遅い艇との差」にし、差を秒で明示する（0.1秒差は素の値の棒では見えない）（2026-10-11、デザイナー役 v6）
- 着の切り替え（1着／2着以内／3着以内）の図は、条件「全国・同じ展示順位」を常に画面に出す（2026-10-12、ファン役 v10）
- 流しの場面では、展示1位の艇に答え（3着以内の割合）を読める大きさで見せる。無いと「展示1位なのに何も無い」と映る（2026-10-12、ファン役 v10b）
- 「?」は答えが決まっていない両方の選択肢に付ける。片側だけだと答えを先に示しているように読める（2026-10-11、デザイナー役 v9e）
- 「記載なし」で行を埋めた表は文字が増えるだけ。事実のある行だけ札を付ける（2026-10-11、デザイナー役 v8）
- 確定済みの画面（結果など）は画面録画＋ズームでなく locator.screenshot() で要素を切り出す。横幅いっぱいの画面（タブ行等）は横にズームしない（倍率1.1〜1.2でも切れた）。座標は getBoundingClientRect() で測り、描いたフレームを目で確かめる（2026-08-19、memory tiktok_pilot_status_2026_08_18）
- Remotion の OffthreadVideo を大きい width/height と負の left/top で拡大すると空白になる。transform: scale()+translate() で拡大する（2026-08-19、memory tiktok_pilot_status_2026_08_18）
- 公開画面から行・図を切り出すときは、行の外へ浮いた tooltip・数値・注記を含め、上の行の途中見出しと次行の数値の一部が残らない境界にする。frame=0 と区画の上下端を完成 MP4 で確認する（2026-10-14、2026-10-14-full-picture-v2.md・2026-10-15-layout-dark.md）
- 非強調行を行全体の opacity で薄くすると、比較に必要な選手名・順位も薄くなる。主役の識別と比較相手の可読性を別々に点検する（2026-10-13、2026-10-13-plan-1626.md）
- 割合の問いが切り替わるとき（周辺の2着以内割合と特定艇1着時の他艇の2着割合は、同じ47%でも別の問い）は、上帯・母数・強調行を一緒に切り替えて確認する（2026-10-16、2026-10-16-split-layout-polish.md・2026-10-16-split-progress.md）

## 配置と余白
- 図は画面幅100%・縦60%を使い、字は最小36px相当（2026-10-11、オーナー v6）
- 安全領域を守るだけで要素を小さく置くと空白に見える。図は字幕の直前まで広げ、空白の帯を検査で測る。下が大きく空く場面は要素を縦に広げて中央へ（2026-10-12、オーナー v10f・デザイナー役 v10b）
- 重要な文字は y≤1420、x≤940。Shorts の下部の帯（y1450 以下）と右の操作ボタン列（x≥960、y900〜1700）に重ねない（2026-10-12、デザイナー役 v11。空白を詰める指示で y1500〜1650 に置かせた失敗から）
- 字幕・注記・出典行は行の間を40px以上。図の上に空きがあれば図を上へ寄せる（2026-10-11、デザイナー役 v9d）
- 札・吹き出し・括弧線は字幕が言う数値の文字に重ねない。札は図の外か棒の中に置いて矢印で指し、括弧線は棒の外側に引く（2026-10-11、デザイナー役 v9b・v9d、2回目で検査に固定）
- 札・枠の中の文字は下余白16px以上。機械検査に「枠内に収まるか」を足す（安全領域・数値の重なりだけでは札の2行目が枠線で切れた）（2026-10-12、デザイナー役 v10b）
- 札の高さは中身の行数に合わせる。揃えるために空白を作らない（2026-10-12、デザイナー役 v9e・v11）
- 同じ図を複数場面で使うときは、ラベルを含む完成枠の高さを共通化すると、字幕の行数による下端の切れを避けやすい。余白の調整は上下を同時に点検する（図を上へ移すと下が空く）（2026-10-14、2026-10-14-full-picture-v2.md・2026-10-15-scene1-r4-scene2-r2.md）
- 幅いっぱいの保存カードは、主役の棒が安全でも右端の比較値・件数が操作ボタン列（x≥960）に重なる。主役と比較値を別々に点検し、検査に元画像の焼き込み値を含める（2026-10-15、2026-10-15-scene1-r4-scene2-r2.md・2026-10-16-split-scene-contract-2.md）

## 動き
- 動きが弱いのは不可。ただし点々の一斉点灯のような、何を表すか分からない動きは不可。並べ替え等は滑らかに（重なり・カクつき無し）（2026-10-11、オーナー v3〜v5）
- 動かすのは見る人が聞きたくなる所だけ。参考は uchita_success の「動くスライド」（2026-10-11、オーナー、BOA-817）
- 小さい件数（0→1）や差（0.00→0.06）はカウントアップしない。字幕が言う値は最初から確定値（2026-10-11、デザイナー役 v8）
- 切り替えで棒を伸び直す図は、値が確定してから2秒止める（2026-10-12、デザイナー役 v10）
- タップは指＋波紋、強調はオレンジ枠。順序は操作→画面変化→0.5秒待機→枠→意味の字幕。STEP 内は固定位置、STEP 間は実スクロール（2026-10-15、2026-10-15-motion-rules.md）
- 実録画面へ答え札を合成するときは、スライダー操作を始める前に旧値を消す。操作の完了時刻だけで字幕を更新すると、操作途中の画面値と前の字幕値が食い違う。frame=0 に加え、操作の開始直後・途中・完了後の静止画で照合する（2026-10-15、2026-10-15-layout-dark.md）
- 強調は全景のまま一筆の四角を描き、描画後に字幕を出す（寄りは復活させない）（2026-10-15、2026-10-15-scene1-r4-scene2-r2.md）
- 連対率の1着率・2連率・3連率は各列の枠を同時に描く。6艇の強調後は説明対象艇の材料カードへ直接切り替え、重ね図へ戻る中継は置かない（2026-10-15、2026-10-15-scene1-r5-scene2-r3.md）
- 長い表の縦パンは、見出しと thead を固定して tbody だけを動かし、強調枠にも同じ移動量を引く。列名が消えると数値の意味を失う（2026-10-15、2026-10-15-scene3-r2.md・2026-10-15-scene3-trial.md）
- 縦パンの前に、表の高さを広げて対象行の下端が収まるかを元画像の座標と倍率で確認する。収まらないときだけ短い本文パンを残し、停止位置で先頭行の札・件数が欠けないことを確かめる（2026-10-15、2026-10-15-scene3-r3.md・2026-10-14-scene1-trial.md）
- 上段と詳細欄を別ページとして切り替えるだけでは、カードを上下にパンする契約を満たさない。連続フレームで同じ部品が動くか確認する（2026-10-17、2026-10-17-split-wind.md）
- 実画面の拡大は縦横比を変えず等倍率で行う。縦横比を変えて余白だけ埋めると文字が変形する。拡大の報告には実倍率と図の下端を添える（2026-10-14、2026-10-14-scene1-r2.md）
- プッシュインは拡大の中心を固定するだけでは主役が中央へ移らず端の数値が切れる。倍率と同時にカメラ中心を主役へ移し、最大倍率の完成フレームで確認する（2026-10-14、2026-10-14-scene1-r3-scene2.md）

## 音・尺・撮影
- チャネル固有の BGM 選曲は [x.md](x.md) へ移動（2026-10-13）
- BGM は1曲の途切れない区間を頭から1本で流す。曲の中の終わりと始まりが入ると違和感が出る。音量の検査だけでなく全尺を聞いて確かめる（2026-10-12、オーナーの12R v12dへの指摘）
- 尺は59秒以内。1分超は申し立てでブロックされる（2026-10-11、オーナー v3〜v5）
- 本番画面の撮影は通信を絞らない。絞るとエラー表示になり、使えない素材と誤認する（2026-10-11、デザイナー役 v9d）
- BGM の区間は ffmpeg silencedetect で無音が無いかを機械で確かめてから決める（ブレイクダウンを切り出して「音楽が鳴っていない」と指摘された）。サイン波の合成音は2回不採用（2026-08-19、memory tiktok_pilot_status_2026_08_18）

- 完成物の検査・合格判定・計画と承認の扱いは [video-qa.md](video-qa.md) へ移動（2026-10-18）
- 動画は恒久的にナレーション無し。ローカル TTS を含む音声合成を使わず、字幕・図・承認済み BGM で完結させる。依頼に無い声・新曲・新しい演出の種類を足さない（2026-10-14、2026-10-14-hq-feedback-no-narration.md）
- Playwright recordVideo の録画サイズが viewport より大きいと、画面が左上に原寸で入り余白が出る環境がある。最終 MP4 の寸法・余白を確認する（2026-10-15、2026-10-15-motion-rules.md）
- Remotion の MP4 に無音の音声トラックがあると、BGM を別入力で渡すだけでは無音側が選ばれることがある。mux で映像・音源の入力を明示し、最終 AAC の LUFS を測る（2026-10-14、2026-10-14-daily-shorts-2026-10-14-19-11.md）
- 拍の長さが決まっていても、答えが出ているのは「拍 − 答えが出るまで」だけ。読む速さは表示の秒数で測る（全貌動画 場面2の試作は4.5秒の拍で表示2.8秒・40字で毎秒14字。答えを次の拍で押すまで残し、1行を全角22字分以内にして直した）。（2026-10-20、visual-designer、sns-video-studio/remotion/src/fullPicture/scene2Timeline.js）
- 重ね図の項目名と枠は「頂点の札の半径＋枠の余白＋16px」以上外へ置き、画面内・Shorts の右ボタン列（x960〜・y900〜1700）の外に収まるかを箱で検査する（6軸で枠が x1080 を越え、5軸で枠が札を横切った）。6艇の札の列も x940 まで。（2026-10-20、visual-designer、scene2Layout.js・verify-full-picture-scene2.js）
- 枠で複数の艇を示すときは艇ごとに枠を分ける（1・2・5号艇を1つの箱にして3・4号艇まで囲った）。重ね図の6艇全体では2号艇を実画面と同じ灰色の半透明にする（白い縁つきの黒は1号艇の白と見分けがつかない）。（2026-10-20、visual-designer、全貌動画 場面2の試作）
- 2行の吹き出しで答えの行を目立たせるには、字の大きさの比を1.25倍以上にし、太さと色の明るさも変える（46/40・太さ 800/700・濃紺とグレー紺では、縦の動画で2行が同じ強さに見えた。前置きの行を 36px・600・#5b6b82 にした）。長い答えの行は自動で縮むので、縮めた後の大きさで比べる（2026-10-20、visual-designer、全貌動画 場面3①、scene2Layout.js の bubbleLine・bubbleFitSize）
- 吹き出しから基準の値を外すときは、比べる語（「全国より」）を図の基準の目印と同じ系統の色で塗って結び付ける（2026-10-20、visual-designer、全貌動画 場面3①）
