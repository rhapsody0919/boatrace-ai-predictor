# X運用プレイブック（2026-08-23策定、2026-08-23追記: 位置づけ再定義）

`docs/reference/x-algorithm-and-growth-notes.md`（Xアルゴリズムの仕組み・調査結果）と、BOA-210のX実地調査（実際の投稿エンゲージメント実測データ）を踏まえて、「日々の運用で何をすべきか」に翻訳した実践ガイド。動画の中身の作り方は`sns-video-producer-prompt.md`・`sns-viral-copywriter-prompt.md`、投稿の手続きは`sns-posting-operations.md`が担当するため、ここでは**アカウント運用そのもの**（投稿以外の日常アクション、投稿の優先順位付け、避けるべき行動）を扱う。

**Xの位置づけ（2026-08-23決定）**: Xそのものでの大規模なフォロワー獲得を主目的にせず、**ブログ・SEO・ブランド認知の補完チャネル**と位置づける。最終ゴール（自治体への役所広告営業、PV・認知度の実績づくり）に対して、X単体のフォロワー数・インプレッションが直接の営業材料になるとは考えにくいという判断から。KPIは「Xがどれだけ伸びたか」よりも「ブログ・サイトへの送客・ブランド想起にどれだけ寄与したか」を優先する。ただし、これはX運用への投資を減らす意味ではない——後述のリプライ戦略のように、低コストで補完的価値を積み上げる施策は積極的に行う。

## 前提知識（詳細は`x-algorithm-and-growth-notes.md`参照）

- フォロワー数そのものより、**投稿ごとの初速エンゲージメント**（投稿直後30〜60分以内の第三者からの反応）が非フォロワーへの露出（Out-of-Network候補入り）を左右する
- Xのランキングは**リプライを圧倒的に重視**する（いいねの27倍、投稿者が返信すれば150倍の重み）
- 実地調査（#ボートレースハッシュタグ）では、**推し活（選手個人への感情移入）・個人の体験談が最も伸び、公式告知・買い目羅列が最も伸びない**
- 音声/BGMの有無はXのランキングに直接影響しない（TikTokと異なる）
- X Communitiesは2026年に廃止済み、外部リンク抑制は2026年7月に公式解消済み

## 絶対厳守（Non-negotiable）

1. **フォロワー数を追う施策を目的化しない**。「フォロワーを増やす」ではなく「1投稿ごとに誰か1人から最初の反応を得る」ことを目標に置く
2. **新機能告知・買い目羅列だけの投稿を作らない**。実地調査でこの型は最弱（自社実測で13ビュー、他アカウントの買い目羅列型も1〜2いいね水準）。機能の告知はブログ・noteに任せ、Xでは「人が読みたくなる文脈」（推し活・体験談・驚き）を必ず添える
3. **通報・大量ミュートを招く投稿をしない**（誤情報・過度な連投・スパム的表現）。ネガティブシグナルはアカウント全体の評判スコアを毀損するため、単発の投稿より優先度が高いリスクとして扱う
4. **X Premiumは投稿量・型が確立するまで見送る**（現状は判断基準に達していない、下記「判断基準の再検討タイミング」参照）
5. **BGM・音源の作り込みに過度な工数をかけない**。ランキングへの直接効果は確認できていないため、字幕での完結性を優先する（`sns-video-producer-prompt.md`のBGMルールは維持しつつ、Xでの成長施策としては期待しない）

## 投稿設計の優先順位（実地調査データに基づく）

投稿を作る際、以下の優先順位でコンテンツの軸を選ぶ。

1. **推し活・選手個人にフォーカスした人間味のあるコンテンツ**（最優先。マスコットキャラ施策と方向性が一致）
2. **個人の体験談・実況口調の内容**（次点。「AIがこう言ってたら本当にそうなった」という一人称の驚き）
3. **会場・データの体系整理（ストック型）**（保存を狙う。TikTok側の知見だが「保存されやすい」という性質はXのブックマーク機能でも応用できる可能性があり、今後検証）
4. **公式告知・機能紹介**（最後の手段。単体では伸びないため、必ず1〜3の要素と組み合わせる）

投稿本文には、**視聴者が反応したくなる「問いかけ」や「賭け（open loop）」を必ず1つ入れる**（`sns-viral-copywriter-prompt.md`の脚本チェックリストと同じ思想をキャプション単体にも適用する）。

## 日次・投稿ごとの運用フロー

### 投稿前

1. 上記「投稿設計の優先順位」に沿った内容か確認する。公式告知単体になっていないか自己点検する
2. 直前の自分の投稿から**2〜3時間以上空いているか**確認する（連投による自己競合を避ける）
3. 可能であれば**火〜木の9〜11時**への投稿を優先する（業界分析ベースの仮説、確証度は中程度。`/x-growth-report`で自社データが蓄積し次第、この仮説を検証・更新する）

### 投稿直後（初速設計）

1. 投稿後、同ジャンル（ボートレース・競艇予想・競馬予想等）で**自分の2〜10倍規模のアカウント2〜3件に、実データ・数値を絡めた質の高いリプライ**を送る（プロフィールへの導線と、自アカウントへの回遊のきっかけを作る）
2. 自分の投稿に返信が来たら、**できるだけ早く返信する**（投稿者が返信することで重みが最大化される、いいねの150倍相当）
3. リプライは機械的な定型文にしない。相手の投稿内容に対する具体的な言及を含める（スパム的リプライはネガティブシグナルのリスクがあるため厳禁）

### 定期メンテナンス（週次目安）

1. **固定ツイートの鮮度確認**: 抽象的な自己紹介ではなく、直近の実測数値（例: 展開予測的中率79%）を反映しているか確認し、古ければ更新する
2. `/x-growth-report`でインプレッション・いいね数の推移を確認し、投稿時間帯・型ごとの傾向を記録する
3. bio・プロフィール画像がブランドと一致しているか確認する（[[boatai_rebrand_investigation_2026_08_19]]のような取りこぼしが再発しないよう、大型ブランド変更時は必ずここも確認する）

## リプライ戦略（2026-08-23決定）

X運用の長期戦略議論（7人パネル）を経て、初動フェーズは**リプライによる関係構築を主戦力にする**方針を採用した。理由: リプライの重み（いいねの27倍、投稿者が返信すれば150倍）は他のどの施策よりも桁違いに大きく、X Communities廃止後の代替導線としても最も再現性が高いため。

**運用方法（半自動フロー）**: `/x-reply-drafts`スキルでClaudeが対象アカウント・返信下書きのリストを生成し、`scratch-tiktok-pilot/x-reply-drafts.md`に出力する。送信はユーザーが個別に手動で行うか、バッチ単位で明示的に承認した場合はClaude Sonnet 5が代行送信する（1バッチごとに毎回確認、包括的な事前承認はしない）。**直接競合（AI予想を掲げるアカウント）は対象から除外する**（2026-08-23決定、比較・牽制と受け取られるリスクを避けるため）。

**初動フェーズは能動的な関与が必要**: ユーザー自身も積極的にリプライを行う想定（2026-08-23合意）。過去に同種の施策（2025-12のX戦略）が仕組み化不足で1週間停止した実績があるため、**4週間を目安に送信率・効果を`/x-growth-report`で確認し、継続/縮小/拡大を判断する**チェックポイントを設ける（詳細は`/x-reply-drafts`スキル参照）。

## X投稿頻度・型選定ロジック（2026-08-24追加、毎日投稿運用）

X運用の長期戦略議論を経て、**可能な範囲で毎日1本投稿する**運用に変更した。投稿履歴は`data/analysis/x-posts/history.json`で管理し、**セッションごとにこの履歴を見てから本日の型・キャラ・題材を判断する**（TikTok側の`data/analysis/tiktok-posts/history.json`と同じ設計思想、ファイルは独立）。

### セッション開始時の運用フロー

1. `data/analysis/x-posts/history.json`を確認し、本日まだ投稿していなければ、**セッションの最初の応答で**「本日Xに動画を投稿しますか？」とユーザーに自発的に確認する（ユーザーから話しかけられるのを待たない）
2. 「はい」と回答があれば、下記の型・キャラ選定ロジックに従って本日の内容を判断し、一言で提案してから制作（`sns-video-producer-prompt.md`の制作フロー）に進む
3. 「いいえ」または反応が無ければ、その日はスキップし`status: "skipped"`として履歴に記録、次のタスクに進む（催促を続けない）。**この`skipped`は「確認した上で見送った日」専用**であり、そもそもその日セッションが一度も開かれなかった日は誰も確認していないため`skipped`を書き込まない（無理に埋め合わせない、記録が単に存在しない日として扱う）
4. 動画完成後は必ずユーザーの承認を得てから投稿する（投稿ごとの明示的承認が必須というルールは不変）
5. 投稿完了後、`history.json`に日付・キャラ・型・題材・動画ファイルパス・投稿ステータスを追記する。可能なら`/x-growth-report`の実績（インプレッション・いいね・プロフィールクリック）も追記する

### 型・キャラ選定ロジック

1. **マスコット3日間ローテーションが未完了なら最優先で継続する**（`history.json`の`mascotRotationStatus`を参照）。day1=キャラA（3本、完了済み）→day2=キャラB→day3=キャラCの順。day2・day3は`X投稿用/`に完成済み動画（`2日目_B_冷静系レーダー.mp4`・`3日目_C_気品系龍神さま.mp4`、いずれも答え合わせ型/児島2R）が既にあるため、追加制作なしでそのまま投稿できる
2. **ローテーション完了後**（3日間終了後）は、勝者キャラが確定していればそのキャラで統一。未確定の場合は暫定でキャラAを使用しつつ、`/x-growth-report`の実績が揃い次第、勝者を確定する
3. 型は`sns-video-producer-prompt.md`のフォーマットライブラリ（答え合わせ型・一覧アピール型・予想数値フック型・本日のデータ一覧型等）から、**直近3投稿と同じ型を連続させない**ように選ぶ
4. 「投稿設計の優先順位」（本ファイル上部）に沿って、推し活・人間味のある文脈を優先する。新機能告知単体は選ばない
5. 予想数値フック型（当日開催中・結果未確定のレースが前提）を選ぶ場合は、**締切まで60分以上の余裕があるレース**が存在するかを先に確認する（無ければ他の型に切り替える。過去に発生した福岡5R→若松2R差し替え事故の教訓、TikTok側の型選定ロジックとも共通の基準）
6. 既存の答え合わせ型ストック（`A2/A3/B2/B3/C2/C3`、唐津9R・江戸川5R・宮島6R・芦屋7R・津3R・大村9R）は、マスコットローテーション完了後の「型のバリエーション」として随時消化してよい
