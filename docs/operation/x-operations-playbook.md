# X運用プレイブック

`docs/reference/x-algorithm-and-growth-notes.md`（Xアルゴリズムの仕組み・調査結果）と、X の実地調査（実際の投稿エンゲージメントの実測）を踏まえて、「日々の運用で何をすべきか」に翻訳した実践ガイド。動画の中身の作り方は`sns-video-producer-prompt.md`・`sns-viral-copywriter-prompt.md`、投稿の手続きは`sns-posting-operations.md`が担当するため、ここでは**アカウント運用そのもの**（投稿以外の日常アクション、投稿の優先順位付け、避けるべき行動）を扱う。X の知見の正本は `docs/knowledge/x.md`、投稿案の評価は `x-channel`（`.claude/agents/x-channel.md`）。

**Xの位置づけ**: Xそのものでの大規模なフォロワー獲得を主目的にせず、**ブログ・SEO・ブランド認知の補完チャネル**と位置づける。最終ゴール（自治体への役所広告営業、PV・認知度の実績づくり）に対して、X単体のフォロワー数・インプレッションが直接の営業材料になるとは考えにくいため。KPIは「Xがどれだけ伸びたか」よりも「ブログ・サイトへの送客・ブランド想起にどれだけ寄与したか」を優先する。ただし、リプライ戦略のように低コストで補完的価値を積み上げる施策は積極的に行う。

## 前提知識（詳細は`x-algorithm-and-growth-notes.md`）

- フォロワー数そのものより、**投稿ごとの初速エンゲージメント**（投稿直後30〜60分以内の第三者からの反応）が非フォロワーへの露出（Out-of-Network候補入り）を左右する
- Xのランキングは**リプライを圧倒的に重視**する（いいねの27倍、投稿者が返信すれば150倍の重み）
- 実地調査（#ボートレースハッシュタグ）では、**推し活（選手個人への感情移入）・個人の体験談が最も伸び、公式告知・買い目羅列が最も伸びない**
- 音声/BGMの有無はXのランキングに直接影響しない
- X Communitiesは2026年に廃止済み、外部リンク抑制は2026年7月に公式解消済み

## 絶対厳守（Non-negotiable）

1. **フォロワー数を追う施策を目的化しない**。「フォロワーを増やす」ではなく「1投稿ごとに誰か1人から最初の反応を得る」ことを目標に置く
2. **新機能告知・買い目羅列だけの投稿を作らない**。実地調査でこの型は最弱。機能の告知はブログ・noteに任せ、Xでは「人が読みたくなる文脈」（推し活・体験談・驚き）を必ず添える
3. **通報・大量ミュートを招く投稿をしない**（誤情報・過度な連投・スパム的表現）。ネガティブシグナルはアカウント全体の評判スコアを毀損するため、単発の投稿より優先度が高いリスクとして扱う
4. **X Premiumは投稿量・型が確立するまで見送る**（下記「判断基準の再検討タイミング」）
5. **BGM・音源の作り込みに過度な工数をかけない**。ランキングへの直接効果は確認できていないため、字幕での完結性を優先する

## 投稿設計の優先順位

投稿を作る際、以下の優先順位でコンテンツの軸を選ぶ。

1. **推し活・選手個人にフォーカスした人間味のあるコンテンツ**（最優先）
2. **個人の体験談・実況口調の内容**（次点。「AIがこう言ってたら本当にそうなった」という一人称の驚き）
3. **会場・データの体系整理（ストック型）**（保存を狙う。Xのブックマークで保存されやすいかは今後検証）
4. **公式告知・機能紹介**（最後の手段。単体では伸びないため、必ず1〜3の要素と組み合わせる）

投稿本文には、**視聴者が反応したくなる「問いかけ」や「賭け（open loop）」を必ず1つ入れる**（`sns-viral-copywriter-prompt.md`の脚本チェックリストと同じ思想をキャプション単体にも適用する）。

## 投稿本数

- **1日の投稿本数の上限は4本**（動画＋ブログ告知＋引用リツイートの合計。引用リツイートも自分のタイムラインに独立した投稿として乗るので数える）。1日4本を超えると投稿どうしの共食いでリーチが下がる
- 目標は**毎日1本**を安定して続けること
- 同じ記事を2回告知しない
- 全貌動画と /today の X 投稿は、検査が通れば自動で送られる（`sns-posting-operations.md`）。その本数も上限に数える

## 日次・投稿ごとの運用フロー

### 投稿前

1. 上記「投稿設計の優先順位」に沿った内容か確認する。公式告知単体になっていないか自己点検する
2. 直前の自分の投稿から**2〜3時間以上空いているか**確認する（連投による自己競合を避ける）
3. 可能であれば**火〜木の9〜11時**への投稿を優先する（業界分析ベースの仮説で、確証度は中程度。`/x-growth-report`で自社データが蓄積し次第、検証・更新する）

### 投稿直後（初速設計）

1. 投稿後、同ジャンル（ボートレース予想・競馬予想等）で**自分の2〜10倍規模のアカウント2〜3件に、実データ・数値を絡めた質の高いリプライ**を送る（プロフィールへの導線と、自アカウントへの回遊のきっかけを作る）
2. 自分の投稿に返信が来たら、**できるだけ早く返信する**（投稿者が返信することで重みが最大化される）
3. リプライは機械的な定型文にしない。相手の投稿内容に対する具体的な言及を含める（スパム的リプライはネガティブシグナルのリスクがあるため厳禁）

### 定期メンテナンス（週次目安）

1. **固定ツイートの鮮度確認**: 抽象的な自己紹介ではなく、直近の実測数値を反映しているか確認し、古ければ更新する
2. `/x-growth-report`でインプレッション・いいね数の推移を確認し、投稿時間帯・型ごとの傾向を記録する
3. bio・プロフィール画像がブランドと一致しているか確認する（大型ブランド変更時は必ずここも確認する）

## リプライ戦略

リプライによる関係構築を主戦力の1つにする。リプライの重み（いいねの27倍、投稿者が返信すれば150倍）は他のどの施策よりも大きく、X Communities廃止後の導線としても再現性が高いため。

- **運用方法**: `/x-reply-drafts`で、「ボートレース」等について今まさに呟いている人を探し、候補と下書きを一覧で提示してまとめて承認を得る。送信は1件ずつ間隔を空ける（同時に送ると bot 的に見える）
- **対象**: 固定リストではなく、都度の生の呟きから探す。フォロワー数は自アカウントの2〜10倍程度を中心に、時々大きめのアカウントにも反応する。直近7日以内に返信済みのアカウントは避ける。予想師・直接競合のアカウントも対象に含めるが、比較・牽制と受け取られないよう、通常より厳格なトーンで書く（`/x-reply-drafts`）
- **トーン**: プロフィールと同じ「開発者本人」の一人称
- **開始と判定**: 始めるかはオーナーが決める。始めたら、4週間を目安に送信率・効果を`/x-growth-report`で確認し、継続/縮小/拡大を判断する

## 判断基準の再検討タイミング

以下の条件が揃ったら、見送っている施策を再検討する。

- **X Premium**: 週5投稿以上を安定して継続でき、かつコンテンツの型（推し活・体験談軸）が固まってから。それ以前の課金は効果が出にくい
- **投稿タイミングの最適化**: `/x-growth-report`で自社データが最低4〜6週間分蓄積されてから、火〜木9-11時仮説の妥当性を検証する
- **リプライ戦略の見直し**: 4週間後の判定で送信率が低い場合は、下書き生成の頻度・粒度自体を見直す

## 型・題材の選び方

投稿履歴は`data/analysis/x-posts/history.json`で管理し、**セッションごとにこの履歴を見てから本日の型・題材を判断する**。セッション開始時の確認の手順は `.claude/rules/content-ops.md` のフローC-2。

1. 型は`sns-video-producer-prompt.md`のフォーマットライブラリ（答え合わせ型・一覧アピール型・予想数値フック型・本日のデータ一覧型等）から、**直近3投稿と同じ型を連続させない**ように選ぶ
2. 「投稿設計の優先順位」に沿って、推し活・人間味のある文脈を優先する。新機能告知単体は選ばない
3. 予想数値フック型（当日開催中・結果未確定のレースが前提）を選ぶ場合は、**締切まで60分以上の余裕があるレース**が存在するかを先に確認する（無ければ他の型に切り替える）
4. **フローA（新機能マルチチャネル展開）で最近公開されたコンテンツ**（`session-start-check.js`の`recentFlowAContent`）も題材の候補源として確認する。新機能そのものではなく、その機能で見えるようになった実データ・実画面を素材として使う（`docs/design/content-ops-flow/spec.md` A4）
