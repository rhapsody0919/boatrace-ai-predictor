# 龍神レーダー TikTok投稿運用フロー（2026-08-24確定）

`sns-video-producer-prompt.md`（動画制作・型選定ロジック）とは別に、「作った後どう投稿・追跡するか」のTikTok版を扱う。Xの`sns-posting-operations.md`と役割は同じだが、プラットフォームごとに分岐させる方針（`sns-marketing-strategy.md`参照）に沿って別ファイルにしている。

## 前提となる制約（Xと共通）

- **投稿は毎回ユーザーの明示的な承認が必要**（Claude側の安全ルール。一度の許可を根拠に以降無許可で投稿し続けることはできない）
- **動画ファイルの添付は自動化不可**（2026-08-24確認済み）。TikTok Studioのアップロード画面（`tiktok.com/tiktokstudio/upload`）のファイル入力に対し、Chrome拡張の`file_upload`ツールでプロジェクト内のmp4ファイルを渡そうとしたが、Xの時と同じ理由（「セッションに明示的に共有された添付ファイルのみ」という制約）で失敗した。毎回ユーザーに手動添付を依頼する前提で設計する。同じ検証を毎回繰り返さない
- **プロフィール写真の自動設定も不可**（2026-08-24確認済み、同じ制約）。ロゴ画像はユーザーに手動アップロードを依頼する

## B. 投稿準備（Claude側で毎回実施）

1. TikTok Studio（`tiktok.com/tiktokstudio/upload`）のアップロード画面を開く
2. 「動画ファイルを`{パス}`から選んで添付してください」とユーザーに明確なパスを伝える（フォルダを探させない）
3. 添付完了の報告を受けたら、キャプション・ハッシュタグを入力する（作法は`sns-viral-copywriter-prompt.md`のTikTok向けセクションを参照、未整備なら次回整備する）
4. 投稿前の最終状態をスクリーンショットで確認し、ユーザーに一言「この内容で投稿していいか」を確認してから投稿ボタンをクリックする

## C. 投稿後のトラッキング

1. `data/analysis/tiktok-posts/history.json`の該当エントリを`status: "posted"`に更新し、`postedAt`を記録する
2. 24時間後を目安に、いいね数・保存数・再生数を確認できれば`metrics`に追記する（TikTok版の定点観測の仕組みはまだ未整備、`/x-growth-report`相当が必要）
3. **投稿完了した動画ファイル（mp4・cover.png）を`sns-video-studio/remotion/out/`から`sns-video-studio/published/tiktok/`に移動する**（2026-08-25追加）。Xの`published/x/`と対称にする運用。`remotion/out/`は「未投稿・ボツ案・検討中」のファイルのみが残る状態を保ち、`history.json`の`videoFile`パスも移動先に更新する。この運用を怠ると`out/`に投稿済み・未投稿・不採用版が無秩序に混在し、2026-08-25時点で43ファイル・116MBまで肥大化した実績がある（旧バージョンの削除漏れも含む）

## D. 1日の投稿本数上限（2026-08-26追加、シャドウバン疑いインシデントを受けて新設）

2026-08-25、1日で7〜8本という異常な頻度で投稿した結果、同日15時台以降の投稿4本（対決煽り型・豆知識型・出目分布型・回収率型）が揃って投稿から18時間以上経っても再生数0のまま、うち1本（対決煽り型）は「コンテンツ審査中」がTikTok公式の目安（新規アカウントで12〜24時間）を超えて長引くインシデントが発生した。それ以前の同日投稿（午前〜正午、3本）は正常に再生数がついていたため、**大量投稿を境に配信が止まった**と推測される。WebSearchで複数の独立ソース（[SocialzAI](https://socialz.ai/blog/tiktok-video-under-review-for-over-24-hours)、[The Scroll School](https://thescrollschool.com/articles/tiktok-shadowban-fix-2026)、[postful.ai](https://blog.postful.ai/shadowbanned-on-tiktok/)）を確認し、短時間の大量投稿がシャドウバンの引き金になりうること、対処法として「パニックで大量投稿・削除を繰り返すのは逆効果」「48〜72時間は新規投稿を完全に停止する」が共通して推奨されていることを確認した。

- **1日の投稿本数は6本を上限とする**（2026-08-26、ユーザー判断で1〜2本案から6本に修正）。当日中にセッションが複数回開かれても、`history.json`の当日エントリ数を必ず確認し、既に6本投稿済みなら新規投稿は翌日に回す
- **審査中が長引いても慌てて削除・再投稿しない**。48時間経過後もコンテンツ審査中のままなら、TikTok Studio内の「設定→サポート→問題を報告」で公式に報告する
- **複数投稿が同時に0再生になるシャドウバンの兆候を検知したら、新規投稿を48〜72時間完全に停止する**。対応すれば7日程度、放置すると最大14日程度で配信が回復するとされる
- セッション開始時のTikTok投稿確認（`.claude/CLAUDE.md`参照）では、`history.json`の当日エントリ数と直近投稿の再生数（0が複数本続いていないか）を必ず確認してから、その日の新規投稿を提案する
