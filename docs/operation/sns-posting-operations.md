# 龍神レーダー SNS投稿運用フロー

`sns-video-producer-prompt.md`（動画制作）・`sns-viral-copywriter-prompt.md`（コピー）とは別に、「作った後どう投稿・追跡するか」を扱う。

## 送り方は2通り

| 種類 | 送り方 | 正本 |
|---|---|---|
| 全貌動画（X の投稿・YouTube 完全版・YouTube Shorts）、/today の X 投稿 | 機械の検査（全貌動画は評価役の検査も）が通れば、承認なしで自動で送る。止めるのはフラグだけ（`sns_auto_send_control.mode` を manual、全体は `sns_x_send_control.paused=true`） | `.claude/CLAUDE.md`「確認のバッチ化を標準運用にする」、ADR-0094、`docs/operation/sns-pdca-loop-runbook.md` |
| それ以外の投稿 | sns-hub 管理画面（`/admin/sns-hub`）で1件ずつユーザーが承認してから送る。手で投稿するときは下の B | このファイル |

## 前提となる制約

- **手で投稿するとき、動画ファイルの添付は自動化できない**。Chrome 拡張の`file_upload`ツールは、Claudeが生成したファイルをパス指定で渡す方式では通らない（「セッションに明示的に共有された添付ファイルのみ」という制約）。毎回ユーザーに手動添付を依頼する
- **Xの標準投稿UIには動画のカバー（サムネイル）編集機能が無い**（X Media Studio のカバー差し替えは Premium が前提で、公式アカウントは非Premium。投稿後の差し替えも不可）。**レンダリング済みmp4のframe=0が、そのままX上のプレビュー静止画になる**。動画制作段階（`sns-video-producer-prompt.md`のセルフレビュー「frame=0で主要テキストが完全に見えているか」）で確認済みであることを、投稿準備に進む前に再確認する

## A. コンテンツ制作

1. `sns-video-producer-prompt.md`の制作フローに従う（実データ確認→UI表示可能かPlaywrightで先に確認→台本→実装→セルフレビュー→レンダリング）
2. `sns-viral-copywriter-prompt.md`のチェックリストに従ってキャプションを作成
3. レンダリング済みファイルを、投稿しやすい名前・フォルダにコピーする（例: `sns-video-studio/published/x/{投稿予定日}_{内容がわかる名前}.mp4`）。`sns-video-studio/remotion/out/`直下は過去の試作が混在しているため、投稿用に整理したコピーを別途作る

## B. 手で投稿するときの準備

1. X の投稿画面を開き、キャプションを入力（ここまでは自動化可能）
2. リンクカードが自動生成された場合、画像が最新ブランドと一致しているか確認する（Xのクローラーキャッシュが古いままのことがある）。不一致なら本文中の裸URLを削除してカード生成自体を回避する
3. 「動画ファイルを`{パス}`から選んで添付してください」とユーザーに明確なパスを伝える（フォルダを探させない）
4. 添付後のプレビューで、動画のframe=0が空白・不完全でないかを目視確認する（Xは投稿後の差し替えができない）
5. 投稿前の最終状態をスクリーンショットで確認し、ユーザーに「この内容で投稿していいか」を確認してから投稿ボタンをクリックする

## C. 投稿後のトラッキング

1. `data/analysis/x-posts/history.json`に日付・型・題材・動画ファイルパス・投稿ステータスを追記する
2. 48時間後・7日後を目安に、インプレッション数・いいね数（可能ならプロフィールクリック数）を確認する。数字から次に変える1点を決めるのは `x-channel`（`.claude/agents/x-channel.md`）

## D. 継続運用のペース

本アカウントは1本ごとに実データ検証・自己レビューを挟むので、同業アカウントの日次〜1日複数回の頻度は目指さない。目標本数は `docs/operation/x-operations-playbook.md`。頻度は少なめでも、「決めた頻度を実際に守れているか」を毎回のセッションで確認する（`session-start-check.js` の `xVideo`）。
