# morning-digest型ネタの古い滞留ターゲットをどう扱うか（未決定）

## 事象

`sns-pipeline-x.md`の定期ポーリング実行（2026-10-02）で、`sns_topic_targets`に
`content_type_id`が`morning-digest`型の`pending`ターゲットが6件滞留していることを確認した。

| topic_id（先頭8桁） | 対象日（topic_textの日付） | 作成日時（UTC） |
|---|---|---|
| 289abb7d | 2026-09-26 | 2026-09-25T20:30 |
| 21804f3a | 2026-09-27 | 2026-09-26T20:30 |
| 0a0aea2e | 2026-09-28 | 2026-09-27T20:30 |
| 1a857906 | 2026-09-29 | 2026-09-28T20:30 |
| b0bb8035 | 2026-09-30 | 2026-09-29T20:30 |
| 3a917018 | 2026-10-01 | 2026-09-30T20:30 |

一方、当日（2026-10-02）分のX向けターゲットは別の実行（`x-pipeline-2026-10-02T10:41:57.879Z`）が
同日中に正常にclaim・生成済み（`draft_id: bfa09c55-...`）だった。つまり「直近1件は毎日ちゃんと
処理されるが、それ以前の分は誰にも処理されず無期限にpendingのまま残る」状態になっている。

## なぜ今回は処理しなかったか

`morning-digest`型の本文は「本日のデータ一覧 {対象日}」「今日の注目」という**当日限定の切り口**
（`sns-pipeline-morning-digest.md`）。対象日が1〜6日前のネタを今日投稿すると、「本日」と書いて
いるのに実際は数日前のデータという、読者に誤解を与える投稿になる。これは`.claude/rules/code-style.md`・
`sns-pipeline-x.md`の「実データ以外は使わない」という絶対厳守事項の精神（データの裏付けは実在しても、
文脈＝鮮度が事実と食い違う）に反すると判断し、6件とも生成せず見送った。claimも行っていない
（処理しない前提でclaimしても意味が無く、DBの変更を増やさない方を優先した）。

## 未決定の論点（ユーザー判断が必要）

1. **滞留したpendingターゲットをどう終わらせるか**: 明示的に`skipped`にする仕組みが無い
   （`sns-pipeline-x.md`・`sns-pipeline-morning-digest.md`のどちらにも「対象日が過ぎた場合」の
   記載が無い）。放置し続けるとsns-hubの進捗マトリクスに古い`pending`が溜まり続ける
2. **なぜ6日分も未処理になったか**: 毎日新しいtopicが作られるたびに、X向けpollingは
   「その日のうち」のものだけ拾えていて、過去分には触れていない可能性がある
   （`getClaimableTopicTargets`はstatus='pending'を全件返すため、本来は古い分も毎回
   候補に挙がっていたはずだが、実際には処理されず積み上がった。原因未調査）
3. **そもそも「対象日が今日でなければ生成しない」というルールを`sns-pipeline-morning-digest.md`
   に明文化すべきか**。現状はこのルールが文書化されておらず、今回の判断はこのRoutine実行時の
   その場の判断に依存した

## 提案

- `sns-pipeline-morning-digest.md`に「対象日が実行日と一致しない`pending`ターゲットは
  `markTopicTargetSkipped`で`skipped`にし、理由に`対象日経過のため見送り`と記録する」旨を明記する
- 上記6件の処理方針（スキップにするか、何らかの形で遅れて投稿するか）をユーザーに確認する
- 6日分滞留した根本原因（claimが実行されなかったのか、claimされたが生成に失敗して
  pendingへ戻されたのか）を別途調査する
