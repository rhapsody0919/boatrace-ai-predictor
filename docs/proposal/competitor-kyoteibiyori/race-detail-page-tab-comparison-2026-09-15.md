# レース詳細ページ タブ再設計: ボートレース日和との比較（2026-09-15）

## 目的・背景

レース詳細ページ（`RaceDetailPage.jsx`）のUI/UXを、ユーザーが使い慣れているボートレース日和の出走表ページ（`race_shusso.php`）のタブ構成に寄せて再設計する。日和のUIをそのまま模倣するのではなく、分かりにくい箇所は龍神レーダーの強み（グラフ・時系列可視化、ドリルダウン）で昇華する方針（過去の日和比較調査と同じ方針、[data-coverage-comparison-2026-09-14.md](./data-coverage-comparison-2026-09-14.md)参照）。

対象タブ（ユーザー指定）: **基本情報 / 枠別情報 / モータ情報 / 今節成績 / 直前情報 / オッズ検索 / オッズ一覧 / 結果**

「データで振り返る」セクション（`RaceReview.jsx`）は不要と明示指示あり、廃止方向で扱う（詳細は後述）。

本ドキュメントは`docs/proposal/competitor-kyoteibiyori/`配下の既存調査（[BOA-282](https://linear.app/boat-ai/issue/BOA-282)横断調査タスク、[data-coverage-comparison-2026-09-14.md](./data-coverage-comparison-2026-09-14.md)、[01-race-card.md](./01-race-card.md)）を踏まえた上で、**レース詳細ページ1画面に絞って**日和の実ページを本セッションで再実機確認し、タブ単位で差分を整理したもの。[01-race-card.md](./01-race-card.md)は2026-08-20時点の調査で9タブ（基本情報/枠別情報/今節成績/直前情報/モーター比較/ボート比較/出目ランク/オッズ/MyData）構成として記録されているが、日和は月2〜5回機能更新されており、2026-09-15時点の実ページは本ドキュメント記載の8タブ構成（結果タブが追加され、モーター比較・ボート比較は統合、出目ランクは独立タブとして残る）に変わっている。**古い資料の9タブ構成は参考にせず、本ドキュメントを最新版として扱う。**

- 日和の実ページを2026-09-15にBrowserで直接確認: `https://kyoteibiyori.com/race_shusso.php?place_no=4&race_no=7&hiduke=20260915`（平和島2日目7R）の全8タブ＋`race_no=1&hiduke=20260914`（結果確定済みレース）で「結果」タブを確認

- 既存Linearチケット（BOA-282, BOA-304, BOA-290, BOA-291, BOA-293, BOA-224, BOA-220, BOA-289, BOA-279, BOA-265, BOA-283, BOA-221等）を`scripts/linear-cli.js get`で個別に本文確認し、重複起票を回避

## 龍神レーダー現状の構造

`RaceDetailPage.jsx`はタブ構成を持たない**単一の縦スクロールページ**。`Header`→`Breadcrumb`→見出し→`PredictionSection`→（本日レースのみ）分析ツールへの導線バナー（`tab=motor`固定）→`RaceNavCard`（同会場のレース一覧）→画面下部固定`RaceBottomNav`、という構成。

`PredictionSection.jsx`が`PredictionPanel`（AI予想）・`RaceResult`（結果）・`RaceReview`（**「データで振り返る」＝ユーザーが不要と指摘した箇所**、BOA-168）の3つを合成し、レース状況（未確定/確定）に応じて表示順を入れ替える。

`PredictionPanel.jsx`の中身（表示順）:
1. `DataRaceTable`（**主役**、行=指標・列=艇番の単一転置テーブル）
2. `VenueTendencyPanel`（会場×枠番の決まり手/トップスタート率/負け決まり手/展示最速転換率、6艇分）
3. `EmbeddedAnalysisSection` ×6〜7（motor/racer/st/extrend/techprofile/returnrate/attackdefenseの各分析ツールタブを折りたたみ埋め込み表示）
4. AI展開予測カード・イン崩れ指数・出目パターン（未確定レースのみ）

`DataRaceTable.jsx`の各行から`/winning-technique?tab=X`（分析ツール、実際は**17タブ**構成: outcome/technique/motor/racer/st/topstart/losing/nige/extime/extrend/techprofile/formranking/returnrate/attackdefense/racecard/venueranking/volatility）へディープリンクする設計。**この分析ツールは既にグラフ・時系列可視化・ドリルダウンの基盤を持っており、レース詳細ページの新タブ構成もこの既存資産（コンポーネント・データ取得ロジック）の再利用を優先すべき**（`.claude/rules/component-reuse.md`）。11タブ（outcome/technique/topstart/losing/nige/extime/formranking/racecard/venueranking/volatility）はレース詳細ページに埋め込まれておらずページ遷移が必要。

**過去の大規模改修で撤去済みのコンポーネント**（`.claude/rules/component-reuse.md`の一覧は現状と乖離しており参考にしない）: `ModelSwitcher`（3モデル切替、unified化で廃止）、`ModelDescription`、`PredictionTable`、`FirstMarkAnimation`（数値不整合で撤去）、複勝予想パネル（BOA-180回収率水増しバグで撤去）。`TrifectaReferenceCard.jsx`・`AttackDefenseTable.jsx`はファイルとして現存するが**呼び出し元が無く実質デッドコード**（別コンポーネント`src/components/analysis/AttackDefenseAnalysis`が同種機能を担っている）。

**オッズ表示は現状ゼロ**。`race_odds`テーブル（単勝・複勝・3連単人気上位、発走60/30/15/10/5分前スナップショット、BOA-49実装）は存在するが、UIから使う`getRacePlaceOdds`（複勝レンジ取得）も呼び出し元が見当たらず未使用。`prediction_odds`（AI予想の想定オッズ）・`TrifectaReferenceCard`も同様に未使用。**日和の「オッズ検索」「オッズ一覧」タブに相当する機能はこのアプリに一切存在しない。**

**今節成績に相当する専用表示も存在しない**（[BOA-291](https://linear.app/boat-ai/issue/BOA-291)で節内の日別進入・着順・ST履歴自体が未取得と既知）。

**結果タブに相当する内容はほぼ実装済み**: `RaceResult.jsx`が着順表（STのWeb Animations演出付き）・配当（単勝/複勝/3連複/3連単/2連単/2連複/拡連複）・決まり手・イン崩れ指数と展開予測の答え合わせまで持つ。ただし独立タブではなく常時表示セクション。

## 「データで振り返る」（RaceReview）セクションの扱い

`RaceReview.jsx`（BOA-168、過去の予想根拠と結果の答え合わせ）は、ユーザー指示により削除対象。ただし以下の考慮点があるため、削除前に決めておくべき論点として明記する:

- `About.jsx`・`FAQ.jsx`が「各レースの予想画面・データで振り返るセクションで、毎回の的中/不的中を確認できます」と説明しており（展開予測79%的中率の実測値の裏付け導線）、削除する場合はこれらの文言も合わせて見直しが必要
- ブログ記事「データで振り返るとは？」（`src/data/blogPosts.js`）が機能紹介記事として存在するため、機能削除後は記事の扱い（削除/現行仕様との整合性修正）を検討
- 日和の「結果」タブは的中検証機能を持たないため、単純に日和スタイルに寄せるなら「結果」タブ＝着順・配当のみで良いが、**AI予想の的中検証という差別化要素を完全に無くしてよいかは事業判断**が絡む。本ドキュメントでは削除の是非自体は判断せず、チケット側で論点として残す
