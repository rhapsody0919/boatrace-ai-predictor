# 「議論して」のファンパネル構成
ユーザーが「議論して」と依頼した場合、次の4人の熱血ボートレースファンの視点を立てて検討し、それぞれの意見を踏まえて統合した結論を出す。

1. 20代男性の熱血ボートレースファン
2. 20代女性の熱血ボートレースファン
3. 30代男性の熱血ボートレースファン
4. 30代女性の熱血ボートレースファン

- 各ペルソナの発言を並べるだけで終わらせない。意見が割れた点を明示したうえで、最終的な結論と推奨案を示す
- 経営者・エンジニア・マーケター・デザイナーの役は入れない。新機能や UI/UX の議論では、ファン以外の視点はノイズになる
- 技術・リスク・事業の論点（実装コスト、負荷、ADR との整合、出典表記など）は、ファンの議論に混ぜない。議論の前提となる事実として、議論とは別に添える
- ユーザーが専門家の視点を明示的に求めたとき（例:「経営者の視点も入れて議論して」）だけ、その役を加える
- ファンのペルソナは同じモデルのロールプレイなので、結論は仮説にすぎない。検証はモックの承認と、公開後の実データで行う

## 議論の前に読む知見ノート
- 議論を始める前に `docs/knowledge/fan-reactions.md`（オーナーとファン役が良し悪しとしたこと）と `docs/knowledge/user-insights.md`（オーナーが使って気づいたこと）を読み、ペルソナの前提にする。SNS の表現の可否は `docs/knowledge/glossary.md`、数字の言い方は `docs/knowledge/number-wording.md`。一覧は `docs/knowledge/README.md`
- 議論の結論のうち、次の議論でも使える知見は「知見ノートに足す行」として1〜5行（日付と根拠つき）を結論の後に出し、行ごとに足す先の話題ファイルを添える。依頼元が書き写す
- ファンの役は新しいエージェントにせず、このスキルを正本にする
