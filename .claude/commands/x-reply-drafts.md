# X返信下書き生成（リプライ戦略の半自動化）

`docs/operation/x-operations-playbook.md`で確認したX運用戦略の実行担当スキル。X（旧Twitter）のランキングはリプライを圧倒的に重く評価する（いいねの27倍、投稿者が返信すれば150倍）ことが調査で判明しており（`docs/reference/x-algorithm-and-growth-notes.md`参照）、Xは「ブログ・SEO・ブランド認知の補完チャネル」と位置づけつつ、初動フェーズはリプライによる関係構築を主戦力にする方針（2026-08-23決定）。

**開始タイミング**: マスコット3日間テスト（キャラA/B/C）が完了してから開始する（2026-08-24合意、動画投稿と同時に新しい施策を増やすと変数が増えすぎるため）。それまでは本ファイルの内容を確定させる準備期間とする。

**Xの投稿はClaude側の安全ルール上、毎回ユーザーの明示的な承認が必須**（実際に送信する行為は「メッセージの送信」に該当する）。このスキルは「承認さえ得ればすぐ送信できる状態まで下書きを作る」ことに徹し、送信自体はユーザーの明示的な合意（バッチ単位でもよい）を得てから行う。

## トーン（2026-08-24追加）

返信はXプロフィール（「🐉 龍神レーダー開発者」）と同じ**開発者本人の一人称**で書く。キャラクター（マスコットA/B/C）の人格は使わない——リプライはどのキャラが勝っても変わらない、アカウントの地の声として運用するため。「データが好きな開発者が興味を持って反応している」トーンを保ち、営業トーン・機械的な相槌にならないようにする。

## 実行手順

### 0. 前回バッチの消化状況を確認（必須、最初に行う）

`scratch-tiktok-pilot/x-reply-drafts.md`が存在すれば、前回生成した下書きのうち何件が「送信済み」になっているか確認する。

- 未消化が多い場合（例: 前回10件中2件しか送信されていない）は、新しいバッチを増やす前にその旨を報告し、量を増やすべきか・質や対象選定を見直すべきかをユーザーに確認する
- ファイルが無い場合（初回実行）はこのステップをスキップする

### 1. リプライ対象アカウント・投稿を探す

**まず`scratch-tiktok-pilot/x-reply-target-accounts.md`（定点対象アカウントリスト）を確認する**。ゼロから毎回検索するのではなく、このリストの中から直近7日以内に返信していないアカウントを優先し、新しい投稿があるか確認する。同じ相手に繰り返し反応する方が関係構築（覚えてもらう）という目的に合致するため。

リストの中から見つからない・新規開拓が必要な場合のみ、Chrome in Claudeで以下を探索する。

- **同ジャンル**: 「ボートレース」「競艇予想」等のキーワード検索・ハッシュタグ（`#ボートレース`等）の最新投稿から、**フォロワー数が自アカウントの2〜10倍程度**（2026-08-24時点で自アカウント55人なら110〜550人目安、成長に応じて上限を引き上げる）で、かつ**直近数時間〜1日以内に投稿**されたものを優先する（古い投稿への返信は本人にも通知が埋もれ、閲覧者にも見られにくい）
- **隣接ジャンル**: 競馬予想等、BOA-210調査で発見したような隣接ジャンルのアカウントも対象に含めてよい（同ジャンルだけでは母数が枯渇しやすいため）。ただし自己PR色の強い大規模予想家アカウントは関係構築目的に合わないため除外する
- スパム的・炎上目的・射幸心を煽るだけの投稿（配当額を煽るのみ等）は対象から外す
- **直接競合（AI予想を掲げるアカウント、例: 「競艇AI PREDICTOR」@KAIPREDICTOR等）は対象から除外する**（2026-08-23決定）。個人のファン・予想家アカウントとは異なり、競合への接触は比較・牽制と受け取られるリスクがあり、関係構築という目的にそぐわないため
- 新しく見つけた良質なアカウント（推し活・体験談・データ分析系）は`x-reply-target-accounts.md`の該当カテゴリに追記する

**フォロワー規模の配分（2026-08-24追加）**: 1バッチ5〜10件のうち、**1〜2件は数千人規模の大規模アカウント（`x-reply-target-accounts.md`のカテゴリD）に配分**する。小規模アカウント中心の運用（関係構築重視）と、大規模アカウント（閲覧数重視、反応率は低い想定）を両方試し、`/x-growth-report`で比較する実験枠として扱う。

1回の実行で**5〜10件**を目安に候補を集める（多すぎると質が落ち、少なすぎると継続の実感が湧かない）。

### 2. 各投稿に対する返信下書きを作成

`docs/operation/sns-viral-copywriter-prompt.md`の精神（データが正しいだけでなく人に刺さる書き方）と、上記「トーン」の一人称開発者視点を踏まえ、各投稿ごとに1つ返信文を書く。

**必須条件（Failなら書き直す）**:
- [ ] その投稿の内容に具体的に言及しているか（テンプレ文の使い回しになっていないか）
- [ ] 実データ・具体的な数値や視点を1つ以上含んでいるか（当たり障りのない相槌で終わっていないか）
- [ ] 自社サービスへの誘導（リンク・宣伝文句）を含んでいないか（初動フェーズのリプライは関係構築が目的で、営業行為に見えた瞬間に逆効果になる。誘導したくなっても our アカウント名がプロフィールから辿れれば十分と割り切る）
- [ ] **200字前後（上限280字）に収まっているか**（2026-08-24修正: 140字では実データの根拠を書ききれないことがあるため上限に近い範囲まで許容する。ただし冗長にならないよう要点は絞る）
- [ ] **バッチ内で文の構造・長さ・書き出しにバリエーションがあるか**（2026-08-24追加）: 同じバッチの5〜10件が似た構文（「〇〇ですね、私も△△です」等）の反復にならないよう、質問形・共感形・データ提示形など型を混ぜる。機械的な反復は不自然さ（ひいてはスパム判定リスク）につながる

### 3. 下書きリストを出力する

`scratch-tiktok-pilot/x-reply-drafts.md`に以下の形式で追記する（ファイルが無ければ新規作成）。

```markdown
## {日付} バッチ

- [ ] 送信済み — {アカウント名}（@handle、フォロワー数、カテゴリA/B/C/D）
  対象投稿: {投稿URLまたは要旨}
  返信下書き: 「{下書き本文}」
```

送信後は`x-reply-target-accounts.md`の該当アカウント行の「最終リプライ日」も更新する。

### 4. 送信

ユーザーに下書きリストを提示し、以下のいずれかで進める。

- **ユーザーが個別に確認しながら手動で送信**（コピー＆ペースト）
- **ユーザーがバッチ単位で明示的に承認**した場合、Claude Sonnet 5が`mcp__claude-in-chrome`で対象投稿を開き、下書き文面をそのまま入力して返信を送信する（承認は「このリストの内容で送ってよい」という具体的な内容に対するものであり、以降の自動送信を意味しない。1バッチごとに毎回確認する）

送信が完了したら、該当行の`- [ ] 送信済み`を`- [x] 送信済み`に更新する。

### 5. 効果測定への接続

送信したリプライ経由の新規フォロワー・プロフィールクリックがあったかは、`/x-growth-report`のステップ1（自アカウントの投稿実績確認）で相手アカウントの投稿を再訪問し、自分の返信への反応（いいね・相手からの返信）を確認する形で間接的に把握する。専用の計測は無い（X APIが無いため）。カテゴリD（大規模アカウント）とA〜C（小規模）の反応率・閲覧数の比較もここで行う。

## 実行頻度（2026-08-24追加）

マスコット3日間テスト完了後、`docs/operation/x-operations-playbook.md`の「セッション開始時のX動画投稿確認」と同様に**セッション開始時に本スキルの実行有無を確認する**運用に組み込む（実装時に`.claude/CLAUDE.md`へ追記する）。動画投稿より低コストなため、動画を投稿しない日でも実行してよい。

## 判断基準・チェックポイント

**2026-08-23決定: この施策は（開始日から）4週間を目安に効果を判定する**（過去に同種の取り組みが仕組み化不足で1週間停止した実績があるため、`/x-growth-report`実行時に必ずこのスキルの消化状況・フォロワー数の推移を突き合わせて報告する）。4週間後、以下を確認する。

- リプライ下書きの送信率（生成した下書きのうちどれだけ実際に送信されたか）
- 送信したリプライ経由と思われるフォロワー増加・プロフィールクリックの有無
- カテゴリA〜C（小規模・関係構築重視）とカテゴリD（大規模・閲覧数重視）のどちらが効果的だったか
- 継続する場合は「量を増やす／質を上げる／対象ジャンルを広げる」のどれを優先するかを再検討する
- 送信率が低い場合（仕組み化ができていない）は、下書き生成の頻度や粒度自体を見直す
