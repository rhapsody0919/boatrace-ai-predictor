# X返信下書き生成（リプライ戦略の半自動化）

`docs/operation/x-operations-playbook.md`で確認したX運用戦略の実行担当スキル。X（旧Twitter）のランキングはリプライを圧倒的に重く評価する（いいねの27倍、投稿者が返信すれば150倍）ことが調査で判明しており（`docs/reference/x-algorithm-and-growth-notes.md`参照）、Xは「ブログ・SEO・ブランド認知の補完チャネル」と位置づけつつ、初動フェーズはリプライによる関係構築を主戦力にする方針（2026-08-23決定）。

**開始タイミング**: マスコット3日間テスト（キャラA/B/C）が完了してから開始する（2026-08-24合意、動画投稿と同時に新しい施策を増やすと変数が増えすぎるため）。それまでは本ファイルの内容を確定させる準備期間とする。

**Xの投稿はClaude側の安全ルール上、毎回ユーザーの明示的な承認が必須**（実際に送信する行為は「メッセージの送信」に該当する）。このスキルは**1件ずつ**「この内容でリプライしてよいか」をユーザーに確認し、承認を得たものだけをその場で送信する（2026-08-24、下書きを一括生成してバッチ単位で承認する方式から変更。バッチ承認は複数の返信がほぼ同時に送信されbot的なパターンに見えるリスクがあるとユーザーから指摘があったため）。

## トーン（2026-08-24追加）

返信はXプロフィール（「🐉 龍神レーダー開発者」）と同じ**開発者本人の一人称**で書く。キャラクター（マスコットA/B/C）の人格は使わない——リプライはどのキャラが勝っても変わらない、アカウントの地の声として運用するため。「データが好きな開発者が興味を持って反応している」トーンを保ち、営業トーン・機械的な相槌にならないようにする。

**相手の熟練度に応じてトーンを変える**（2026-08-25追加）: 対象アカウントのbio・投稿内容から、ボートレースへの熟練度を判断してから下書きを書く。

- **カジュアル層**（例: 「久しぶりに見ました」「あまり詳しくない」等の自己申告、専門用語を使わない投稿）: 実データを**説明する**トーンでよい。相手が知らなそうな情報を教えることは歓迎される
- **熟練層**（例: 支部・準優システム・水面特性等の専門的な話題を自分の言葉で語っている、bioで競艇歴の長さを示している）: 実データで**説明する**のではなく、**相手の主張・仮説を検証する**トーンに切り替える。相手が既に知っていそうなことを教える形になると「上から目線」「豆知識を披露された」ように映りリスクが高い（2026-08-25、実際にこの切り替えをユーザーから指摘され、返信を書き直した実例あり）
- 熟練層への返信で、こちらの検証結果が相手の主張と食い違う・データが不完全な場合は、断定せず**控えめ・自信なさげなトーン**で提示する（例: 「気になったので集計してみたのですが」で始め、「的外れでしたらすみません🙏」等で終える）。相手の知識を否定する形にならないよう配慮する
- 判断に迷う場合はカジュアル層寄りに倒す（熟練層向けの慎重なトーンをカジュアル層に使っても不自然にはなりにくいが、逆は説教くさくなるリスクがある）

## 対象の探し方（2026-08-24、方針転換）

**固定の対象アカウントリストは使わない**。「ボートレース」「競艇」について今まさに呟いている人に、その都度反応しに行く方が、（1）同じ相手への反復訪問より自然に見える、（2）会話が新しい層のフォロワーネットワークに広がる可能性が高い、という理由でユーザー判断により方針転換した（2026-08-24）。当初検討した「定点対象アカウントリスト」で継続的に同じ相手に絡む設計は不採用。

- Chrome in Claudeで「ボートレース」「競艇予想」等のキーワード検索・ハッシュタグ（`#ボートレース`等）を開き、**直近数時間以内に投稿された**ものを優先して探す（鮮度が命。古い投稿への返信は本人にも通知が埋もれ、閲覧者にも見られにくい）
- **検索クエリに`-filter:replies`を付けて、他人へのリプライを最初から除外する**（2026-08-25追加）。これを付けずに検索すると、個人間の会話（例: 「ぴーちゃん」宛の返信）がヒットしやすく、そこに割り込むと会話に無関係な第三者が乱入したように見えてしまう。X検索は独立した投稿（単独ツイート・引用リポストの本文）のみを対象にする
- 検索結果は公式メディアアカウント（スポニチボートレース等）・チケットショップ公式・プロモーション企画（フォロー&リポストキャンペーン等）・自己PR色の強い予想師アカウント（「◯◯予想」「的中率◯％」を名乗るアカウント）で埋まりやすい。これらは対象外とし、**個人の感想・観戦記録・データへの疑問等、一次情報として書かれた投稿**を探す
- フォロワー数は自アカウントの2〜10倍程度を中心に、時々（1バッチ5〜10件のうち1〜2件目安）数千人規模の大きめアカウントも含めて反応率・閲覧数の違いを観察する
- 隣接ジャンル（競馬予想等）も対象に含めてよいが、自己PR色の強い大規模予想家アカウントは除外する
- スパム的・炎上目的・射幸心を煽るだけの投稿（配当額を煽るのみ等）は対象から外す
- **直接競合（AI予想を掲げるアカウント、例: 「競艇AI PREDICTOR」@KAIPREDICTOR等）は対象から除外する**（2026-08-23決定）。個人のファン・予想家アカウントとは異なり、競合への接触は比較・牽制と受け取られるリスクがあり、関係構築という目的にそぐわないため
- `sns-video-studio/x-reply-sent-log.md`（下記ステップ0参照）で**直近7日以内に返信済みのアカウントは避ける**（同じ相手への頻繁な接触は不自然に見えるため）

## 実行手順

実行は2段階に分ける（2026-08-25、1件ずつ探して即下書きする方式で手戻りが多発したため変更）。**フェーズA（候補集め）で5件を確定させてから、フェーズB（下書き・送信）に進む**。フェーズAは下書きを書かない軽い確認、フェーズBは確定済みの5件だけを対象にするため、却下による手戻りがフェーズAの安いコストの間に吸収される。

### 0. 直近の送信履歴を確認（必須、最初に行う）

`sns-video-studio/x-reply-sent-log.md`が存在すれば、直近7日以内に返信したアカウント一覧を確認し、今回の探索でその重複を避ける。ファイルが無い場合（初回実行）はこのステップをスキップする。

### フェーズA: 候補を5件確定させる

#### 1. 候補を1件スクリーニングする

上記「対象の探し方」に従って候補を探す。明らかな除外対象（他人へのリプライ・公式メディア・予想師・競合・直近7日以内に返信済み）はこの時点で機械的に弾き、ユーザーに見せない。

#### 2. 候補をユーザーに提示し、可否だけ確認する

生き残った候補について、**投稿内容・アカウント情報（bio・フォロワー数）・熟練度診断（カジュアル層/熟練層）・困りごとの有無（ツール紹介の例外に該当するか）**を一言添えて提示し、**「この投稿を対象にしてよいですか？」とだけ確認する（この時点ではまだ下書きを書かない）**。

- 承認されたら「確定リスト」に追加し、次の候補探しに進む
- 却下されたらその候補は破棄し、次の候補探しに進む
- **5件確定するまでステップ1〜2を繰り返す**（却下された分は5件にカウントしない）

### フェーズB: 確定した5件を1件ずつ下書き・送信する

#### 3. 返信下書きを作成

確定リストから1件を選び、`docs/operation/sns-viral-copywriter-prompt.md`の精神（データが正しいだけでなく人に刺さる書き方）と、上記「トーン」の一人称開発者視点を踏まえ、その投稿に対する返信文を1つ書く。

**下書きを提示する前に、フェーズAで判定済みの熟練度・トーン方針を一言添える**（例:「熟練層なので検証トーンで書きます」「困りごと系なのでツール紹介を含めます」）。

**ツール紹介の例外に該当する場合は、下書きと同時にスクショも用意しておく**（後から「画像があると尚良い」と言われて撮り直す往復を避ける。撮影手順は下記「ツール紹介の例外」参照）。

**必須条件（Failなら書き直す）**:
- [ ] その投稿の内容に具体的に言及しているか（テンプレ文の使い回しになっていないか）
- [ ] 実データ・具体的な数値や視点を1つ以上含んでいるか（当たり障りのない相槌で終わっていないか）
- [ ] 自社サービスへの誘導（リンク・宣伝文句）を含んでいないか、**ただし下記「ツール紹介の例外」に該当する場合を除く**（初動フェーズのリプライは関係構築が目的で、営業行為に見えた瞬間に逆効果になる。誘導したくなっても our アカウント名がプロフィールから辿れれば十分と割り切る）
- [ ] **200字前後（上限280字）に収まっているか**（2026-08-24修正: 140字では実データの根拠を書ききれないことがあるため上限に近い範囲まで許容する。ただし冗長にならないよう要点は絞る）
- [ ] 直前に送った（同じセッション内の）返信と文の構造・書き出しが似すぎていないか（質問形・共感形・データ提示形など型を変える）
- [ ] 上記「トーン」の熟練度判定を行ったか（カジュアル層=説明、熟練層=検証、迷ったらカジュアル層寄り）
- [ ] 複数の数値を並べる場合、箇条書き（改行+「・」）で構造化して視認性を上げているか（2026-08-25、文章で並べると読みにくいとの指摘あり）
- [ ] **「競艇」という語を使っていないか**（2026-08-25追加）: `.claude/rules/code-style.md`の表記統一ルール（「ボートレース」で統一、役所広告除外リスクのため例外なし）はリプライ本文にも適用される。**相手の投稿・bioが「競艇」表記でも、こちらの返信文では「ボートレース」に置き換える**（相手の言葉をそのまま引用返しすると混入しやすいので特に注意。実際に下書きに紛れ込みユーザー指摘で送信前に修正した実例がある）

### ツール紹介の例外（2026-08-25追加）

原則リンク・宣伝文句は含めないが、**相手が「買い目がわからない」「予想の仕方に迷っている」等、明示的に困りごと・悩みを投稿している場合に限り**、boat-ai.jpのツール（データ分析ページ、「AI用にコピー」機能等）をさりげなく紹介してよい。一般的な宣伝ではなく、相手の困りごとへの具体的な解決策として提示する文脈に限定する。

- 該当する実画面のスクショ（例: 「AI用にコピー」ボタン、データ出走表）をPlaywrightで撮って添付すると説得力が増す。撮影はローカルdevサーバー（`npm run dev`）に対して行う
- 画像添付は`file_upload`ツールが動画添付と同じ理由（Claude生成ファイルのパス指定を受け付けない）で失敗するため、**ユーザーに手動添付を依頼する**（スクショはSendUserFileでチャットに送り、そこから保存・ドラッグ&ドロップしてもらう）
- この例外はあくまで「困りごとへの返信」限定。相手が特に悩みを表明していない一般的な投稿への返信では、これまで通りツール紹介は行わない

**データの裏取りは、Supabaseに実際に問い合わせて検証する**（想像や一般論で数値を作らない）。`race_entries`・`race_results`・`racer_profiles`（選手の支部・出身地等、`racer-fortune-telling`機能向けに2026-08にスクレイピング済み）等を組み合わせれば、会場別成績・支部別成績等その場で集計できることが多い。「このデータは無い」と即断する前に、`information_schema`やコードベース内の`.from("テーブル名")`を横断grepしてテーブル構成を確認する（2026-08-25、当初「支部データは無い」と回答したが、ユーザーの指摘で`racer_profiles`テーブルの存在に気づき実際に集計できた実例あり）。

#### 4. ユーザーに下書きを1件ずつ確認する（2026-08-24、方式変更）

対象アカウント・投稿の要旨・返信下書きを提示し、**「この内容でリプライしてよいですか？」と個別に確認する**。複数件をまとめて一覧で提示して一括承認を得る方式は取らない（候補の可否確認はフェーズAで既に済んでいるため、ここでは文面の内容確認のみ）。

- 承認された場合: Claude Sonnet 5が`mcp__claude-in-chrome`で対象投稿を開き、下書き文面をそのまま入力して送信する（またはユーザーが手動で送信する）。送信後、`sns-video-studio/x-reply-sent-log.md`に日付・アカウント・投稿要旨・返信内容を追記する
- 却下された場合: 同じ候補で文面だけ書き直すか、フェーズAに戻って別候補を探すかをユーザーに確認する
- 確定リストの5件を消化するまでステップ3〜4を繰り返す（1回のセッションの目安は5件。多すぎると質が落ちる。ユーザーが途中で終了を指示したらそこで打ち切る）

#### 5. 相手から返信が来た場合、こちらからも返信する（2026-08-25追加）

送信したリプライに対して相手から好意的な返信があった場合、**こちらからも一言返信する**（Xのランキングでは投稿者自身の返信がいいねの150倍評価される、`docs/reference/x-algorithm-and-growth-notes.md`参照）。会話を1往復で終わらせず、自然に続けられる限り継続する方が費用対効果が高い。

- このフォローアップ返信はフェーズAの「5件確定」のカウントには含めない（新規候補探しとは別枠の、既存の会話継続）
- トーン・実データ含有・承認フロー等の他の必須条件は通常の返信と同じ
- ユーザーから直接「返信が来ていた」と共有された場合は、その場で内容を確認し、フォローアップ案を提示する

#### 6. 効果測定への接続

送信したリプライ経由の新規フォロワー・プロフィールクリックがあったかは、`/x-growth-report`のステップ1（自アカウントの投稿実績確認）で相手アカウントの投稿を再訪問し、自分の返信への反応（いいね・相手からの返信）を確認する形で間接的に把握する。専用の計測は無い（X APIが無いため）。フォロワー規模の異なる相手への反応率・閲覧数の違いもここで比較する。

## 実行頻度（2026-08-24追加）

マスコット3日間テスト完了後、`docs/operation/x-operations-playbook.md`の「セッション開始時のX動画投稿確認」と同様に**セッション開始時に本スキルの実行有無を確認する**運用に組み込む（実装時に`.claude/CLAUDE.md`へ追記する）。動画投稿より低コストなため、動画を投稿しない日でも実行してよい。

## 判断基準・チェックポイント

**2026-08-23決定: この施策は（開始日から）4週間を目安に効果を判定する**（過去に同種の取り組みが仕組み化不足で1週間停止した実績があるため、`/x-growth-report`実行時に必ずこのスキルの消化状況・フォロワー数の推移を突き合わせて報告する）。4週間後、以下を確認する。

- 実際に送信できた件数（1回あたり5〜10件を安定して継続できているか）
- 送信したリプライ経由と思われるフォロワー増加・プロフィールクリックの有無
- フォロワー規模の異なる相手（自分の2〜10倍 vs 数千人規模）でどちらが効果的だったか
- 継続する場合は「量を増やす／質を上げる／対象ジャンルを広げる」のどれを優先するかを再検討する
- 送信率が低い場合（仕組み化ができていない）は、実行頻度や1回あたりの目標件数自体を見直す
