現在ブランチの PR を Codex (OpenAI) にレビューさせ、指摘へ対応し、approve に収束させる。Codex はレビュー観点を `AGENTS.md` から読む。Codex はコードを書き換えない (read-only)。修正は必ず Claude が行う。

このコマンドは boatAI の既存レビューフロー（`/code-review` によるセルフレビュー → PR コメントに記載 → ユーザーへの完了報告 → ユーザー承認後にマージ）に対する**追加の第三者チェック**として使う。マージの最終承認はこれまで通りユーザーが行う。**自動マージはしない。**

前提: PR が作成済みで、`npm run build` がグリーンであること。`/code-review` (Claude セルフレビュー) を先に通し、指摘への対応をコミット・push 済みであること。

base ブランチ = `$ARGUMENTS`（未指定なら `master`）。

## ループ手順 (approve に収束するまで繰り返す)

1. **レビュー実行**: `bash scripts/codex-review.sh <base>` を実行し、返ってきた JSON (`verdict` / `summary` / `findings[]`) を読む。
   - 終了コード 2 (実行エラー) なら停止し、原因 (未認証・diff 取得失敗など) をユーザーに報告。`codex login` 未済が典型（`! codex login` の形でユーザーに実行してもらう）。
2. **findings へ対応** (各 finding ごとに判断):
   - `critical` / `high`: **必ず対応**。コードを修正する。
   - `medium` / `low`: 修正するか、修正しない場合は**反論として理由を記録**。
   - 各 finding に対し Claude が「修正」か「反論 (誤検出/許容できる理由)」かを自分で判断する。反論する場合は根拠を示す (推測で却下しない)。
3. **修正を検証**: 修正したら `npm run build` を実行し、成功を確認。UI/挙動に関わる修正は Playwright 等での動作確認も行う。失敗したら直してから次へ。
4. **コミット**: 修正を `fix: ... (Codexレビュー指摘対応)` 形式でコミットし、PR ブランチに push。
5. **再レビュー**: 1 に戻り、再度 `scripts/codex-review.sh` を実行。
   - `verdict == "approve"` (critical/high 0 件、終了コード 0) になったら**収束**。ループを抜ける。
   - まだ block なら 2〜5 を繰り返す。
6. **無限ループ防止**: 同一ラウンドを **最大 5 回**まで。5 回で収束しない、または同じ指摘が往復するだけで進展しない場合は停止し、残った findings と各々への対応/反論をユーザーに提示して判断を仰ぐ。

各ラウンドで「指摘 → 対応 (修正 or 反論理由)」を簡潔に記録し、収束後の報告に含める。

## 収束後

approve に収束したら、以下をユーザーへの完了報告に含める（PR コメントへの記載も忘れずに、プロジェクト CLAUDE.md の既存ルールに従う）。

- Codex レビューの各ラウンドの指摘と対応（修正 or 反論理由）
- 修正後の検証結果 (`npm run build` + 該当する動作確認)
- **マージ可否の確認をユーザーに求める**（このコマンドはマージを実行しない）
