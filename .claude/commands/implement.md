# Linear チケット自動実装

引数: $ARGUMENTS (Linear チケットID。例: BOA-123)

## 手順

### 1. チケット情報の取得
Linear MCP を使って、チケット `$ARGUMENTS` の詳細情報を取得してください（認証が切れていたら `scripts/linear-cli.js` に切り替える。`.claude/CLAUDE.md`）：
- タイトル
- 説明（実装要件）
- 優先度
- ラベル
- 関連チケット

### 2. 要件の確認と作業場所
- 影響範囲が1ファイルに閉じない、または挙動が変わるチケットは、実装方針を考える前に `spec-ambiguity-detector` にチケット本文をそのまま渡し、決まっていない点を列挙させる（`.claude/CLAUDE.md`「実装前の要件確認」）。確認が要る点が2つ以上あれば分割を提案する
- `git worktree` で最新の `origin/master` から作業ツリーとブランチを用意する。ブランチ名は `claude/boa-123-<要約>` の形にする（`codex/` は Codex 専用）

### 3. 並列調査（サブエージェント）
以下の2つのサブエージェントを**並列で**起動してください（Agent tool。Agent Teams機能はこのプロジェクトでは使わない。理由は`.claude/CLAUDE.md`「サブエージェントの使い分け」参照）：

**エージェントA: コードベース調査**
- チケットの要件に関連する既存コードを探索
- 変更が必要なファイルを特定
- 既存のパターン・規約を確認

**エージェントB: 影響範囲分析**
- 変更による影響範囲を分析
- 依存関係を確認
- 既存テストの有無を確認

### 4. 実装計画（Plan）
調査結果をもとに、**実装前に計画を提示**してください：
- 変更対象ファイル一覧
- 各ファイルで行う変更の概要
- 実装の順序（依存関係を考慮）
- リスクや懸念点

**ユーザーの承認を得てから**次のステップに進んでください。
計画に問題がある場合は、フィードバックを反映して計画を修正してください。

### 5. 実装
承認された計画をもとに実装を行ってください：
- 既存のコーディング規約（`.claude/rules/code-style.md`）に従う
- モバイルファーストで実装
- デザイントークン（`src/styles/design-tokens.css`）を使用

### 6. 並列検証（サブエージェント）
実装完了後、以下のサブエージェントを**並列で**起動してください：

**エージェントC: ビルド検証**
- `npm run build` でビルドエラーがないか確認

**エージェントD: コード品質チェック**
- 実装がチケットの要件を満たしているか確認
- セキュリティ上の問題がないか確認
- パフォーマンスの懸念がないか確認

**エージェントE: データ精度検証（新規の集計・分析機能を含む場合のみ）**
- `data-accuracy-verifier` サブエージェントを使う
- 集計結果が実データと一致するかだけを見る。コード品質はエージェントDの担当

### 7. コミット & Linear 更新
- 変更をコミット（コミットメッセージに `$ARGUMENTS` を含める）
- Linear でチケットの状態を `In Progress` にする（BOA チームの状態は `Backlog`/`Todo`/`In Progress`/`Done`/`Canceled`/`Duplicate`。「レビュー待ち」は無い。マージしたら `Done`）
- チケットにコメントで実装内容のサマリーを追加

### 8. PR 作成
`/create-pr` コマンドの要領で PR を作成してください。
PR の説明に Linear チケットへのリンクを含めてください。その後は `.claude/CLAUDE.md`「実装完了後の自動レビュー」に従う。

## 注意事項
- 実装が大きすぎる場合は、ユーザーに分割を提案してください
- 不明な要件がある場合は、実装前にユーザーに確認してください
- テストファイルがある場合は、テストも更新してください
